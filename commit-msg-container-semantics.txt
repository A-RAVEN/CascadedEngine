feat(codegen): 容器与包装器语义落地，归档 codegen-container-semantics

工具与生成物（本 change 的交付物）：
- 分类先取规范化类型：uint32_t / uint64_t 这类别名不再落进 Opaque（改动前实测就是 Opaque）。
- 容器识别：按规范化基名（vector / map / string / unordered_* …）并支持 C 数组按维度；字段表逐成员
  给出 key / element 两个指向同构描述的指针，嵌套容器因此能表达多层（vector<vector<int>> 的两层
  都在表里）；多维 C 数组的元素描述按维度下移一层（int a[2][3] → int[3] → int）。
- 包装器（NameHash / PathHash / HashObj）只记录 FieldFlags::Wrapper、不算不透明；HasOpaqueElement
  只记裸指针 / 托管指针。
- 序列化：容器读写改为按容器类型递归（cgWriteContainer / cgReadContainer）；无序容器先排成规范顺序
  （map 按键、set 按元素本身，值不参与排序）；读前先清空目标容器，读回内容只由载荷决定；C 数组按
  "先 extent、再逐个元素"写，多维因此天然分层。生成的相等判断改用递归的逐层比较 —— std::equal 对
  多维数组的"行"会退化成比较行地址，会让 equal() 恒假（本轮自己改出来的回归，已修）。
- 哈希：容器按同一套规范顺序累加，元素显式调用它自己的哈希特化（浮点先做 -0.0 → +0.0 与 NaN 规范
  化），不再写 h.hash(item) —— 平凡可拷贝的元素会先走整块字节那条分支，规范化会静默失效。
- 六条拒绝路径，各有具名夹具、非零退出码与点名成员/原因的 stderr：参与排序的一侧没有全序 17、
  元素是裸/托管指针 15、重复键容器 14、键或元素不可默认构造 16、按位存储容器 13、元素是内含无序
  容器的结构体 12。全序判据接受 operator<=>（只认 operator< 会把只有 <=> 的真实键类型如 NameHash
  全部误拒，这条误拒已实测）。
