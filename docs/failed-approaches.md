# 失败方案台账（engine-codegen-framework 及本项目通用）

> **用途**：记住"想过、试过、被实测否决"的方案，避免每一轮或每个新开的子 agent 从零推理时**把同一批坑再踩一遍**。
> **纪律（勿违反，否则台账自己会变成新病灶）**：
> - **只追加**；表格；每条 ≤3 行；**禁行号**（会漂移）；**禁过程叙述**。
> - **台账本身不作为审查对象** —— 去审它的措辞就是"审描述"，必然不收敛。
> - **必须写"何时可以重新考虑"**，否则台账会退化成对好想法的永久封杀。
> - **写入时机**：某轮发现"上一轮修复自己引入的问题"／某组数字被撤回／某方案被实测否决 → **当场补记，不拖到轮末**。
> - **读取时机**：① 提任何方案**之前**；② 作为 **Workflow / 子 agent 的固定输入**（它们没有历史上下文，不喂就一定重提旧方案）。
> - **举证责任在提出方**：新方案与下表某条**实质相同**时，必须给出「**这次哪里不同**」的**可核证据**；**给不出即作废**，不得实施、不得上报为发现。
