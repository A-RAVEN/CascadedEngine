# csharp-bindings Specification

## Purpose
按冻结的投影矩阵把被标注的 C++ 接口生成成两侧绑定（C ABI thunk + 版本化函数表 + 句柄表 + 布局清单 + C# 声明），并规定生成期怎么拒绝无法投影的形状。
## Requirements
### Requirement: 一个接口一份产物，两侧由同一次生成产出
生成器 MUST 为每个被标注为可绑定的接口产出两份接口文件：C++ 侧的 `<接口>.Bindings.cpp`（thunk + 函数表 + 取表函数 + 句柄表样板）与 C# 侧的 `<接口>.Bindings.cs`（包装类 + 句柄结构体 + 布局清单常量）。接口需要的公开记录和枚举可以另外产出按类型命名的共享 `.Bindings.cs`；这些文件 MUST 与引用它们的接口文件来自同一次生成。每个接口的方法集合与顺序 MUST 在两侧完全一致；MUST NOT 允许一侧手改而与另一侧错开。

同一限定公开值类型的共享文件 MUST 具有确定内容。重复生成时内容必须逐字节相同，同名不同限定名或同名不同内容 MUST 生成失败；共享文件不得复制接口内部的 C 镜像、函数表或错误通道。

此外，生成器 MUST 在同一次构建内、按登记表发射输入产出**跨接口**的两份登记产物：C++ 侧宿主登记表（编号清单、`get_interface_api` 路由、`EngineApi` C++ struct 及其装配代码与编译期断言）与 C# 侧 `EngineApi.Bindings.cs`（与 C++ struct 逐字段同批对照的托管 struct、版本/大小/编号生成常量）。登记产物 MUST 与接口产物同样落在构建目录、不进源码树；重跑 MUST 逐字节相同；`build.py` 的期望产物前缀清单 MUST 包含登记产物，缺失即构建失败。宿主与 `Host.cs` 消费登记产物后，MUST NOT 再各自保留手写的编号常量、镜像 struct 或逐接口取表分支。

#### Scenario: 两侧方法集合逐条对齐
- **WHEN** 对一个被标注接口跑生成器
- **THEN** 生成的 C++ thunk 数量、名字顺序 MUST 与 C# 包装里的方法数量、名字顺序逐条相同（比对脚本给出条数与逐条差异）

#### Scenario: 共享值类型不复制接口内部产物
- **WHEN** 一个接口使用公开记录或枚举，另一个接口随后使用同一限定类型
- **THEN** 两个接口仍各有自己的两份接口文件，共享值类型文件 MUST 只含公开值类型且内容一致，不得出现第二份函数表、布局清单或接口私有转换函数

#### Scenario: 逐接口判据不得把共享值类型当成接口
- **WHEN** `Tools/CodeGen/check_bindings.py` 扫描同时包含接口产物和共享公开值类型产物的目录
- **THEN** `check_surface` 与 `check_alignment` MUST 只处理具有对应 `.Bindings.cpp` 的接口，共享值类型 MUST 改走公开内容、哈希和唯一性判据，不得要求它包含接口类或异常类

#### Scenario: 登记产物与接口产物同批生成且可核缺失
- **WHEN** 在一次构建后人为删除登记表或 `EngineApi.Bindings.cs` 产物再重跑 `build.py` 的绑定核对
- **THEN** 期望产物前缀检查 MUST 点名缺失项并让构建失败；正常构建下两侧 struct 的字段与编号 MUST 出自同一份登记产物，`check_bindings.py` 的编号期望对账 MUST 为 0 处差异

### Requirement: 生成的 C ABI 面只允许审计表规定的形状
生成器 MUST 只按 `csharp-bindable-surface` 的投影矩阵出形状：blittable 标量与结构体、`T const* + 数量`、不透明句柄、`char const* + len`、以及**函数指针 + `void* user`**（回调那一行；`user` 只作不透明令牌，生成代码 MUST NOT 解引用它）。生成的 C ABI 签名里 MUST NOT 出现容器类型（`castl::vector` / `map` / `string` 等）、模板、`shared_ptr` / `unique_ptr` / `weak_ptr`、C++ 引用。

#### Scenario: 签名里出现容器类型即算不合格
- **WHEN** 扫描生成的 `<接口>.Bindings.cpp` 里所有 `extern "C"` 声明
- **THEN** 容器类型名、模板尖括号、`shared_ptr`/`unique_ptr`/`weak_ptr`、C++ `&` 引用的命中数 MUST 全为 0（脚本逐类给命中数与命中行）

### Requirement: 回调必须带保活与注销，异常必须转成错误码
带 `castl::function<void(...)>` 参数的已审计回调方法 MUST 生成真实的注册、调用与注销通路，MUST NOT 再要求用"本轮未实现"排除。C ABI 必须使用与原始回调参数顺序一致的原生函数指针和不透明 `void* user`，并产生内部注册号与注销伴生；注册号、函数指针和用户令牌 MUST NOT 出现在公开 C# 表面。生成的托管注册表 MUST 保活委托，替换、置空和表面对象释放 MUST 同时清理原生注册与托管保活项。原生函数指针 MUST 调到生成的托管桥，MUST NOT 生成空体 thunk 或固定签名的桩。

回调桥 MUST 阻止非主线程直接进入托管委托，并 MUST 阻止回调执行期间修改同一个回调注册。用户委托抛出的异常 MUST 在托管桥内捕获，MUST NOT 穿过原生回调边界；下一次主线程调用 MUST 通过对应接口的异常类型上报统一错误表中的回调错误标识与原始异常文本。`Tools/CodeGen/CodeGenMain.cpp` 的生成期错误表、`Tools/CodeGen/check_bindings.py` 的 `ERROR_CODE_TABLE` 与 `Tools/CodeGen/README.md` MUST 同步包含该标识，判据不得再把合法的回调错误码当成未知错误。

#### Scenario: 未排除的回调方法必须生成真实调用
- **WHEN** 对一个带 `castl::function<void(...)>` 参数的已审计方法生成绑定并触发原生回调
- **THEN** 生成器 MUST 成功，托管委托 MUST 按原参数类型与顺序收到真实读数，且原生实现确实持有由生成代码安装的回调

#### Scenario: 替换和置空必须清理旧注册
- **WHEN** 先注册一个委托，再用另一个委托替换，随后置空并分别触发原生事件
- **THEN** 替换后只有新委托执行，置空后两个旧委托都不再执行，生成注册表中对应保活项 MUST 已删除

#### Scenario: 回调执行期间修改同一个注册必须失败
- **WHEN** 用户委托在执行期间尝试替换或清空它自己
- **THEN** 桥 MUST 返回可诊断错误且不得销毁正在执行的回调，进程 MUST 继续运行

#### Scenario: 用户委托抛异常不得跨边界
- **WHEN** 一个已注册委托抛出异常，随后主线程再调用 `UpdateSystem` 或回调注册方法
- **THEN** 异常 MUST NOT 穿出原生回调边界，后续公开调用 MUST 抛出对应接口异常并包含统一回调错误标识和原始异常文本

### Requirement: 函数表版本化，且本 change 只做"版本相等"校验
生成的函数表 MUST 是带 `abi_version` 与 `size` 的结构体，由 `extern "C"` 的取表函数填充并返回实际大小；取表函数的签名 MUST 让调用方把自己的版本与大小传进来（`GetApi(uint32 version, uint32 size, <表>* out)`），引擎侧 MUST 只写调用方 `size` 与真实表大小中较小的那一段，并 MUST 回填自己真实的大小。**本 change 只要求"版本相等 + 大小相等"这一档**（与已落地的 `Scripting/Managed/Host.cs` 校验口径一致）；"旧侧按自己较小的 size 也能通过"的追加兼容 MUST NOT 写进本 change 的验收 —— 在 `GetApi(out)` 这种只有出参的签名下它不成立（引擎不知道调用方缓冲区多大，写下去就越界）。

#### Scenario: 版本或大小不等必须拒绝
- **WHEN** 用错误的 `abi_version` 或错误的 `size` 调取表函数
- **THEN** MUST 返回 0（表示拒绝）且 MUST NOT 往调用方缓冲区里写超出其 `size` 的字节

#### Scenario: 相等时通过并回填真实大小
- **WHEN** 用正确的版本与大小调取表函数
- **THEN** MUST 返回真实表大小，且调用方缓冲区里的字段与生成物逐项一致

### Requirement: 句柄分配与释放由生成物负责，且带代际号
生成的句柄 MUST 同时编码序号与代际号；释放 MUST 让代际号进位，使旧句柄 MUST 被识别为失效而不是命中新对象。释放 MUST 让生成物不再持有该对象的强引用 —— 释放之后，句柄表里那一项的强引用 MUST 为空，否则对象永不被析构。**每个被绑定的接口 MUST 无条件生成两个泛用入口**：`extern "C" void <接口>_ReleaseHandle(void* self, uint64_t handle)` 与 `extern "C" void* <接口>_ResolveHandle(void* self, uint64_t handle)`（后者把句柄换成对象指针，失败时置"句柄失效"错误码并返回空）。**`ResolveHandle` 是必需的**：C ABI 面所有方法入口的第一个参数都是 `void* self`，没有任何一个收定宽句柄，没有解析入口就无法用句柄调到方法。这两个入口及按方法生成的 `<接口>_Release<方法名>` MUST 保持发行者角色，既有的按方法生成入口 MUST 保留（不得为了改名去动既有调用点），既有序号、代际和发行者校验行为不得因新增目标类型而改变。返回 `castl::weak_ptr<T>` 的方法 MUST 投影成**弱句柄**：句柄表存弱引用、MUST NOT 抬高 `use_count()`，对象析构后旧句柄 MUST 被判失效 —— 且这个失效判定 MUST 走"弱引用已过期"这条路径，MUST NOT 只靠释放时的代际进位来产生。`shared_ptr<T>` 入参 MUST 反查句柄表并重建目标类型，反查失败 MUST 只置错误码而不崩溃；`weak_ptr<T>` 入参 MUST 继续生成期拒绝。MUST NOT 生成"句柄背后的内存由托管侧 free/delete"这种跨边界所有权。

每个接口 MUST 在函数表末尾追加 `<接口>_ResolveTargetHandle` 与 `<接口>_ReleaseTargetHandle`，不得重排既有槽或改变 ABI 版本。公开 C# 的已绑定接口返回 MUST 使用目标入口，非接口数据对象的强/弱句柄继续使用发行者入口。

句柄表项 MUST 同时记录发行者与目标对象的完整限定类型。`shared_ptr<T>` 入参 MUST 从强返回句柄复用强引用、从弱返回句柄临时取得强引用；借用句柄、错误类型、已失效句柄 MUST 失败且不得进入原生实现。目标接口解析借用返回时 MUST 要求发行者见证存在且仍存活；旧发行者路径可以保留无见证借用句柄到显式释放，但不得用它取得公开目标表面。两类释放 MUST 先按各自角色校验，再清除表项和引用并进位；目标死亡或见证过期不得阻止清理。借用释放不销毁目标，现有回调借用作用域不变。

公开租约释放 MUST 使用目标释放入口并检查错误通道，成功才清租约；释放后的表面对象调用 MUST 抛出 `ObjectDisposedException`，不得进入原生 thunk。`null` 对象参数 MUST 在进入原生接口前拒绝。

#### Scenario: 释放后的旧句柄必须报失效
- **WHEN** 创建一个资源拿到句柄、释放它、再用同一个数值调用任一方法
- **THEN** 调用 MUST 返回"句柄失效"错误码（不是崩溃、也不是命中新对象），且错误码可与其他错误区分

#### Scenario: 跨头文件目标接口能够解析和释放
- **WHEN** 一个接口返回另一个头文件中已绑定接口的强或弱智能指针，并由公开 C# 取得目标表面对象
- **THEN** 公开解析、方法调用和释放 MUST 使用目标接口入口与同一原生对象，错误目标类型 MUST 失败；旧发行者入口和非接口数据对象句柄的既有测试 MUST 保持原结果

#### Scenario: 旧发行者错配与新目标释放在同一对象上并存
- **WHEN** `IWindow` 发行一个目标为 `IWindowSystem` 的借用句柄
- **THEN** 旧 `IWindowSystem_ReleaseHandle` MUST 继续因发行者不符而失败，新 `IWindowSystem_ReleaseTargetHandle` MUST 能按目标类型清理同一句柄；按方法生成的 `IWindow_ReleaseGetWindowSystem` MUST 仍可按发行者释放

#### Scenario: 无见证和过期见证的借用句柄必须受控
- **WHEN** 目标接口解析一个无见证或见证已过期的借用句柄，随后显式释放有效表项
- **THEN** 目标解析 MUST 失败，释放 MUST 仍清除槽位与弱引用并进位；旧发行者路径的无见证兼容行为不得使公开目标解析绕过见证要求

#### Scenario: shared_ptr 入参按句柄种类重建
- **WHEN** 分别把强返回句柄、弱返回句柄、借用句柄和错误类型句柄传给 `shared_ptr<T>` 参数
- **THEN** 强返回句柄 MUST 复用原对象，弱返回句柄 MUST 在调用期间保活同一对象，借用句柄与错误类型 MUST 报错且原生实现调用次数为 0

#### Scenario: weak_ptr 入参不得被误当成 shared_ptr
- **WHEN** 一条方法接收 `weak_ptr<T>` 参数
- **THEN** 生成器 MUST 非零退出并点名该参数，不得以"弱返回句柄已支持"为理由生成入参绑定

#### Scenario: 目标释放与释放后调用都有托管行为判据
- **WHEN** 公开 C# 取得一个跨接口或同接口资源表面对象，调用 `Dispose` 后再次调用其方法
- **THEN** 合法目标释放 MUST 成功且不得误走发行者入口，释放后调用 MUST 抛出 `ObjectDisposedException`，发行者和其他表面对象 MUST 保持可用

#### Scenario: 释放后生成物不再持有强引用
- **WHEN** 在夹具上创建一个资源拿到句柄，释放该句柄，然后读句柄表里那一项的强引用字段（产物被 `#include` 进测试，那张表在同一个翻译单元里可见）
- **THEN** 该强引用 MUST 为空；若不为空，这条判据 MUST 变红。判据 MUST NOT 用 `use_count()` 差值代替（差值既会被"删得不干净"骗过，也会把外部合法持有者判红）

#### Scenario: 弱句柄在对象被回收后判失效，且不靠释放动作
- **WHEN** 用句柄的解析入口把弱句柄换成对象指针、调到方法之后，让持有方自己回收对象（整个过程中 MUST NOT 调任何释放入口），再用同一个句柄调解析入口
- **THEN** 解析入口 MUST 返回空且错误码为"句柄失效"；同时用一个 `std::weak_ptr` 见证者的 `expired()` MUST 为真，证明对象确实已经析构。MUST NOT 用"读那个忽略 `self` 的每接口全局错误码"来证明这件事

#### Scenario: 弱句柄不改变持有方与引用计数
- **WHEN** 夹具方法返回 `castl::weak_ptr<T>` 拿到句柄，比较拿到句柄前后的 `use_count()`
- **THEN** 两次读数 MUST 相同

### Requirement: 布局清单与启动自检
生成器 MUST 为每个过界结构体同时产出 C++ 与 C# 两份同源常量（`size` + 每个字段 `offset`）。成员可以是标量或另一个纯标量记录时，生成器 MUST 递归产出嵌套类型的清单，并保留嵌套字段路径；遇到字符串、容器、指针、智能指针或自定义所有权成员 MUST 非零退出并点名完整成员路径。生成器 MUST 另提供可由托管启动过程读取的布局清单入口，`Host.Boot` MUST 逐项比对本侧清单与引擎侧清单，不一致 MUST 点名"哪个类型哪个字段"并拒绝继续初始化。任何布局计算 MUST 来自真实 `sizeof` / `offsetof`，MUST NOT 用手算偏移、假设嵌套记录紧凑排列，或把 C++ `static_assert` 当成托管启动自检。

#### Scenario: 嵌套记录也必须逐字段自检
- **WHEN** 对一个包含另一个纯标量记录的结构体生成绑定，并比较两侧布局清单
- **THEN** 嵌套类型、字段路径、大小与偏移 MUST 全部对应；临时改变任一嵌套字段宽度而不重新生成时，启动自检 MUST 失败并点名该字段路径

#### Scenario: 非标量所有权成员仍然拒绝
- **WHEN** 嵌套记录的任意层级出现字符串、容器、指针、智能指针或自定义所有权成员
- **THEN** 生成器 MUST 非零退出并点名该成员，MUST NOT 把它静默摊平成匿名字节

### Requirement: 不可投影的形状必须在生成期点名，显式排除必须写理由
本能力沿用 `csharp-bindable-surface` 的四类不可投影（① 模板方法或泛型接口；② 所有权不明的裸指针；③ 依赖隐式转换的重载；④ 语义越界），MUST NOT 改动这四类的定义。生成器对 ① 与 ③ MUST 自动识别并在生成期非零退出、逐条打印"接口::方法 + 类别 + 建议"；对 ② 与 ④ MUST 要求接口作者用 `CA_BIND_SKIP(方法, "理由")` 逐方法排除（因为同样形状的方法在审计表里有的可绑、有的不可绑，机器判不出来）。带理由的排除 MUST 只打印、退出码 0；**排除但没写理由**是独立的一条错误，MUST 非零退出并点名该方法。生成器 MUST NOT 对不可投影的方法生成"能编译但调用即崩"的绑定。

#### Scenario: 未写理由的排除必须报错
- **WHEN** 在接口里排除一个方法但理由留空
- **THEN** 生成器非零退出，诊断里 MUST 点名该方法并说明"排除必须写理由"

#### Scenario: 带理由的语义越界排除只打印不报错
- **WHEN** 排除 `CRenderBackend::Release`（或 `IOManager::Initialize`）并写明理由
- **THEN** 生成器退出码为 0，日志里 MUST 出现该方法的排除理由，且产物里 MUST 有它被排除的注释

#### Scenario: 模板方法与隐式转换重载自动报错
- **WHEN** 在被标注接口里加一个 `template<typename T> void Set(T const&)` 方法
- **THEN** 生成器非零退出，诊断里 MUST 把它归到 ① 类并给建议；不需要任何 `CA_BIND_SKIP`

### Requirement: 未标注的接口一律不处理
生成器 MUST 只处理被显式标注为可绑定的接口；未被标注的接口 MUST 既不生成产物也不报错，且 MUST 在日志里列出生成了哪些接口、跳过了哪些接口（跳过清单可核）。

#### Scenario: 未标注接口不产出任何文件
- **WHEN** 对一个没有被标注的接口所在模块跑生成器
- **THEN** 该接口的产物文件数 MUST 为 0，且日志的"跳过"清单里 MUST 列出它

### Requirement: 每个矩阵行必须有 conformance 夹具
生成器 MUST 让投影矩阵的每一行都能指到一个夹具接口（矩阵在 `Tools/CodeGen/README.md` 第十三节，行数与该节的表逐字一致），并 MUST 有脚本按行打印"矩阵行 → 夹具"映射、断言每一行恰好对应一个夹具、且该夹具生成的 C ABI 签名逐字符合矩阵里写的形状。`castl::weak_ptr<T>` 那一行 MUST 是弱句柄正向夹具；`castl::function<void(...)>` 那一行 MUST 也是正向夹具，除签名外还要执行注册、调用、替换、置空和异常断言。四类不可投影的夹具仍然各自独立存在，MUST NOT 因回调变成正向用例而删除。"会抛异常"那一行 MUST 断言"错误码 + 文本"。MUST NOT 用"矩阵行数与夹具数相等"作为判据，也不能只数回调方法名而不触发真实回调。

#### Scenario: 矩阵每一行都能指到一个夹具
- **WHEN** 跑 conformance 脚本
- **THEN** 输出的映射行数 MUST 等于矩阵实际行数，每行恰好一个夹具；"无夹具的行数"与"签名不符数" MUST 都为 0，回调行还必须有真实行为断言

#### Scenario: 回调那一行必须生成并调用而不是被拒绝
- **WHEN** 跑 conformance 脚本里 `castl::function<void(...)>` 那一行
- **THEN** 它 MUST 生成真实注册入口与注销伴生，夹具触发后 MUST 读到预期参数；`expected.txt` 和 README MUST NOT 再把这一行写成"本轮未实现"或"拒绝"

#### Scenario: 回调行为被改成空桩时必须报错
- **WHEN** 临时把回调夹具的原生桥改成不调用托管委托，或把注销改成保留保活项
- **THEN** 对应行为测试 MUST 非零退出并点名失效行为；恢复后 MUST 重新通过

### Requirement: 生成器先核对审计表
生成器在生成前 MUST 核对"被标注接口的每个纯虚方法在审计表里都有结论"，对不上 MUST 非零退出并点名缺哪条。MUST NOT 让审计表与生成器各自演进而互不知情。

#### Scenario: 接口新增方法而审计表没跟上时生成器必须拒绝
- **WHEN** 给被标注接口加一个纯虚方法但不更新审计表
- **THEN** 生成器非零退出，诊断里 MUST 点名"哪个接口的哪个方法缺审计结论"

### Requirement: 托管侧的绑定产物必须参与编译
生成的 `<接口>.Bindings.cs` MUST 被编进托管程序集；构建 MUST 把生成物所在目录以属性传给托管工程。托管侧 MUST NOT 手抄生成物里的常量（函数表大小、函数表成员偏移），MUST 直接引用生成物里的常量。

#### Scenario: 生成物里的类型能从程序集里找到
- **WHEN** 构建完成后在托管程序集里查生成物声明的类型名与常量名
- **THEN** 它们 MUST 都存在；MUST NOT 只在磁盘上有一份没人编译的 `.cs`

#### Scenario: 生成物缺失时构建必须失败
- **WHEN** 不传生成物目录属性（或目录里没有 `.cs`）就编托管工程
- **THEN** 构建 MUST 失败并说明缺的是生成物目录，MUST NOT 静默编出一个缺绑定的程序集

### Requirement: 被绑定到托管侧的接口，其函数表里不许有桩
**对真实接口**，每个进入函数表的槽 MUST 真的调用了实现。判定口径 MUST 是结构的、且 MUST 能挡住"看起来调了"的写法：先剥掉 `//` 与 `/* */` 注释，再要求函数体里出现 `object-><方法名>(` 形式的调用，且该调用的结果 MUST 出现在 `return` 里或被赋给命名变量（投影返回 `void` 的槽允许只调用）；`decltype` / `sizeof` / `noexcept` 上下文里的出现、以及 `(void)` 前缀丢弃结果的出现 MUST NOT 算作调用了实现。**另有一条独立红条件**：投影后的返回类型是 `void`、而实现返回的原始拼写去掉 `const` 后不是 `void` 时 MUST 判为缺陷。MUST NOT 用"某句注释文本出现了几次"当判据。对夹具接口，桩数 MUST 被打印出来但 MUST NOT 参与判定。同时 MUST 断言"该接口的 thunk 数等于独立清单里的方法数"，否则整个方法被排除掉也能全绿。

#### Scenario: 真实接口的桩数必须为 0
- **WHEN** 跑绑定判据脚本，解析真实接口产物里函数表成员对应的 thunk 函数体
- **THEN** 桩数 MUST 为 0；非 0 时脚本 MUST 非零退出并逐条打印"接口 + 方法 + 该槽体内既没有调实现"；修复前必须能读出 10 个

#### Scenario: 注释与丢弃结果的写法都不许喂绿
- **WHEN** 把某个桩体的那句形状注释改写成含 `object->` 的文本，或把 thunk 写成 `(void)object->M(); return {};`
- **THEN** 判据 MUST 仍然把该槽判为桩并非零退出

#### Scenario: 调了实现但丢掉返回值也算缺陷
- **WHEN** 某个方法的实现返回非 `void`（例如 `void*`），而生成的 thunk 只写了 `object->M();`、投影后的返回类型却是 `void`
- **THEN** 判据 MUST 把该槽判为缺陷并非零退出

#### Scenario: 整个方法被静默排除时必须被发现
- **WHEN** 把某个方法从发射循环里过滤掉，使它的 thunk 与函数表成员一起消失
- **THEN** 判据 MUST 非零退出并点名"该接口少了哪个方法"；MUST NOT 因为桩数为 0、两侧对齐 0 处就通过

#### Scenario: 算不出真实接口时必须报判据失效
- **WHEN** 把一个只有夹具产物的目录传给判据
- **THEN** 判据 MUST 退出 2 并打印"算不出真实接口"，MUST NOT 因为"真实接口集合为空"就当作 0 桩通过

### Requirement: 构建必须跑绑定判据
`python build.py` MUST 调用 `Tools/CodeGen/check_bindings.py`，MUST 把当前构建配置的产物目录传给它，并 MUST 转发该脚本的 stdout（否则判据打印的夹具桩数会被吞掉），该脚本非零退出时构建 MUST 失败。判据脚本的产物目录 MUST 只有一个来源（命令行参数），MUST NOT 在脚本里另留一份硬编码路径给签名对拍或两侧对齐用。MUST NOT 让签名对拍与桩计数只作为一条需要人手敲的命令存在。

#### Scenario: 把某个方法的实现改成桩后构建必须失败
- **WHEN** 临时把发射器源码改成让 `IWindow` 某个槽落回只返回零值的分支，再跑 `python build.py --config Debug`
- **THEN** 构建 MUST 失败，输出里 MUST 点名该接口与该桩，MUST NOT 出现 `BUILD SUCCESSFUL`；还原后构建恢复通过。造这条红态 MUST NOT 靠修改生成物（构建会重新生成覆盖掉），也 MUST NOT 靠给该方法加排除理由（那样 thunk 直接消失、桩数不升）

#### Scenario: 构建日志里必须看得到夹具桩数
- **WHEN** 跑一次成功的 `python build.py --config Debug`
- **THEN** 构建日志里 MUST 出现一行夹具桩数（本轮修完应为 6），MUST NOT 被 `capture_output` 吞掉而只剩一行产物摘要

#### Scenario: 判的必须是当前配置的产物
- **WHEN** 不带 `--config` 跑 `python build.py`（默认配置的产物在另一个目录）
- **THEN** 判据 MUST 读该配置目录下的产物；`build.py` MUST 把它传给判据的那个目录逐字打印出来，该行 MUST 是当前预设的目录（不带 `--config` 时应出现 `x64-relWithDebugInfo`）

#### Scenario: 产物目录不存在必须与发现桩分开
- **WHEN** 直接跑判据脚本、把产物目录指向一个不存在的目录
- **THEN** 脚本 MUST 退出 2 并打印"产物目录不存在，判据自身失效"，MUST NOT 与"发现桩"共用退出码 1。MUST NOT 用"把构建目录改名再跑 build.py"造这条红态 —— 构建自己会重建那个目录

### Requirement: 标量、枚举与不透明指针的返回值必须走真实现
返回 `bool` 的方法 MUST 投影成 `int32_t` 并真实回读实现的结果（`0` / `1`）；返回枚举的方法 MUST 投影成 `int32_t` 并用显式转换回读（枚举不能隐式转整数），且 MUST 有一条经 C ABI 面的枚举值读数断言；返回 `void*` 的方法 MUST 投影成 `uint64_t` 的不透明令牌并真实回读（MUST NOT 被当成返回 `void` 而丢弃）。**`uint64_t` 这条投影 MUST 只适用于 `void*` 这一种拼写** —— 其它 `T*` 返回 MUST 仍走"拒绝 + 要求 `CA_BIND_SKIP` 写理由"，MUST NOT 被静默绑成裸地址令牌。

#### Scenario: bool 返回值在两侧都能取到真值
- **WHEN** 让一个返回 `bool` 的方法分别返回真与假，各从 C ABI 面读一次
- **THEN** 两次读数 MUST 分别是 `1` 与 `0`；修复前这个槽恒为 `0`，所以这条判据必须能变红

#### Scenario: 枚举返回值不许编不过
- **WHEN** 对一个返回 `enum class` 的方法跑生成器并编译
- **THEN** 生成的 thunk MUST 用显式转换把枚举转成 `int32_t`，构建 MUST 通过；写成直接返回枚举 MUST 编不过（这条判据靠构建失败来证明它有效）

#### Scenario: 返回 void* 的方法不能丢掉返回值
- **WHEN** 让一个返回 `void*` 的方法返回一个非零地址，从 C ABI 面读回
- **THEN** 读回的值 MUST 等于那个地址；MUST NOT 返回 0、也 MUST NOT 把该槽发成返回 `void`。断言 MUST 用一个假实现（返回固定哨兵地址）来做，MUST NOT 要求真窗口 —— 这一层的测试不加载窗口模块、开不了窗口

#### Scenario: 其它指针返回不许走不透明令牌
- **WHEN** 给被标注接口加一个返回 `T*`（不是 `void*`）且没写 `CA_BIND_SKIP` 的方法
- **THEN** 生成器 MUST 非零退出并点名该方法，MUST NOT 把它投影成 `uint64_t` 裸令牌

### Requirement: 字符串入参与两段式返回必须真有实现
字符串入参 MUST 由 `char const* + len` 构造出实现要的类型后再调用。返回字符串（`castl::string_view` 或按值的 `castl::string`）的方法 MUST 生成"先问长度、再拷出"的两个伴生函数，且**每个伴生自己实现**：取长度那次与拷出那次各自重新取一次实现的值，MUST NOT 依赖跨调用的暂存状态。拷出那次 MUST 按调用方给的容量截断并以零结尾，**容量为 0 时 MUST 一个字节都不写**（容量是无符号的，"容量减一"在 0 时会下溢成最大值）；长度由取长度那个伴生提供，拷出那次 MUST NOT 承诺回填长度。**这类方法 MUST NOT 进函数表，也 MUST NOT 发 `extern "C"` 直出入口与直出 thunk** —— 只删表槽会把空体 thunk 留在产物里（被桩判据算成一个桩），整段排除又会把刚发的两个伴生一起删掉，三个都不发才自洽。同时 MUST 断言"取长度那次给的长度 == 拷出那次写入的字节数"，否则长度算错、拷贝只写一半的实现能同时骗过两个单独断言。

#### Scenario: 两个伴生都必须有函数体
- **WHEN** 在生成物里查取长度与拷出这两个伴生符号
- **THEN** 每个符号 MUST 至少有两处命中（一处声明、一处定义）；只有声明的不算通过；同时 MUST NOT 存在对应的 `extern "C"` 直出入口

#### Scenario: 长度与拷出必须对得上
- **WHEN** 经 C ABI 面设一个非空名字，先调取长度、再调拷出
- **THEN** 取长度给出的值 MUST 等于设进去的名字长度，也 MUST 等于拷出写入的字节数；三者不等即算不合格（只断言"取长度非 0"会被长度算错的实现骗过）

#### Scenario: 截断时仍必须以零结尾
- **WHEN** 用一个明显小于文本长度的容量调拷出伴生
- **THEN** 写入的字节数 MUST 小于容量、最后一个字节 MUST 是零；且不崩

#### Scenario: 容量为 0 时一个字节都不写
- **WHEN** 用容量 0 调拷出伴生
- **THEN** MUST NOT 写入任何字节、MUST NOT 崩（这条挡的是"容量减一"在无符号下溢后写满整段的情况）

### Requirement: 回调注册号与资源句柄必须分离
回调注册号 MUST 只用于回调注册与注销，并同时标识接口、方法和本次注册；资源句柄的 `ReleaseHandle` MUST NOT 用来释放回调。注销旧注册号时 MUST NOT 清除后来替换的新回调。

#### Scenario: 旧注册号不能误删新回调
- **WHEN** 安装新回调后使用旧注册号调用注销伴生，再触发事件
- **THEN** 新回调 MUST 仍然执行，旧注册对应的保活项 MUST NOT 被重新建立

### Requirement: 回调中的借用接口对象必须在返回后失效
原生回调参数若是一个已绑定接口的裸指针，托管桥 MUST 用该接口的公开表面对象承载，并保证所有权仍属引擎。借用对象只允许在回调执行期间使用；回调返回后，托管桥 MUST 撤销借用状态，之后调用该对象任意方法 MUST 得到明确失效异常而不是原生悬垂访问。

#### Scenario: 保存回调对象后在回调外使用
- **WHEN** 用户委托保存回调收到的接口对象，并在回调返回后调用它的方法
- **THEN** 调用 MUST 抛出明确失效异常，进程 MUST 不崩溃；回调执行期间的同名调用 MUST 能读到真实对象数据

### Requirement: 默认比较运算符不得阻止纯标量记录镜像
纯标量记录带有编译器默认的比较运算符时，生成器 MUST 仍把它视为数据记录。静态工厂、自定义比较和不改变数据布局的非虚便利方法也 MUST NOT 单独阻止镜像；记录仍须满足公开字段、标准布局、可默认构造和无虚函数。虚函数、非公开字段、非默认构造及含文本、容器、指针、智能指针或自定义所有权成员的记录 MUST 在生成期被拒绝。生成器不得再因 `cacore::Rect<float>` 的 defaulted `operator<=>` 而拒绝 `FloatRect` 与 `MonitorInfo`。

#### Scenario: FloatRect 的默认比较运算符不妨碍生成
- **WHEN** 对包含 `cacore::Rect<float>` 的 `MonitorInfo` 生成嵌套镜像
- **THEN** 默认比较运算符 MUST 被允许，两个矩形与 DPI MUST 全部生成

#### Scenario: 非虚便利方法与对象语义分别处理
- **WHEN** 对带静态创建函数和非虚查询方法的公开数据记录生成镜像，再对含虚函数或非公开字段的记录重复生成
- **THEN** 前者 MUST 成功并保持字段布局，后者 MUST 非零退出并点名不满足条件的类型或成员；不得再把所有非默认方法统一视为拒绝理由

### Requirement: 逐方法转换必须在 C ABI、原生实现和公开 C# 之间组合
生成器 SHALL 为每条方法的每个参数和返回值建立同一份转换描述，并从中生成 C ABI 声明、原生调用前转换、原生实参、返回值转换、函数表槽和公开 C# 调用。普通返回、记录返回、文本伴生和智能指针返回 MUST 复用同一份参数转换；返回类型 MUST NOT 改变参数是否被转换。

任何已接受形状只要缺少 C ABI、原生调用或公开 C# 中任意一层的实现，生成器 MUST 在写产物前非零退出并点名接口、方法和参数，不得生成零值 thunk、退回不透明指针或静默省略公开方法。已有真实接口的"函数表不许有桩"判据继续适用。

#### Scenario: 智能指针返回不得漏掉复杂实参转换
- **WHEN** 一条返回 `shared_ptr<T>` 的方法同时接收数据记录、枚举、标志位、文本、字节和另一个句柄
- **THEN** 原生实现 MUST 收到每个参数转换后的真实值，返回的对象 MUST 能由目标接口解析；把任意一个参数改成不同读数时 MUST 能在实现侧观察到对应变化

#### Scenario: 只有部分实现的组合必须生成失败
- **WHEN** 一条方法使用了能投影到 C ABI、但没有原生转换或公开 C# 表面的组合
- **THEN** 生成器 MUST 非零退出且不留下这一接口的新产物，不得让该槽以固定零值或缺失公开方法的方式通过检查

### Requirement: 公开 C# 枚举与数据记录必须来自真实声明并可跨接口共享
生成器 SHALL 从 C++ 声明生成公开 C# 枚举、平坦记录和嵌套记录。枚举 MUST 保留常量名称、实际值和底层类型；用于 `EnumFlags<T>` 的枚举 MUST 带 `[Flags]`，公开方法使用该枚举 `T`。公开记录 MUST 保留字段名称、顺序和对应托管类型，平坦记录不得再因缺少嵌套关系而从公开方法中消失。接受的全部定宽整数与 `bool` MUST 有精确 C# 映射，包括 `uint16_t` 和 `bool`；未识别标量 MUST 生成失败，不得回退成 `void*`。公开 C 镜像中的布尔按一个字节存储，公开记录字段 MUST 还原为 `bool`。

同一限定 C++ 值类型被多个接口使用时 MUST 只有一份确定的公开 C# 类型产物，重复生成的内容 MUST 逐字节相同。相同短名但不同限定名的类型 MUST 非零退出并点名双方，不得静默覆盖。所有共享 `.Bindings.cs` 产物 MUST 被现有托管通配符编进程序集，公开类型中不得出现原生指针或句柄。

托管验证 MUST 实际读取枚举常量值与底层类型、`[Flags]`、公开记录字段顺序，并用 `Marshal.SizeOf` / `Marshal.OffsetOf` 读取 C# 结构体的真实 CLR 布局，再与生成清单及原生 `sizeof` / `offsetof` 对比。只比较生成器写出的两组常量或只做委托签名赋值 MUST NOT 被视为值内容或布局验收。

#### Scenario: 平坦记录和枚举形成公开签名
- **WHEN** 一条方法接收含窄枚举与标志位的平坦数据记录，另一个方法接收或返回普通枚举
- **THEN** 托管编译期签名断言 MUST 能引用对应公开记录和枚举，记录字段、枚举常量和底层类型与 C++ 一致，方法不得以 `int` 或不透明指针替代这些公开类型

#### Scenario: 公开值内容和真实 CLR 布局必须可失败
- **WHEN** 在托管启动检查中读取公开枚举、记录和 C 镜像，并临时把枚举实际值、字段顺序、`bool` / `uint16_t` 类型或字段宽度改错
- **THEN** 枚举值与底层类型、`[Flags]`、字段顺序、`Marshal.SizeOf` 或 `Marshal.OffsetOf` 的对应断言 MUST 失败并点名类型或字段；不得只依赖 C++ 镜像测试或生成清单常量

#### Scenario: 两个接口使用同一记录不产生重复定义
- **WHEN** 两个分别生成的接口在其公开签名中使用同一个限定 C++ 记录或枚举
- **THEN** 托管构建 MUST 只编译一份该公开类型，重复产物哈希一致；把两处内容改成不同定义时构建 MUST 失败并点名该类型

#### Scenario: 同名不同类型不得覆盖
- **WHEN** 两个不同限定名的 C++ 记录或枚举具有相同短名并进入公开表面
- **THEN** 生成或构建对账 MUST 非零退出并点名两个限定名，不得保留后生成的一份冒充双方

### Requirement: 包装值与字节数组必须有真实的公开托管调用
独立 `NameHash` / `PathHash` 入参的公开 C# 类型 SHALL 为 `string`，独立 `HashObj<T>` 入参 SHALL 为 `T`，`castl::vector<uint8_t> const&` 入参 SHALL 为 `byte[]`。生成器 MUST 在内部调用层完成文本编码、记录转换、数组固定和原生句柄处理，公开类型和公开方法签名中不得出现指针、原生句柄或 `delegate*`。

字节数组 MUST 在整个原生调用期间保持固定。空数组 MUST 能表示零长度输入，托管 `null` 数组 MUST 在进入原生前抛出参数异常；原生空指针配非零长度 MUST 报空指针错误。托管数组在调用返回后的修改不得回写到已经由原生实现复制的输入。该路径只承诺调用内重建，不得把异步保存输入指针的方法标成安全。

#### Scenario: 包装值与字节数组的签名和值都正确
- **WHEN** 托管调用同时传入名称、路径、哈希对象所含记录、字节数组和其他参数
- **THEN** 编译期签名断言 MUST 分别接受 `string`、`string`、记录、`byte[]` 和其他对应类型，原生实现 MUST 收到完整文本、规范化路径、记录值和逐字节相同的数据

#### Scenario: 空输入和调用后修改具有确定行为
- **WHEN** 分别传入空数组、`null` 数组以及原生空指针配非零长度，并在一次成功调用返回后修改原数组
- **THEN** 空数组 MUST 合法，`null` 数组 MUST 抛出参数异常，非法原生指针组合 MUST 报错且不进入实现，原生已复制数据 MUST 不受调用后修改影响

### Requirement: 跨头文件接口投影必须有构建期已知接口清单
`build.py` SHALL 先通过 `CodeGen.exe --list-bind-interfaces` 从每个主头实际 `CA_BIND` 形状收集 `<短名>=<完整限定名>`，聚合后通过重复的 `--known-interface <短名>=<完整限定名>` 传给正式生成。`CODEGEN_BINDINGS` 的期望产物前缀只用于产物存在性检查，MUST NOT 被当作完整接口清单。已知清单 MUST 只用于类型投影和诊断，不得让未在主头文件标注的接口额外生成产物。

跨头文件返回抽象接口时，目标接口的完整限定名 MUST 在已知清单中，否则生成器 MUST 非零退出并说明缺少哪个目标。非接口数据对象的智能指针返回可以继续只提供原生发行者句柄，但不得因此生成伪造的公开 C# 资源对象。共享公开类型的文件名、原生目标类型名和公开接口短名 MUST 分别按各自规则核对；同短名不同限定名 MUST 非零退出，不得用短名猜测不同的 C++ 类型相同。

#### Scenario: 分头生成的发行接口与资源接口能够组合
- **WHEN** 资源接口和发行接口位于不同头文件，构建清单包含双方并分别运行生成器
- **THEN** 发行接口的公开 C# 方法 MUST 返回目标资源表面对象，目标接口的函数表 MUST 能解析和释放返回句柄，托管构建不得缺少目标类型

#### Scenario: 清单来自实际标记而非部分期望产物
- **WHEN** 一个输入头包含多个 `CA_BIND` 接口，而 `CODEGEN_BINDINGS` 的期望产物前缀只列其中一部分
- **THEN** 收集清单 MUST 仍包含全部实际标记接口及其完整限定名，既有跨接口返回不得因未列入期望前缀而被判未登记

#### Scenario: 同短名不同限定名必须拒绝
- **WHEN** 两个命名空间中存在同短名接口，或已知清单条目与返回目标的完整限定名不一致
- **THEN** 生成或清单聚合 MUST 非零退出并点名冲突双方，不得只凭短名选择目标接口

#### Scenario: 未登记抽象接口不得生成悬空公开类型
- **WHEN** 一条跨头文件方法返回一个具有纯虚方法、但不在构建期已知清单中的接口
- **THEN** 生成器 MUST 非零退出并点名目标接口与缺失清单，不得留下引用不存在 C# 类型的产物

### Requirement: 接口编号由锁文件治理，标注与判据脚本都不携带编号
进入宿主登记表的接口，其编号的唯一来源 MUST 是入库文件 `Tools/CodeGen/interface-ids.lock`（数据行制表符四列：编号、短名、完整限定名、头文件路径；按 `# scope host` / `# scope fixture` 注释分段，每段带该段历史最高号水位）。`CA_BIND` 标注 MUST NOT 带编号参数——带编号的标注 MUST 被生成期非零拒绝并点名；`Tools/CodeGen/check_bindings.py` MUST 以锁文件为期望来源，MUST NOT 保留手抄编号表。默认构建只做核对，**口径一律按段**：段内编号唯一、段内从该段起点连续、登记表输入的接口名集合与锁内该段名集合完全相等（多一行少一行都点名）——宿主段与夹具段是各自独立的号空间，夹具段永不进宿主路由，构建模式 MUST NOT 改写锁文件。分配新编号 MUST 只经显式 `--update-ids` 模式：既有名字的号保持不动，新名字由工具自动取该段下一个可用号并推进水位，其余行一字不动。"编号与名字的绑定"一旦变化（改号、换号），生成常量与 `Tables` 清单必然变化，MUST 被"产物逐字节基线对账"抓到——构建核对不承诺抓名字集合不变的换号。编号换源前后，既有全部绑定产物与登记表产物 MUST 逐字节不变。

#### Scenario: 标注上写编号必须被拒绝
- **WHEN** 某个进入登记表输入的接口写成了 `CA_BIND(8)`
- **THEN** 生成器 MUST 非零退出并点名该接口，文本 MUST 说明编号由锁文件治理、标注只声明绑定意图；MUST NOT 产出任何登记产物

#### Scenario: 新接口进表由工具发号，人不接触数字
- **WHEN** 一个无参 `CA_BIND` 接口新进入登记表输入而锁里没有它，先跑 `--update-ids` 再跑构建
- **THEN** `--update-ids` MUST 只在锁中追加它一行（该段下一个可用号），既有行逐字不动；随后构建 MUST 通过，且该号在登记表 C++ 常量、托管编号常量与 `Tables` 清单三处一致

#### Scenario: 删行与换号分别有各自的抓法
- **WHEN** ①删除锁中任一接口行后重跑构建；②把锁中两行的编号互换（名字集合不变）后重跑构建与产物对账
- **THEN** ①构建 MUST 非零并点名受影响接口；②构建核对 MAY 通过，但产物逐字节基线对账 MUST 不一致并点名差异文件；两态还原后 MUST 全绿且哈希复锚

### Requirement: 发射器采集原生类的公开非纯虚形态
对带 `CA_BIND` 的类，发射器 MUST 采集其全部公开成员函数（非模板、非析构），不再限定纯虚：非纯虚与非虚公开方法 MUST 能进表；返回类型为该类的 `T&`/`T const&` MUST 投影为 C ABI `void`、托管表面 MUST 返回同一表面对象保持链式调用——**此类"返回自身"MUST 被 `check_bindings.py` 的"丢返回值"判据显式豁免**（豁免识别限于"返回值是该类自身引用"；其余"有返回值却不写回"仍按缺陷拒绝，豁免不得放宽到任意返回值）；带默认构造的类 MUST 生成 `Create` 入口（分配实现并登记句柄）；静态工厂可进表的范围**限于返回值是纯标量记录**——返回值含容器/文本/句柄的工厂维持"返回位置容器"拒绝（`RenderPass::New` 属此类，其托管替代是镜像类型字段赋值）；同名不同签名的重载 MUST 按出现顺序出槽——第一个保持现有槽名，其后加 `_<序数>` 后缀，托管侧生成同名重载；模板方法与依赖隐式转换的重载 MUST 维持拒绝。被审计接口（现全部为纯虚）在新采集规则下的产物 MUST 与规则变更前逐字节一致。

#### Scenario: 非虚与自返回方法真实过界
- **WHEN** 夹具类含一个非虚方法、一个返回自身引用的链式方法、一个返回纯标量记录的静态工厂和一个默认构造，且都被采集
- **THEN** 生成的 C ABI MUST 含各自槽位（自返回槽返回 `void`），托管调用 MUST 到达原生实现并读到真实副作用计数；链式两次调用在原生侧 MUST 恰好 +2 且顺序一致

#### Scenario: 丢返回值判据的豁免边界
- **WHEN** ①豁免规则未实现时采集含链式方法的夹具；②把豁免写成"任何有返回值方法都放行"后跑既有"丢返回值"拒绝夹具
- **THEN** ①`check_bindings.py` MUST 以"丢返回值"点名链式方法（红，实现豁免后 0 处）；②非自身引用的丢返回值缺陷 MUST 仍被点名（豁免过界即红）

#### Scenario: 重载槽不重名、互不串
- **WHEN** 夹具接口有两个同名不同签名（无隐式转换歧义）的方法
- **THEN** extern 槽名 MUST 互不相同（第二个带 `_2` 后缀），托管侧 MUST 是两个同名重载；分别调用 MUST 命中各自原生重载，计数互不冒充

#### Scenario: 返回容器的工厂与模板都维持拒绝
- **WHEN** 被采集类里有返回含容器记录的静态工厂，或一个模板成员函数
- **THEN** 生成器 MUST 非零退出并点名（工厂按"返回位置容器"、模板按 ① 类；或被 `CA_BIND_SKIP` 显式排除并写理由）；MUST NOT 出现"生成了但桩"的中间态

### Requirement: 真实头部的投影快照必须入库并对账
生成器 MUST 提供只解析不产物的快照模式，对 `Interface/RenderInterface/header/` 下的 `CRenderBackend.h`、`GPUGraph.h`、`ShaderStruct.h`、`GPUTexture.h` 四份真实头各产出"采集清单 + 排除清单（逐方法原因）"，快照 MUST 入库（本 change 的 `evidence/原生头投影快照.txt`）。对账 MUST 用**与生成器不同源的第二份清单**：判据脚本自行以剥注释后的文本解析（取类体、按分号切声明、摘方法名，与 `check_bindable_audit.py` 同族手法）从同一头文件生成公开方法清单，与快照逐条对账——同一生成器漏采的方法不会在两侧同时消失。差异（任一侧多方法、排除理由变化）MUST 非零点名具体方法；独立清单还 MUST 满足"条数 ≥ 头内已知构件数"的下界锚（`GPUGraph.h`：13 链式构件 + 10 访问器，以当场重算为准）。快照是后续"原生直绑"批决定绑定面与排除面的唯一依据。

#### Scenario: 改真实头必须同步快照
- **WHEN** 向 `GPUGraph.h` 临时加一个公开方法后跑快照对账（变异由主 agent 代跑并当场还原）
- **THEN** 独立文本清单 +1 而快照未变，对账 MUST 非零并点名该新方法；还原后 MUST 复绿

#### Scenario: 删快照行必须被点名
- **WHEN** 手工从快照删除一条方法行后跑对账
- **THEN** 对账 MUST 非零并点名该方法两侧计数不符（对账脚本不许只比"快照对快照"）

### Requirement: 绑定面合法换源必须走换锚程序，禁止以跳过封存来"继承"旧锚
绑定面**合法**变化（接口增删、退役、换源）导致产物必然变化时，MUST 走换锚程序：①换锚前一次全绿构建；②旧基线清单（逐文件哈希）整份封存进本 change `evidence/`（不删不掩）；③新产物全集重取哈希入新基线文件，`check_binding_baseline.py` 指向新锚；④换锚前后两份清单的差异行数与逐文件列表 MUST 打印入档（哪些产物消失/新增/内容变化）。未封存旧锚直接重取基线 MUST 被判据拒绝（脚本要求旧锚文件存在且与当次输出可比对）；换锚 MUST NOT 被用来掩盖换源之外的意外改动——差异清单中出现"换源解释不了"的文件（非绑定面关联产物）时，收口 MUST 失败并点名该文件。

#### Scenario: 换锚留双账且差异可解释
- **WHEN** 桥退役与原生进表完成后执行换锚
- **THEN** evidence MUST 同时有旧锚（封存件）与新锚；两锚差异 MUST 逐文件列明且每条能指认到换源动作（桥产物删除/原生产物新增/登记表与 EngineApi 换面）；出现指认不了的差异 ⇒ 收口红

#### Scenario: 跳过封存的换锚被拒绝
- **WHEN** 演练：删除旧锚封存件后运行基线对账脚本
- **THEN** 脚本 MUST 非零退出并点名"缺旧锚封存件，换锚不可审计"；补回后 MUST 复绿（红绿两段留档）
