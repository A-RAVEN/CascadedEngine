# csharp-bindable-surface Specification

## Purpose

把"哪些接口方法能给 C# 用、用什么形状过界"写成逐方法可核的结论，并用脚本兜住"接口加了方法却没人审"的情况；它是绑定生成器的输入规格，不靠改接口签名去迁就 C ABI。
## Requirements
### Requirement: C ABI 面只允许五类形状
引擎接口暴露给 C# 的那一层（下称"C ABI 面"）MUST 只使用五类形状：blittable 标量与递归纯标量记录、`T const* + 数量` 视图、不透明句柄（定宽整数 + 代际号）、"真实签名的原生函数指针 + 不透明 `void* user`"回调形状、以及**反向接口的"一张函数表 + 一个不透明 `void* user`"形状**（独立第五类，第 4 类仍是单回调；函数表含接口每**被绑定**虚方法投影出的函数指针，**一个虚方法 MAY 投影成多条**如两段式 Len/Copy；每条函数指针的参数 MUST 仍落在前四类内）。回调注册号与注销伴生 MUST 留在内部层。容器类型（`castl::vector` / `map` / `unordered_map` / `set` / `string`）与模板类型 MUST NOT 出现在 C ABI 面上 —— 它们只在 C++ 接口面出现，由投影层翻译。

#### Scenario: 审计表里没有"直接把容器写在 C ABI 面"的行

- **WHEN** 复核 `evidence/bindable-audit.md` 里每一行的"投影形状"列
- **THEN** 该列只出现 blittable 类型、递归纯标量记录、`X const* + count`、`uint64_t 句柄`、`char const* + len`、"函数指针 + `void* user`"、以及"函数表 + `void* user`"这些写法；出现一个容器类型名即算不合格

#### Scenario: 回调形状具有独立第四类而不是被硬塞进句柄

- **WHEN** 复核 10 个 `IWindowSystem::Set*Callback` 的投影行
- **THEN** 每行 MUST 明确写出原生函数指针、不透明用户令牌、内部注册号和注销伴生，回调首参 MUST 是回调期间借用的 `IWindow`，MUST NOT 再写成普通窗口资源句柄或禁止出现 `IWindow*`

#### Scenario: 模板只在投影层被单态化

- **WHEN** 某个接口方法的参数是 `castl::vector<BindingInfo>` 这样的具体化容器
- **THEN** 审计表 MUST 把它投影成"元素类型 + 数量"的形状（`BindingInfoC const* + count`），而接口本身保持 `castl::vector<BindingInfo>` 不变

#### Scenario: 反向接口形状是函数表加 user 且参数仍在前四类

- **WHEN** 复核反向接口（C# 实现 C++）的投影行
- **THEN** 该行 MUST 写成"函数表（每虚方法投影出的函数指针，可多条）+ `void* user`"，每条函数指针的参数 MUST 只含 blittable/视图/句柄/内存窗；出现容器/模板/智能指针过界即算不合格

### Requirement: 每类 C++ 形状都有确定的投影，且逐方法留痕
所有被审计接口的每个纯虚方法 MUST 在审计表里有且只有一行，逐列写清：接口::方法、C++ 形状、投影形状、是否拷贝、谁分配、可绑性（可绑 / 需快路 / 不可绑）。"不可绑"的行 MUST 给出理由与处置建议；MUST NOT 出现"待定""视情况"这类没有结论的写法。

#### Scenario: 漏一个方法脚本就红

- **WHEN** 被审计接口里新增一个纯虚方法，而审计表没有对应行
- **THEN** `python Tools/CodeGen/check_bindable_audit.py` MUST 非零退出并点名"哪个接口的哪个方法缺审计行"

#### Scenario: 不可绑却不写理由也红

- **WHEN** 审计表某行把可绑性写成"不可绑"，但理由或建议为空
- **THEN** 同一个脚本 MUST 非零退出并点名该行

### Requirement: 智能指针与所有权的投影规则
接口返回**强**智能指针（`castl::shared_ptr<T>` / `std::unique_ptr<T>` 等）的方法 MUST 投影为"返回不透明句柄"，句柄表由投影层持有对应智能指针，并 MUST 有配对的显式释放入口；释放 MUST 让投影层不再持有该强引用。接口返回**弱**智能指针（`castl::weak_ptr<T>`）的方法 MUST 投影为"返回弱句柄"：句柄表 MUST 持有弱引用、MUST NOT 抬高对象的 `use_count()`，对象析构后旧句柄 MUST 被判失效。接口接收 `shared_ptr<T>` 参数的方法 MUST 投影为"接收句柄"，由投影层反查并重建目标类型的 `shared_ptr<T>`。`weak_ptr<T>` 入参不在本 change 的支持范围内，MUST 继续生成期拒绝；该排除不影响 `weak_ptr<T>` 返回形成弱句柄。每个方法的分配归属 MUST 从三档里选一档并写进审计表：调用方提供缓冲区、投影层分配 + 配对释放、引擎持有 + 只读视图。MUST NOT 出现"native 分配、C# 侧 delete"这种跨边界所有权。

句柄表项 MUST 同时记录发行者与目标对象的完整限定类型。现有原生解析、泛用释放和按方法释放入口 MUST 保持发行者角色，继续支持非接口数据对象和既有窗口行为；公开 C# 的已绑定接口返回 MUST 使用追加的目标接口解析与释放入口。目标接口 MUST 能按目标类型解析并释放跨头文件句柄，发行接口与目标接口可以使用不同实例，错误目标类型 MUST 失败。

强返回句柄作为 `shared_ptr<T>` 入参时 MUST 复用表内强引用，弱返回句柄 MUST 在调用期间取得强引用；借用句柄没有可持有的智能指针所有权，作为 `shared_ptr<T>` 入参时 MUST 失败且不得进入实现。类型不符、代际不符、目标对象已死亡或所有权不适用的反查 MUST 只置错误码和具体文本而不崩溃。目标接口解析借用句柄时 MUST 要求发行者见证存在且仍存活；旧发行者路径中的无见证借用句柄不得因此获得公开目标表面。两类释放 MUST 能清除目标已死亡或见证过期的有效表项并进位，不得因解析失败而遗留槽位。

#### Scenario: 每个返回强智能指针的方法都有配对的释放入口
- **WHEN** 复核审计表里所有"返回智能指针（`shared_ptr` / `unique_ptr`）"的行
- **THEN** 每一行 MUST 在"投影形状"列同时给出句柄类型与释放入口名（例如 `uint64_t` + `crb_release`），独占语义的还要写明"释放即作废"

#### Scenario: 发行者入口与目标入口分别校验
- **WHEN** 一个头文件中的发行接口返回另一个头文件中已绑定资源接口的强智能指针
- **THEN** 旧发行者入口 MUST 继续按发行者解析和释放，新目标接口入口 MUST 按目标类型解析和释放；目标接口释放后旧句柄 MUST 失效，错误资源类型或错误发行者 MUST 按各自角色失败

#### Scenario: 无见证或过期借用句柄不得进入公开目标表面
- **WHEN** 借用返回的发行者没有存活见证，或见证已经过期
- **THEN** 目标接口解析 MUST 失败；有效表项的显式释放仍 MUST 清理槽位和弱引用并进位，旧发行者入口的兼容行为不得被用来绕过目标校验

#### Scenario: weak_ptr 入参继续明确拒绝
- **WHEN** 一条方法接收 `castl::weak_ptr<T>` 或 `std::weak_ptr<T>` 参数
- **THEN** 生成器 MUST 非零退出并点名该参数；该结果不得被解释为拒绝 `weak_ptr<T>` 返回或弱返回句柄的强引用保活

#### Scenario: shared_ptr 入参重建真实对象
- **WHEN** 发行接口创建的资源句柄被传给另一个接口的 `shared_ptr<T>` 参数
- **THEN** 原生实现 MUST 收到指向同一对象的 `shared_ptr<T>`；弱返回句柄在调用期间 MUST 有强引用保活，借用句柄 MUST 被拒绝且实现调用次数为 0

#### Scenario: 弱智能指针不许被当成裸指针拒绝
- **WHEN** 复核被审计接口里所有返回 `castl::weak_ptr<T>` 的方法
- **THEN** 每一行 MUST 归到"弱句柄"这一投影形状，MUST NOT 被标成 ② 类（② 的定义是所有权不明的**裸指针**，`weak_ptr` 不是裸指针）；归不进任何一类的行说明矩阵漏了一类，必须回头补本条

#### Scenario: 弱句柄不改变持有方与引用计数
- **WHEN** 一个由引擎内部持有的对象通过弱句柄交给托管侧，比较交出前后的 `use_count()`
- **THEN** 两次读数 MUST 相同（交出弱句柄不产生新持有者），且该对象 MUST 仍能在引擎判定"该回收"时被回收 —— 弱句柄的存在 MUST NOT 阻止回收

### Requirement: 四类不可投影的形状必须被点名，而不是被静默生成
以下四类形状 MUST 在审计表里标成"不可绑"并给出改法建议：① 模板方法或泛型接口；② 所有权不明的裸指针（返回 `T*`、或在参数位置上没有写明谁持有）；③ 依赖隐式转换的重载（同名不同参数类型，C ABI 侧必须改名，语义会变）；④ **语义越界** —— 技术上绑得了、但脚本不该调的入口（模块初始化期的依赖注入、销毁整个后端之类）。投影层 MUST NOT 为这四类形状生成"看着能编译、调用即崩溃"或"让脚本越权"的绑定。**② 的参数位置开两条唯一合法化通道**：其一，`CA_BIND_INJECT(方法, 参数)` 声明该指针由引擎默认提供——注入后方法按"可绑（注入）"进审计表并写明钩子来源；注入参数 MUST NOT 出现在 C ABI 与托管表面（脚本永远没有提供该指针的入口），thunk MUST 经固定名宿主钩子取值，钩子缺失 MUST 生成期拒绝。其二，**内存窗配对**：`const void*` 参数与同参数表内相邻唯一的整型长度参数（常见 `uint64_t`）MUST 可配对联结为托管 `byte[]` 投影——thunk 以固定内存传指针与长度，其余参数原样过界；配对不唯一（多个整型候选）或长度参数缺失 MUST 生成期点名该方法并拒绝，MUST NOT 猜测配对或把裸指针暴露给托管。**② 的返回位置开一条唯一例外**：返回指向可序列化记录类型的非拥有裸指针 MUST 走"记录两段式投影"——托管得该记录的序列化只读副本，原生返回空指针时托管 MUST 得 `null` 且 MUST NOT 解引用；指向后端资源/调度器等所有权不明返回值的裸指针仍不可绑。**① 开一条唯一通道**：模板成员 MUST NOT 被自动单态化采集；需要绑定具体形态时，声明头文件 MUST 以 `CA_BIND_INSTANTIATE(方法名, 类型列表)` 文本声明（编译期 no-op，不改原生签名、不新增原生函数），生成器按声明逐形态出具体槽与托管同名重载；声明的形态编译不过 MUST 在构建期点名，未在声明中列出的模板形态 MUST NOT 进任何表面，该通道 MUST NOT 被用来给原生接口加方法。**② 的返回位置容器开一条同族通道**：返回只读标量容器（`castl::vector<标量> const&`，design D13）MUST 走"标量容器两段式"——出 count 查询与定长拷贝一对槽，元素限可 blittable 标量/枚举；记录容器、含句柄/文本的容器、非常量引用返回维持不可绑。未经上述通道合法化的形状维持不可绑：返回位置的 `T*`（非可序列化记录两段式者）、未经注入声明或内存窗配对的参数裸指针、映射容器维持不可绑，MUST NOT 以任何其他方式"顺手绑上"。审计表换面重切时，既有 ② 标记的 `FindShaderStructData`/`FindShaderRootStructData` 两行 MUST 按两段式通道重新归类、④ 标记的 `CRenderBackend::Release`/`Initialize` MUST 维持语义越界不可绑（`CA_BIND_SKIP`），MUST NOT 借换面悄悄改结论。

#### Scenario: 四类形状在审计表里各有明确结论
- **WHEN** 复核 `evidence/bindable-audit.md` 的不可绑清单
- **THEN** 每一行 MUST 能归到 ①–④ 中的一类；归不进去的行说明矩阵漏了一类，必须回头补本条而不是把它塞进现有四类里

#### Scenario: 语义越界的一类也必须有真实例子
- **WHEN** 复核不可绑清单里属于第 ④ 类的行
- **THEN** 每行 MUST 写清"为什么不许脚本调"（而不是"暂时没做"），并给出不暴露时脚本该走哪条替代路径

#### Scenario: 参数位置裸指针经注入合法化
- **WHEN** 夹具方法带一个裸指针参数并声明 `CA_BIND_INJECT`，托管侧调用
- **THEN** 托管表面与 C ABI MUST 都没有该参数；原生实现 MUST 收到宿主钩子提供的指针值；把注入写在非指针参数或不存在的参数名上 MUST 生成期非零点名

#### Scenario: 内存窗上传逐字节一致
- **WHEN** 托管经内存窗投影方法上传一段字节
- **THEN** 原生实现 MUST 收到与 `byte[]` 逐字节一致的内存与正确长度；配对判据（相邻唯一整型）不满足的夹具方法 MUST 生成期点名

#### Scenario: 两段式投影空命中不越界
- **WHEN** 记录查询在原生侧未命中（返回空指针）
- **THEN** 托管 MUST 得 `null` 且 MUST NOT 出现对空指针的解引用；对所有权裸指针形态的同类声明 MUST 生成期拒绝

#### Scenario: 返回位置标量容器两段式读取
- **WHEN** 绑定接口方法返回 `vector<标量> const&`，托管先查 count 再按 count 拷贝
- **THEN** 两次读数 MUST 一致且逐元素相等；空容器 count=0 且拷贝槽 MUST NOT 在零长度上解引用；返回记录容器或含句柄/文本容器的同类声明 MUST 生成期拒绝

#### Scenario: 模板经声明出槽、未声明形态不可见
- **WHEN** 夹具声明两个实例化形态并构建
- **THEN** 两形态各自出槽且托管调用到达正确实例；对未声明形态的托管调用 MUST 不存在（表面文本判据 0 命中）；拼错类型名 MUST 构建/生成期点名

### Requirement: 热路径的零拷贝快路必须显式声明
对每帧多次调用、且参数是容器的接口方法，允许在**接口上另加**一个零拷贝快路重载（接受 `T const* + count`），默认实现委托给易用版本；MUST NOT 反过来把易用版本删掉。审计表 MUST 为需要快路的方法标出"需快路"，并写出快路重载的建议签名。

#### Scenario: 需要快路的方法在审计表里有建议签名

- **WHEN** 复核审计表里标成"需快路"的行
- **THEN** 每行 MUST 给出建议的 `...Span` 重载签名，且该签名只使用第 1 条允许的五类形状

### Requirement: 异常不跨边界
C ABI 面的每个入口 MUST 捕获接口方法抛出的异常，转成"错误码 + 一条文本"返回；MUST NOT 让异常穿过边界。审计表 MUST 为会抛异常的接口方法标出它在 C ABI 面的错误码类型。

#### Scenario: 审计表为每个可绑方法给出错误上报方式

- **WHEN** 复核审计表里"可绑"或"需快路"的行
- **THEN** 每行 MUST 写出它的失败上报方式（返回值错误码 / 出参错误码 / 不失败），且与"异常不跨边界"这条一致

### Requirement: 可投影但尚未实现的形状必须显式排除，不许静默发桩
审计表结论是"可绑"、但投影层还没有实现那条投影路径的形状，生成器 MUST NOT 静默生成"签名对、调用恒返回零"的桩。这类方法 MUST 由接口作者用 `CA_BIND_SKIP(方法, "理由")` 显式排除，理由里 MUST 出现"本轮未实现"并点名缺的是哪条投影路径；审计表里这些行的"可绑性"列 MUST 继续保持"可绑"，并在备注列写明"本轮未实现"。**这一类 MUST NOT 被写成 ①–④ 中的任何一类** —— 四类说的是"形状本身不可投影"，这一条说的是"实现进度"。

`castl::function<void(...)>` 回调与递归纯标量记录镜像已经由本 change 实现，MUST NOT 再把它们列为"本轮未实现"的例子。其余尚未实现的形状以 `Tools/CodeGen/README.md` 的当前清单为准；生成器 MUST 对"既没实现、又没被排除"的这类方法非零退出并点名。实现某一形状时必须同步删除对应接口排除、审计备注和文档备注，三者不得各自停留在不同阶段。

#### Scenario: 未实现的形状没被排除时生成器必须拒绝
- **WHEN** 在被标注接口里留一个仍属生成器未实现清单的形状，且不给它写 `CA_BIND_SKIP`
- **THEN** 生成器 MUST 非零退出，诊断里 MUST 点名该接口与方法，并 MUST 说明缺的是哪条投影路径；MUST NOT 生成一个空体 thunk

#### Scenario: 已实现的回调与嵌套镜像不得继续排除
- **WHEN** 复核 `IWindowSystem` 的 10 个回调、`GetMonitor`、唯一审计表和生成器文档
- **THEN** 这些条目 MUST NOT 再写"本轮未实现"；其他未实现形状的排除理由与行为 MUST 保持不变

### Requirement: 回调投影必须定义完整生命周期
每个 `castl::function<void(...)>` 回调 MUST 在审计表中明确登记为"函数指针 + 不透明用户令牌 + 内部注册号/注销伴生"的投影，**MUST NOT 被排除**。投影规格 MUST 定义注册、替换、置空、注销、表面对象释放、重入和异常传播的完整语义：回调参数 MUST 保持原顺序；用户令牌 MUST 只作不透明数据，**原生生成代码（C++ thunk/代理）MUST NOT 解引用它**（原生侧只把 user 原样传给函数指针）；**托管桥（`[UnmanagedCallersOnly]` 静态方法）用 `GCHandle.FromIntPtr(user).Target` 解回托管对象是第 4 类形状的既有语义**（现有 `OnSetKeyCallback` 已如此），反向接口的 C# 实例解回同此语义，不构成对"原生不得解引用"的违反。公开 C# MUST 只暴露托管委托或表面对象，MUST NOT 暴露注册号、函数指针或用户令牌；注册表 MUST 保活委托，替换/置空/释放 MUST 同时清理原生注册与托管保活项。

回调首参若是已绑定接口的裸指针，审计表 MUST 把它投影成"回调期间借用的表面对象"，而不是可长期持有的资源句柄。借用对象只在回调执行期间有效；回调返回后 MUST 撤销借用状态，后续调用 MUST 抛出明确失效异常。回调执行期间修改同一个注册 MUST 失败且不得销毁正在执行的回调；用户委托异常 MUST 在托管桥内转成错误状态，MUST NOT 穿过原生回调边界，下一次主线程调用 MUST 通过对应接口异常类型上报统一错误表中的回调错误标识和原始文本。

回调投影 MUST 有正向 conformance 夹具，至少执行注册、调用、替换、置空、表面对象释放、回调后借用失效、执行期修改注册失败和用户委托异常转错误码。生成器 MUST NOT 为未排除的回调方法生成空体 thunk；`expected.txt` 与 README MUST NOT 再把这类方法登记为本轮拒绝项。

#### Scenario: 未排除的回调方法生成真实注册与调用

- **WHEN** 对一个带 `castl::function<void(...)>` 参数的已审计方法生成绑定，并从托管侧注册委托后触发原生回调
- **THEN** 生成器 MUST 成功，托管委托 MUST 按原参数类型与顺序收到真实读数，且原生实现确实持有由生成代码安装的回调

#### Scenario: 回调参数顺序不得改变

- **WHEN** 夹具回调包含窗口、两个整数、两个浮点数和窄枚举参数
- **THEN** 托管委托收到的参数顺序 MUST 与 C++ `castl::function<void(...)>` 完全一致，不能把用户令牌插到公开委托参数中

#### Scenario: 替换和置空必须清理旧注册

- **WHEN** 先注册一个委托，再用另一个委托替换，随后置空并分别触发原生事件
- **THEN** 替换后只有新委托执行，置空后两个旧委托都不再执行，生成注册表中对应保活项 MUST 已删除

#### Scenario: 表面对象释放必须注销回调

- **WHEN** 注册回调后释放持有它的 C# 表面对象，再触发原生事件
- **THEN** 已释放对象的委托 MUST NOT 再执行，原生注册与托管保活项 MUST 已清理，其他表面对象的回调 MUST 仍可用

#### Scenario: 回调借用对象返回后必须失效

- **WHEN** 用户委托保存回调收到的接口对象，并在回调返回后调用它的方法
- **THEN** 调用 MUST 抛出明确失效异常，进程 MUST 不崩溃；回调执行期间的同名调用 MUST 能读到真实对象数据

#### Scenario: 回调执行期间修改同一个注册必须失败

- **WHEN** 用户委托在执行期间尝试替换或清空它自己
- **THEN** 桥 MUST 返回可诊断错误且不得销毁正在执行的回调，进程 MUST 继续运行

#### Scenario: 用户委托抛异常不得跨边界

- **WHEN** 一个已注册委托抛出异常，随后主线程再调用 `UpdateSystem` 或回调注册方法
- **THEN** 异常 MUST NOT 穿出原生回调边界，后续公开调用 MUST 抛出对应接口异常并包含统一回调错误标识和原始异常文本

#### Scenario: 公开表面不得泄漏回调内部令牌

- **WHEN** 检查生成的公开 C# 回调注册方法签名与表面对象
- **THEN** 公开签名 MUST 只出现托管委托和表面对象，MUST NOT 出现 `ulong registration`、`void* user` 或函数指针参数

#### Scenario: 托管桥解回 user 是既有语义而原生层不解引用

- **WHEN** 检查生成的 C++ thunk/代理与托管桥对 user 令牌的处理
- **THEN** C++ 原生生成代码 MUST 只把 user 原样传给函数指针（不解释不解引用）；托管桥 MUST 经 `GCHandle.FromIntPtr(user).Target` 解回托管对象（与现有 OnSetKeyCallback 同语义）；原生层出现解引用 user 即算不合格

### Requirement: 嵌套记录只允许递归纯标量投影
结构体成员若属于另一个记录类型，投影层 MUST 只在那个类型自身及其全部祖先成员也都是标量、枚举、标志位或纯数据记录时递归镜像（快速路径）。这里的纯数据记录 MUST 具有公开字段、标准布局、可默认构造且无虚函数；静态工厂、默认或自定义比较以及非虚便利方法不改变其纯数据身份。布局清单 MUST 保留嵌套字段路径和真实偏移；任何一层出现字符串、容器、指针、智能指针、自定义所有权成员、非公开字段、非默认构造或联合体时，MUST NOT 走本条的快速镜像。**其中"仅因成员含一层容器/文本、且位于参数位置"的记录 MUST 改走"序列化块记录"投影（见新增要求），MUST NOT 被静默丢弃或硬塞进快速镜像**；其余情况（返回位置的容器、映射容器、定长数组、联合体等）MUST 维持生成期拒绝。

#### Scenario: MonitorInfo 的两个矩形与 DPI 都有独立镜像字段
- **WHEN** 投影 `MonitorInfo`
- **THEN** 两个 `FloatRect` 与 `m_DPIScale` MUST 分别出现在同源布局清单和公开 C# 记录类型中，MUST NOT 用匿名字节数组代替字段

#### Scenario: 嵌套层级里藏有非 blittable 成员时不得进快速镜像
- **WHEN** 一个外层标量记录包含另一个记录，而后者含有字符串、容器、指针、智能指针或自定义所有权成员
- **THEN** 生成器 MUST NOT 把它塞进快速镜像；该记录若符合序列化块的"参数位置 + 一层容器/文本"条件 MUST 改走序列化块投影，否则 MUST 非零退出并点名嵌套成员路径

#### Scenario: 非虚便利方法与虚函数必须区分
- **WHEN** 两个记录具有相同数据字段，其中一个只有静态工厂和非虚查询，另一个声明了虚函数
- **THEN** 前者 MUST 能按上述两条路径之一投影（快速镜像或序列化块），后者 MUST 在生成期被拒绝；不得仅凭"存在自定义方法"作统一结论

### Requirement: 枚举、标志位与公开数据记录的投影必须保持真实布局
普通枚举方法参数和返回 SHALL 沿用 `int32_t` 投影；`uenum::EnumFlags<T>` 方法参数 SHALL 按 `MaskType` 对应的定宽整数投影。记录字段中的普通枚举 SHALL 按枚举真实底层类型镜像，`EnumFlags<T>` 字段 SHALL 按其唯一 `m_mask` 的定宽类型镜像。公开数据记录 SHALL 保持真实 `sizeof` / `offsetof`，不得因统一拉宽枚举或标志位而改变偏移。

公开数据记录可以包含默认或自定义比较、静态工厂和非虚便利方法；记录及其全部嵌套成员 MUST 仍满足公开字段、标准布局、可默认构造和无虚函数。含文本、容器、指针、智能指针、自定义所有权成员、非公开字段或联合体的类型 MUST NOT 被视为可镜像记录。

#### Scenario: 窄枚举与标志位不得被统一拉宽
- **WHEN** 一个公开数据记录包含底层类型小于 `int32_t` 的枚举和 `EnumFlags<T>` 字段
- **THEN** C 镜像字段 MUST 使用各自真实底层类型，且两侧 `sizeof` 与每个字段的 `offsetof` 相同；不得写成统一的 `int32_t` 字段

#### Scenario: 非虚便利方法不妨碍纯数据记录投影
- **WHEN** 一个满足公开字段、标准布局、可默认构造且无虚函数的记录带有静态创建函数或非虚查询方法
- **THEN** 该记录 MUST 能按字段投影，且这些方法不改变任何 C ABI 字段或托管公开字段

#### Scenario: 有对象语义的记录仍然拒绝
- **WHEN** 记录含虚函数、非公开字段、非默认构造、联合体，或任意嵌套层级含文本、容器、指针、智能指针或自定义所有权成员
- **THEN** 生成器 MUST 非零退出并点名完整类型或成员路径，不得按匿名字节镜像

### Requirement: 独立包装值与字节入参必须有确定的值语义
独立的 `cacore::NameHash const&` 和 `cacore::PathHash const&` 入参 SHALL 投影为 `char const* + uint64_t len`，由原生侧构造目标类型并沿用现有名称哈希与路径规范化。独立的 `cacore::HashObj<T> const&` 入参 SHALL 按其包含的 `T` 值投影，并由原生侧重新构造 `HashObj<T>`；不得跨边界复制缓存哈希、有效位或内部视图。`T` MUST 满足公开数据记录要求，且 MUST 具有消费翻译单元可见的显式哈希来源：`CA_REFLECT(serializable)` 生成特化、`custom_hash_trait<T>` 或 `CA_HASH_BY_BYTES`。缺少哈希来源时 MUST 在生成期拒绝，不得留到原生编译期才暴露。

`castl::vector<uint8_t> const&` 入参 SHALL 投影为 `uint8_t const* + uint64_t count`，原生侧在调用前重建向量。空指针仅在数量为零时合法；空指针配非零数量 MUST 失败且不得进入实现。上述包装值和字节投影 SHALL 能与其他已支持参数组合，不得要求它们是方法的唯一参数。

包装值返回、包装值嵌入记录或容器、`HashObj` 缓存状态以及异步字节视图不在这些投影规则内；遇到这些形状 MUST 显式拒绝，不得静默丢弃语义。

#### Scenario: 名称与路径由原生构造语义重建
- **WHEN** 通过 C ABI 传入包含非 ASCII 文本的名称和需要规范化的路径
- **THEN** 原生实现收到的 `NameHash.string()` MUST 等于输入文本，`PathHash` MUST 等于用同一文本经现有 C++ 构造函数得到的对象，且参数后的其他实参仍保持原值

#### Scenario: 哈希对象只传所含值
- **WHEN** 通过 C ABI 传入一个 `HashObj<T>` 的镜像值
- **THEN** 原生实现收到的 `Get()` 各字段 MUST 与输入一致，且对象 MUST 与直接执行 `HashObj<T>{value}` 得到相同的哈希状态；不得从调用方内存读取私有缓存字段

#### Scenario: 没有哈希来源的记录不得构造 HashObj
- **WHEN** 一个记录满足公开数据记录布局条件，但消费翻译单元中没有生成哈希特化、`custom_hash_trait<T>` 或 `CA_HASH_BY_BYTES`
- **THEN** 独立 `HashObj<T>` 入参 MUST 在生成期非零退出并点名缺少的哈希来源；正向夹具 MUST 先接入显式哈希来源再验证构造

#### Scenario: 字节入参与其他参数组合
- **WHEN** 一条方法同时接收记录、标量、文本或句柄以及 `castl::vector<uint8_t> const&`
- **THEN** C ABI MUST 只出现定宽类型和指针加数量，原生实现 MUST 收到全部参数的对应值，空指针配非零字节数时调用次数 MUST 为 0

### Requirement: 含容器的输入记录经序列化块投影，两侧格式同源生成
成员含 `castl::vector`（元素为标量、枚举、纯标量记录、**`CA_BIND_VALUE` 值类**——本批扩类，design D11）或文本或**命名映射容器（键 `cacore::NameHash`，值限标量/枚举/记录/值类——本批扩类，D11）**或**接口对象引用（`shared_ptr<已挂 CA_BIND 的接口类型>`，按绑定对象句柄过界、thunk 从绑定对象表反查重建——本批扩类，D11）**的**参数位置（const 引用入参）**记录，MUST 按"序列化块"投影：生成器出该记录的托管镜像类型（字段级、可赋值构造）与序列化代码，过界线形由生成器两侧同源产出，C++ 侧 thunk 经 `cacore::codegen` 序列化设施反序列化为栈对象后调用原生——**原生签名与实现 MUST NOT 因此改动**。三类扩类元素的线形：值类容器元素按四字段线形（kind/handle/nameptr/len）逐个重复；映射按 count + 重复（key 线形, value 线形）；接口引用按对象句柄 uint64，句柄查无对象 MUST 边界拒绝并置错误码，MUST NOT 解引用空指针。**MUST NOT（扩类不放松边界）**：键非 `NameHash` 的映射、指向未绑定类型的智能指针、返回位置的映射容器、跨表对象引用——任一出现 MUST 生成期拒绝并点名，MUST NOT 静默丢字段；块头三项（格式版本号、类型限定名哈希、字段布局哈希）照旧同源覆盖新类别字段。块头 MUST 含三项：格式版本号、类型完整限定名的哈希、**字段布局哈希**（各字段"名+类型+偏移"序列的哈希，与布局清单同源）——缺第三项时"字段改名而类型序不变"的块与正确块字节完全相同，检不出来。字段名、偏移、类型 MUST 出自与布局清单同一来源生成的两侧代码，不允许一份手抄。私有字段记录 MUST 经 `CA_REFLECT`/`CA_CODEGEN_FRIEND` 标注取得序列化可见性（只加标注，不改字段布局）。**返回位置的容器、非 const 引用/指针的出参方向、`unordered_map`（键非 NameHash 的）、定长数组与联合体 MUST NOT 走本投影**（出参投影是独立形状，本批不做、生成期拒绝并留名）。

#### Scenario: 值类容器与映射成员往返逐字段一致
- **WHEN** 托管构造含 `vector<值类>` 与 `map<NameHash, 记录>` 成员的夹具记录、跨界调用、原生实现逐字段读出
- **THEN** 原生收到的对象各字段（含值类四字段逐项与映射键值对数）MUST 与托管构造完全一致；被调实现计数 MUST +1

#### Scenario: 接口引用成员经句柄反查重建
- **WHEN** 托管把已绑定的接口对象引用写入夹具记录字段后跨界调用
- **THEN** 原生实现 MUST 收到指向同一对象的 `shared_ptr`；故意写入坏句柄 MUST 边界拒绝、实现调用计数 0、MUST NOT 解引用空指针

#### Scenario: 未支持类别生成期点名
- **WHEN** 夹具记录含 `map<int, T>` 成员、指向未绑定类型的智能指针成员被采集
- **THEN** 生成器 MUST 非零退出并点名类别与恢复路径，MUST NOT 生成"签名对、调用行为未定义"的中间态

### Requirement: 资源引用值类按线形组合投影且往返无损
`ImageHandle`/`BufferHandle` 这类"值语义资源引用"（内部持智能指针或名称哈希、作哈希键、自身不可进反射表）MUST 以专用投影过界：线形为 `(kind 枚举, 对象句柄 uint64, 名称 ptr+len)` 的四类线形组合；托管侧 MUST 得到与该值类构造通道一一对应的静态工厂（按已绑定对象句柄构造、按名称构造等）；C++ 侧组装 MUST 复用既有智能指针入参反查与名称哈希原生构造语义——同一对象句柄过界后 MUST 解析到同一实例，按名构造 MUST 与原生同名直接构造的结果一致。该值类自身的成员方法 MUST NOT 被采集为表面（只作为参数/返回的过界值）。无效句柄或非法名称 MUST 在边界被拒并置错误码，MUST NOT 进入实现。本条的机制验证以夹具等价类承担（真实值类尚未进登记表，条文对它暂不触发绑定义务；直绑批按真实头快照把两值类接入时，本条即为其验收标准——不存在"规范已生效却无人可验"的空转态）。

#### Scenario: 构造通道往返同一性
- **WHEN** 夹具值类分别用"按对象句柄构造"与"按名称构造"两条通道建引用并传给原生方法
- **THEN** 原生实现收到的对象 MUST 与该对象为同一实例、名称哈希与原生直接构造逐位一致；类型枚举读出与构造通道一致

#### Scenario: 坏引用不进实现
- **WHEN** 用已释放句柄或空名构造引用后调用
- **THEN** 调用 MUST 返回错误码、错误文本点名参数，且原生实现调用计数 MUST 不变
