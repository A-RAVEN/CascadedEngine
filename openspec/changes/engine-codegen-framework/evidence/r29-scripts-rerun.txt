# Generated evidence for task 9.52(2): the six archived evidence scripts re-run in one pass, with the
# output written straight to this file as UTF-8 bytes.
#
# What was wrong before. This file used to hold THREE sections recorded at different moments — a
# `FileNotFoundError` stage, a cp1252 `UnicodeEncodeError` stage, and a "runs, but exit 1" stage — with
# nothing saying which was superseded; the Chinese check names had been destroyed (67 `?` characters);
# and the file's own TOTAL said 7 failures while the body named 6.
#
# What replaces it. `evidence/rerun_scripts.py` runs all six scripts as subprocesses in ONE pass,
# captures their bytes and decodes them as UTF-8 (each script reconfigures its own stdout/stderr to
# UTF-8, which is what keeps the Chinese names intact), and COUNTS the failure lines from the captured
# text. The summary at the bottom of each section is therefore computed from the body it summarises and
# cannot drift away from it.
#
# The working directory is a parameter, so "runs from any directory" is measured twice below instead of
# asserted: once from the repository root, once from a subdirectory.
#
# Historical note, kept on purpose, because it explains why some checks fail and why that is currently
# acceptable: the four `verify_round*.py` scripts assert on WORDING that later revisions changed
# deliberately (they look for phrases such as "no live build.py:<line> citation" or "REQ#build.py does
# not write line numbers"). A failure there is NOT evidence about the current tree — the current tree's
# checks live in the change's `tasks.md` and Review Log. `check_codegen_failure.py` and
# `check_emit_order.py` execute real code paths and are expected to exit 0.
#
