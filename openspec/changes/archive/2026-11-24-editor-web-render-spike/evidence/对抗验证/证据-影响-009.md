## 4. 影响

- 「逐字节不变」在工件里不可复现：判定脚本必须显式给 `--baseline` 与 `--product-dir`，而 tasks 4.1 一个都没给；仓库里同时存在 200 条级别的旧锚与 221 条的新锚，脚本 docstring 指向较旧那份。
- 上一批的同类证据文件里只有一行「基线对账：缺失 0 / 不一致 0 / 多余 0」，没有命令、没有锚名 —— 这已经证明这种写法会让读者无法判断比的是哪一版产物；spike 的 4.1 照抄了同一写法。
- 因为脚本不在 build.py 里，4.1 若不写命令，就没有任何自动环节能留下可核读数；「0/0/0」可以来自任意一次手工运行。

## 5. 建议的能失败判据

1. tasks 4.1 写死命令与两个路径（先定「当前锚」是哪份，并把 docstring 与新锚之间的矛盾处理掉）。
2. 验收：命令退出码 0，输出第一行必须是「基线对账：缺失 0 / 不一致 0 / 多余 0」，完整输出贴进 `evidence/4.1-基线.txt`，文件里同时写命令与锚文件名。
3. 反向构造：把 `--product-dir` 指向一个空目录，命令必须变成「缺失 N」并退出码 1 —— 证明这条判据不是恒绿。
