## 4. 影响

- 现有三个端口号已被占用（18390 默认、18391 窗口面板用例、18392 资产浏览器用例），两个编辑器用例都专门写了「避开」注释。spike 若照编辑器模式自建 HttpListener 提供服务，又没分配端口，最自然的选择就是默认 18390 —— 此时若本机开着编辑器，`Start()` 直接抛异常，整条正控失败，错误文本与互操作无关。
- 若选 `file://`，WebView2 对本地文件的导航/资源加载前提、`getImageData` 的跨源限制、以及「页面从哪份构建产物来」都没有写；若选内联 HTML，则 `EditorWeb/spike.html + src/spike.ts` 的构建任务（1.2）失去落点。
- 任何选择都要落到 tasks 里；现在四份工件对加载方式 0 规定。

## 5. 建议的能失败判据

1. tasks 1.2/2.2 写死加载方式：`file://`（写明绝对路径从哪里解析）或专用端口（例如 18393，并写进 `CASCADED_WEBRENDER_SPIKE_PORT`）。
2. 验收：启动前 `Test-NetConnection -Port <端口>` 或监听失败必须以点名端口的错误码判红（`E_SPIKE_PORT`），不得落到「互操作不可行」。
3. 若选 `file://`：加一条断言「导航 URL 以 file:// 开头，且静态资源相对 spike.html 解析」，并在 evidence 里贴 WebView2 导航读数。
