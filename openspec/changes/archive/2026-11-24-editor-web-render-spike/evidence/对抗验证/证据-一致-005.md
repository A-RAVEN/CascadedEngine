## 一、spec 把「独立进程」等同于「不复用」

`spec.md` 要求 1 原文（逐字，第 5 行，节选）：

> spike MUST NOT 复用 EditorService 一次性状态机（独立进程/独立入口），MUST NOT 改动现有 editor-window-panel / editor-asset-browser 实现。

`tasks.md` 2.2 原文（逐字，第 15 行，节选）：

> - [ ] 2.2 独立原型入口：tester 用例 TestWebRenderSpike（Main.cpp + --list 登记，独立进程跑，照 TestEditorAssetBrowser D8 先例，不复用 EditorService 一次性状态机）……

## 二、先例本身是「独立进程 + 启动 EditorService」

`Main.cpp` 原文（逐字，第 6480 行，位于 `TestEditorAssetBrowser` 内）：

```cpp
	::SetEnvironmentVariableA("CASCADED_EDITOR", "1");
```

`EditorService.cs` 原文（逐字，第 120 行）：

```cpp
        internal static bool Enabled => Environment.GetEnvironmentVariable("CASCADED_EDITOR") == "1";
```

`EditorService.cs` 状态机入口与终态（逐字，第 139/148/308 行）：

> 139：`internal static void Tick(IWindowSystem system, ScriptRenderBackend backend, bool renderBound)`
>
> 148：`if (!Enabled || s_state == 3 || s_state == 4)`
>
> 308：`s_state = 4;`

`Host.cs` 每帧调用（逐字，第 309 行）：

> `Editor.EditorService.Tick(s_system, s_renderBackend, s_renderTablesBound);`

也就是说，TestEditorAssetBrowser 这个「先例」里，编辑器窗口、WebView2 控制器、环境创建、消息泵全部由 EditorService 提供。

## 三、文档自己写明独立进程的唯一理由是状态机不能同进程

`docs/testing.md` 原文（逐字，第 42 行，节选）：

> `TestEditorAssetBrowser` 由 `editor-asset-browser` 加入（**第 23 条，`--list` 最后一行；必须独立进程跑** —— 编辑器服务是进程级一次性状态机，`TestEditorWindowPanel` 收尾会主动停服务，两个编辑器用例同进程不能共存，所以它**不进全量同进程顺序跑**，只按 `--test TestEditorAssetBrowser` 跑）

「两个编辑器用例同进程不能共存」是进程隔离的理由，与「不复用 EditorService」无关。照这句话执行，「独立进程」只解决冲突，不解决复用。

## 五、结论与改法

spec 的 MUST NOT 与 tasks 点名的先例互相抵消：按先例做，就是复用 EditorService；按 MUST NOT 做，就没有先例可照，而且 2.2 也没给环境创建/窗口/泵的替代落点（见主张-一致-004）。这条 MUST 现在无法被判红，也无法被判绿。

改法：把「不复用」落成三条可核断言（进程环境不含 CASCADED_EDITOR、日志不含 EditorService 行、代码不调 EditorService.Tick/EditorWindow.Create），2.2 验收按这三条写；或者删掉 MUST NOT，承认原型入口借用 EditorService 的环境创建，把「独立」重新定义清楚。
