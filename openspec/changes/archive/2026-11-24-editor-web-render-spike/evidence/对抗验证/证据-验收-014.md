- 面：验收可失败性-④（4.2 可行性结论「可核」）
- 严重度：minor
- 主张：1.1 与 4.2 两处判定之间没有一致性判据，也没有翻转说明的要求，三段自相矛盾可以同时过。

## 一句话结论

同一条结论在工件里出现两次（1.1 研究时一次、4.2 收尾时一次），但没有一处要求它们对得上。可核性依赖于读者自己去比对两份 evidence——这不是判据。

## 为什么这条判据现在不能失败

1. 1.1 与 4.2 各自自带验收，各自都能单独通过；两份 evidence 里的判定相反也不触发任何判据。
2. 判定翻转本身是合理的事（实现尝试可能推翻研究结论），但合理不等于可以不说。没有「翻转必须给触发证据」的要求，读者无法分辨「翻转」与「写错了」。
3. 与主张-验收-012 合起来看：4.2 既不与 2.3 的实际路径对照，也不与 1.1 的判定对照，于是这份结论只对「它自己写的那句话」负责。

## 加严建议（可直接落进工件）

1. 4.2 的 evidence 必须有一节「与 1.1 判定的对照」，逐候选写：1.1 判定 / 4.2 判定 / 是否一致。
2. 不一致时必须点明翻转的触发证据（哪一条运行读数或哪份文档让结论改变）；没有触发证据即不合格（`E_WEBSPIKE_VERDICT_DIVERGED`）。
3. 4.2 引用的版本号必须与 1.1 逐字相同（与主张-验收-006 的建议衔接）。
