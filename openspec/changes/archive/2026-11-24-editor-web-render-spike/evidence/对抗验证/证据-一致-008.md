# 证据 008：tasks 3.1 的「或写死纯色」让期望值出现第二个未定义口径

## 一、tasks 3.1 允许换期望

`tasks.md` 3.1 原文（逐字，第 20 行）：

> - [ ] 3.1 正控判据（能失败）：网页 canvas 中心像素经 getImageData 回传 C++ 断言 == (255,0,0,255)（或写死纯色）；反例（原生未渲染/互操作断链）canvas 空白/黑 MUST 红。验收：独立进程两后端（D3D12 主；Vulkan 不要求）正控过；红态构造可核（evidence/3.1-*.txt）。

## 二、其余三处都固定为 (255,0,0,255)

`spec.md` 场景 1（逐字，第 10 行，节选）：

> - **THEN** 网页 canvas 中心像素 MUST == (255,0,0,255)……

`tasks.md` 2.1（逐字，第 14 行，节选）：

> 验收：构建过；共享句柄产出可核；离屏读回中心 == (255,0,0,255)（原生侧正控）。

`proposal.md`（逐字，第 12 行，节选）：

> - **正控判据**：网页 canvas 真实显示原生渲染像素（读回核对，沿用 (255,0,0,255) 精确匹配惯例）……

`design.md` D4 同样写「== (255,0,0,255)（或写死纯色期望）」，也没有给替代值。

## 三、grep 读数

```text
PS> Select-String -Path '...\spec.md','...\tasks.md' -Pattern '255,0,0,255|写死纯色'
spec.md:5  ……中心像素 MUST 等于写死期望（沿用 (255,0,0,255) 精确匹配惯例）……
spec.md:10 - **THEN** 网页 canvas 中心像素 MUST == (255,0,0,255)……
tasks.md:14 - [ ] 2.1 ……离屏读回中心 == (255,0,0,255)（原生侧正控）。
tasks.md:20 - [ ] 3.1 ……断言 == (255,0,0,255)（或写死纯色）……
```

「写死纯色」在工件里没有跟随任何四元组；唯一的具体期望仍是 (255,0,0,255)。

## 四、结论与改法

括注给了第二个口径却不给值，等于允许执行者自选颜色。它与 spec 场景 1 的固定 MUST 直接冲突：选非纯红的纯色时，tasks 3.1 可通过而 spec 场景 1 不成立。

改法：删掉「（或写死纯色）」；或在 tasks 3.1 与 spec 场景 1 同时写死纯色四元组（必须与 tasks 2.1 的原生侧期望同源）。
