## 4. 影响

- 按 tasks 2.2 的字面（写在 `Main.cpp` 的 tester 用例里），C++ 代码调不到 `CreateCoreWebView2ControllerAsync`，也拿不到 `Bounds` 属性；tester 既不链接 WebView2，也没有原生 WebView2 头，编不过。
- 实现者要让它能跑，只能自行发明一个托管侧类（文件、命名空间、门控、从 `Host.Tick` 调用的位置、关闭路径），这些全部落在 tasks/design 的验收之外；2.2 的验收只核 `--list` 与「独立进程起原型窗」，不核这个入口存在。
- 结论：**「独立原型入口不复用一次性状态机」是本次的核心声称，但没有任何一条任务落在可执行处**；这不是细节缺失，而是 2.2 按字面不可执行。

## 5. 建议的能失败判据

1. tasks 2.2 拆两条：C++ 用例（`--list` 登记、独立进程、每帧 `pScriptHost->Tick(0.016)` + `pWindowSystem->UpdateSystem()`）与托管侧新文件（点名路径，如 `Scripting/Managed/EditorWebRenderSpike/WebRenderSpikeWindow.cs`）。
2. 托管侧任务写死：`CoreWebView2Environment.CreateAsync(null, <专用数据目录>)` → `CreateCoreWebView2ControllerAsync(Hwnd)` → `Bounds = 整客户区` → `Navigate(spike.html)`，并在 `Host.Tick` 里点名调用点与门控。
3. 验收加两条能失败的检查：① `Select-String -Path 'Scripting/Managed/Host.cs' -Pattern 'WebRenderSpike'` 必须命中恰 1 处；② 原型窗读数行 `controller=1/nav=1`（读不到或 0 判红）。
