## 三、构建入口没有登记新页面

`EditorWeb\vite.config.ts` 的多页输入：

```ts
    rollupOptions: {
      input: {
        index: 'index.html',
        assets: 'assets.html',
      },
    },
```

只有两个页面入口。`build.py` 的 `build_editor_web()`：

```python
    completed = subprocess.run([npm, "run", "build"], cwd=str(web_dir))
    if completed.returncode != 0:
        raise RuntimeError(f"npm run build 失败，退出码 {completed.returncode}")
    dist = web_dir / "dist"
    # editor-asset-browser 3.1：两个页面都要在（index.html = 右面板对象检查器，assets.html = 底部资产
    # 浏览器 dock，各由一个 WebView2 控制器加载）。少一个就在构建期报出来，不留"运行时才发现缺页面"。
    for page in ("index.html", "assets.html"):
        if not (dist / page).is_file():
            raise RuntimeError(f"前端构建没有产出 {page}：{dist}")
    target = BUILD_DIR / "bin" / "editor-web"
    if target.exists():
        shutil.rmtree(target)
    shutil.copytree(dist, target)
```

只校验 `index.html` 与 `assets.html`，然后把整个 `dist` 拷到 `bin/editor-web`。

## 四、按任务字面实现会发生什么

1. 新建 `EditorWeb/spike.html` 与 `EditorWeb/src/spike.ts`。
2. 不改 `EditorWeb/vite.config.ts` 的 `rollupOptions.input`。
3. 跑 `npm run build`：`tsc --noEmit` 通过、`vite build` 成功退出。
4. `dist` 里只有 `index.html`、`assets.html` 及其资源，没有 `spike.html`；`build.py` 的页面校验也不会报错，整目录拷贝后 `bin/editor-web` 同样没有 `spike.html`。
5. tasks 1.2 的验收“构建过；grep spike.html 含 canvas”仍然通过（`grep` 查的是源码文件里的 `<canvas>`，不是构建产物）。

所以“构建过”这条验收对“页面是否真的被构建进 `bin/editor-web`”恒真；`spike.html` 的构建入口在仓库里并不存在，`tasks.md` 1.2 也没有点名改 `EditorWeb/vite.config.ts`（也没点名把 `spike.html` 加进 `build.py` 的页面校验）。这是本条 claim 的核心。

## 五、本面结论

- 三个名字当前都零命中，属于新增；工件措辞（“如”）没有把不存在的文件说成存在，这一半不判阻断。
- `EditorWeb/vite.config.ts` 只登记 `index.html` 与 `assets.html`，`build.py` 只校验这两个页面；不把 `spike.html` 加进多页输入，`npm run build` 仍成功但产物里没有它。
- `tasks.md` 1.2 的“构建过”对“`spike.html` 是否被产出”不可失败，且任务没点名 `EditorWeb/vite.config.ts` 这一处必改文件。
- 以上合并成 `主张-存在-003.json`。
