## 一、正文的 MUST：先核实，再实现

`spec.md` 要求 2 正文（逐字，第 19 行）：

> spike MUST 先核实 WebView2/Chromium 实际可用的原生 D3D12 共享纹理→网页 canvas 路径（联网核文档/版本，按 CLAUDE.md 用 MCP 工具），再按核实结果实现。结论 MUST 可核：可行路径 MUST 给运行读数；零拷贝互操作不可行 MUST 给具体阻塞证据（API 缺失/版本/文档 URL），MUST NOT 用「看起来不行」口头断言。CPU 读回→canvas.putImageData MUST 作为兜底概念验证正控（保证「原生渲染能显示进网页」可证）。结论 MUST 留档 evidence 并回写 TODO/008 未决问题。

## 二、场景却给「尚未核实」开了通过口

同要求场景 1（逐字，第 21–24 行）：

> #### Scenario: 兜底正控可跑通
>
> - **WHEN** 零拷贝互操作不可行（或尚未核实）
> - **THEN** CPU 读回共享纹理→网页 canvas.putImageData MUST 仍能显示原生像素并通过正控；evidence MUST 注明此路径非零拷贝

「或尚未核实」这五个字与正文的「MUST 先核实」直接冲突：按场景执行，核实不是前置条件；正文的核实义务没有对应的红态。

## 三、场景 2 也接不住「未核实」

同要求场景 2（逐字，第 27–29 行）：

> #### Scenario: 不可行结论有阻塞证据
>
> - **WHEN** 判定零拷贝共享纹理→WebGPU 在 WebView2 不可行
> - **THEN** evidence MUST 含具体阻塞（缺失的 API 名 / WebView2 版本 / 文档 URL）+ 退路建议（路线 B 透明叠层 / CPU-GPU 桥）；MUST NOT 仅口头断言

它只在「判定不可行」时触发；「还没核实」不落在任何场景的 WHEN 里，因此没有 Must 红的条件。

## 四、tasks 1.1 的验收在 spec 里没有落点

`tasks.md` 1.1（逐字，第 9 行）：

> - [ ] 1.1 核实原生 D3D12 共享纹理→WebView2 网页 canvas 的可用互操作路径（按 CLAUDE.md 用 MCP 工具联网核 WebGPU/WebView2/DXGI 文档与版本）：候选①零拷贝共享纹理互操作（Chromium/WebView2 是否暴露）②VideoFrame→importExternalTexture 桥 ③CPU 读回→canvas.putImageData 兜底。验收：evidence/1.1-互操作研究.md 含每条候选的核实命令/文档 URL/WebView2 版本 + 可行/不可行判定；不可行有具体阻塞（缺失 API 名/版本），非口头断言。

这条任务的验收只能由执行者自觉；spec 场景允许跳过它仍通过正控。

## 六、结论与改法

正文与场景对「核实是不是前置」给出了相反的规定；后果是本 change 最值钱的产出（可行性结论）可以合法缺失，而 3.1 正控仍然绿。

改法：删「（或尚未核实）」；或拆场景为「尚未核实 → MUST 红（缺 1.1 证据）」与「判定不可行 → 阻塞证据 + 兜底正控过」两条，并把 1.1 的验收挂到一条能失败的断言上（evidence 缺任一条候选的核实命令/版本/URL 即红）。
