## 三、MDN 原文

URL：<https://developer.mozilla.org/en-US/docs/Web/API/GPUDevice/importExternalTexture>

抓取结果（HTTP 200）关键句逐字：

> The **`importExternalTexture()`** method of the [`GPUDevice`](https://developer.mozilla.org/en-US/docs/Web/API/GPUDevice) interface takes an [`HTMLVideoElement`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement) or a [`VideoFrame`](https://developer.mozilla.org/en-US/docs/Web/API/VideoFrame) object as an input and returns a [`GPUExternalTexture`](https://developer.mozilla.org/en-US/docs/Web/API/GPUExternalTexture) wrapper object containing a snapshot of the video that can be used as a frame in GPU rendering operations.

`source` 参数的说明：

> The [`HTMLVideoElement`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement) or [`VideoFrame`](https://developer.mozilla.org/en-US/docs/Web/API/VideoFrame) source of the video snapshot.

判定：

- 工件写「`importExternalTexture` 收 VideoFrame」——**漏了 HTMLVideoElement**；作为简写不算错，但作为「逐项核过」的 API 描述不完整。
- 工件写「不收裸共享句柄」——MDN 的源类型只有 HTMLVideoElement / VideoFrame，**属实**；没有出现 DXGI 句柄、NT 句柄、Vulkan external memory 之类的源类型。

## 五、GPUWeb 议题 #5167

URL：<https://github.com/gpuweb/gpuweb/issues/5167>

用 GitHub API 读取（`Invoke-RestMethod 'https://api.github.com/repos/gpuweb/gpuweb/issues/5167'`）的真实元数据：

正文逐字（节选）：

> **Problem:**
> `importExternalTexture()` currently requires its source to be HTMLVideoElement or VideoFrame. There is no standard way to turn a platform‑shared GPU texture handle, already supported by many media / realtime apps (Unity, Touch Designer, Notch...) into either of those objects, so WebGPU developers must round‑trip through CPU memory.
>
> **Proposal:**
> Add a constructor or factory, e.g.
> ```js
> new VideoFrame({ sharedTexture: { dxgiHandle, width, height, format } })
> // (similar fields for IOSurface / dma‑buf).
> ```

判定：

- 这条议题正文直接支持 design 的两句话：「标准 WebGPU 无直接导入 DXGI 共享句柄入口」和「零拷贝可能不可行」。
- 议题 `state=closed`、`label=invalid` 说明这个提案**没有进入规范**，不等于能力已经存在；引用时必须写清这一点，不能把 closed 读成「已支持」。
- 议题提出的 `new VideoFrame({ sharedTexture: ... })` 是**提案里的假想 API**，不是现行 API；tasks 1.1 的「缺失 API 名」可以点名它不存在，但不能把它当成可调用的入口。

## 六、对工件的判定

1. **「`importExternalTexture` 收 VideoFrame，不收裸共享句柄」**：核心属实，但漏 HTMLVideoElement；design 没给规范 URL。判 minor，不判 blocking。
2. **「标准 WebGPU 无直接导入 DXGI 共享句柄入口」**：属实；可引 MDN + GPUWeb #5167。design 没写出处，但这句话本身不是凭空发明。
3. **「零拷贝可能不可行」**：有依据的假设，不是臆测；design 也把它标成「预期可能结论」、spec 要求不可行必须给阻塞证据，方向是对的。缺陷是：
   - design 没把 #5167 / MDN 写进依据；
   - 路径①「Chromium/WebView2 实验性共享纹理互操作（若该版本暴露）」没有点名任何候选 API 名或版本号，tasks 1.1 的「缺失 API 名/版本」无法落到一个具体名字，容易写成「看起来不行」；
   - 建议把缺失 API 写成具体形态：`importExternalTexture` 只接受 HTMLVideoElement / VideoFrame；没有 `GPUDevice.importSharedTexture` / `GPUDevice.importExternalTexture({ source: dxgiHandle })`；`VideoFrame` 没有从 DXGI 共享句柄构造的构造器（#5167 提议的 `new VideoFrame({ sharedTexture })` 未进规范）。
