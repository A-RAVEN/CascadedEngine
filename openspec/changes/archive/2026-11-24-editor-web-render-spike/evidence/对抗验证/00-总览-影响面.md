## 结论

15 条主张：**6 条阻断级（blocking）、9 条误导级（misleading）**。核心问题不是「spike 做不出来」，而是
**三条 MUST 互相互斥、且多处验收没有能失败的判据**：

1. `tasks 2.2` 把 WebView2 控制器创建写成 C++ tester 用例的事，但全仓 C++ 侧没有 WebView2（该 API 只在托管包），托管侧入口/门控/关闭三样全部无任务。
2. 绑定「逐字节不变」与「后端纹理带共享句柄」互相矛盾：`GPUTexture` 在 14 个可绑接口里，要拿句柄最直接的做法就是改它，而改它必然重生成绑定产物。
3. 零拷贝与 CPU 读回兜底在验收读数上不可区分：没有 `path=` 字段，`3.1` 只看中心像素，核心结论只能靠 evidence 散文。

## 经核未发现问题的点（避免误伤）

- **「独立进程避开 EditorService 一次性状态机」在机制上可行**：`EditorService.Enabled` 默认假（`EditorService.cs:120`），
  `Tick` 在门控关时直接返回（`:148-151`），`Shutdown` 对未启动是空操作且幂等（`:254`）。阻断不在静态状态本身，
  而在「新托管入口 / 关闭 / 门控登记」三处缺失。
- **C# 原型代码不会碰生成器**：编辑器 C# 文件 0 处 `CA_REFLECT/CA_CODEGEN`，`CODEGEN_ANNOTATED` 区间 0 处 Editor/Scripting。
  冲突只出在原生的共享句柄面。
- **绑定基线脚本存在且能失败**：`check_binding_baseline.py` 有真实比对与 `--self-test` 自检，问题只在 spike 4.1 没把它钉到具体锚。
- **既有红态惯例可借用**：`CASCADED_EDITOR_SELFTEST=no-runtime/no-dock-controller/no-facade` 与 `CASCADED_CSHARP_*_SELFTEST`
  已经是成熟做法，spike 直接照抄即可，不需要新发明机制。

## 建议的修订优先级（给主循环）

1. 先决定**共享句柄走不走可绑面**（影响-004/008）：这是唯一会让两条 MUST 直接互斥的点，且决定 4.1 的写法。
2. 再补**托管侧入口 + 关闭 + 门控登记**（影响-001/002/003）与**兜底字节通道**（影响-007/011），让 2.2/2.3 可执行。
3. 最后补**能失败的验收**：`path=` 字段（013）、红态开关（014）、多点像素（015）、同跑目录规则（010）、
   `--list`/全量/文档登记（012）、绑定锚钉死（009）。
