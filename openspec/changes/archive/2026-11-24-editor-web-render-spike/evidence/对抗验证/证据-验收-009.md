# 证据：主张-验收-009

- 面：验收可失败性-③（2.1 原生离屏读回与 3.1 网页 canvas 是否两套独立判据）
- 严重度：misleading
- 主张：「红三角或纯色」的二义与「只看中心一个点」的判据合起来，使「清屏为红、不画任何几何」也能过 2.1。

## 一句话结论

三处工件对「画面是什么」写得不一致，而像素判据只有一个中心点。按其中一种读法，一次清屏就能满足判据；仓库既有先例用背景绿 + 中心红两个点把「清屏」和「画了」分开，本工件退了回去。

## 为什么这条判据现在不能失败

1. 「纯色」有两种读法：整幅清屏为红；或常量色三角形。按第一种读法，D3D12 只需 `ClearRenderTargetView` 为红，中心像素就满足断言，不需要顶点缓冲、不需要绘制调用、不需要着色器。
2. 期望只有一个点。清屏渲染与真画一个三角形在中心点上是同一个值，判据无法区分。
3. 工件内部本身不一致：proposal 与 design 允许纯色，tasks 与 spec 场景写红三角。执行者按 design 做纯色，验收按 tasks 看中心像素，两边都不算错。
4. 仓库先例已经给出了更严且现成的办法：背景点 + 中心点两点判定（命令 3）。本工件没有采用，等于主动放松。

## 加严建议（可直接落进工件）

1. 统一措辞：proposal.md:10、design.md:25 删掉「或纯色」，与 tasks/spec 一致写死「红三角」。
2. 像素判据改成两点：背景点 == `(0,255,0,255)`、中心点 == `(255,0,0,255)`，任一点不符即红（照 `Main.cpp:2347-2349`）。清屏为红的实现会因为背景不是绿而失败。
3. 若确实想保留「纯色」形态，必须另立一条判据把它和清屏分开（例如纯色画面里必须存在一个不同色的标记像素），否则删掉这个形态。
