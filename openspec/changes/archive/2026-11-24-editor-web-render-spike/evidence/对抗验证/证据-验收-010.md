# 证据：主张-验收-010

- 面：验收可失败性-③（2.1 原生离屏读回与 3.1 网页 canvas 是否两套独立判据）
- 严重度：Blocking
- 主张：两条判据各自只要求「中心是纯红」，没有任何同源绑定；两个红可以互不相干，两绿不等于「原生像素进了网页」。

## 一句话结论

一个判据证「原生侧某张图中心是红」，另一个判据证「网页 canvas 中心是红」。本 spike 要证的是「网页上那块红就是原生渲染的那张图」。工件里没有任何一处把两边绑成同一幅图。

## 为什么这条判据现在不能失败

1. 2.1 的绿来自「原生读回某张图的中心像素」。3.1 的绿来自「网页 canvas 的中心像素」。工件没有规定这两张图必须是同一幅，也没有规定两边的像素值必须逐项相等。
2. 于是至少三条路径都能让两条判据同时绿而核心命题为假：
   - 网页胶水页用本地常量红画一块（见主张-验收-003）；
   - 原生读回的是一张普通离屏纹理，网页显示的是另一张（见主张-验收-008）；
   - 网页显示的是上一帧或缓存的旧图（无帧序号绑定，见主张-验收-002）。
3. 唯一可能提供同源证据的是 3.2 的抓窗截图 + read_image 核对，但它是人的核对、不进自动化判据，且在 design.md:39 里与 getImageData 断言是「或」的关系。
4. 常量 `(255,0,0,255)` 作为唯一共同量，信息量太小：它无法区分来源、无法区分帧、也无法区分哪张纹理。

## 加严建议（可直接落进工件）

1. 原生侧每帧写不可猜的标记：用帧序号与一个常量种子算出 4 个角像素值写进 4 个角，并把整图哈希（算法与种子只在 C++ 侧）写进读数行。
2. 网页回传必须带同一帧的 4 个角像素值 + 整图哈希（由页面从 canvas 位图算出）+ 帧序号；C++ 逐项对账。
3. 三项（哈希、4 角、帧序号）任一不等判 `E_WEBCANVAS_MISMATCH` 退出 1。这样「网页自己画红」「原生读的是另一张图」「显示的是旧帧」都过不了。
4. 3.2 的抓窗核对从「或」改成「且」（与主张-验收-001 的建议一致），因为它是唯一从外部视角看画面的证据。
