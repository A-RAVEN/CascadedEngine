## 一、同一句里两个相反的要求

`tasks.md` 3.1 原文（逐字，第 20 行）：

> - [ ] 3.1 正控判据（能失败）：网页 canvas 中心像素经 getImageData 回传 C++ 断言 == (255,0,0,255)（或写死纯色）；反例（原生未渲染/互操作断链）canvas 空白/黑 MUST 红。验收：独立进程两后端（D3D12 主；Vulkan 不要求）正控过；红态构造可核（evidence/3.1-*.txt）。

「两后端」与「Vulkan 不要求」不能同时成立；括号没有说 Vulkan 是「必须过」「允许不过」还是「不跑」。

## 二、Non-goals 明确排除 Vulkan

`proposal.md` 原文（逐字，第 34 行）：

> - **Vulkan 共享纹理互操作**：本 spike 只 D3D12（Vulkan↔WebGPU 更不成熟，留后续）。

同文件第 28 行（逐字，节选）：

> - **不动**：现有 editor-window-panel / editor-asset-browser 实现与规范；Vulkan 后端；生成器/绑定产物（逐字节不变）；dock 框架。

## 三、spec 没有 Vulkan 正控要求

`spec.md` 要求 3 原文（逐字，第 33 行，节选）：

> 现有 tester 用例 + CoreTests MUST 全绿；绑定产物 MUST 逐字节不变（spike 不碰生成器/原生绑定面）。

这里说的「现有 tester 用例」是既有用例（含 Vulkan 回归），不是「原型窗在 Vulkan 上正控过」。原型正控在 spec 里只有 D3D12 共享纹理这一条。

## 四、grep 读数

```text
PS> Select-String -Path '...\tasks.md','...\proposal.md' -Pattern '两后端|Vulkan'
tasks.md:20 - [ ] 3.1 ……验收：独立进程两后端（D3D12 主；Vulkan 不要求）正控过……

proposal.md:34 - **Vulkan 共享纹理互操作**：本 spike 只 D3D12……
```

4.1 的「两后端」指既有用例的回归（合理），3.1 的「两后端」指原型正控（越界且与括号矛盾），两处措辞同一个词但含义不同。

## 五、结论与改法

3.1 的验收句既无法执行也无法判红：不知道该跑几个后端、期望什么读数。若真按「两后端」跑原型窗，就要求 Vulkan 侧也有共享纹理路径——proposal 明确说没有、留后续。

改法：改成「独立进程 D3D12 正控过」，给出命令与期望读数；Vulkan 若顺手跑只作诊断、不入验收。要保留 Vulkan 正控则先改 Non-goals 与 spec（本批不建议）。
