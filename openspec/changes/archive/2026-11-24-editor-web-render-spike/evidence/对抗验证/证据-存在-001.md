### 2.3 共享纹理创建/导出在仓库里零现成代码


`Interface\RenderInterface\header\GPUTexture.h` 的纹理描述（共享相关字段为零）：

### 2.4 `D3D11_RESOURCE_MISC_SHARED` 不属于 D3D12 资源描述

本机 Windows SDK 头（`C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um\`）：

```text
d3d11.h
1251:         D3D11_RESOURCE_MISC_SHARED	= 0x2L,
```

它是 `D3D11_RESOURCE_MISC_FLAG` 的成员，写在 `D3D11_RESOURCE_DESC.MiscFlags` 上。D3D12 侧对应的共享机制是：

```text
d3d12.h
3019:         D3D12_HEAP_FLAG_SHARED	= 0x1,
...
9159:         virtual HRESULT STDMETHODCALLTYPE CreateSharedHandle(
```

`D3D12_RESOURCE_DESC` 没有 `MiscFlags` 字段；D3D12 共享纹理要走 `D3D12_HEAP_FLAG_SHARED` 堆标志 + `ID3D12Device::CreateSharedHandle`。因此设计里“带 `D3D11_RESOURCE_MISC_SHARED` 的纹理”这一写法，若照字面在 D3D12 后端创建渲染目标，是编不过的；括号里的“或 D3D12 shared handle”才是 D3D12 的路径。工件把两个不同 API 族的写法并列成同一件事，且没有说明前者需要额外的 D3D11 设备/纹理，属于会误导实现的写法。

## 三、本面结论

- 目录、工程名、模块注册名真实；“`D3D12RenderBackend` 类”不存在，真实类名 `RenderBackend_D3D12`（不判阻断，但实现者需知道）。
- “D3D12 后端渲染到共享纹理”没有现成可复用代码：全仓 `MISC_SHARED`/`HEAP_FLAG_SHARED`/`CreateSharedHandle`/`SharedHandle` 零命中，`GPUTextureDescriptor` 无共享字段。
- `D3D11_RESOURCE_MISC_SHARED` 是 D3D11 的 `MiscFlags`，不是 D3D12 资源描述字段；D3D12 共享纹理须 `D3D12_HEAP_FLAG_SHARED` + `CreateSharedHandle`。
- 以上合并成 `主张-存在-001.json`。
