## 4. 影响

- 原型窗一旦按 2.2 建出 WebView2 控制器，就多了一个持有导航事件回调的 COM 对象；`Host.Shutdown` 只调 `EditorService.Shutdown` 再按固定清单释放表面对象，**没有任何位置关闭原型控制器**，工件里也 0 处任务/验收要求关闭。
- 本仓库把「处置 WebView2 全部先于 hostfxr_close」写成 editor-window-panel D1 硬判据，CSharpHost 注释记录了关闭顺序不当导致的 `0xC0000005`；把控制器留到运行时关闭之后是同一个失败类。
- 后果是「验收全绿、退出码 0」与「进程在退出时崩/下一次运行不稳定」可以同时成立：3.1/3.2/4.1 都只跑一次、只看绿态，没有关闭读数，也没有连跑两次的判据。

## 5. 建议的能失败判据

1. tasks 2.2 补一句关闭路径：原型窗关闭时 `controller.Close()` + `window.CloseWindow()/Dispose()`，并在 `Host.Shutdown` 里紧跟 `EditorService.Shutdown` 之后调用（先于 hostfxr_close）。
2. 验收：关闭日志点名「原型控制器已关闭」；读数行 `prototypeController` 关闭后为 0；同一命令连跑两次退出码都是 0，且当前目录没有新增 `crash_*.dmp`。
3. 反向构造：注释掉关闭调用后，上述连跑判据必须变红（至少一次崩溃 dump 或退出码非 0），把「关闭任务存在」做成可失败判据。
