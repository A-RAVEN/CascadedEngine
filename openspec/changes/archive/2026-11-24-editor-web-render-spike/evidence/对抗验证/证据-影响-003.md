## 4. 影响

- 独立入口必须新开一个门控（`Host.Tick` 只认 `CASCADED_EDITOR=1` 与若干 `CASCADED_CSHARP_*_PROBE=1`，没有「只起原型窗」的现成开关）。
- 若门控按既有做法写在 `Host.cs`（与 `EditorService.Tick` 并列），`check_csharp_host_readme.py` 第 ④ 项会要求它出现在 `CSharpHost/README.md` 环境变量表；spike 的 tasks 没有这个条目，4.1 的回归清单也不跑这个脚本，于是「层③检查变红」与「spike 验收全绿」可以同时存在。
- 若门控写在新文件里，检查只扫 `Host.cs`/`UserScript.cs`，完全看不见 —— 形成静默漏登记（更隐蔽的降级）。

## 5. 建议的能失败判据

1. tasks 2.2 写死门控变量名，并要求读取点写在 `Host.cs`。
2. 加一条文档任务：同步登记到 `CSharpHost/README.md` 的环境变量表。
3. 4.1 的回归命令清单加 `python Tools/check_csharp_host_readme.py`；验收：退出码 0，且 `Select-String -Path 'CSharpHost/README.md' -Pattern '<门控变量名>'` 命中 ≥1。
4. 反向构造：删掉 README 那一行后该脚本必须退出码 1 并点名该变量 —— 这证明判据能失败。
