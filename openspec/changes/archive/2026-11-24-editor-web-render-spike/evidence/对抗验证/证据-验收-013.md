# 证据：主张-验收-013

- 面：验收可失败性-④（4.2 可行性结论「可核」）
- 严重度：misleading
- 主张：4.2 的「TODO/008 已更新」任何编辑都算；而那条未决问题主体是 Vulkan↔WebGPU，本 spike 排除 Vulkan，一半必然答不了，也不检查有没有写清「仍未知」。

## 一句话结论

回写这件事本身没有判据：改一个字也算「已更新」。而目标条目跨平台，本 spike 只做 D3D12，于是「已更新」很容易被后来人读成「这个问题解决了」。

## 为什么这条判据现在不能失败

1. 「TODO/008 已更新」没有任何形式约束：在文件里加一行、改一个标点、删掉原文，都满足「已更新」。这与 `tasks.md` 开头「每条给命令 / 产物 + 期望读数」的口径不符。
2. 目标条目跨平台：主体是 Vulkan↔WebGPU（命令 2），本 spike 只做 D3D12（命令 3）。按最诚实的写法，4.2 只能回答 DXGI 这半句，另一半必须写「仍未知」——但工件里没有任何地方要求写这句（命令 4：「仍未知」「未测」均 0 命中）。
3. 于是回写有两种坏结局都可发生：只写 D3D12 已跑通而不提 Vulkan，后来人可能当成整条已解决；或者把 Vulkan 也顺手写个判断，而 spike 根本没测过。
4. design.md:45 只写「结论回写 TODO/008 未决问题 1」，同样没有说清范围与格式。
