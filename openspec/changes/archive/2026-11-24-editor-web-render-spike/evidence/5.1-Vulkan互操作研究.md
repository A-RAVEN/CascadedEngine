# 5.1 Vulkan 互操作研究：VK_KHR_external_memory（Win32 句柄）→ WebView2 网页 canvas

> 结论一句话：**Vulkan 设备支持外部内存导出/导入（本机实测扩展在位），但网页侧没有任何 API 能接收
> Vulkan 外部内存句柄**——零拷贝在 WebView2 上不可行；另外引擎的 Vulkan 后端创建设备时**没有启用**
> `VK_KHR_external_memory_win32`（本批不改后端公共代码），所以本批实现走 **CPU 读回**（`path=cpu-readback`），
> 共享句柄在**助手自建的同一物理设备 VkDevice** 上验证。

## 二、WebGPU 规范检索词与零命中输出

```powershell
$r = Invoke-RestMethod 'https://api.github.com/repos/gpuweb/gpuweb/contents/spec/index.bs?ref=main' -Headers @{'User-Agent'='dsh'}
[IO.File]::WriteAllBytes("$env:TEMP\webgpu.bs", [Convert]::FromBase64String($r.content))
foreach ($pat in @('Vulkan','VkExternalMemory','OPAQUE_WIN32','externalMemory','vkGetMemoryWin32HandleKHR','VK_KHR_external_memory')) {
  (Select-String -Path "$env:TEMP\webgpu.bs" -Pattern $pat -AllMatches).Count }
```

实测输出（2026-11-24）：

```text
  Vulkan => 14 行命中
  VkExternalMemory => 0 行命中
  OPAQUE_WIN32 => 0 行命中
  externalMemory => 0 行命中
  vkGetMemoryWin32HandleKHR => 0 行命中
  VK_KHR_external_memory => 0 行命中
```

`Vulkan` 的 14 处**不是**互操作入口，逐处核对过：181–191 行是规范引用条目（"Vulkan 1.3" 的 spec 链接），
5881/5882/5913/16634/16635 行是 "See … in the Vulkan spec" 的**语义参考**（隐式 LOD、纹素过滤、线段光栅化），
17673/17706/17713/17936/18140 行是规范表格里的 **HTML 注释占位**。没有任何"导入 Vulkan 外部内存/句柄"的 API。

即：**标准 WebGPU 没有接受 `VkExternalMemory` / NT 句柄 / `OPAQUE_WIN32` 的入口**（与 1.1 对 DXGI 的结论同一类），
`importExternalTexture` 的 source 仍是 `(HTMLVideoElement or VideoFrame)`（1.1 已逐字引规范 IDL；本次快照未变）。

## 三、Vulkan 侧的机制与文档依据

- 导出：`VK_KHR_external_memory` + `VK_KHR_external_memory_win32`，句柄类型
  **`VK_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_WIN32_BIT`**（NT 句柄）；
  图像创建时 `VkExternalMemoryImageCreateInfo.handleTypes = OPAQUE_WIN32`，
  分配时 `VkExportMemoryAllocateInfo.handleTypes = OPAQUE_WIN32`，再用
  [`vkGetMemoryWin32HandleKHR`](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetMemoryWin32HandleKHR.html) 取 `HANDLE`。
  参考页逐字："To export a Windows handle representing the payload of a Vulkan device memory object, call:
  `VkResult vkGetMemoryWin32HandleKHR(...)`"、"For handle types defined as NT handles, the handles … hold a
  reference to their payload … **must** release ownership … using `CloseHandle`"。
- 导入（第二消费者）：[`VkImportMemoryWin32HandleInfoKHR`](https://docs.vulkan.org/refpages/latest/refpages/source/VkImportMemoryWin32HandleInfoKHR.html)
  放进 `VkMemoryAllocateInfo.pNext`。参考页逐字："Applications **can** import the same payload into multiple
  instances of Vulkan, **into the same instance from which it was exported**, and multiple times into a given
  Vulkan instance. In all cases, each import operation **must** create a distinct `VkDeviceMemory` object."
  —— 同一实例内导入是规范明确允许的，所以"第二消费者"可以在同一个 VkDevice 上做。
- CPU 读回：`vkCmdCopyImageToBuffer` → 宿主可见缓冲 `map` → 逐行紧凑拷贝（Vulkan 读回惯例）。

## 五、不可行的具体阻塞（不是口头断言）

| 阻塞 | 具体事实 |
|---|---|
| 缺失 API（网页侧） | 标准 WebGPU 没有"导入平台共享句柄"的方法：`VkExternalMemory` / `OPAQUE_WIN32` / `externalMemory` / `vkGetMemoryWin32HandleKHR` / `VK_KHR_external_memory` 在 WebGPU 规范里 **0 命中**；`importExternalTexture` 只收 `HTMLVideoElement` 或 `VideoFrame`（1.1 逐字 IDL） |
| 缺失桥接对象（网页侧） | WebCodecs `VideoFrame` 构造只收 `CanvasImageSource` 或 `AllowSharedBufferSource`（1.1 逐字 IDL），没有"Vulkan 外部内存句柄"重载 |
| 规范层已关闭该提案 | [GPUWeb #5167](https://github.com/gpuweb/gpuweb/issues/5167) 状态 closed / not_planned；维护者：这类互操作"在浏览器引擎侧，不属网页平台规范" |
| 本机运行时 | WebView2 **157.0.4341.60**（1.1 实测）没有这类网页入口；Electron 的引擎内部实现（#46811）不适用于 WebView2 嵌用方 |
| 引擎侧（本批不修） | `RenderBackend_Vulkan.cpp` 的 `GetDeviceExtensionNames` 只启用 `VK_KHR_swapchain`（+GPL），**没有**启用 `VK_KHR_external_memory_win32`；设备函数 `vkGetMemoryWin32HandleKHR` 因此不可用。规范要求"spike MUST NOT 改动 Vulkan/D3D12 后端公共代码"，所以助手在**自建的同一物理设备 VkDevice** 上启用该扩展完成共享句柄验证 |

## 六、判定

- **Vulkan 零拷贝共享图像 → 网页 canvas：不可行**（网页侧无入口；与 D3D12 同一根因）。本批实现**不**做零拷贝。
- **Vulkan 共享图像本身（导出 + 同一实例导入 + 读回）**：设备支持、规范允许，本批在非绑定面助手里验证（5.2）。
- 本批实际路径：**CPU 读回**（`vkCmdCopyImageToBuffer` → map → C++→C#→网页），运行读数 `path=cpu-readback`。
- 退路：与 1.1 / 4.2 相同（路线 B 透明叠层 / CPU-GPU 桥）；Vulkan 侧若要真零拷贝，需**同时**具备"引擎后端启用
  external memory 扩展"与"WebView2 暴露引擎侧导入能力"两件事，缺一不可。
