# csharp-render-structured-buffer 实施任务

用户故事：

- **US1**：C# 渲染调用方需要用图内结构化缓冲驱动着色输出（颜色等数据走缓冲而非顶点属性），并能在调用当场得到点名的拒绝。
- **US2**：引擎维护者需要缓冲字段名、读写类型、元素数与缓冲名解析在适配层被挡下，绝不进入两后端"未知字段静默跳过"与 `CA_ASSERT` 断言路径。
- **US3**：渲染验证人员需要两个后端的真实像素证据证明缓冲数据确实进入输出，且漏绑字段、错缓冲名、改缓冲数据都会让判据失败。

日志与文本记录统一写入 `openspec/changes/csharp-render-structured-buffer/evidence/`；`GPUBackendTester` 运行期产物（`test_output/*.log`、`*.png`、报告 JSON）留在 `test_output/`（被 `.gitignore` 忽略），由 `Tools/check_csharp_structured_buffer.py` 从该目录校验，像素验收的关键读数同时抄入 evidence。每条红态必须来自缺陷仍存在时的真实命令；不得用预期失败文本代替运行输出，不得在仓库其他位置留临时探针或日志。`GPUBackendTester.exe` 的一切运行（含 `--headless`、`--test`、`--list`、负向开关与变异实验）由主 agent 代跑：执行者把命令与变异步骤准备好上报，取回真实读数记入证据后再勾条目；CoreTests 与 `Tools/*.py` 由执行者自跑。
