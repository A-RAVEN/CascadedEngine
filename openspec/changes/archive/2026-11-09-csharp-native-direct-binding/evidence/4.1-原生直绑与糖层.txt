csharp-native-direct-binding 4.1 执行记录（2026-11-09）
=========================================================

一、实现面（文件 + 关键点）
---------------------------
1) 生成器值类构造通道（Tools/CodeGen/CodeGenMain.cpp）
   · 参数投影：值类的**全部**对象构造通道都出 switch 分支。此前只出第一条 ⇒ ImageHandle 的
     WindowHandle→Backbuffer 通道缺失，Present 在边界被判「无效的资源引用类型」。
   · 名称通道改用枚举里精确的 `Internal = 0`。此前 pickKindConstant 跳过 0，把名称通道错配成
     Backbuffer=2，与 WindowHandle 对象通道撞号 ⇒ 生成的 switch 重复 case，构建红
     （error C2196: case value '2' already used，见 %TEMP%\cnb-build-1.log）。
   · 新增 Invalid 态通道（生成 `BufferHandle.Invalid`）：记录字段的「未设置」要能过界
     （IndexBufferData.indexBufferHandle 在原生 `DrawCall::New()` 里就是默认构造的 Invalid 句柄），
     否则每个 AddPass 都被句柄解析拒（块错误码 12）。

2) 托管糖层 Scripting/Managed/NativeRenderSugar.cs
   · 目标对象（design D12）：窗口目标 = GetWindowHandle + GetSizeSafe + ImageHandle.FromWindowHandle
     + isBackbuffer=true；捕获目标 = CreateGPUTexture（RGBA8 / 2D / 1 层 / 1 mip / 1 采样，
     TransferSrc|TransferDst|RT）+ ImageHandle.FromGPUTexture + 托管记尺寸。
   · 上传糖（design D2）：ScriptUpload.ScheduleData(handle, byte[])（offset=0、copy=true）。
   · 图（design D11/D13）：托管计划（缓冲登记表 / 顶点流 / 每个 pass 的记录与参数表 / 呈现表）→ 提交时
     逐 pass `AddPass(RenderPass 序列化块)` + `Present`，再跑完整性校验，最后 `ExecuteGraph`。
     `PassCount` 读 `GetPassIndices().Length`（D13 的计数/拷贝两段式；注意它数的是**图阶段**，
     含 ScheduleData 的数据上传阶段，比 render pass 数多）。
   · 顶点流三种布局与越界判据、绘制顶点数上限、缓冲描述/字节数/重名、空图、Present 目标类型，
     全部在进入函数表调用前拒绝（design D6）。
   · 参数结构：元数据经 FindShaderStructData / FindShaderRootStructData 两段式只读副本；
     SetFloat3 / SetStruct / SetBuffer / SetImage / SetSampler 的字段级校验（类型名、元素数、只读、
     表内字段、子结构资源字段）全在托管层；释放后使用抛 ObjectDisposedException 且原生调用 0。
   · 管线默认值逐字段复写 `CPipelineStateObject.h` 的默认成员初始化（cullMode=eNone、
     channelMask=eRGBA、depthCompareOp=eGEqual、msCount=e1 …）：写成 0 会变成 eBack 剔除、
     或关掉颜色写。
   · 视口/剪裁矩形写成**整张目标**：序列化块反序列化出来的 `HashObj<ViewRectData>` 恒为有效，
     写零矩形会把执行器默认的整目标视口覆盖成 0×0；批级 `ShaderInfo.path` 也必须写真实路径
     （空路径是「有效」的 PathHash，会覆盖 pass 级路径 ⇒ 实测断在 ShaderLibrary::GetShaderFileInfo）。

3) 宿主 CSharpHost/private/CSharpHost.cpp：4.1 起额外把**原生** CRenderBackend 登记为编号 8 的默认实例
   （桥编号 3 保留到 5.1 与桥文件同轮删除）。

4) 托管入口 Scripting/Managed/Host.cs：绑原生后端表（编号取生成常量）+ 四张目标类型表；
   布局自检换到五张原生表的清单；四个探针改为接收糖层后端对象。

5) 用例 Scripting/Managed/UserScript.cs：四探针改写糖层；每个探针输出一行机器可读读数
   `[托管 读数] probe=… graphSelf=… captureSelf=… pass=… exec=… | reject=…`。C++ 用例按
   graphSelf 取原生 GPUGraph*，再从图附件的 ImageHandle 取同一份 GPUTexture / WindowHandle
   （附件里的句柄在反序列化时从同一张对象表解析，与 C# 侧是同一对象）。

6) 判据换面 Scripting/Managed/SurfaceSignatureCheck.cs：桥五接口的签名断言退役，换成原生五类
   直绑表面 + 糖层的编译期签名断言（参数/返回类型写死，映射错即编译不过）。
