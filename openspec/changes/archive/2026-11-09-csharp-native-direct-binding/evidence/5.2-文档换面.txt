   after:  `扫描 8 个接口、对账 91 条方法、命中 0 处问题（审计表：…\bindable-audit.md）`

2) 审计范围段（旧 → 新）：
   before: “审计范围现在是 12 个接口（… `IScriptTexture` / `IScriptRenderTarget` / `IScriptRenderGraph` /
            `IScriptRenderBackend` / `IScriptShaderStruct`）。其中后五个是脚本渲染适配面……”
   after:  “审计范围现在是 8 个接口（`CRenderBackend` / `IReadbackToken` / `GPUGraph` / `ShaderStruct` /
            `GPUTexture` / `WindowHandle` / `IWindow` / `IWindowSystem`），合计 91 条公开方法……
            **过渡期桥五个接口的 28 条方法随 5.1 退役移出审计面**（行同时删除，不是放过）。”
   口径句同改：“脚本按**纯虚方法名**对账” → “脚本按**公开方法名**对账（含非纯虚 virtual 与非虚
   公开方法；模板按 `CA_BIND_INSTANTIATE` 计）”。

3) 限制清单反向（旧 → 新）：
   before: “**本 change 的明确限制**：不支持 `std::span`；不支持包装值（…）作为返回值、嵌入记录或容器
            元素；……不支持容器出参、映射容器、联合体、定长数组；……”
   after:  “**仍然不支持（明确限制，逐条带拒绝行为）**：`std::span`；`weak_ptr<T>` 入参；异步保存输入
            指针；容器**出参**；键不是 `NameHash` 的映射 / 未绑定类型的智能指针 / 返回位置的记录容器……
            ” + “**已落地的新形状（原限制清单里列过，现在反向：能力 + 判据）**：参数位置内存窗（D2）、
            返回位置记录两段式（D8）、`CA_BIND_INSTANTIATE`（D9）、序列化块 7 类元素（D11 + 记录 17）、
            返回位置标量容器两段式（D13）、`CA_BIND_VALUE` 与 `CA_BIND_INJECT` 前置批能力。”

4) **两条必写的 `--update-ids` 说明（新增，逐字如下）**：
   · “**发号命令必须带 `--config Debug`**：`python build.py --config Debug --update-ids` —— `--update-ids`
      靠构建目录里的 `compile_commands.json` 定位每个输入头的 include 集合；不带 `--config Debug` 时脚本
      指向默认的 RelWithDebInfo 构建目录，那里没有（或不是与当前头匹配的）编译数据库，工具拿不到
      include，所有输入头都会 parse failed。”
   · “……名字消失时 `--update-ids` 删行（**只删本头自己的行**：`--update-ids` 以输入头为界取消失集合，
      早期"按短名全局删"的实现会删掉别的头里的同名行，已按头作用域收窄）。”
     依据：`Tools/CodeGen/CodeGenMain.cpp` 的 `updateInterfaceIds(...)` 注释与实现（单头入参、
     消失集合只从本头标注里取）；`build.py` 的 `update_interface_ids()` 使用按 `--config` 选择的
     `BUILD_DIR / compile_commands.json`。
