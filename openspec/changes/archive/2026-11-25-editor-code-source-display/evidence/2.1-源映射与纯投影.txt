## ② 真实 shLib 字节提取（算法同 EditorService.TryExtractShaderSourcePaths）

命令：PowerShell 复算同一个算法（uint64 m_ShaderFiles 条数 → 首条键 → 长度前缀可打印 ASCII 路径，按首条键目录前缀过滤、去重；提取条数必须等于声明条数）。
* VulkanShaderLibrary.shLib：声明条数 16、提取条数 16、一致=True
    映射 CAResources/<路径>.slang：存在 16、缺失 0
* D3D12ShaderLibrary.shLib：声明条数 16、提取条数 16、一致=True
    映射 CAResources/<路径>.slang：存在 16、缺失 0

结论：两个真实 shLib 各声明 16 条、按字节提取 16 条（格式一致），全部 16 条都能映射到现有 .slang；
本仓库真实库没有缺源条目（design Context 里「Vulkan 21 条含 5 条缺源」是裸子串搜索把 .hslang
包含文件与一个长度字节伪串算进来的计数；m_ShaderFiles 两个库实测都是 16 条）。缺源分支由
TestCodeSourceDisplay 的写死夹具（Shaders/Missing 无 .slang）覆盖。

## ③ 夹具布局复算（TestCodeSourceDisplay 的两个 shLib 字节）

* Vulkan 布局（键+有值 path）：声明 3、提取 3、一致=True、路径=Shaders/Alpha,Shaders/Beta,Shaders/Missing
* D3D12 布局（键+空 path）：声明 4、提取 4、一致=True、路径=Shaders/Alpha,Shaders/Beta,Shaders/Missing,Shaders/Shared
