# 证据-验收-014：单张 240px dock 截图既证不了「无程序集」也证不了「有 .cs」

## 1. 默认 dock 高度 240（命令 + 真实输出）

```powershell
Select-String -Path 'Scripting/Managed/Editor/EditorService.cs' -Pattern 'DefaultDockHeight|CASCADED_EDITOR_DOCK_HEIGHT' | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line.Trim() }
Select-String -Path 'CSharpHost/README.md' -Pattern 'CASCADED_EDITOR_DOCK_HEIGHT' | Select-Object -First 1 | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line }
```

即 240px 高时第 8 行已经不可见。

## 2. 真实根排序后的行位置（命令 + 真实输出）

```powershell
# 资源根条目 = 相对 CAAssets；源条目 = 相对工程根（CAResources/… 与 Scripting/…）
$data = Get-ChildItem 'CAAssets' -Recurse -File | ForEach-Object { $_.FullName.Substring((Resolve-Path 'CAAssets').Path.Length+1).Replace('\','/') }
$slang = Get-ChildItem 'CAResources/Shaders' -Recurse -Filter *.slang -File | ForEach-Object { 'CAResources/Shaders/' + $_.FullName.Substring((Resolve-Path 'CAResources/Shaders').Path.Length+1).Replace('\','/') }
$cs = Get-ChildItem 'Scripting' -Recurse -Filter *.cs -File | ForEach-Object { 'Scripting/' + $_.FullName.Substring((Resolve-Path 'Scripting').Path.Length+1).Replace('\','/') }
$list = [System.Collections.Generic.List[string]]::new()
foreach($x in (@($data)+@($slang)+@($cs))){ [void]$list.Add($x) }
$list.Sort([System.StringComparer]::Ordinal)
Write-Output ("排序后条目总数: " + $list.Count)
0..7 | ForEach-Object { Write-Output ("  [{0,2}] {1}" -f ($_+1), $list[$_]) }
Write-Output ("D3D12 shLib 位置: " + ($list.IndexOf('D3D12ShaderLibrary.shLib') + 1))
Write-Output ("Vulkan shLib 位置: " + ($list.IndexOf('VulkanShaderLibrary.shLib') + 1))
Write-Output ("首条 .cs 位置: " + ($list.IndexOf('Scripting/Managed/Assets/AssetDatabase.cs') + 1))
Write-Output (".cs 条目数: " + ($list | Where-Object { $_ -like 'Scripting/*.cs' }).Count)
Write-Output (".slang 条目数: " + ($list | Where-Object { $_ -like 'CAResources/Shaders/*.slang' }).Count)
```

真实输出：

```text
排序后条目总数: 59
  [ 1] CAResources/Shaders/FinalBlit.slang
  [ 2] CAResources/Shaders/Imgui.slang
  [ 3] CAResources/Shaders/Test/TestBlitToScreenPass.slang
  [ 4] CAResources/Shaders/Test/TestCSharpTextureSampling.slang
  [ 5] CAResources/Shaders/Test/TestComputeVertexBuffer.slang
  [ 6] CAResources/Shaders/Test/TestNaiveTriangle.slang
  [ 7] CAResources/Shaders/Test/TestSimpleTriangle.slang

D3D12 shLib 位置: 20
Vulkan shLib 位置: 59
首条 .cs 位置: 21
.cs 条目数: 38
.slang 条目数: 16
```

隐藏两条 shLib 后共 57 条，顺序为：16 条 .slang（1-16）→ 3 条 .res（17-19）→ 38 条 .cs（20-57）。所以 240px 视口（约 7 行）里：

- 第 1-7 行是 `CAResources/Shaders/*.slang`；
- 任何 `.cs` 行都在第 20 位以后，看不到；
- 若 shLib 没被隐去，它在第 20/59 位，也看不到。

## 3. 抓窗抓的是视口（逐字引文）

`Scripting/Managed/Editor/EditorWindow.cs`：

```csharp
m_DockCaptureTask = m_DockController.CoreWebView2.CapturePreviewAsync(
    CoreWebView2CapturePreviewImageFormat.Png, stream);
```

`CapturePreviewAsync` 抓的是 WebView2 当前渲染视口，不滚动、不拼整页；页面本身没有搜索框或过滤控件（`EditorWeb/assets.html` 只有 `#refresh-assets` 一个按钮），要看到第 20 行以下必须滚动。

## 4. 可写死但没写死的读数（逐字引文）

`EditorWeb/src/assets.ts`：

```ts
summaryEl.textContent = `共 ${assets.length} 条`;
```

页面本来就把总条数打成文本，截图可以核对「共 N 条」；但 tasks 3.2 没有写 N，也没有要求截图必须包含该文本。

## 5. 边界：小临时夹具时这条能失败

如果 3.2 用的小临时工程根只有 1 条 shLib + 2 份 .slang + 2 份 .cs + 1 条 .res，隐藏 shLib 后仅 5 行，240px 内全可见，「无程序集条目」与「有 .cs 行」都能由截图判红/判绿。本主张针对的是工件没有钉死这一点：tasks 3.2 只写「临时工程根含 shLib+.slang+注册 C#+.cs」，没给文件名、字节数、期望条数；真实根（16 .slang + 38 .cs + 2 shLib + 3 .res）同样满足这句字面描述，却因 59 条里前 16 行全是 .slang、.cs 从第 20 位起而在顶部截图里不可判。判据随夹具而变，就无法从 evidence 复现「无程序集条目」到底是哪一种夹具下的结论。
