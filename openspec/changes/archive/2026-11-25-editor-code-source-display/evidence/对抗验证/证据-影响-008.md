# 证据 影响-008：两条恒真判据——「dll 不出现」与「check_csharp_host_readme 0 问题」

对应主张：`主张-影响-008.json`（severity = misleading）

审查对象：`specs/editor-code-source-display/spec.md` Requirement 3 与「dll 隐去 cs 源显现」场景、`tasks.md` 2.2/2.3/3.1/4.1；对照 `Tools/check_csharp_host_readme.py`、`EditorService.cs`、CAAssets 与 dll 实际位置。

审查快照（SHA-256 前 16 位）：`spec.md` `05A061C9058DD644`、`tasks.md` `90FD91739A78EC59`、`AssetDisplay.cs` `38F3F9B13CD870E5`。

## 一、「dll 条目不出现」没有反事实

资源根 CAAssets 里没有任何 .dll：

```text
PS> (Get-ChildItem 'CAAssets' -Recurse -File -Include *.dll).Count
0
PS> Test-Path 'Scripting/Managed/Scripting.Managed.dll'
False
PS> Get-ChildItem 'out/build' -Recurse -Filter 'Scripting.Managed.dll'
out\build\x64-debug\bin\Scripting.Managed.dll
out\build\x64-debug\managed\Scripting.Managed.dll
```

`AssetDisplay.cs:107-114` 的种类映射只有 `.shlib` / `.tex` / `.mesh` / `.res`，`.dll` 不在里面（未知扩展名落 `file`，但也必须先被资源根枚举到）。注册显示资源用的 `"Scripting.Managed.dll"`（spec.md:33）只是标识串，不是资源根里的文件。

因此：不注册 C# 显示资源时，list-assets 也不会有 dll 条目；注册后「dll 不出现」仍成立。工件把它写进 3.1 与 3.2 的验收（`spec.md:38`、`tasks.md:22`），它不能证明 C# 提供者真的生效，也不能在实现漏注册时变红。

## 二、C# 的 registered 语义没有断言

`spec.md:33`：

> MUST 注册 (csharp-script, `"Scripting.Managed.dll"`, `CSharpSourceDisplayProvider`)；该提供者 MUST NOT 产 dll 条目，MUST 扫 `Scripting/`……产每个源文件一条（kind=csharp-source，path/nodeId=相对工程根源路径，**registered=true 当程序集存在**）。

`spec.md:38`（场景）只断言：

> ……MUST 含每个 .cs 源条目，path/kind=csharp-source/sizeBytes 逐条等于写死期望；dll 不在 CAAssets 也 MUST 引入源条目

没有 `registered`。而「程序集存在」按注册标识串判是 False（`Scripting/Managed/Scripting.Managed.dll` 不存在），若实现照字面 `File.Exists(注册 path)`，38 条 .cs 全 registered=false 也能过验收。

## 三、check_csharp_host_readme 看不到新 env

脚本只扫描两个文件（`Tools/check_csharp_host_readme.py`）：

```text
:49 HOST_CS = REPO / "Scripting" / "Managed" / "Host.cs"
:50 USER_SCRIPT_CS = REPO / "Scripting" / "Managed" / "UserScript.cs"
:140 def parse_env_names(text: str) -> set[str]:
:141     return set(re.findall(r'GetEnvironmentVariable\("(CASCADED_[A-Z0-9_]+)"', text))
:217 used_env = parse_env_names(read(HOST_CS)) | parse_env_names(read(USER_SCRIPT_CS))
```

编辑器环境变量全部在 `EditorService.cs` 里读（实测 9 个：`CASCADED_EDITOR`、`CASCADED_EDITOR_PORT`、`CASCADED_EDITOR_PANEL_WIDTH`、`CASCADED_EDITOR_DOCK_HEIGHT`、`CASCADED_EDITOR_WEBVIEW2_DATA`、`CASCADED_EDITOR_READINGS_FILE`、`CASCADED_EDITOR_STOP`、`CASCADED_EDITOR_SPIKE*`），脚本从来没扫它。

当前 README 对新 env 的命中数：

```text
PS> (Select-String -Path 'CSharpHost/README.md' -Pattern 'CASCADED_EDITOR_SHADER_SOURCE_ROOT|CASCADED_EDITOR_CSHARP_SOURCE_ROOT|CASCADED_EDITOR_PROJECT_ROOT').Count
0
```

也就是说：tasks 2.3 的「新 env 登记 CSharpHost/README」就算完全不做，4.1 的「check_csharp_host_readme 0 问题」仍是 0 问题。这条验收恒真。

## 四、红态怎么构造

- 删掉 `tasks.md:16` 的 `注册 (csharp-script, "Scripting.Managed.dll", 提供者)`：3.1 会因 .cs 条目缺失而红（这部分有效），但「dll 条目不出现」仍绿——证明该条判据无效。
- 从 `CSharpHost/README.md` 删掉 `CASCADED_EDITOR_ASSET_ROOT` 行：`check_csharp_host_readme.py` 仍退出 0（它不扫编辑器 env），证明「README 缺条目」无法被发现。

## 五、建议改法

1. C# 提供者红态改为「注册/不注册显示资源两次枚举，.cs 条目有/无」；「dll 不出现」改成夹具真放一个 `.dll` 到资源根的正控。
2. 场景与 2.2 验收补 `registered` 逐条期望，并写死「程序集存在」的判定路径。
3. env 登记用可失败判据：README grep 必须命中三个新名字，或扩展 check_csharp_host_readme 的扫描范围到 `Scripting/Managed/Editor/*.cs` 并同步自检。
