# 证据-验收-009：「源根不存在」与「源根空」只覆盖了一态

## 1. spec 的两态要求（逐字引文）

`openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md`：

```text
#### Scenario: 源根空容错

- **WHEN** 源根不存在或无 .slang
- **THEN** 提供者 MUST 产空列表（list-assets ok=true，源条目空），MUST NOT 报错或整体失败
```

要求正文：「源根不存在/空 MUST 产空列表而非报错。」

## 2. tasks 只写「源根空」（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/tasks.md' -Pattern '源根空|源根不存在' | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line.Trim() }
```

真实输出（节选）：

```text
15: …源根空/不存在产空列表不报错。验收：构建过；已知 .slang 夹具源条目==写死期望；shLib 条目隐去；源根空容错（evidence/2.1-*.txt）。
21: …红态：源根空→源条目空不报错；**提供者未注册→落默认 shLib 仍显**…
```

3.1 的红态文字只有「源根空」，没有「源根不存在」；`tasks.md:15` 的 2.1 验收才提到「源根空/不存在」，但验收记录要求是 `evidence/2.1-*.txt`，没有命令与期望读数。

## 3. 缺失目录与空目录是两条路径（逐字引文）

`Scripting/Managed/Editor/EditorService.cs` 对资产根本身就分了两态：

```csharp
if (!Directory.Exists(root))
{
    errorMessage = "资产根不可用：目录不存在（\"" + root + "\"）";
    return null;
}
var entries = new List<AssetEntry>();
foreach (string file in Directory.EnumerateFiles(root, "*", SearchOption.AllDirectories))
```

即：缺失目录要先判存在，空目录才靠枚举自然为空。源根若照抄枚举但不判存在，`Directory.EnumerateFiles` 会抛 `DirectoryNotFoundException`（现有代码在 `ExecuteListAssets` 里有 `catch (DirectoryNotFoundException ex)` 把它转 `E_ASSET_ROOT`——那是资产根的错误面，不是源根容错）。

## 4. 「不报错」比 spec 松（逐字引文）

spec 要求 `list-assets ok=true`；tasks 3.1 只写「不报错」。`ok=false + E_ASSET_ROOT` 也是「没抛异常」，但它表示整体失败，按 tasks 字面也能算「不报错」——判据比 spec 弱。
