# 证据-验收-006：两条 shLib 下「父程序集注册态」不唯一

## 1. 真实资源根有两条 shLib（命令 + 真实输出）

```powershell
Get-ChildItem 'CAAssets' -Filter *.shLib -File | ForEach-Object { $_.Name + '  ' + $_.Length + ' B' }
```

真实输出：

```text
D3D12ShaderLibrary.shLib  293737 B
VulkanShaderLibrary.shLib  145710 B
```

## 2. 枚举对每个文件各调一次 Describe（命令 + 真实输出）

```powershell
Select-String -Path 'Scripting/Managed/Editor/EditorService.cs' -Pattern 'foreach \(string file in Directory.EnumerateFiles|described = AssetDisplayProviders' | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line.Trim() }
```

真实输出：

```text
1100: foreach (string file in Directory.EnumerateFiles(root, "*", SearchOption.AllDirectories))
1124: IReadOnlyList<AssetEntry> described = AssetDisplayProviders.Resolve(kind).Describe(context);
```

即两条 shLib 各触发一次 `Describe`；若 ShaderSourceDisplayProvider 每次都扫 `CAResources/Shaders`（16 份 .slang），会产 2×16 条 path/nodeId 完全相同的源条目，区别只在 `registered=HasResource(本 shLib)`。

## 3. 工件的字段语义与去重口径（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/design.md','openspec/changes/editor-code-source-display/tasks.md' -Pattern 'registered=HasResource|去重|预置 shLib' | ForEach-Object { $_.Filename + ':' + $_.LineNumber + ': ' + $_.Line.Trim() }
```

真实输出（节选）：

```text
design.md:24: **去重**：注册显示资源的 path 若已在 CAAssets 枚举到（如 shLib），不重复引入（以文件枚举那条为准）；代码型提供者产源条目时隐去程序集自身条目。
design.md:38: …shader 源条目 registered=HasResource(shLib relative)…
tasks.md:21: …临时工程根预置 shLib（CAAssets）+ 已知 .slang（CAResources/Shaders）+ 注册 C# 显示资源 + 已知 .cs（Scripting/）→ list-assets 断言…
```

## 4. 结论

- 两条父 shLib 的注册态可以不同（一条 `CreateResource` 成功、另一条不注册）；两条同 nodeId 条目按 nodeId 去重后，留下哪条的 `registered` 由枚举顺序决定——工件没有钉。
- 3.1 的夹具只写「预置 shLib」单条（`tasks.md:21`），写死期望覆盖不到两父 shLib 的情形；真实根的视觉验收不校验 registered。
