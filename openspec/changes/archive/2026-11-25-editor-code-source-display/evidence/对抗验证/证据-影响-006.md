# 证据 影响-006：源根扫不到时静默空列表、扫出错时未定义，且提供者契约「不碰文件系统」被违反

对应主张：`主张-影响-006.json`（severity = blocking）

审查对象：`design.md` D4、`specs/editor-code-source-display/spec.md` Requirement 2 的「源根空容错」、`tasks.md` 2.1；对照 `AssetDisplay.cs` 提供者契约、`EditorService.cs` 异常面、`openspec/specs/editor-asset-browser/spec.md` 显式失败要求。

审查快照（SHA-256 前 16 位）：`design.md` `BB8AD764922E5D86`、`tasks.md` `90FD91739A78EC59`、`spec.md` `05A061C9058DD644`、`AssetDisplay.cs` `38F3F9B13CD870E5`、`EditorService.cs` `BE0F7040B5C5E015`、存量规范 `ABF4C58735D0C503`。

## 一、工件怎么写

`design.md:34`（D4）逐字：

> 源根默认：shader＝`CAResources/Shaders`、C#＝`Scripting`（相对工程根）。env 覆盖（`CASCADED_EDITOR_SHADER_SOURCE_ROOT` / `CASCADED_EDITOR_CSHARP_SOURCE_ROOT`，登记 CSharpHost/README）。工程根取资源根的上级约定或 env `CASCADED_EDITOR_PROJECT_ROOT`（测试传临时工程根隔离）。源根不存在/空 → 提供者产空条目列表（不报错，浏览器不该整体失败，照 editor-asset-browser 未知扩展名落 file 的容错）。

`specs/editor-code-source-display/spec.md:19`：

> ……源根不存在/空 MUST 产空列表而非报错。

`spec.md:29`（场景「源根空容错」）：

> - **THEN** 提供者 MUST 产空列表（list-assets ok=true，源条目空），MUST NOT 报错或整体失败

`tasks.md:15` 的验收只有一句「源根空容错（不报错）」。

## 二、静默降级：配错与真空无法区分

生产默认没有 `CASCADED_EDITOR_PROJECT_ROOT`，工程根取「资源根的上级」。资产根是 README 已登记的可覆盖开关 `CASCADED_EDITOR_ASSET_ROOT`（`CSharpHost/README.md:121`「覆盖资产浏览器的资源根……任意已存在目录」）。把资产根指向任意临时目录（视觉验收就要求这么做）时，工程根同步挪到那个临时目录的上级，源根 `%TEMP%/CAResources/Shaders` 大概率不存在 → 提供者按规格返回空列表、`ok=true`、无日志、无警告，用户看到「没有 .slang/.cs 源文件」，实际是源根配错。

存量规范对资产根的要求相反（`openspec/specs/editor-asset-browser/spec.md`）：

> `spec.md:11`：……门面失败 / 根非法 / 枚举 IO 错误 MUST 显式 E_ASSET_ROOT，MUST NOT 用 ok 空数组冒充成功。
>
> `spec.md:58`：……根目录不存在 MUST 显式报错（错误码 + 文本点名原因），MUST NOT 静默返回空列表冒充成功。

同一个 dock 里，资产根失败必须显式、源根失败必须静默——两条规则互相矛盾，且没有任何「略去了什么」的标记，调用方无法取回完整信息。

## 三、源根存在但扫描出错：没有处置

`EditorService.cs:1033-1062` 现有的 catch 把 IO 异常全部转成资产根错误：

```text
catch (UnauthorizedAccessException ex)
{
    FailListAssets(client, command, "资产根没有访问权限：" + ex.Message);
}
catch (IOException ex)
{
    FailListAssets(client, command, "枚举资产根时 IO 错误：" + ex.Message);
}
...
catch (ArgumentException ex)
{
    FailListAssets(client, command, "资产根路径非法：" + ex.Message);
}
```

提供者在 `Describe` 里扫目录（`design.md:28-30`），源目录的权限/非法路径异常会走同一条链路：错误码 `E_ASSET_ROOT`、文本点名「资产根」，但真正的坏路径是源根；整个列表（含 .tex/.mesh/.res）一起失败。若实现改成在提供者内 `catch { }`，则变成少几行且无任何标记。规格对这两种情况都没有规定，tasks 2.1 也没有红态。

## 四、契约与线程

`AssetDisplay.cs:49-50` 逐字：

> /// 描述一个资产所需的上下文（资产中心的输入）：v1 是"相对路径 + 文件元数据 + 资源根"，
> /// 由编辑器服务在枚举时填好；提供者不碰文件系统、不调门面（那些都在主线程命令里已经做完）。

本批让提供者做递归目录扫描，直接推翻这句契约，但没有一条任务去改它。扫描发生在 `ExecuteListAssets` 的 `EnumerateAssets` 内，仍属主线程命令执行，**没有破坏线程边界**；但两个 shLib 会各扫一遍同一源根（见 005），命令耗时随源树增长，工件没有任何范围/耗时口径。

## 五、红态怎么构造

```text
$env:CASCADED_EDITOR_SHADER_SOURCE_ROOT='C:\<>|\nope'
```

按当前实现，`Directory.EnumerateFiles` 抛 `ArgumentException` → `E_ASSET_ROOT`，文本却写「资产根路径非法」——期望是「点名源根」。另一种红态：不设 `CASCADED_EDITOR_PROJECT_ROOT`、把 `CASCADED_EDITOR_ASSET_ROOT` 指向空临时目录，源条目为空且无日志；按「静默降级算缺陷」应红。

## 六、建议改法

1. 源根不存在 → 空列表 + 一行点名绝对路径的日志（并进读数文件），验收断言该行存在。
2. 源根不可读/非法 → 提供者内捕获成带源路径的 warning，或把错误文案改成点名源根；不许冒成「资产根…」也不许静默吞。
3. 改 `AssetDisplay.cs` 的契约注释；给扫描范围（是否整个 `CAResources`）与耗时口径。
4. tasks 2.1 加两条红态（非法源根、默认工程根推导），3.1 断言缺失日志。
