# 证据-验收-012：两条源根未分别做增删

## 1. 两套独立提供者（逐字引文）

`openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md`：

```text
MUST 有 `ShaderSourceDisplayProvider`（kind=shader-library），`Describe(shLib 上下文)` MUST NOT 产 shLib 自身条目，MUST 扫源目录（默认 `CAResources/Shaders`，env `CASCADED_EDITOR_SHADER_SOURCE_ROOT` 可配）递归 `*.slang` 产每个源文件一条 `AssetEntry`…
```

```text
MUST 有「显示资源注册表」`RegisterDisplayResource(kind, path, provider)`…该提供者 MUST NOT 产 dll 条目，MUST 扫 `Scripting/`（env `CASCADED_EDITOR_CSHARP_SOURCE_ROOT` 可配）递归 `*.cs` 产每个源文件一条（kind=csharp-source…）
```

两个根（CAResources/Shaders 与 Scripting）互不相同，两个提供者也是两个文件（tasks 2.1 / 2.2）。

## 2. 新用例只写一次「源增删」（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/tasks.md' -Pattern '源增删' | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line.Trim() }
```

真实输出：

```text
21: - [ ] 3.1 tester 用例 `TestCodeSourceDisplay`…+ 源条目数==源文件数；源增删→assets-changed；红态：…
```

没有指定是 .slang 还是 .cs，也没有要求两条各做一次。

## 3. 缓存缺陷为何不会红

若 ShaderSourceDisplayProvider 在第一次 Describe 时把 `CAResources/Shaders` 的文件列表存进静态字段，之后不再重扫：用例只往 `Scripting/` 增删 .cs 时，CSharpSourceDisplayProvider 重扫、事件照发、断言照绿；反之亦然。两条源根各有一条「一次性预置」断言（tasks 3.1 的 .slang/.cs 源条目逐条写死）也覆盖不到「第二次枚举时源目录变了」的情形——那是 assets-changed 场景，不是首次枚举场景。
