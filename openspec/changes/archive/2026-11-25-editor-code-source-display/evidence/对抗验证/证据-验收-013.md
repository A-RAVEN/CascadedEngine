# 证据-验收-013：生效规范的旧截图场景仍要求列出两个 shLib

## 1. 旧视觉场景（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/specs/editor-asset-browser/spec.md' -Pattern 'VulkanShaderLibrary.shLib' | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line }
```

真实输出：

```text
87: - **THEN** 截图 MUST 经 read_image 核对底部 dock 可见且列出预置资产行（五列：路径/种类/大小/修改时间/已注册；路径 MUST 含相对资源根全前缀：VulkanShaderLibrary.shLib / D3D12ShaderLibrary.shLib / CSharpProbe/Contrast.res / CSharpProbe/Imported_A.res / CSharpProbe/Imported_B.res）；抓窗方法 MUST 先实测正控验证能抓到 dock 的 WebView2 内容（首选 CoreWebView2.CapturePreviewAsync 经自检钩子落盘，不依赖前景；PrintWindow 不作假设），MUST NOT 置前/最小化/移动用户窗口（C:\Users\76956\.dsh\AGENTS.md §2）；抓不到内容或缺截图或画面不符 MUST 判不通过
```

## 2. 增量 spec 没有改这条需求（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/specs/editor-asset-browser/spec.md' -Pattern '^## |^### Requirement' | ForEach-Object { $_.LineNumber.ToString() + ': ' + $_.Line }
```

真实输出：

```text
1: ## MODIFIED Requirements
3: ### Requirement: 显示提供者必须资产中心且按种类注册，核心资源接口不动
```

没有「资产浏览器必须有视觉与读回验收且回归零差异」这条需求的 MODIFIED 段。

## 3. 新要求（逐字引文）

- specs/editor-code-source-display/spec.md：「MUST 有 `ShaderSourceDisplayProvider`（kind=shader-library），`Describe(shLib 上下文)` MUST NOT 产 shLib 自身条目…」
- tasks.md 3.2：「…dock 显示 .slang/.cs 源文件（kind=shader-source/csharp-source）、**无 shLib/dll 程序集条目**…」

## 4. 结构校验仍通过（命令 + 真实输出）

```powershell
openspec validate editor-code-source-display --strict
```

真实输出：

```text
Change 'editor-code-source-display' is valid
```

`openspec validate` 只做结构校验，不会把「旧视觉场景要求两个 shLib 行」与「新要求 shLib 不出现」判成冲突。

## 5. 结论

合并后的生效规范里两条 MUST 互斥：一条要求截图含两个 shLib 路径，另一条要求 shLib 条目不得出现。按本 change 实现后，旧的视觉场景必然红；按旧场景做视觉验收，本 change 必然不通过。必须先 MODIFIED 旧视觉需求，否则这类验收永远不可能同时成立。
