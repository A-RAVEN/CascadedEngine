# 证据-一致-002：源条目的 path 基准与「工程根」定义三处不一致

- 攻击面：工件一致性（面③：源根约定）
- 结论：生效规范要求 nodeId=path=相对资源根；新规范要求源条目相对工程根；两者对同一文件给出不同字符串，且工程根只在 design 有定义、tasks 只写 env、spec 完全不定义。
- 与并行面的关系：path 基准冲突的同一实测已由 `主张-验收-001` 与 `主张-溯源-008` 落盘；本条不重复其证据，只补「工程根」这个概念在 spec / design / tasks 三处定义不一致的部分（references 保留以便合并）。

## 一、处一：同一条目的 path 基准互斥

生效规范 :16（未修改）：

> 返回条目 MUST 与真实文件逐条一致（path/nodeId/sizeBytes/kind/modifiedUtc/registered/children 七项）；nodeId MUST = path = 相对资源根路径

新能力规范 :19（本次新增）：

> MUST 扫源目录（默认 `CAResources/Shaders`，env `CASCADED_EDITOR_SHADER_SOURCE_ROOT` 可配）递归 `*.slang` 产每个源文件一条 `AssetEntry`（kind=shader-source，path/nodeId=相对工程根源路径……）

design :30 给出具体形态：

> 源文件条目大小/修改时间取源文件 FileInfo；源文件不在 CAAssets，path 用相对工程根的源路径（如 `CAResources/Shaders/Test/TestSimpleTriangle.slang`、`Scripting/Managed/Host.cs`），nodeId=path。

资源根是仓库根 `CAAssets`：

```text
PS> Select-String -Path 'CSharpHost/README.md' -Pattern 'CASCADED_EDITOR_ASSET_ROOT'
CSharpHost\README.md:121: | `CASCADED_EDITOR_ASSET_ROOT` | 覆盖资产浏览器的资源根（只影响资产浏览；导入器仍按默认根扫描） | 仓库根 `CAAssets` | …… |
CSharpHost\README.md:451: | `CASCADED_EDITOR_ASSET_ROOT` | 覆盖资产浏览器的资源根（默认仓库根 `CAAssets`；只影响资产浏览枚举，不动用户文件） | 仓库根 `CAAssets` | …… |
```

同一个源文件：

- 相对工程根：`CAResources/Shaders/Test/TestSimpleTriangle.slang`（design :30 的写法，文件实测存在）。
- 相对资源根：`../CAResources/Shaders/Test/TestSimpleTriangle.slang`（`Path.GetRelativePath(CAAssets, 该文件)` 的结果）。

两者不相等；生效规范 :16 的 MUST 按字面要求后者，新规范要求前者。change 没有 MODIFY :16，因此 apply 后两条 MUST 无法同时满足。

```text
PS> Test-Path 'CAResources/Shaders/Test/TestSimpleTriangle.slang'
True
PS> Get-ChildItem 'openspec/changes/editor-code-source-display' -Recurse -File | Select-String -Pattern '相对资源根路径'
（零命中：新工件只用「相对工程根」，没有解释与 :16 的关系）
```

## 二、处二：「工程根」定义三处不一致

design :34：

> 源根默认：shader＝`CAResources/Shaders`、C#＝`Scripting`（相对工程根）。env 覆盖（`CASCADED_EDITOR_SHADER_SOURCE_ROOT` / `CASCADED_EDITOR_CSHARP_SOURCE_ROOT`，登记 CSharpHost/README）。工程根取资源根的上级约定或 env `CASCADED_EDITOR_PROJECT_ROOT`（测试传临时工程根隔离）。

tasks :17（2.3）：

> ……源根 env + 工程根 env CASCADED_EDITOR_PROJECT_ROOT；**新 env 登记 CSharpHost/README**。

新能力规范全文：

```text
PS> Select-String -Path 'openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md' -Pattern 'CASCADED_EDITOR_PROJECT_ROOT'
（零命中）
PS> Select-String -Path 'openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md' -Pattern '工程根'
spec.md:19: ……path/nodeId=相对工程根源路径……
spec.md:33: ……path/nodeId=相对工程根源路径……
（只有使用，没有定义）
```

- design 有两个机制（资源根上一级 + env 覆盖），且 Open Questions :65 说「env CASCADED_EDITOR_PROJECT_ROOT 优先」。
- tasks 2.3 只写「工程根 env」，没有任务去实现「资源根的上级」这个默认；若执行者只照 tasks，未设 env 时工程根从哪来没有交代。
- 规范只写「相对工程根」，既不给默认值也不给 env 名；第三方只读规范无法复现路径。

这不是措辞差异：在真实编辑器（不设 `CASCADED_EDITOR_PROJECT_ROOT`）里，工程根若取不到，`CAResources/Shaders` 与 `Scripting` 都解析不出来，源条目会全空，而规范仍要求 source entries 出现。

## 三、为什么算矛盾

- 同一个 `.slang` 文件在同一个 list-assets 响应里只能有一个 path/nodeId；:16 与 :19 给出两个不同的 MUST。
- 规范把「工程根」当作已知概念使用，却在规范内没有定义；design 与 tasks 对机制的描述不一致（两个机制 vs 只有 env）。
- tasks 3.1 的临时工程根用例没有说明如何同时设资源根与工程根；若只设资源根，按 design 的默认推导成立，但 tasks 没写这条实现，红绿都可能靠巧合。

## 四、建议修法

1. 规范里写全工程根：资源根是 `<工程根>/CAAssets`，默认取资源根的上一级；`CASCADED_EDITOR_PROJECT_ROOT` 覆盖且优先；给出两者同时存在时的优先级。
2. 同时 MODIFY editor-asset-browser :16：资源根内文件仍用相对资源根；源文件条目用相对工程根（并写清前缀与唯一性），或改为互不冲突的 nodeId 命名空间。
3. tasks 2.3 补「不设 env 时按资源根上一级推导工程根」的实现与断言；tasks 3.1 增加「只设资源根、不设 PROJECT_ROOT」的场景，证明默认推导真的生效。
