# 证据 影响-005：真实根有两个 shLib，工件只认一个——两次 Describe 产同 nodeId 条目，registered 归属未定

对应主张：`主张-影响-005.json`（severity = blocking）

审查对象：`design.md` D2/D5/D6、`specs/editor-code-source-display/spec.md`「shLib 隐去 slang 源显现」、`tasks.md` 2.1/3.1；对照 CAAssets 实际文件与 `TestEditorAssetBrowser` 夹具。

审查快照（SHA-256 前 16 位）：`design.md` `BB8AD764922E5D86`、`tasks.md` `90FD91739A78EC59`、`spec.md` `05A061C9058DD644`、`EditorService.cs` `BE0F7040B5C5E015`。

## 一、真实资产根里有两个 shLib

```text
PS> Get-ChildItem 'CAAssets' -Filter *.shLib | Select-Object Name,Length
D3D12ShaderLibrary.shLib  293737
VulkanShaderLibrary.shLib 145710
```

## 二、工件只预置一个

`specs/editor-code-source-display/spec.md:23`：

> **WHEN** 临时工程根预置 shLib（CAAssets）+ 已知 .slang 源（CAResources/Shaders），注册 shader-library 提供者后 list-assets

`tasks.md:21`（3.1）：

> 临时工程根预置 shLib（CAAssets）+ 已知 .slang（CAResources/Shaders）+ 注册 C# 显示资源 + 已知 .cs（Scripting/）→ list-assets 断言……

既有 `TestEditorAssetBrowser` 也只放一个：`Main.cpp:6411` 的 `ShaderLibraries/Browser.shLib`。

## 三、两个 shLib 都在时会发生什么

`design.md:28-30`（D3）：每个 shLib 上下文都「扫源目录 `CAResources/Shaders/`（递归 *.slang）产每个源文件一条」。两个 shLib 各被枚举一次 → 同一源根被扫两遍 → 16 条 nodeId 相同的条目出现两次。

`design.md:38`（D5）把 `registered` 定义为父程序集注册态：

> `registered=父程序集是否注册`（shader 源条目 registered=HasResource(shLib relative)……）

`design.md:42`（D6）：

> ③ 合并去重（按 nodeId）→ 按 path 序数排序

两份条目的 nodeId 相同但 `registered` 不同（只有当前后端的 shLib 在注册表里），保留哪条取决于收集顺序；`EditorService.cs:1100` 用 `Directory.EnumerateFiles` 收集、`:1133` 才排序，去重发生在排序之前，于是 **registered 的真假随文件系统枚举顺序变化**。

若去重只覆盖 D2 所说的「注册显示资源 vs 资产根枚举」这一对，同分支的 16×2 条重复不会被合并——list-assets 出现 32 行重复路径，`spec.md:24`「源条目数 MUST 等于源目录 .slang 文件数」在真实根上不成立。

另有一条退路：只给当前后端的 shLib 绑 `(kind,path)`。此时另一个 shLib 落默认提供者照显，违反提案 Why 里用户裁定的「代码型资产不显示程序集本身」，而单 shLib 夹具同样测不到。

## 四、红态怎么构造

3.1 夹具改成预置两个 shLib（一个注册、一个不注册）、源根放 2 份 .slang：

- 期望 A（合并成 2 条，registered 按写死规则）：当前实现若未写死规则，16/2 条数或 registered 会随机不符。
- 期望 B（只给当前后端绑定）：断言另一个 shLib 不出现；当前单 shLib 夹具永远绿。

## 五、建议改法

1. 写死多程序集规则：同一源文件只产一条（按真实源路径去重，不按 nodeId 碰运气）；`registered` 取「当前后端」还是「任一相关 shLib」二选一。
2. 去重优先级写成确定规则（精确绑定 > 种类默认），不依赖枚举顺序。
3. 3.1 夹具改双 shLib + 双 .slang，断言条数与 registered 写死期望；补「只绑当前后端时另一个 shLib 是否显示」的期望。
