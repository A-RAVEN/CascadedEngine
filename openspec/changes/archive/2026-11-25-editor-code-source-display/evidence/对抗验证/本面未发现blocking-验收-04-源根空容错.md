# 本面未发现 blocking——④源根空容错

本面（验收可失败性 · ④源根空容错）本轮出了 2 条主张，最高 severity 为 `misleading`，没有 Blocking：

| 主张 | severity | 一句话 |
|---|---|---|
| 主张-验收-009 | misleading | spec 要求「源根不存在/空」两态都容错，tasks 3.1 红态只写「源根空」；缺失目录与空目录是两条代码路径，且「不报错」没钉 `ok=true`。 |
| 主张-验收-010 | minor | 容错红态缺正控：只断言「源条目空」，提供者没接线或整体条目被清空也能绿；需保留一条数据型条目证明只有源来源为空。 |

为什么不构成 Blocking：这条验收本身可以失败——提供者对缺失目录抛异常会被 `ExecuteListAssets` 的 `catch (DirectoryNotFoundException ex)` 转成 `E_ASSET_ROOT`，`ok=false` 红；真正的问题只是两态覆盖不全、缺正控，属于加严判据，不是「永远不可能红」。按主张-验收-009/010 的修订即可提升为一条能失败的红态。

本轮禁跑 tester，未实测红态，只核工件与代码路径（证据见 `证据-验收-009.md`、`证据-验收-010.md`）。
