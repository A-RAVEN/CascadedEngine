# 证据-溯源-007：`registered=true 当程序集存在` 与已生效协议冲突，且「存在」不可判

> 定位以逐字引文为准；行号是 2026-11-25 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-007（面⑤ registered 语义）
- 攻击面：无中生有
- 严重度：blocking
- 工件：`design.md:38`、`spec.md:33`、`PROTOCOL.md:127`、`openspec/specs/editor-asset-browser/spec.md:11/:16`
- 一句话：`registered` 已被协议钉死为「HasResource 读数」，dll 不在注册表时该值只能是 false；工件却约定 true，并把它解释成「程序集存在」，而「存在」连一个可解析路径都没有。

## 二、工件原文

`design.md:38`：

> **registered=父程序集是否注册**（shader 源条目 registered=HasResource(shLib relative)；C# 源条目 registered=dll 是否视为注册——dll 不在注册表，约定 registered=true 当程序集存在）

`spec.md:33`：

> registered=true 当程序集存在

## 三、已有协议（已生效，不得无声明改写）

`Scripting/Managed/Editor/PROTOCOL.md:127`：

> | `registered` | bool | 该路径在资源注册表里**已有条目**（门面 `HasResource(path)` 读数）；未注册的文件同样列出，只是本字段为 `false` |

`openspec/specs/editor-asset-browser/spec.md:11`：

> 每行 MUST 含相对路径 / 种类（扩展名映射）/ 大小（字节）/ 修改时间 / 是否已注册（门面 `HasResource`）

同文件 `:16`：

> registered MUST 等于 HasResource 读数且**真值与假值都出现**（恒假实现不得过）

## 四、命令与真实输出

```powershell
PS> Select-String PROTOCOL.md -Pattern 'registered'
127: | `registered` | bool | 该路径在资源注册表里**已有条目**（门面 `HasResource(path)` 读数）；未注册的文件同样列出，只是本字段为 `false` |
PS> Select-String openspec\specs\editor-asset-browser\spec.md -Pattern 'registered'
11: ... 是否已注册（门面 `HasResource`）...
16: ... registered MUST 等于 HasResource 读数且**真值与假值都出现** ...
```

dll 确实不在注册表（这也是 design 自己写的），且注册显示资源的 path 是裸名：

```text
design.md:24：C# 脚本注册（csharp-script, "Scripting.Managed.dll", CSharpSourceDisplayProvider）
实测：CAAssets 无 dll；dll 在 out/build/x64-debug/bin/Scripting.Managed.dll
```

`HasResource("Scripting.Managed.dll")` 的读数只能是 false；把显示值写成 true ≠ HasResource。

## 五、「程序集存在」不可判

- 注册 path = `"Scripting.Managed.dll"`（裸名，不含目录、不含 preset）。
- 实际文件 = `out/build/<preset>/bin/Scripting.Managed.dll`（preset 由构建配置决定，C# 侧没有这个信息；另有 `managed/` 副本）。
- 因此提供者即便想查「存在」，也不知道该拼哪个路径；spec 也没定义基准目录。这是无中生有的一个谓词：字段值不来自任何真实读数。

## 六、验收抓不到

`tasks.md:21` 的 C# 断言只要求：

> .cs 源条目逐条 path/kind/sizeBytes/registered==写死期望

写死期望可以由实现自己填（true），没有「必须等于 HasResource」的读数对照；`spec.md:38` 的 C# 场景也只列 path/kind/sizeBytes，未列 registered。于是这条语义改写不会被现有判据打红。

## 七、结论与建议

- blocking：要么 dll 真注册进资源注册表（那 registered 可如实为 true），要么 csharp-source 的 registered 如实写 false 并在 UI 上另设「程序集存在」字段/提示；不能把 registered 改义。
- 若确实需要「程序集存在」语义，应新增字段（协议加法 + PROTOCOL.md / protocol.ts / EditorProtocol.cs 三处镜像），并给出存在判据的基准路径（例如由注册显示资源显式携带 dll 绝对路径或相对 bin 路径）。
- 现有验收要加一条「csharp-source.registered == HasResource(注册 path) 读数」的对照，才能让这条判据可失败。

## 八、边界

- 核了：PROTOCOL.md、已生效 spec、design/spec 的 registered 写法、dll 实际位置、CAAssets 无 dll、验收字段清单。
- 没核：没有运行 list-assets 观察 registered 的实际输出（change 尚未 apply，无实现）；HasResource("Scripting.Managed.dll") 的 false 是按注册表语义与实测 CAAssets 无该文件推断，未跑门面验证。
