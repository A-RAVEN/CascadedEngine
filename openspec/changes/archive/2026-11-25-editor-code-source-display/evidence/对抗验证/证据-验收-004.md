# 证据-验收-004：`.cs` 源条目 registered 期望无法独立写死

## 1. 工件的口径原文（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/design.md','openspec/changes/editor-code-source-display/tasks.md','openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md' -Pattern 'registered=true 当程序集存在|程序集存在|注册时写死 Scripting.Managed.dll' | ForEach-Object { $_.Filename + ':' + $_.LineNumber + ': ' + $_.Line.Trim() }
```

真实输出（节选）：

```text
design.md:38: 源文件条目：kind=shader-source/csharp-source；path/nodeId=相对工程根源路径；sizeBytes/modifiedUtc=源文件 FileInfo；**registered=父程序集是否注册**（shader 源条目 registered=HasResource(shLib relative)；C# 源条目 registered=dll 是否视为注册——dll 不在注册表，约定 registered=true 当程序集存在）。…
design.md:64: 2. C# dll 路径如何确定（注册时写死 Scripting.Managed.dll vs 取 Assembly.Location）——取注册指明 + 默认 Scripting.Managed.dll。
tasks.md:16: …（kind=csharp-source，registered=true 当程序集存在）；注册 (csharp-script, "Scripting.Managed.dll", 提供者）…
spec.md:33: …（kind=csharp-source，path/nodeId=相对工程根源路径，registered=true 当程序集存在）…
```

注意 design 的 Open Question 只裁决了「路径来源」（注册写死 vs Assembly.Location），没有裁决「存在性」按哪个基准探测。

## 2. 两种探测口径给出相反期望（命令 + 真实输出）

程序集实际位置：

```powershell
Get-ChildItem -Path '.','out' -Recurse -Filter 'Scripting.Managed.dll' -File -ErrorAction SilentlyContinue | ForEach-Object { $_.FullName + '  ' + $_.Length }
```

真实输出（节选）：

```text
E:\Projects\CascadedEngine\out\build\x64-debug\bin\Scripting.Managed.dll  452608
E:\Projects\CascadedEngine\out\build\x64-debug\managed\Scripting.Managed.dll  452608
```

- 按 `Assembly.Location`：本进程里该值恒为上面第一条，恒存在 ⇒ registered 恒 true。
- 按「临时工程根 + 注册 path」：tester 的临时工程根由 `std::filesystem::temp_directory_path() / ("CascadedAssetBrowser_" + ctx.backendName)` 一类路径新建，里面没有 `Scripting.Managed.dll` ⇒ registered 恒 false。

两种都与「registered=true 当程序集存在」这句话字面自洽，但写死期望一个取 true、一个取 false；实现若恒返回 true（或恒 false），只要与所选口径一致就永远绿。

## 3. 编辑器自己记录的 Assembly.Location 口径（逐字引文）

`Scripting/Managed/Editor/EditorService.cs`：

```csharp
Host.LogFromEditor("[编辑器] 程序集位置：" + typeof(EditorService).Assembly.Location +
                   "；AppContext.BaseDirectory=\"" + AppContext.BaseDirectory + "\"");
```

同文件注释：「hostfxr 宿主下 AppContext.BaseDirectory 可能是空字符串（实测错误日志里 root 打印成相对…）」。

## 4. 结论

`registered` 是七字段里唯一一个既不受夹具文件字节控制、也没有第二态可写的字段；在探测口径钉死之前，tasks 3.1 的「registered==写死期望」不能失败，也不能证明程序集存在性被正确判断。
