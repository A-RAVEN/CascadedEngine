对应主张：`主张-影响-004.json`（severity = misleading）

审查对象：`design.md` D6、`specs/editor-code-source-display/spec.md` Requirement 2；对照 `EditorService.cs` 的 `BroadcastAssetsChangedIfNeeded`、`PROTOCOL.md` 2.5、`EditorWeb/src/assets.ts`。

## 二、本批之后发生什么

工件只承诺源条目增删（`design.md:42`）：

> assets-changed 快照比对沿用（源条目增删也广播）。

隐去 shLib 条目后：

- 往 CAAssets 新增/删除 `.shLib`：16 条源条目的 path 都不变，`s_lastAssetPaths` 与 current 相同 → `added=0`、`removed=0`，**不广播**。本批之前，同一个文件增删会广播 added/removed=1，客户端收到后重拉列表（`assets.ts:124-129` 的处理就是收到事件重发 list-assets）。
- shLib 被注册/注销（`HasResource` 翻转）：只改 16 条源条目的 `registered` 布尔，path 集合不变 → **永不广播**。`assets.ts:85` 的第五列直接渲染 `entry.registered`，于是 dock 会一直显示旧的「已注册/未注册」，直到用户手动点刷新。

## 三、为什么这是影响面缺口

1. 工件把「assets-changed 协议 MUST 不变」（增量规范第 5 行）理解为字段形状不变，但这里退化的是**触发条件**：真实文件系统变化不再产生通知。
2. 3.1 的验收只列「源文件增删 → assets-changed」（`tasks.md:21`），没有任何一条覆盖「程序集增删」或「registered 翻转」；实现无论选广播还是不广播都能过。
3. 这不是新引入的全局缺陷（registered 翻转本来就不广播），但本批把 16 行 UI 状态绑到一个被隐去的程序集上，影响面从 1 行扩大到 16 行，且程序集层面的增删通知被本批直接删掉了。

## 四、红态怎么构造

在 TestEditorAssetBrowser 里加一步：预置一个未注册的 `ShaderLibraries/Added.shLib`（或删掉现有 Browser.shLib）后再枚举，期望收到至少一条 `assets-changed`。按当前设计该期望必红（added=0/removed=0，收不到事件），而现有工件没有任何断言要求它绿。

## 五、建议改法

1. D6/spec 写死三种变化的期望读数：源文件增删、程序集文件增删、registered 翻转。
2. 3.1 增加「新增/删除一个 shLib」与「注销 shLib 后 registered 翻转」两条断言；若决定不广播，就在 UI 文案与工件里明写「程序集变化需手动刷新」，并说明为什么可以接受。
