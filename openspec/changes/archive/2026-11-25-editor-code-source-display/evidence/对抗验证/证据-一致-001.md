## 四、为什么算矛盾（不是措辞问题）

- 同一份生效规范里 :87 要求 shLib 行出现、:52 要求 shLib 行不出现；两条都是 MUST，没有优先级说明。
- 第 23 用例的断言 3 条条目是写死的，新实现按 spec :19 只能产出 2 条；这是「实现正确 → 既有用例失败」的直接冲突，不是测试可以两边都过。
- tasks 4.1 排除了这个用例，等于让冲突在验收里不可见；按项目规则「验收必须能失败」，这属于把一个必红项藏起来。

1. 本 change 增补对 editor-asset-browser 视觉/回归要求的 MODIFIED：:87 的期望行改为「无 shLib/dll、含 .slang/.cs 源行」，并点名工程根与具体源文件。
