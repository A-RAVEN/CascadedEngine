# 证据-验收-010：容错场景没有正控

## 1. 工件原文（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md','openspec/changes/editor-code-source-display/tasks.md' -Pattern '源条目空' | ForEach-Object { $_.Filename + ':' + $_.LineNumber + ': ' + $_.Line.Trim() }
```

真实输出：

```text
spec.md:29: - **THEN** 提供者 MUST 产空列表（list-assets ok=true，源条目空），MUST NOT 报错或整体失败
tasks.md:21: …红态：源根空→源条目空不报错…
```

两处都只要求「源条目空」，没有要求同一次枚举里还有别的条目。

## 2. 为什么这会恒绿

- 若 ShaderSourceDisplayProvider 没有注册（或注册了但没被调用），源码根本不会执行扫描 → 源条目天然为空 → 断言绿。
- 若 ExecuteListAssets 在某个分支把所有条目都丢了（例如 `described == null` 时 `continue` 的边界写错、或异常被吞后返回空列表），源条目也为空 → 断言绿。
- tasks 3.1 只在正控部分写「源条目逐条==写死期望」，但红态场景没有绑定「先有 N 条、再清空、再恢复」的顺序；实现者可以在独立的一次 list-assets 里只做「源根空」这一步。

证据只来自于工件文本（本轮禁跑 tester），结论是判据结构问题：缺一条与源条目无关的正控条目，就无法区分「容错」与「没输出」。
