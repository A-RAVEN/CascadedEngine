# 证据-验收-003：「注册显示资源去重」无重复可构造

## 1. 工件原文（命令 + 真实输出）

```powershell
Select-String -Path 'openspec/changes/editor-code-source-display/specs/editor-code-source-display/spec.md','openspec/changes/editor-code-source-display/tasks.md','openspec/changes/editor-code-source-display/design.md' -Pattern '去重|Scripting.Managed.dll' | ForEach-Object { $_.Filename + ':' + $_.LineNumber + ': ' + $_.Line.Trim() }
```

真实输出（节选）：

```text
spec.md:33: MUST 有「显示资源注册表」`RegisterDisplayResource(kind, path, provider)`…MUST 注册 (csharp-script, "Scripting.Managed.dll", `CSharpSourceDisplayProvider`)；该提供者 MUST NOT 产 dll 条目，MUST 扫 `Scripting/`…递归 `*.cs` 产每个源文件一条…注册显示资源 path 若已在 CAAssets 枚举到 MUST 去重（不重复引入）。
spec.md:43: - **THEN** MUST NOT 重复引入该 path 条目（按 nodeId 去重）
tasks.md:17: …③ 按 nodeId 去重 + path 序数排序…去重（注册 path 已在 CAAssets 不重复）…
tasks.md:21: …list-assets 断言 **shLib/dll 条目不出现** + .slang/.cs 源条目逐条…
design.md:24: **去重**：注册显示资源的 path 若已在 CAAssets 枚举到（如 shLib），不重复引入（以文件枚举那条为准）…
```

## 2. 为什么没有重复可去

- 唯一被 MUST 注册的显示资源 path 是 `Scripting.Managed.dll`（spec.md:33）。
- 该 path 的提供者产出条目 path/nodeId = `Scripting/` 下各 `.cs` 源路径（spec.md:33：「MUST 扫 `Scripting/`…递归 `*.cs` 产每个源文件一条（kind=csharp-source，path/nodeId=相对工程根源路径…）」）。
- 去重按 nodeId（spec.md:43）。`.cs` 源条目 nodeId 与 `Scripting.Managed.dll` 不相等；CAAssets 里若真有一条 dll，它来自文件枚举、nodeId=相对资源根路径（`Scripting.Managed.dll`），与源条目也不重复。

因此「注册 path 已在 CAAssets 枚举到」这一条件下，两个来源的条目集合没有交集，去重逻辑永远无事可做——无论实现是否写了去重，验收都绿。

## 3. 反例核对（代码路径推导，非实测）

若把 `Scripting.Managed.dll` 放进临时 CAAssets：文件枚举产 1 条 `kind=file` 的 dll 条目（KindOf 无 .dll 映射，落 file），显示资源产 `.cs` 源条目；按 nodeId 去重不会删任何一条，而 dll 条目仍显示。也就是「去重」既不覆盖也没有被这个夹具检验。
