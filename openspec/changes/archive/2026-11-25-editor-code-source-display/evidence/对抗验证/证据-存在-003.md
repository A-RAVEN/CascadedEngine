## 三、佐证：`ShaderReflectionData` 里没有源路径串（D3 的推理本身成立）

`Interface/ShaderCompiler/header/Compiler.h`（`struct ShaderReflectionData` 全文成员）：

```cpp
L566: CA_REFLECT(serializable)
L567: struct ShaderReflectionData
L568: {
L569: public:
L570: 	castl::vector<ShaderBindingSpaceData> m_BindingData;
L571: 	castl::vector<ShaderVertexAttributeData> m_VertexAttributes;
L572: 	castl::unordered_map<cacore::NameHash, ShaderStructData> m_ShaderStructs;
L573: 	ShaderBindingInfo m_BindingInfo;
...
L600: };
```

没有 `path` / `sourcePath` / `filePath` 之类的字符串成员（对该头文件 grep `sourcePath|filePath` 零命中；唯一相近的命中是接口方法 `L627: virtual void AddSourceFile(const char* path) = 0;`，不是 `ShaderReflectionData` 的成员），所以「C# 侧拿不到源路径串、只能扫源目录」这条推理真实成立。

## 四、结论

工件 `design.md:9` 的 `ShaderFileInfo.path` 只在 D3D12 后端成立；Vulkan 后端没有名为 `ShaderFileInfo` 的类型。机制（`m_ShaderFiles` 键为 `cacore::PathHash`、值结构含 `cacore::PathHash path`）两后端都在，所以按 misleading 记，不按 blocking。改法：按后端点名两个值类型即可，不动判据。
