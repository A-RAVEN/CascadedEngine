> `Scripting/Managed/Editor/DisplayProviders/ShaderSourceDisplayProvider.cs`（kind=shader-library）：Describe(shLib) **不产 shLib 条目**，扫源根（默认 CAResources/Shaders，env CASCADED_EDITOR_SHADER_SOURCE_ROOT）递归 *.slang 产源条目（kind=shader-source，path/nodeId=相对工程根源路径，sizeBytes/modifiedUtc=源 FileInfo，registered=HasResource(shLib)，children 空）；源根空/不存在产空列表不报错。

## 三、两种注册读法的后果

- 读法 A：按种类默认注册（`Register("shader-library", provider)`，与 spec 的 `kind=shader-library` 最一致）。任何 `.shLib` 都落该提供者；`ShaderLibraries/Browser.shLib` 被隐去，源根在临时目录下为空 → ① 只剩 2 条 ≠ 3、② 变 3 ≠ 4，两条断言必红。
- 读法 B：按 `(kind, path)` 只绑真实两个 shLib 名。第 23 用例的夹具不是这两个名字，能过；但任务没有要求注册 `VulkanShaderLibrary.shLib` / `D3D12ShaderLibrary.shLib` 这两条（也没写键），漏注册就 shLib 照显、源文件不显——特性在生产里静默不生效。

## 四、为什么本批验收发现不了

`tasks.md:26`（4.1）逐字：

> 现有 22 用例同进程两后端 name+status 与基线（归档 2026-11-25-source-importers-png-obj/evidence/4.1-全量-*.json）零差异

实测基线条目数：

```text
4.1-全量-d3d12.json: 22 条
4.1-全量-vulkan.json: 22 条
```

`Main.cpp` 全量段（`12161-12200`）正好 22 条 `runTestWithDiagnostics`，不含 `TestEditorAssetBrowser`（第 23）、`TestWebRenderSpike`（第 24）、`TestSourceImporters`（第 25）。三条独立进程用例只出现在 `--list`（`11782` / `11786` / `11790`）与单独 `--test` 分支（`12134` / `12139` / `12145`）。因此读法 A 造成的第 23 用例变红，在工件规定的验收读数里完全看不见。

## 五、红态怎么构造

按种类默认注册 shader 提供者（或放在 `AssetDisplayProviders` 的静态初始化里），跑：

```text
out\build\x64-debug\bin\GPUBackendTester.exe --backend vulkan --test TestEditorAssetBrowser
```

预期红：`E_ASSETBROWSER_LIST`（条目数 2 ≠ 3）、`E_ASSETBROWSER_REFRESH`（3 ≠ 4）。红态真实存在而验收范围不覆盖它，属于「波及面与静默降级」缺陷。

## 六、建议改法

1. 在 2.1 写死注册语句（文件 + 键 + 调用点），并把键写进 spec 场景，二选一：按 `(kind,path)` 绑两个真实 shLib 路径；或按种类默认注册并同步改第 23 用例夹具/回归范围。
2. 4.1 补三条独立进程用例的命令与期望读数（明确「不进全量 report」的口径），否则「现有用例全绿」不可核。
