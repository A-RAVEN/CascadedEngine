# 证据-存在-002：shader 导入器的扫描根是 `CAResources`，不是 `CAResources/Shaders`

对应主张：`主张-存在-002.json`（severity=misleading）。只读命令 + 读文件，未跑构建、未跑 tester。

## 一、`.slang` 今天全在 `Shaders/` 下（所以错误没被暴露）

```powershell
(Get-ChildItem -Path CAResources -Recurse -File -Filter *.slang | Measure-Object).Count            # → 16
Get-ChildItem -Path CAResources -Recurse -File -Filter *.slang |
  Where-Object { $_.DirectoryName -notlike '*\Shaders*' } | Select-Object -ExpandProperty FullName # → 空输出
Get-ChildItem -Path CAResources -Directory | Select-Object -ExpandProperty Name                    # → Images / Models / Shaders
```

16 份全在 `CAResources/Shaders`（含 `Shaders/Test/` 下 9 份），所以「扫 Shaders」与「扫 CAResources 全树」今天结果相同 —— 这是巧合，不是约定与扫描根一致。

## 四、结论与影响

shLib 覆盖的是 `CAResources` 全树下所有 `.slang`；工件 `design.md:52` 的「与 ShaderImporter 扫描根一致」为假句。把显示映射钉在子目录 `CAResources/Shaders` 后：任何放在 `CAResources` 根或其它子目录下的 `.slang` 都会进 shLib，却不进显示；而 spec/tasks 的验收（源条目数 == 源目录 `.slang` 数）两侧都量 `Shaders`，判不出这条漏显。今天 16/16 全在 `Shaders` 下，所以实施不阻断，但这句话必须改，默认源根也应与真实扫描根对齐（或显式写明「只覆盖 Shaders 子集」并给出理由）。
