## 三、三条正面冲突

1. **逐条一致**：本批让 `.shLib` 不出现（`specs/editor-code-source-display/spec.md:19`「Describe(shLib 上下文) MUST NOT 产 shLib 自身条目」），真实文件 `VulkanShaderLibrary.shLib` / `D3D12ShaderLibrary.shLib` 在 CAAssets 里实存，条目与文件不再逐条一致。
2. **nodeId = 相对资源根**：本批要求源条目 `path/nodeId=相对工程根源路径`（同文件 `:19`、design.md:30 的例子 `CAResources/Shaders/Test/TestSimpleTriangle.slang`），不再是相对资源根。
3. **视觉截图**：存量场景要求截图里出现两个 shLib 路径；本批 3.2 要求「无 shLib/dll 程序集条目」（`tasks.md:22`），同一张 dock 截图不可能同时满足。

## 四、为什么 `openspec validate` 不拦

```text
PS> openspec validate editor-code-source-display
Change 'editor-code-source-display' is valid
```

它只校验增量文件结构与 Requirement 格式，不校验与存量规范的语义冲突。归档动作会把增量 Requirement 覆盖到存量同一标题下，另外两条 Requirement 原样保留；此后 `openspec/specs/editor-asset-browser/spec.md` 自身包含互斥 MUST，任何按它写的验收都会踩到一条。

## 五、建议改法

1. 增量规范补 MODIFIED Requirement 覆盖第 1 条：「条目来源」写成「资产根文件 + 注册显示资源 + 代码型源条目」，并写死 path/nodeId 语义（与 003 一起定）。
2. 补 MODIFIED 覆盖第 5 条的视觉场景：断言改为「无 shLib/dll 程序集条目、出现 .slang/.cs 源条目」，明确取代旧 shLib 路径断言。
3. 保留 `.shLib` 夹具的场景改成「该条目是否出现由注册键决定」，不要同时断言「真实文件逐条一致」。
