# csharp-render-shader-constants 实施任务

用户故事：

- **US1**：C# 渲染调用方需要用着色器常量参数（而非顶点属性）驱动着色输出，并能在调用当场得到点名的拒绝。
- **US2**：引擎维护者需要无效的类型、字段、下标与块名在适配层被挡下，绝不进入后端既知的空元数据崩溃路径。
- **US3**：渲染验证人员需要两个后端的真实像素证据证明常量参数数据确实参与输出，且省略或改错参数会让判据失败。

日志与文本记录统一写入 `openspec/changes/csharp-render-shader-constants/evidence/`；`GPUBackendTester` 运行期产物（`test_output/*.log`、`test_output/*.png`、报告 JSON）留在 `test_output/`（被 `.gitignore` 忽略），由 `check_csharp_constant_color.py` 从该目录校验，4.1 的关键读数同时抄入 evidence。每条红态必须来自缺陷仍存在时的真实命令；不得用预期失败文本代替运行输出，不得在仓库其他位置留下临时探针或日志。

## 6. 判据来源与不放松声明

本 change 全部校验规则的字节数（`float3` = 12 字节）、数组长度（`colorStruct[3]`）与像素期望值都溯源到已核实的产品事实：`CAResources/Shaders/Test/TestTriangleWithConstantColor.slang` 的结构定义、`Interface/ShaderCompiler/header/Compiler.h` 的 `ShaderStructData`/`SubStructReference` 字段、`D3D12ShaderStruct.cpp` 构造函数体内第一处实际使用即解引用空元数据（读码可证，仅 D3D12 侧），以及 `TestTriangleWithConstantColor` 的清除色 `(0, 0, 1, 1)`。不新增发明数量；不放松既有三角形、窗口、回调与像素判据；宿主失败检查的 ABI 期望值随 v7 同步更新（6 → 7）属于版本对齐而非放松——受控失败退出码 1、错误码 4 与无转储断言全部保留；流名查重把现状静默覆盖改为拒绝，属加严。`CRenderBackend` 追加纯虚导致未同步实现者编译失败是期望行为而非回归。
