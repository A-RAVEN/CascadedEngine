## 编译期现场一：生成文本用 C++20 关键字当变量名（build-12 红）

`build.py` 在 CSharpHost 编译段失败：

```
BindingRegistry.Bindings.cpp(119): error C2059: syntax error: 'requires'
BindingRegistry.Bindings.cpp(120): error C2760: syntax error: '<' was unexpected here; expected '{'
BindingRegistry.Bindings.cpp(120): error C2059: syntax error: 'constant'
```

生成文本是 `const int32_t requires = CSharpHostBindingRequiresInstance(route.id);` —— `requires`
在 `/std:c++20` 下是关键字。已改名 `requiresInstance`；build-13 复绿。

**决定（可编译性闸门）**：不为 `check_bindings.py` 另加"再编译一遍生成物"的预检 —— 编译器
（ninja 硬门）已经兜住这类问题，再跑一遍编译的代价大于收益；`check_bindings.py` 维持
编号/表面/对齐/错误码等文本判据。这条决定连同本次现场记在这里。

## 回归修复（生成器模板）与红态复跑（build-15）

修法（只动生成器里的 `get_interface_api` 模板）：
1. 顺序改为：未知编号 → 角色未登记 → **默认实例解析** → `size==0` 探针 → `out` 空检查 → 回表；
2. 默认实例缺失时**直接返回 0、不写宿主 LastError**（由托管侧 `s_renderBindError` 与探针失败文本
   点名接口）；
3. **未知编号 / 角色未登记仍然写宿主 LastError** —— `TestCSharpWindow` 的"未知接口编号 9"判据依赖它。

> **分界记一笔**：这两类错误必须分开处理 —— "未知编号"是给调用的明确拒绝（写 LastError，
> 测试依赖）；"缺少默认实例"属于渲染绑定失败（不写 LastError，窗口路径必须保持 LastError 为空）。
> 后人容易为了"少一条日志"把两类一起静音，那会同时打破 spec csharp-host 的两条判据。
