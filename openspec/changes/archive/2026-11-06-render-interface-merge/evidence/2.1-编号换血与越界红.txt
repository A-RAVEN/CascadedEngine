## 绿态（还原 `CA_BIND(7)` 后重跑同两条）

- cmd1d EXIT=0：`绑定：接口 5 个 / 方法 25 条 / 产物 5 个 / 拒绝 0 条`（**拒绝 0 条**；
  见下面的"教训"——第一次手工绿跑漏了 `--known-interface`，`GetWindowTarget` 被丢）
- cmd2d EXIT=0：`登记：接口 7 个（1 = IWindow、2 = IWindowSystem、3 = IScriptRenderBackend、
  4 = IScriptRenderGraph、5 = IScriptRenderTarget、6 = IScriptShaderStruct、7 = IScriptTexture）`
- `python Tools\CodeGen\check_bindings.py --product-dir out\build\x64-debug\codegen\bindings`：
  `登记表问题 0 处`、`夹具登记表问题 0 处`、`脚本渲染适配面问题 0 处`、exit 0。

**教训（写成可复核的判据链）**：手工跑 `CodeGen.exe` 必须**镜像 `build.py` 的全部参数**。
第一次手工绿跑只拷贝了 `--registry-part/--emit-registry`，漏了 build.py 从
`--list-bind-interfaces` 聚合出来的 7 条 `--known-interface`；生成器解析不到
`castl::shared_ptr<cawindow::IWindow>` 的目标接口，`IScriptRenderBackend.GetWindowTarget`
被静默丢弃（`拒绝 0 条`，产物少一条方法）。`check_bindings` 当场抓到：
`IScriptRenderBackend（表面层）：C++ 多 ['GetWindowTarget']，C# 表面多 无`。补齐 7 条
`--known-interface` 后同一构造复绿。结论：**手工命令之后必须跑 check_bindings**，
"命令 exit 0"不能代替产物判据。
