# 任务 5.1：新增接口成本演练（D8 判据③）

演练对象：在 1.1 夹具上新增一个"进登记表"的接口编号（`CA_BIND(10)`），走通
"编号标注 → 分片 → 汇合 → 生成绑定 + 登记产物 → check_bindings 编号对账"全流程，
记录**手写改动面**，再还原并复绿。

## 四处手写改动（演练清单）

| # | 类型 | 本次落点 | 说明 |
|---|---|---|---|
| ① | 带号标注 | 新夹具头 `Tools/CodeGen/BindableShapes.RenderRegistryDrill.h` 的 `CA_BIND(10)` | 编号只写在标注上；生成器从宏文本读 |
| ② | 登记输入 / 角色登记 | `build.py` 的 `CODEGEN_BINDINGS` 条目 + `CODEGEN_REGISTRIES` 的 `fixture` 输入列表 | 夹具接口不进真实宿主，所以它的"宿主工厂/角色登记"落在构建期登记输入；真实接口的同类落点是 `CSharpHost.cpp` 的 `kBindingPolicies` 一行 |
| ③ | 审计表行或豁免说明 | 夹具头注释写明"不进审计表、按既有夹具豁免" | `check_bindable_audit.py` 的 `INTERFACES` 不含夹具；CodeGen 生成时打印"跳过审计核对" |
| ④ | 编号期望行 | `Tools/CodeGen/check_bindings.py` 的 `FIXTURE_BINDING_NUMBERS` 增加 `10` | 连续性断言同时要求夹具编号 8..10 |

## 结论（要能失败）

- 除上面四处外，**不需要**改 `EngineApi`（生成器发射）、`Host.cs` 绑定序列、`CSharpHost.cpp` 路由；
- 若必须改这三处之一，即"合并未达标"，回到任务 1–3 修正；
- 演练残留（新夹具头 + 两处登记项 + 期望行）全部还原后，`check_bindings.py` 与构建复绿。

## 还原（演练残留全部删除后复绿）

演练完删除的完整清单是**五步**（四处输入 + 构建目录旧输出）：
1. 删除新夹具头 `Tools/CodeGen/BindableShapes.RenderRegistryDrill.h`；
2. `build.py` 的 `CODEGEN_BINDINGS` 条目；
3. `build.py` 的 `CODEGEN_REGISTRIES` fixture 输入项；
4. `Tools/CodeGen/check_bindings.py` 的 `10:` 期望行；
5. 删除构建目录里 build-19 的旧产物（codegen 只写不删）：
   `out\build\x64-debug\codegen\bindings\IBindRegistry10.Bindings.*` 与
   `out\build\x64-debug\codegen\bindings\fixture\drill.registry.part`。

**实测教训（build-20 红）**：只还原四处输入、不删第 5 步的旧产物时，`check_bindings` 扫到孤儿
`IBindRegistry10.Bindings.cpp`，把它当"未豁免的真实接口"并报
`托管表面问题：解析不到接口头`。这说明"手写改动面 = 四类"只对**输入面**成立；**产物面**天然有
残留清理责任在构建系统（与 `docs/TODO.md` 的"期望检查仍是前缀通配"那条同族：旧产物/改名件能
骗过或卡住闸门）。清理后 build-21 复绿。

最终构建（build-21）读数见 5.3 evidence；`check_bindings.py` 在还原后的产物上复跑
`登记表问题 0 处` / `夹具登记表问题 0 处`。
