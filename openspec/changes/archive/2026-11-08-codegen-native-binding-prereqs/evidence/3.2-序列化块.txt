3.2 序列化块记录（D8）

一、红态（改造前，用 3.1 的 CodeGen.exe 对加了 PassLike 的夹具头直接跑）
命令：CodeGen.exe Tools/CodeGen/BindableShapes.NativeShapes.h --emit-binding --out-dir <临时> --audit-script Tools/CodeGen/check_bindable_audit.py <构建同款 include> -xc++
读数（逐字）：
  CodeGen: 拒绝嵌套记录 —— PassLike：类型 ca_bind_fixture::PassLike 的成员 m_PrivateCount 不是公开字段（非公开字段不能镜像）
  CodeGen: --emit-binding 返回 1
  退出码 1

二、实现（生成器）
  1) 夹具：`PassLike`（公开 `castl::vector<PassAttachment>` / `castl::vector<EPassMode>` /
     `cacore::NameHash`，私有 `uint32_t m_PrivateCount` 经 `CA_CODEGEN_FRIEND(PassLike)`）；
     `IBindNativeShape::ConsumePass(PassLike const&)`。
  2) 识别：参数位置、成员含一层容器/文本、且**不同时出现在返回位置**的记录走序列化块
     （同时出现在返回位置的记录留给镜像路径 —— 既有"嵌入记录"诊断因此零改动）。
  3) 字段形状：标量 / 枚举 / 文本（NameHash、PathHash、castl::string）/ 一层
     `vector<标量|枚举|纯标量记录>`；元素记录只允许标量/枚举字段。越界形状生成期非零拒绝：
     `vector<vector<T>>`（"两层容器"）、`unordered_map`/`map`/`set`/定长数组（"映射容器 / 定长数组"）、
     非 const 引用出参（"出参方向"）、string_view（反序列化会悬空）、裸指针/智能指针；每个都写明
     恢复路径（真实实例出现时立扩形状批 / 出参投影批）。
  4) 块头三项：`formatVersion = 1u` + 类型完整限定名的 FNV-1a 64 + **字段布局哈希** =
     `FNV("字段名:类型:偏移;" 序列，含元素记录逐字段展开)`。布局哈希覆盖"名+类型+偏移"，
     "字段改名但类型序不变"的块与正确块字节不同。
  5) C++ 侧：生成 `<记录>.BindingCodec.h`（`#pragma once`，跨接口共享；同一个 TU 里被多个
     接口产物 include 也只展开一次）：`Serialize` 写块头+字段，`Reader/Deserialize` 逐项校验并
     返回 1/2/3/4（版本/类型/布局/载荷）；thunk 把 4 映射到本接口的具名错误码
     `BAD_BLOCK_VERSION=1007` / `BAD_BLOCK_TYPE=1008` / `BAD_BLOCK_LAYOUT=1009` /
     `BAD_BLOCK_PAYLOAD=1010`，失败时**不调用原生实现**（实现计数保持 0）。
     四条块错误码**只发给确实用了序列化块的接口**（本批是 IBindNativeShape）——这是保住
     "既有产物逐字节不变"硬锚的关键：全局错误码表原本让 70 个既有产物全变。
  6) 托管侧：`<记录>.Bindings.cs` = 公开镜像类（字段名/顺序与 C++ 一致）+ internal
     `<记录>Codec.Serialize`（同一份字段清单；BinaryWriter 小端，标量按自身宽度、文本 u64 长度前缀、
     容器 u64 个数前缀），块头三项用同一组常量；元素记录另发 `<元素>.Bindings.cs`；
     Calls 层 `byte[] + fixed`，公开表面收镜像类。

三、执行期四轮红（全部为我这轮引入，逐条修）
  1) C3493/C2326：`buildSerializedElementFields` 的 visitor lambda 用了外层 `declaration`。→ 放进
     `FieldSink` 经 `CXClientData` 传入。
  2) CS1503：Calls 层把 `passBytes`（byte[]）传给要 `byte*` 的参数。→ 改传 `passBytesPtr`。
  3) `EPassMode`：枚举共享文件没有 .cpp，被"共享值类型"反查点名。→ 在 `SHARED_VALUE_TYPES` 登记。
  4) 既有夹具回退 + 基线 70 个产物变：
     · `RejectWrapperNestedRecord`（含顶层 NameHash）被误收进序列化块候选，默认构造门抢答了旧的
       "嵌入记录"诊断 → 候选排除"同时出现在返回位置"的记录，且默认构造门移到形状检查之后、
       隐式默认构造放行；
     · 70 个既有产物变化 = 全局错误码表新增 1007–1010 → 改为按接口过滤后，基线恢复
       "缺失 0 / 不一致 0 / 多余 0"。
