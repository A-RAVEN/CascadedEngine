## MODIFIED Requirements

### Requirement: 一个类型一次调用出一份产物（三节）

`CodeGen.exe` SHALL 支持在**一次调用**里同时产出反射表、读写代码、哈希代码三节，并把它们写进**一份** `<类型名>.codegen.h`（输出目录由 `--emit-all --out-dir <目录>` 给出）。节顺序 MUST 固定为 **反射 → 序列化 → 哈希**；文件头注释、`#pragma once` 与运行时头的 `#include`（`CodeGenMeta.h` / `CodeGenSerialization.h` / `CodeGenHash.h`）MUST 各只出现一次；每节 MUST 保留自己的 `// Generated by CodeGen <某个> emitter for <类型>` 注释行。文件名 MUST 带 `.codegen.h` 后缀 —— 生成目录本身在 include 路径上，用 `<类型名>.h` 会遮蔽同名的真实头。三节的内容 SHALL 与改造前**由同一段发射代码产出**（判据：`-o` 的单节输出与改造前那三份同名产物逐字节相同，76 个类型 × 3 节 = 228 次）。旧命名的三份产物（`<类型名>.Reflection.h` / `.Serialization.h` / `.Hash.h`）MUST 由生成段清掉，清理范围 MUST 覆盖**所有预设**的 `out/build/*/codegen/` 目录，MUST NOT 与新的那一份在 include 路径上共存。命令行接口、退出码表与 `Tools/CodeGen/README.md` 的示例 SHALL 同步更新；`--out-dir` 与 `--emit-all` 的搭配关系（单独给单发射标志 + `--out-dir` 是用例错误、退出码 2）、"一次给两个不同的发射标志 → 退出码 10"、以及退出码 5 / 6 / 9 / 13 / 14 / 15 / 16 / 17 的行为 SHALL 全部保留 —— `--emit-all` MUST 仍然要求三节都能出，MUST NOT 改成"能出哪节就出哪节"。

#### Scenario: 一次调用一份产物

- **WHEN** 用一个类型跑 `--emit-all --out-dir <目录>`
- **THEN** 目录里 MUST 只有**一份** `<类型名>.codegen.h`（含三节），旧的三个文件名 MUST 一个都不存在；工具标准输出里 `CodeGen wrote: ` MUST 只有一行；用 `-o` 单节输出的字节 MUST 与改造前那三份同名产物逐字节相同（228 次全同）

#### Scenario: 文档同步

- **WHEN** 复核 README
- **THEN** 接口表、退出码表与示例 MUST 反映"一次调用写一份文件"；README 里的命令原样可跑（`verify_readme.py` 0 处不符）；工具里 `--emit-all` 那条报错文本 MUST 不再写"三份 / 三个后缀"

#### Scenario: 空输出目录按缺值拒绝

- **WHEN** 传 `--emit-all --out-dir=`（等号后面是空的）或 `-o ''`
- **THEN** MUST 以退出码 2 拒绝并说明目录/路径为空；MUST NOT 把产物写到**当前盘符的根目录**（实测未加这条检查时，`--out-dir=` 会让产物落到盘符根且退出码为 0）

#### Scenario: 接受集合的差异写在明处

- **WHEN** 复核 `--emit-all` 与逐个发射的关系
- **THEN** README MUST 写明：`--emit-all` 让三节的拒绝条件**全部**生效，所以标注没带 `serializable`（退出码 9）、含 `vector<bool>`（13）、含指针成员（15）的类型在 `--emit-all` 下会被拒，而这些类型用单发射反射仍能出码；并给出对照命令与退出码

### Requirement: 生成物必须被真实引擎目标消费

生成代码 SHALL 被至少一个真实引擎目标的编译单元 `#include`，并在该编译单元内对生成表做编译期断言。生成物只活在**构建目录**里（出仓之后源码树没有入库副本、也没有黄金样本副本），所以"被消费"的判据是：消费方 include 的那一份产物由生成段写出来，且它与类型定义逐条对得上 —— 名字对不上或没写出来就 MUST 以"找不到文件"失败，断言对不上就 MUST 以编译错误失败；两者都 MUST NOT 静默通过。

#### Scenario: 真实类型的生成物进入真实编译单元

- **WHEN** 构建 `Rendering` 目标，其中 `Interface/RenderInterface/private/GPUBufferDescriptorReflection.cpp` 包含真实类型 `graphics_backend::GPUBufferDescriptor` 的定义与它的生成物 `<类型名>.codegen.h`
- **THEN** 该编译单元编译通过，且生成表的字段数、字段名与每个字段的偏移（`offsetof`）都与类型定义逐条对得上（对不上即编译错误）

#### Scenario: 消费方 include 的名字对不上时构建失败

- **WHEN** 把某个消费方的 `#include "<类型名>.codegen.h"` 改成一个构建目录里不存在的名字（例如旧的 `<类型名>.Hash.h`），再构建
- **THEN** 该编译单元以"找不到文件"（`C1083`）失败，构建整体失败，MUST NOT 静默通过

#### Scenario: 注解对不上时生成段重跑

- **WHEN** 改动某个被标注类型的成员（增删或改名）而不手工删除产物
- **THEN** 生成段的账本指纹（含被解析头的哈希）因此变化，那一行 MUST 重跑并重写产物；重写后的产物若与消费方的编译期断言不符，MUST 以编译错误失败

#### Scenario: 生成表被替换成别的类型时失败

- **WHEN** 把构建目录里某份产物手工换成另一个类型的生成结果，再构建
- **THEN** 消费方的编译期断言（类型名 / 字段数）失败，构建整体失败
