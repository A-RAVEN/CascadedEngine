## 判据 A：文件存在、六行行为表齐备
--------------------------------------------------------------
`Test-Path IOManager_FS\README.md` → True（9852 字节）

表头逐字核对：`| # | 场景 | 改前（静默或未类型化） | 改后 | 实测读数 |` → 存在
六个编号行实测（正则 `^\| <n> \|`）：
```
| 1 | **越界读**（批内位置 + 请求长度 > 文件尺寸） | …
| 2 | **创建期尺寸失败**（路径不存在、路径是目录） | …
| 3 | **提交期打不开源文件**（建批之后文件被删/权限变化） | …
| 4 | **中途短读**（建批之后源文件被截短） | …
| 5 | **写目标打不开**（父目录不存在、没有写权限等） | …
| 6 | **写流失败**（`write()` / `flush()` 之后流状态变坏） | …
```
⇒ 六行齐备，每行都带"改前 / 改后 / 实测读数（指向 evidence 文件）"三列。
第 6 行如实写明"本批没有独立的注入读数"（制造 open 成功但 write 失败需要磁盘满或只读句柄，
测试里没有稳定手段），没有编造读数。

==============================================================
## 判据 B：示例输出与 evidence 存档逐字一致
--------------------------------------------------------------
方法：把 README 里所有以 `[I/O 错误通道 ` 开头的引用行抽出来，与 evidence 里的真实日志逐字比对
（日志行去掉 ANSI 颜色前缀 `ESC[38;2;128;128;128m` / `ESC[0m`，README 里已注明"照抄去掉前缀后的正文"）。
比对对象：`evidence/1.2-1.5-5.1-绿态-tester日志-vulkan.log` 与
`evidence/1.2-1.5-5.1-红态-tester日志-vulkan.log`。

真实输出：
```
证据绿态行数=6  证据红态行数=6  README 引用行数=8
README 行与绿态证据逐字相同: 6
README 行与红态证据逐字相同: 2
不一致行数=0
六行全部被引用
```
⇒ 判据成立：README 引用 8 行 = 绿态全部 6 行 + 红态 2 行（1.2 / 5.1），逐字相同、无一编造，
且绿态六行没有遗漏任何一条。

## 附：README 里同时给出的"怎么把它弄红"四条
--------------------------------------------------------------
1. `IOBatchImpl::Read` 越界分支改回静默接受 ⇒ 只有 1.3 那行不成立；
2. 删掉 `SubmitAndWait` 的 `gcount()` 检查 ⇒ 只有 1.4② 那行不成立；
3. `IOManagerImpl::Batch` 换回裸 `std::filesystem::file_size` ⇒ 1.2 与 5.1 两行变成"不是 io_error"；
4. 删掉 `WriteBatchImpl::SubmitAndWait` 的 `is_open()` 检查 ⇒ 只有 1.5 那行不成立。
这四条就是本 change 红绿两轮里真实发生过的对照（红态读数见 `evidence/*-红态.txt`），
写进 README 是为了回归时能按同样的动作把链路重新弄红。
