# 证据-溯源-003：失败面只列三条，C# IO 异常会穿出主线程命令执行，客户端收不到任何结果

> 定位以逐字引文为准；行号是 2026-11-23 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-003
- 攻击面：无中生有（把「失败可见」写成三条穷举，漏掉真正会静默的一类）
- 严重度提示：misleading
- 工件：`design.md` / `specs/editor-asset-browser/spec.md`
- 一句话：`Directory.EnumerateFiles(root, AllDirectories)` 与取文件元数据会抛 IO 类异常；`ExecuteCommand` 只捕 `ObjectDisposedException` 与 `IWindowException`，IO 异常会穿到 `Host.Tick` 外层 catch，于是这条请求既没有 `result` 也没有 `event`——从客户端看就是「发出去没回音」。

## 二、工件原文

`design.md:51`（节选）：

> 命令执行（主线程）内：`GetResourceRootPath()` 取根 → `Directory.EnumerateFiles(root, AllDirectories)` → 每文件 `FileInfo`（大小/修改时间）+ 扩展名映射种类 + `HasResource(相对路径)` 定 registered → 经默认提供者成条目。监听线程绝不碰这些。**门面未绑/根为空字符串/目录不存在 → 显式错误**（不静默空列表冒充成功；目录存在但无文件 = 合法空态）。

`specs/editor-asset-browser/spec.md:52`：

> 文件枚举与门面调用 MUST 在引擎主线程的命令执行内；监听线程 MUST 只做网络 I/O 与形状校验，MUST NOT 调引擎绑定 API。门面未绑定 / 根路径非法 / 根目录不存在 MUST 显式报错（错误码 + 文本点名原因），MUST NOT 静默返回空列表冒充成功。

`tasks.md:17`（2.3，节选）：

> 门面未绑/根非法/目录不存在 → 显式错误（不静默空列表）；目录存在无文件 → ok 空数组。

三处都只列了「门面未绑 / 根为空字符串 / 根目录不存在」这一组固定状态，没有一条覆盖「枚举本身抛异常」。

`Scripting/Managed/Host.cs:306-308`：


`Scripting/Managed/Host.cs:364-368`（Tick 的外层 catch，逐字）：

```csharp
            catch (Exception ex)
            {
                s_lastError = "Tick 抛异常：" + ex.GetType().Name + ": " + ex.Message;
                LogLine(s_lastError); // 文本必须回到引警侧，否则只剩一个光秃秃的错误码
```

组合后果：枚举抛异常 → `ExecuteCommand` 不接 → `DrainInbound` 不接 → `EditorService.Tick` 不接 → `Host.Tick` 外层 catch 把异常吞成一行日志并返回错误码。这条 `requestId` 的 `result` 永远不会 `Enqueue`，客户端侧没有任何可判断的失败信号（只能等超时）。这不是「空列表冒充成功」，而是「无声挂起」，比规范禁止的那种更隐蔽。

## 六、关联观察（不计入本条主张，供主循环处置时一并看）

同一要求的前一行把空目录写成两条互斥的 MUST：

`specs/editor-asset-browser/spec.md:5`：

> 目录存在但无文件 MUST 显示空态；**MUST NOT 把空目录或门面失败冒充成正常列表**。

`specs/editor-asset-browser/spec.md:17-20`（同一份规范的空根场景）：

> - **WHEN** 资源根存在但无文件，发 list-assets
> - **THEN** 返回 MUST 为空数组（ok=true）；前端 MUST 显示空态文案，MUST NOT 报错

若把「ok=true 的空数组」理解为「正常列表」，两处直接冲突；若把「空态」理解为非列表的特殊界面，两处才能同时成立——规范没有把这层区分写出来。这是措辞级但会影响实现判据的歧义，按「一条主张一个文件」的规矩不并入本条。

## 七、边界

- 核了：`ExecuteCommand` 的完整 catch 列表（全文检索 `catch` 只找到 `ObjectDisposedException` 与 `IWindowException` 两处）、`Host.Tick` 外层 catch、design/spec/tasks 三处失败面原文、本机 `Directory.EnumerateFiles` 的异常类型。
- 没核：没有实际构造「访问被拒的子目录」去跑（只读约束下不能改 ACL、也不能跑编辑器）；「异常穿出后客户端挂起」是由代码路径推出的，最终以主循环实跑为准。
- 没把「文件在枚举与 FileInfo 之间被删」写成必然：本机 `FileInfo.Length` 对不存在文件没有抛（实测返回空值），所以这一条只作为「耗时窗口」提醒，不作为主张依据。
