## 三、现有 README 对拍脚本只比名字，不比值

`Tools/check_csharp_host_readme.py` 的探针开关判据：

```text
check_csharp_host_readme.py:217: used_env = parse_env_names(read(HOST_CS)) | parse_env_names(read(USER_SCRIPT_CS))
check_csharp_host_readme.py:277: missing = sorted(name for name in used_env if name not in readme_env)
check_csharp_host_readme.py:279: problems.append("README 的环境变量表缺这些开关：" + "、".join(missing))
```

`CASCADED_EDITOR_SELFTEST` 这个名字已经出现在 README 表里（现有值是 `no-runtime`），所以即使新增 `no-facade` 而 README 一字不改，`used_env - readme_env` 仍为空，脚本照样绿。这就是「看起来有对拍、实际只按名字」的静默漏登记。

## 四、PROTOCOL.md §5 的对外映射也应有一行

`PROTOCOL.md` §5 是「面板控件与命令一一对应」的对外约定（现有的 `set-title` / `set-size` / `undo` 都在里面）。新增资产区后，`list-assets` / `assets-changed` 没有对应的 §5 行；1.1 只要求加命令/事件/类型/错误码，5.2 又把 PROTOCOL.md 写成「已在 1.1 更新」，这条 UI 映射就落空了。它不是阻塞项（协议本体仍在 1.1 定义），但属于「新增能力同步对外文档」的漏项。

## 五、已核不立（同批影响面，未形成主张的理由）

- **welcome 是否要带 assets**：D5/D6 明确「客户端连接后拉 list-assets；刷新重拉」，协议没有要求 welcome 携带资产；不构成缺陷。
- **EventMessage.objectId 改可选对既有事件的影响**：`object-changed` / `object-invalidated` 的 C# 构造（`EditorProtocol.BuildChangedEvent` / `BuildInvalidatedEvent`）仍显式带 objectId；TS 侧 `handleEvent` 对 `object-invalidated` 分支不受可选性影响。需要新增 `assets-changed` 分支是 3.1 已写的事，不另立主张。
- **`list-assets` 非对象作用域撞既有形状校验**：`EditorProtocol.IsObjectScoped` 只认四命令，`s_knownCommands` 加一行后 `list-assets` 无 objectId 合法；`args` 只在 set-title/set-size 分支校验。当前代码没有会拒绝 list-assets 的结构。
- **`check_binding_baseline` / 既有绑定产物**：本批改的是手写 `Host.cs` / `EditorService.cs` / `EditorProtocol.cs` / `AssetDisplay.cs` 与前端，不碰 `Tools/CodeGen/` 输入与 `CA_BIND` 头；生成产物目录不变，基线的 221 条对账不受影响。真正的失败面在「新增第 23 用例与既有编辑器用例同进程」上（见 影响-001）。
- **`HasResource` 的路径键**：`cacore::PathHash` 的三个构造函数都经 `cafs::path` 的 `generic_string()` 生成键（`CACore/header/HashKeys.h:173/177/182`），所以键是经路径库规范化的字符串；只要实现按 design D2 传「相对资源根的正斜杠路径」，和注册时使用的相对路径就能对上。本轮没有把「路径分隔符不一致」立为缺陷：`cafs::path` 在 Windows 上对反斜杠的具体归一行为我没有实测，不把未测结论写成主张。
- **空目录 / 根非法 / IO 异常 / 门面未绑四种语义**：工件已区分「空目录 = ok 空数组」与其余 E_ASSET_ROOT（spec 要求 1、4.1 步骤）；本轮没有发现它们再次混淆。真正的漏项是「门面异常」这一层（见 影响-002）。
- **根为空字符串 / 根非法（风险，未立主张）**：tasks 2.3 的捕获清单只有 `DirectoryNotFoundException/UnauthorizedAccessException/IOException`，没有写「枚举前先对 root 做空串 / `Directory.Exists` 检查」。.NET 的 `Directory.EnumerateFiles("")` 抛的是 `ArgumentException` 而不是这三类（我没有在本机跑 .NET 探针，故不把这条写成 blocking 主张）；实现时若只靠 catch，空根会穿到 Host.Tick，和 影响-002 是同一类静默挂起。建议 tasks 2.3 明确「先判空串 / `Directory.Exists` 再枚举」，并把空串写进 4.1 的根非法用例。
