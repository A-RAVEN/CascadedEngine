## 一、三份工件都要求 E_ASSET_ROOT

`design.md` D2 原文（逐字）：

> 错误码：新增 **`E_ASSET_ROOT`**（资产根不可用：门面未绑/根非法/目录不存在/枚举 IO 错误），不用 E_INVALID_ARG 兜底（其 PROTOCOL.md 触发定义是 set-size 参数，语义不合）。**这修改了 editor-window-panel 的封闭错误码枚举**（六→七）——故本批 MODIFIED 该能力协议要求（命令五→六、事件二→三、错误码六→七），不是「纯加法不改既有要求」。

`specs/editor-asset-browser/spec.md` 要求 2 原文（逐字）：

> 新增 MUST 仅为加法：命令 `list-assets`（非对象作用域）、事件 `assets-changed`、类型 `AssetEntry`（nodeId/path/kind/sizeBytes/modifiedUtc/registered/children）、错误码 `E_ASSET_ROOT`。……字段名/错误码逐字一致。

要求 2 场景原文（逐字）：

> **THEN** 字段名与错误码 MUST 逐字一致；协议版本 MUST 均为 1；既有五条命令形状不变；命令集 MUST 为六条、错误码 MUST 为七条（含 E_ASSET_ROOT）

`tasks.md` 1.1 原文（逐字）：

> 1.1 ……、错误码 `E_ASSET_ROOT`（资产根不可用）；协议版本保持 1；既有五条命令/六条错误码形状语义不动。**同步 MODIFIED `editor-window-panel` 协议要求**（命令五→六、事件二→三、错误码六→七，见 specs/editor-window-panel/spec.md）。验收：文档含 list-assets/assets-changed/AssetEntry/E_ASSET_ROOT 逐字定义（grep）；版本仍 1。

## 二、1.2/1.3 的镜像清单没有它

`tasks.md` 1.2 原文（逐字）：

> 1.2 镜像 `EditorWeb/src/protocol.ts`：AssetEntry 接口、CommandName 加 'list-assets'、ResultOk.value 加 assets、EventMessage 加 'assets-changed'。验收：`npm run build`（EditorWeb）过；字段名与 PROTOCOL.md 逐字一致（对照）。

`tasks.md` 1.3 原文（逐字）：

> 1.3 镜像 `EditorProtocol.cs`：s_knownCommands 加 list-assets；BuildAssetsResult / BuildAssetsChangedEvent；形状校验认 list-assets（无 objectId 合法）。验收：构建过；未知命令仍 E_BAD_MESSAGE（既有用例不红）；list-assets 无 objectId 不被拒。

两条清单都没有 `ErrorCode` / 错误码常量：1.2 列的是接口、命令名、结果值、事件名；1.3 列的是命令集、两个构建方法、形状校验。`tasks.md` 4.1 的断言清单同样只写「门面未绑/根非法显式错误」，没有点名 code。

## 三、两侧现状仍是六码，构建不会替我们抓住

`EditorWeb/src/protocol.ts` 原文（逐字）：

> ```ts
> export type ErrorCode =
>   | 'E_PROTOCOL_VERSION'
>   | 'E_UNKNOWN_OBJECT'
>   | 'E_OBJECT_INVALIDATED'
>   | 'E_INVALID_ARG'
>   | 'E_UNDO_EMPTY'
>   | 'E_BAD_MESSAGE';
> ```

`EditorProtocol.cs` 原文（逐字）：

> ```cs
> internal const string ErrorProtocolVersion = "E_PROTOCOL_VERSION";
> internal const string ErrorUnknownObject = "E_UNKNOWN_OBJECT";
> internal const string ErrorObjectInvalidated = "E_OBJECT_INVALIDATED";
> internal const string ErrorInvalidArg = "E_INVALID_ARG";
> internal const string ErrorUndoEmpty = "E_UNDO_EMPTY";
> internal const string ErrorBadMessage = "E_BAD_MESSAGE";
> ```

两侧 `E_ASSET_ROOT` 命中数：

```text
PS> Select-String -Path 'EditorWeb/src/protocol.ts','Scripting/Managed/Editor/EditorProtocol.cs' -Pattern 'E_ASSET_ROOT'
（无输出，0 命中）
```

`BuildError(int requestId, string code, string message)` 收的是 `string`，所以即使 C# 侧不加常量，代码也能编译；TypeScript 的 `ResultError.error.code` 是 `ErrorCode | string`，不加联合成员也不会编译失败。构建过 ≠ 三处错误码一致。

## 四、结构校验不会发现

```text
PS> openspec validate editor-asset-browser --strict
Change 'editor-asset-browser' is valid
```

`openspec validate` 校验 change 结构；它不会把 `tasks.md` 1.2/1.3 的省略当作错误，也不会替我们跑 4.1 的 E_ASSET_ROOT 断言。

## 五、结论与改法

错误码已经在 design、spec、tasks 1.1 与 `editor-window-panel` 增量里定为 `E_ASSET_ROOT`，但两侧镜像任务没有把它列进要改的项，4.1 也没有断言它。照字面执行 1.2/1.3，会留下「PROTOCOL.md 七码 / protocol.ts 六码 / EditorProtocol.cs 六码」的三处不一致，而「错误码逐字一致」这条 spec 判据没有任何任务能变红。

改法：tasks 1.2 明确 `ErrorCode` 加 `'E_ASSET_ROOT'`；tasks 1.3 明确加 `ErrorAssetRoot` 常量（或错误码表加一行）；tasks 4.1 增加断言「门面未绑/根非法/目录不存在返回的 code 必须是 E_ASSET_ROOT」，并给红态读数。
