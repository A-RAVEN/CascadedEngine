# 证据 002：`registered` 只覆盖 false，修改时间 / nodeId / children 不在逐条一致里

对应主张：`主张-验收-002.json`（severity = blocking）

审查对象：`tasks.md` 4.1；`specs/editor-asset-browser/spec.md` 场景「列表与真实文件逐条一致」与需求正文。

审查快照：`tasks.md` `82A8E1D6703946E2…`、`spec.md` `83E0F933550EFAF0…`（SHA-256 前 16 位；2026-11-23 22:29:58–22:30:12 写入）。

## 一、`registered` 只有 false 分支

任务原文（`tasks.md:26`）：

> - [ ] 4.1 tester 第 23 用例 `TestEditorAssetBrowser`（Main.cpp + --list 登记）：预置已知文件到临时资源根并设到 ResourceManagingSystem → 起编辑器服务 → WebSocket 发 list-assets 断言条目与真实文件逐条一致（路径/大小/种类/registered，期望写死）→ 新增文件刷新断言 +1 + assets-changed → 空根空态 → 根非法显式错误（SetResourceRootPath 设非法路径）→ 门面未绑 E_ASSET_ROOT（CASCADED_EDITOR_SELFTEST=no-facade 构造）→ IO 异常 E_ASSET_ROOT 不挂起（根指向不存在目录）。验收：--list 23 行含 TestEditorAssetBrowser；两后端 --headless 该用例过；失败面各自能红（evidence/4.1-*.txt）。

“预置已知文件到临时资源根并设到 ResourceManagingSystem”在现有测试里的同义写法是设根路径，不是注册资源。上一批 `TestCSharpAssets` 就是先设根、再由 C# 探针注册：

```text
PS> Select-String -Path 'Test/GPUBackendTester/Main.cpp' -Pattern 'SetResourceRootPath\(root.generic_string\(\)\)'
Main.cpp:7473: ctx.pResourceManagingSystem->SetResourceRootPath(root.generic_string());
```

4.1 没有要求 `RegisterFactory` + `CreateResource`。临时根下的文件对 `HasResource` 全是 false：

```text
PS> Select-String -Path 'GeneralResources/header/CAResource/ResourceManagingSystem.h' -Pattern 'HasResource'
ResourceManagingSystem.h:43: virtual bool HasResource(castl::string const& path) const = 0;
```

全部期望写死为 false 时，一个根本不调用 `HasResource`、永远返回 false 的实现也能全绿。测试进程里其实可以造出 true：

```text
PS> Select-String -Path 'Test/GPUBackendTester/Main.cpp' -Pattern 'CppProbe'
Main.cpp:6826: ctx.pResourceManagingSystem->RegisterFactory("CppProbe", nativeFactory);
Main.cpp:6827: auto nativeResource = ctx.pResourceManagingSystem->CreateResource("CppProbe", "ReverseProbe/Cpp.res");
```

也就是说，红态不是造不出来，而是 4.1 没要求造。更糟的是 4.1 又把期望写成“registered MUST 等于 HasResource 读数”：

```text
PS> Select-String -Path 'openspec/changes/editor-asset-browser/specs/editor-asset-browser/spec.md' -Pattern 'registered MUST 等于 HasResource'
spec.md:10: - **THEN** 返回条目 MUST 与真实文件逐条一致（相对路径/大小/种类/registered）；大小 MUST 等于 FileInfo 实测字节；registered MUST 等于 HasResource 读数
```

被测输出来自 `HasResource`，期望也来自 `HasResource`，同一个源；只有至少一条 true、一条 false 同时存在，才能区分“接线正确”与“恒假”。

## 二、修改时间被需求要求、被判据漏掉

需求正文（`spec.md:5`）明确要求每行含修改时间：

> 编辑器右面板 MUST 有资产区，列出资源根（门面 `GetResourceRootPath`）下的编辑器资产文件，每行 MUST 含相对路径 / 种类（扩展名映射）/ 大小（字节）/ 修改时间 / 是否已注册（门面 `HasResource`）。

但场景与任务都只列四个字段：

```text
PS> Select-String -Path 'openspec/changes/editor-asset-browser/specs/editor-asset-browser/spec.md' -Pattern '每行 MUST 含|modifiedUtc'
spec.md:5: 编辑器右面板 MUST 有资产区，列出资源根（门面 `GetResourceRootPath`）下的编辑器资产文件，每行 MUST 含相对路径 / 种类（扩展名映射）/ 大小（字节）/ 修改时间 / 是否已注册（门面 `HasResource`）。
spec.md:24: 新增 MUST 仅为加法：命令 `list-assets`（非对象作用域）、事件 `assets-changed`、类型 `AssetEntry`（nodeId/path/kind/sizeBytes/modifiedUtc/registered/children）、错误码 `E_ASSET_ROOT`。
```

`tasks.md:26` 的“（路径/大小/种类/registered，期望写死）”也没有 `modifiedUtc`、`nodeId`、`children`。一个 `modifiedUtc` 恒为空串、`nodeId` 不等于相对路径、`children` 恒非空的实现仍能通过 4.1。2.2 的“单测”本来可以兜底 `nodeId` / `children`，但它没有可执行的落点（见证据 001）。

## 三、`assets-changed` 没有绑定到第二次枚举

设计 D5 的口径是：

> 服务端每次枚举与上次快照比对，差异则广播 assets-changed（其它客户端随之重拉）。

首次 `list-assets` 时“上次快照”为空，按字面也会出现差异并广播。若测试只断言“收到过 assets-changed”，首个枚举的事件就可能满足；任务 4.1 只写“新增文件刷新断言 +1 + assets-changed”，没有要求事件必须对应第二次枚举或新增文件摘要。

## 四、已核实能红的部分

- **刷新 +1**：现有 `EditorService.ExecuteCommand` 没有资产枚举缓存；如果新实现把首次结果缓存并复用，第二次 `list-assets` 的条目数不会 +1，4.1 能红。这个判据本身是可失败的。
- **大小**：测试写入已知字节数，期望写死，能红。
- **种类**：`.shLib` 与未知扩展名的映射是写死的，能红。
- **门面未绑 / IO 异常**：4.1 已在本轮修订中加入 `CASCADED_EDITOR_SELFTEST=no-facade` 与“根指向不存在目录”的步骤，这两个失败面现在有构造路径；不在本主张范围。
- **未知命令**：见证据 001，既有 `explode` 断言能红。

## 五、建议改法

1. 在临时根里造“一条已注册、一条未注册”：用 `RegisterFactory` + `CreateResource` 注册一个资源（可复用 `CppProbe` 或测试专用类型），再放一个不注册的文件；把 `registered` 的期望写死为 true / false，不要拿 `HasResource` 当期望。
2. 用 `std::filesystem::last_write_time` 把两条文件的修改时间设为固定 UTC 值；在 `PROTOCOL.md` 写死 `modifiedUtc` 的字符串格式，测试按固定值断言。
3. 同时断言 `nodeId == 相对路径`、`children` 为空、`.shLib` → `shader-library`、未知扩展名 → `file`。
4. `assets-changed` 绑定到第二次枚举：先消费或记录首次事件，再要求新增文件后的那次事件带新增文件摘要；不要只断言“收到过”。
