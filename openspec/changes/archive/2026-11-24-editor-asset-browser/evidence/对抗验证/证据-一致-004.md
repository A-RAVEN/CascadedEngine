## 一、要求 1 写了五列与空态

`specs/editor-asset-browser/spec.md` 要求 1 原文（逐字）：

> 编辑器右面板 MUST 有资产区，列出资源根（门面 `GetResourceRootPath`）下的编辑器资产文件，每行 MUST 含相对路径 / 种类（扩展名映射）/ 大小（字节）/ 修改时间 / 是否已注册（门面 `HasResource`）。MUST 有刷新动作重新枚举。目录存在但无文件 = 合法空态（ok=true 空数组）；门面失败 / 根非法 / 枚举 IO 错误 MUST 显式 E_ASSET_ROOT，MUST NOT 用 ok 空数组冒充成功。本批 MUST 只读，MUST NOT 提供编辑/删除/重命名/导入。

场景 3 原文（逐字）：

> **WHEN** 资源根存在但无文件，发 list-assets
> **THEN** 返回 MUST 为空数组（ok=true）；前端 MUST 显示空态文案，MUST NOT 报错

## 二、场景 1 的「逐条一致」漏了修改时间

场景 1 原文（逐字）：

> **WHEN** 资源根预置已知文件（含 .shLib 与测试资产），客户端发 list-assets
> **THEN** 返回条目 MUST 与真实文件逐条一致（相对路径/大小/种类/registered）；大小 MUST 等于 FileInfo 实测字节；registered MUST 等于 HasResource 读数

要求 1 说每行 MUST 含修改时间，场景 1 的「逐条一致」括号里只有四项：相对路径、大小、种类、registered，没有 modifiedUtc。`tasks.md` 4.1 原文照抄同一组：

> WebSocket 发 list-assets 断言条目与真实文件逐条一致（路径/大小/种类/registered，期望写死）

所以 `modifiedUtc` 只有在 design D2 的字段表里出现，没有任何验收断言它的值、格式或 UTC 语义。

## 三、空态文案没有落在任何能看 DOM 的验收里

`tasks.md` 4.1 原文（逐字）：

> ……新增文件刷新断言 +1 + assets-changed → 空根空态 → 门面未绑/根非法显式错误。验收：--list 23 行含 TestEditorAssetBrowser；两后端 --headless 该用例过；失败面各自能红（evidence/4.1-*.txt）。

4.1 是 `GPUBackendTester` 的 C++ 用例：它用 WebSocket 发命令、读 JSON；`--headless` 表示不靠可见窗口。它能断言「返回空数组」，但看不到 `EditorWeb` 的 DOM，也就不能断言「前端显示空态文案」。

`tasks.md` 4.2 原文（逐字）：

> 4.2 截图视觉验收（主循环，编辑器硬要求）：交互模式真实打开编辑器（门控 + 正确 CWD），资产区渲染预置资产；desktop-screenshot 截图 + read_image 核对资产区可见且列出预置资产行。验收：截图存 evidence/4.2-截图.png + read_image 核对记录；无截图或不符判不通过。

4.2 只预置资产、只核对「列出预置资产行」，没有空根场景。`tasks.md` 3.1 的验收原文（逐字）：

> 验收：npm run build 过；4.2 截图核对资产区渲染；既有窗口面板功能不红。

3.1 自己要求 `main.ts` 加空态显示，但验收只回到 4.2 的非空截图；空态文案缺失时，3.1、4.1、4.2 没有一条会红。

## 四、结论与改法

要求 1 的「修改时间」和「空态」都是 MUST，但：

- 修改时间：要求有、场景 1 与 4.1 都没有断言；`modifiedUtc` 的字符串格式（ISO 8601？UTC？本地时间？）也没有任何一份工件写死。
- 空态：规范说前端 MUST 显示空态文案；能看前端的只有 4.2，而 4.2 只跑非空预置资产；4.1 是 C++/headless，看不到 DOM。

建议把场景 1 的逐条一致清单补上修改时间，并在 4.1 写死一个固定样例（例如 UTC ISO 8601）与比对方式；4.2 增加空根场景的第二张截图 + `read_image` 核对空态文案，或把空态写成 4.1 能观察到的前端检查。若产品上决定不要空态或不要修改时间，就改要求 1 并在 proposal 说明，不能只把验收放宽。
