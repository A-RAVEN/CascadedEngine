## 一、规范场景要求三个具体属性

`specs/editor-asset-browser/spec.md` 要求 3 原文（逐字）：

> MUST 有 `IDisplayProvider`（C# 编辑器侧）+ 按种类注册表 + 默认提供者（一文件一条目，children 空）。接口输入 MUST 是资产标识（资产中心），输出 MUST 是显示条目树——v1 退化文件=资产 1:1，为 v2 程序集展开/衍生物归组留口。显示逻辑 MUST NOT 加到 `IResource` 核心反向接口上。

同要求场景原文（逐字）：

> **WHEN** 经默认提供者描述一个文件资产
> **THEN** MUST 产出恰好一个条目，children MUST 为空，nodeId MUST 等于相对路径

## 二、任务写「单测」，但没有测试入口

`tasks.md` 2.2 原文（逐字）：

> 2.2 新增 `Scripting/Managed/Editor/AssetDisplay.cs`：IDisplayProvider（资产中心 Describe→条目树）+ 按种类注册表 + DefaultFileDisplayProvider（一文件一条目 children 空）；种类映射 .shLib/.tex/.mesh/.res，未知落 file。验收：构建过；默认提供者单测断言一文件一条目、nodeId=相对路径、children 空；IResource.h/门面头 grep 无改动。

这里只有「默认提供者单测」六个字：没有测试文件、没有测试函数名、没有运行命令。项目当前测试层是三层，且都是 C++ 或 Python：

`docs/testing.md` 原文（逐字）：

> 三层：① CoreTests ② GPUBackendTester ③ `Tools/check_*.py` + `Tools/CodeGen/check_*.py`。

`Test/CoreTests/` 目录下是 C++ 文件（`ResourceBatchTest.cpp` / `BindingsLayoutTest.cpp` 等），没有 C# 测试项目；`AssetDisplay.cs` 本身还不存在（`Scripting/Managed/Editor/` 现有 `EditorProtocol.cs` / `EditorSceneView.cs` / `EditorWindow.cs` / `EditorService.cs` / `PROTOCOL.md`）。

## 三、4.1 的断言清单不含 children/nodeId

`tasks.md` 4.1 原文（逐字）：

> 预置已知文件到临时资源根并设到 ResourceManagingSystem → 起编辑器服务 → WebSocket 发 list-assets 断言条目与真实文件逐条一致（路径/大小/种类/registered，期望写死）→ 新增文件刷新断言 +1 + assets-changed → 空根空态 → 门面未绑/根非法显式错误。

清单里只有路径、大小、种类、registered；没有 `children` 必须为空，也没有 `nodeId` 必须等于相对路径。默认提供者若返回非空 children 或错误 nodeId，4.1 的「条目与真实文件逐条一致」仍可能通过（它比的是四个字段），spec 场景 3 不会红。

## 四、结论与改法

spec 要求 3 的核心场景（一文件一条目、children 空、nodeId=相对路径）目前只在 tasks 2.2 的验收句里以「单测」出现，但项目没有 C# 单测层，任务也没点名入口；4.1 的端到端断言又不覆盖这三个属性。结果是这条 MUST 没有任何可执行、可失败的验收。

改法二选一：① 在 4.1 增加逐条断言（`children` 必须为空数组、`nodeId` 必须等于预置文件的相对路径），并给红态（默认提供者返回 `children=[自身]` 或 nodeId 用绝对路径）；② 若确实要单测，点名新增的 C# 测试入口、文件与运行命令，并把它接进现有测试层。不能只写「单测」。
