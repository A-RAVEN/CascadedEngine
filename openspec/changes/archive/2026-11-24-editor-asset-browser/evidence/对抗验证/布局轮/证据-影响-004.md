## 3. 像素中心判据对高度不敏感

命令与命中：

```powershell
Select-String -Path 'Test/GPUBackendTester/Main.cpp' -Pattern 'captureHeight / 2|r == 255 && g == 0' | Select-Object LineNumber,Line
```

```text
4604  (static_cast<size_t>(captureHeight / 2) * static_cast<size_t>(captureWidth) +
4615  return r == 255 && g == 0 && b == 0 && a == 255;
```

代码原文 `Main.cpp:4586-4615`（节选）：

```cpp
		int captureWidth = 0;
		int captureHeight = 0;
		if (!ParseSize(readings.Get("capture"), captureWidth, captureHeight) || captureWidth <= 0 ||
			captureHeight <= 0)
		...
		const size_t index =
			(static_cast<size_t>(captureHeight / 2) * static_cast<size_t>(captureWidth) +
			 static_cast<size_t>(captureWidth / 2)) * 4u;
		...
		// 判据（工件修订：与既有探针一致的精确像素，不放宽）：离屏捕获中心必须精确是三角形红。
		return r == 255 && g == 0 && b == 0 && a == 255;
```

采样点始终是**捕获目标自己的中心**，而三角形也画在捕获目标中心；捕获目标是 720 高还是 520 高，中心都是红的。所以「像素读回中心仍精确 (255,0,0,255)」只能证明「捕获目标存在且画了三角形」，**不能证明捕获目标按新视口高重建**。任务 3.3 把它列为核心验收之一，属于把不敏感的判据当作敏感判据。

## 4. GetWindowCount 不受影响（补充核对）

`Main.cpp:4780` 的断言：

```cpp
	if (countAfterStart != baselineCount + 1)
```

引擎的 `GetWindowCount` 只统计 `IWindowSystem` 创建的窗口；第二个 WebView2 控制器是子 HWND，不经 `NewWindow`，所以这条断言在三分区后仍为 +1，不需要改。任务 3.3 没提它是合理的——问题在于它同时也没提上面 2.1-2.5 里真正会破的几条。

## 5. 建议的改法

任务 3.3 应逐条点名（改前原文 → 改后期望）：

- 4802-4803：加 `viewportRect.y == 0`、`dockRect.y == viewportRect.h`、`dockRect.w == clientWidth`、`viewportRect.h == clientHeight − DockHeight`、`panelRect.h == viewportRect.h`；解析 `dock=`。
- 4977：`viewportRect.h` 期望改 `640 − DockHeight`；`panelRect.y == 0`、`panelRect.h == 640 − DockHeight`。
- 5186：`capture` 期望改 `580x(560 − DockHeight)`。
- 4.1 就绪判据：明确 `controller`/`nav` 是第一控制器还是改成 `dockController`/`dockNav`，并同步 4.1 与 5.1 的验收文字。
- 像素判据保留，但注明它不证明高度；高度证据放在 `capture` 尺寸与 M6 批级/绘制级矩形（`Main.cpp:4875-4888`）上。
- 在 tasks 里写死 `DockHeight` 的默认数字，避免测试从读数反推期望（见 `证据-影响-002.md` 第 5 节）。
