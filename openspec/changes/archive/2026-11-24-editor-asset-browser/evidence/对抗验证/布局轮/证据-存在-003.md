# 证据-存在-003：PrintWindow 是真实 API，但工件点名的截图手段里没有 PrintWindow 实现

对应主张：`主张-存在-003.json`（severity=misleading）
攻击面：真实存在性
审查对象：`openspec/changes/editor-asset-browser/design.md:85`、`tasks.md:29`、`tasks.md:81`、`specs/editor-asset-browser/spec.md:81`；本机截图脚本 `C:/Users/76956/.dsh/skills/desktop-screenshot/capture.ps1`；Windows SDK 头文件 `C:/Program Files (x86)/Windows Kits/10/Include/10.0.26100.0/um/WinUser.h`；微软官方文档
审查快照：design.md `23F83364A67108FC`（00:10:13）、tasks.md `18F17F295C208209`（00:12:18）、specs/editor-asset-browser/spec.md `65F2330C8240EAE0`（00:10:30）

判定口径：PrintWindow 本身是真实 Win32 API（这一条成立）；缺陷是工件把「用 PrintWindow 按 HWND 抓窗」写成视觉验收判据，却没有任何已存在的脚本/命令承载它——被点名的 `desktop-screenshot` 技能只做屏幕像素拷贝，没有 HWND 参数、没有 PrintWindow 调用。API 存在 ≠ 工件点名的工具能做这件事。

## 一、PrintWindow 是真实 API（先确认符号存在）

Windows SDK 10.0.26100.0 的 `WinUser.h`：

命令：

```powershell
$h = 'C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um\WinUser.h'
Select-String -Path $h -Pattern 'PrintWindow|PW_RENDERFULLCONTENT'
```

真实输出：

```text
4610:#define PW_RENDERFULLCONTENT    0x00000002
4617:PrintWindow(
```

声明上下文（`Get-Content $h | Select-Object -Skip 4612 -First 8`）：

```text
WINUSERAPI
BOOL
WINAPI
PrintWindow(
    _In_ HWND hwnd,
    _In_ HDC hdcBlt,
    _In_ UINT nFlags);
```

微软官方文档（2026-11-24 抓取，HTTP 200）：<https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow>

```text
The PrintWindow function copies a visual window into the specified device context (DC), typically a printer DC.
BOOL PrintWindow(HWND hwnd, HDC hdcBlt, UINT nFlags);
Header: winuser.h (include Windows.h)
Library: User32.lib
DLL: User32.dll
```

结论：`PrintWindow` 是 user32 的真实导出 API，工件写这个名字本身没有错；同时注意该文档页的 `nFlags` 表只列了 `PW_CLIENTONLY`，而截图 WebView2 这类合成内容通常需要 `PW_RENDERFULLCONTENT`（本机头文件 `WinUser.h:4610` 有定义，值 `0x2`）。

## 二、工件点名的截图手段没有 PrintWindow（缺口在这里）

工件原文：

- `design.md:85`：「…desktop-screenshot 截图 + 主循环 read_image 核对…用 PrintWindow 按 HWND 抓窗（被挡也能抓，不动前景），不置前/不最小化/不移动用户窗口。无截图无条件不通过。」
- `tasks.md:29`（4.2）：「…**用 PrintWindow 按 HWND 抓窗（被挡也能抓，MUST NOT 置前/最小化/移动用户窗口，AGENTS §2 2026-11-24 用户明令禁止前置窗口）** + read_image 核对底部 dock 可见且列出预期行…」
- `specs/editor-asset-browser/spec.md:81`：「截图 MUST 用 PrintWindow 按 HWND 抓窗、MUST NOT 置前/最小化/移动用户窗口（AGENTS §2）；缺截图或画面不符 MUST 判不通过」

被点名的工具是 `desktop-screenshot` 技能。它的脚本 `C:/Users/76956/.dsh/skills/desktop-screenshot/capture.ps1`：

命令：

```powershell
$p = "C:\Users\76956\.dsh\skills\desktop-screenshot\capture.ps1"
Select-String -Path $p -Pattern 'PrintWindow|CopyFromScreen'
Select-String -Path $p -Pattern '^param\(|Mode = |Window = |OutDir'
```

真实输出：

```text
（PrintWindow 命中 0 条）
126:$g.CopyFromScreen($rect.Left, $rect.Top, 0, 0, $bmp.Size)
19:param(
20:[ValidateSet('full', 'window', 'title', 'region')][string]$Mode = 'full',
21:[string]$Window = '',
27:[string]$OutDir = ''
```

脚本注释里声明的四种模式（第 10-13 行）：

```text
full    - the whole virtual desktop (all monitors)
window  - the current foreground window
title   - the first visible window whose title contains -Window
region  - the rectangle given by -X -Y -W -H (virtual-screen coordinates)
```

关键事实：

1. 参数表没有 `-Hwnd`，只有 `full/window/title/region` 四种模式。
2. `window` 模式取的是**前台窗口**（第 78 行附近 `GetForegroundWindow`），这与 4.2「MUST NOT 置前」直接冲突；`title` 模式虽能按标题找窗，但抓图仍走第 126 行的 `CopyFromScreen`（屏幕像素），窗口被其它窗挡住时抓到的是上层窗口。
3. 全文件 `PrintWindow`/`GetWindowDC`/`BitBlt` 零命中——不存在按 HWND 渲染窗内容的实现。

工件里也没有点名任何**已存在**的 PrintWindow 脚本或命令；tasks 的 3.x/4.2/5.x 没有一条要求创建这样一个脚本。执行者要么临时写脚本（未进工件、未进验收），要么违反「MUST NOT 置前/移动窗口」去用 `capture.ps1`，两者都不在工件允许的路径里。

## 三、判定

- 符号 `PrintWindow` 真实存在（user32，WinUser.h 4617；微软文档 User32.dll）——这一项通过，不是「符号不存在」。
- 但工件把「用 PrintWindow 按 HWND 抓窗」写成 4.2 的硬验收判据，同时把 `desktop-screenshot` 点名成截图手段；该脚本只有 `CopyFromScreen`，抓不到被遮挡的窗，且 `window` 模式依赖前台窗口。**判据的执行手段在工件里不存在**。
- 结论：**misleading（不阻断 apply；4.2 截图验收按现有工件无法直接执行，需要先补一个 PrintWindow 抓窗脚本/命令并验证 WebView2 内容抓得到）**。
