## 4. 第二控制器用的是托管 NuGet 接口，不是新的原生绑定

`Scripting/Managed/Scripting.Managed.csproj:31`：

```xml
    <PackageReference Include="Microsoft.Web.WebView2" Version="1.0.4370.26" />
```

既有唯一控制器的创建与 Bounds 设置都走这个包：

```csharp
m_ControllerTask = m_EnvironmentTask.Result.CreateCoreWebView2ControllerAsync(Hwnd);
...
m_Controller.Bounds = new System.Drawing.Rectangle(ViewportWidth, 0, PanelWidth, ClientHeight);
```

（`Scripting/Managed/Editor/EditorWindow.cs:176`、`:202`）

第二个控制器重复同样的 `CreateCoreWebView2ControllerAsync` + `Bounds`（只是 Bounds 换成 dock 矩形），不需要扩展 `IWindow`/`IWindowSystem` 绑定面，也不需要改 CodeGen 接入清单。因此「第二控制器/布局均 C# 侧，不碰生成器/原生接口」在当前工件描述下成立。

## 5. 保留意见

- 任务 3.2 把第二控制器创建写在 `EditorService.cs`，但 `EditorService` 目前没有 `Microsoft.Web.WebView2.Core` 的 `using`（`EditorService.cs:12-23`），环境任务 `m_EnvironmentTask` 是 `EditorWindow` 的私有字段（`EditorWindow.cs:37`）。这不影响绑定产物，但会影响第二控制器的失败处置与关闭（见 `证据-影响-001.md`）。
- 若实现者为了第二个控制器新建第二个 `CoreWebView2Environment.CreateAsync`，仍在托管侧，不改变本结论。

## 6. 结论

⑤ 的声称在现有工件与代码结构下**仍真**，本面未发现需要落主张的「绑定产物会变」问题；不做修订要求。
