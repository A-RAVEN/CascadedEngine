`panel` 的高度与 `viewport` 的高度都直接取 `s_window.ClientHeight`，没有 `DockHeight`。任务 3.2/design 第 77 行只要求「加 dock 矩形」，没有要求把这两个高度改成 `ClientHeight−DockHeight`。按字面实现，读数行会是「viewport 全高 + dock 矩形」，三个矩形互相重叠，不满足 spec 场景第 27 行的「三者铺满客户区」；而且既有 `TestEditorWindowPanel` 的铺满判据正好用的是 `viewportRect.h != clientHeight || panelRect.h != clientHeight`（`Main.cpp:4802-4803`），会继续绿。

## 4. set-size 高度判据与新视口高冲突

代码原文 `EditorService.cs:718-733`：

```csharp
                    case "set-size":
                    {
                        if (command.Width <= 0 || command.Height <= 0)
                        {
                            Enqueue(client, EditorProtocol.BuildError(command.RequestId,
                                EditorProtocol.ErrorInvalidArg, "set-size 的宽高必须 > 0"));
                            return;
                        }
                        // B2（工件修订）：宽度必须**大于面板宽**，否则左侧视口宽 ≤ 0（分栏没有渲染区）。
                        if (s_window != null && command.Width <= s_window.PanelWidth)
                        {
                            Enqueue(client, EditorProtocol.BuildError(command.RequestId,
                                EditorProtocol.ErrorInvalidArg, "set-size 的宽度必须大于面板宽 " +
                                                                s_window.PanelWidth + "（否则视口宽 ≤ 0）"));
                            return;
                        }
```

宽度已经按「视口宽 ≤ 0」加了一条判据，高度没有对应的「视口高 ≤ 0」判据；spec 第 4 行仍写「高 MUST >0」，也就是说 `height=100`（小于 dock 高）在协议层合法。它会一路走到 `SetSizeCore` → `SyncLayout` → `s_scene.Resize(viewportWidth, 100−DockHeight)`；`EditorSceneView.Build` 的入口判据是：

```csharp
            if (viewportWidth <= 0 || viewportHeight <= 0)
            {
                LastError = "视口尺寸非法：" + viewportWidth + "x" + viewportHeight;
                return false;
            }
```

（`Scripting/Managed/Editor/EditorSceneView.cs:85-89`）

于是 `SyncLayout` 的第 597-600 行走 `Disable("scene view 改尺寸重建失败：…")`，编辑器被禁用。规范说这条 set-size 合法，实际却把编辑器关掉——工件没有更新高度判据，也没有写「窗口被外部缩到不大于 dock 高」的处置。

命令：

三处都只出现「默认值与范围 1..客户区高−1」「默认值+范围 1..客户区高−1」「dock 高默认值 CASCADED_EDITOR_DOCK_HEIGHT 可配，范围 1..客户区高−1」，没有任何数字。任务 3.2 又要求把默认值登记进 `CSharpHost/README.md` 配置表，任务 3.3 要求把「视口高 = ClientHeight−DockHeight」「capture 尺寸」「改尺寸后的 680/320/640」等期望写死——没有默认数字，测试只能从环境变量或被测读数反推期望，等于让被测物自己定义判据。

## 6. 建议的能失败判据

- 启动后（未做任何 SetWindowSize）就断言读数 `viewport.h == ClientHeight−DockHeight`、`capture == (ViewportWidth)x(ClientHeight−DockHeight)`，并断言窗口 pass 的批级/绘制级矩形高度等于该值（`Main.cpp:4875-4888` 的 M6 正控已有形状）。
- 把 `set-size height <= DockHeight` 写成 `E_INVALID_ARG` 红态用例（期望目标尺寸不变、零原生调用、编辑器不被禁用），并同步修改 spec 第 4 行。
- 在 design/tasks 里写死 dock 默认数字，3.3 的期望用该数字，不从读数反推。
