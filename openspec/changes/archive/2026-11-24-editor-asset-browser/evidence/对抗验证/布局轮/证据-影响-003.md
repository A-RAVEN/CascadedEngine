
命中（逐字）：

```text
224  " HttpStatus=" + m_NavigationHttpStatus + "（HTTP 错误页也算导航成功）");
292  m_NavigationOk = args.IsSuccess || args.HttpStatusCode >= 100;
```

代码原文 `EditorWindow.cs:289-296`：

```csharp
            // 判据：**收到 HTTP 响应**就说明导航到达了本机服务（哪怕 404/503 的说明错误页）——WebView2 对
            // HTTP 错误页会给出 IsSuccess=false + WebErrorStatus=Unknown，但 HttpStatusCode 是真实状态码；
            // 只有 HttpStatusCode==0（无响应/连接失败/被拦截）才是真网络故障，按贴附失败禁用编辑器。
            m_NavigationOk = args.IsSuccess || args.HttpStatusCode >= 100;
```

design 第 78 行要求第二控制器失败「与既有控制器同处置」。若第二控制器复用这套判据，`assets.html` 返回 404 也会被判为导航成功；`EditorService` 只会在 `s_window.Error` 非空时 `Disable`（`EditorService.cs:460-464`），而这里 `Error` 保持空，编辑器继续 running。

## 5. 波及与静默路径

1. **部分构建**：`npm run build` 产出 index.html 但漏了 assets.html（多页面入口没配、文件被删、拷贝漏项），`GET /assets.html` → 404 纯文本「找不到资源」，dock 显示这五个字；编辑器不 Disable，不写日志，两个编辑器用例全绿。这就是规范禁止的「静默 404」。
2. **整目录缺失**：index.html 不存在时，任何路径（包括 `/assets.html`）都会命中第 1265 行的 503 说明页。场景 `WHEN bin/editor-web/ 无面板或 dock 资源时请求对应页` 的字面条件在「整个目录都缺」时被 index 门短路，**测不到 assets.html 单独缺失**；场景可以在不写一行 dock 资源判据的情况下通过。
3. **验收缺口**：任务 3.2 的验收没有资源缺失项；4.2 的截图验收只在正常构建下看 dock 行，不会构造 assets.html 缺失；5.x 也没有对应红态。

## 6. 建议的能失败判据

- 静态资源按页判：请求 `/assets.html` 时检查 `assets.html` 是否存在，缺则返回说明「资产浏览器页面未构建（bin/editor-web/assets.html 不存在）」的 503 HTML 错误页并写一次日志；index.html 缺失的错误页保留。
- 任务 3.2 加一条可执行验收：临时移走 `bin/editor-web/assets.html`（保留 `index.html`），`GET /assets.html` 必须是说明原因的错误页（503 + 正文含 `assets.html`），MUST NOT 是 `text/plain` 的 404「找不到资源」。
- 第二控制器的导航判据不能复用「HttpStatus>=100 即成功」：要么只在 200 时算成功，要么把 dock 的 `navHttp` 单独写进读数并断言 200；失败时走 `Disable`。
