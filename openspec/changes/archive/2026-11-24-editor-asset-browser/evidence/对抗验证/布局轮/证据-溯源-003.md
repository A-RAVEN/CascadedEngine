# 证据-溯源-003：PrintWindow「被挡也能抓」没有依据

## 一、工件把它写成了事实

命令：

```powershell
Select-String -Path 'openspec/changes/editor-asset-browser/*.md','openspec/changes/editor-asset-browser/specs/*/*.md' -Pattern '被挡也能抓'
```

真实输出（逐字）：

```text
design.md:85:…用 PrintWindow 按 HWND 抓窗（被挡也能抓，不动前景），不置前/不最小化/不移动用户窗口。
tasks.md:29:…**用 PrintWindow 按 HWND 抓窗（被挡也能抓，MUST NOT 置前/最小化/移动用户窗口，AGENTS §2 2026-11-24 用户明令禁止前置窗口）**…
tasks.md:82:…改后：tasks 4.2/design D7/spec 要求 5 视觉场景改 PrintWindow 按 HWND 抓窗（被挡也能抓，不动前景），MUST NOT 置前/最小化/移动用户窗口；已记 AGENTS §2。依据：用户当场明令。
```

「被挡也能抓」是断言，不是任务；它出现在 3 处，无一处附实测。

## 二、微软官方函数页怎么说（联网核）

抓取 `https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow`（HTTP 200，2024-02-22 更新），逐字：

```text
nFlags — The drawing options. It can be one of the following values.
| PW_CLIENTONLY | Only the client area of the window is copied to hdcBlt. ... |
Remarks:
The application that owns the window referenced by hWnd processes the PrintWindow call and renders the image
in the device context that is referenced by hdcBlt. The application receives a WM_PRINT message or, if the
PW_PRINTCLIENT flag is specified, a WM_PRINTCLIENT message.
```

判据：① 官方页面列出的绘制选项只有 `PW_CLIENTONLY`，**没有** `PW_RENDERFULLCONTENT`；② PrintWindow 的画法是把 `WM_PRINT`/`WM_PRINTCLIENT` 发给目标窗口自己，由它往 DC 里画。也就是说，能不能抓到取决于目标窗口是否处理这条绘制消息，而不是取决于「窗口有没有被挡住」。

本地 SDK 头文件里确有该宏，但它在头里、不在官方函数页的语义表里：

```powershell
Select-String -Path 'C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um\WinUser.h' -Pattern 'PW_RENDERFULLCONTENT|PW_CLIENTONLY'
```

```text
#define PW_CLIENTONLY           0x00000001
#define PW_RENDERFULLCONTENT    0x00000002
```

## 三、要抓的东西是什么

本批的 dock 是**第二个 WebView2 控制器**（design D9:75、spec 壳要求），其像素由 WebView2 自己的合成器（DirectComposition 路径）产出，不经父窗口的 `WM_PRINT` 处理；场景视口是引擎的硬件 flip swapchain。两者都不在「父窗口收到 WM_PRINT 后自绘」这条路上。

项目自己的对外文档已经记录过本机同类抓取失败：

```powershell
Select-String -Path 'CSharpHost/README.md' -Pattern '抓不到硬件 flip 内容'
```

```text
CSharpHost/README.md:129:…屏幕捕获（WGC/BitBlt/DXGI）在本机虚拟显示适配器环境中抓不到硬件 flip 内容（原生 C++ 正控也白），已降为 `CASCADED_EDITOR_DISPLAY_PROOF=1` 的可选诊断，不参与断言。
```

PrintWindow 不在那句清单里，但也没有任何本地读数证明它对 DirectComposition 内容有效。

## 四、仓库里没有 PrintWindow 实现，唯一截图脚本抓的是屏幕前台

```powershell
Select-String -Path (Get-ChildItem -Recurse -Include *.cs,*.md,*.cpp,*.h,*.ps1,*.py -File | Where-Object { $_.FullName -notmatch '\\out\\' }) -Pattern 'PrintWindow|PW_RENDERFULLCONTENT'
```

真实输出：4 处，全部在 change 工件的 design/tasks/spec，`Scripting/`、`Test/`、`Tools/`、任何 `.ps1` 零命中。

```powershell
Select-String -Path "$env:USERPROFILE\.dsh\skills\desktop-screenshot\capture.ps1" -Pattern 'PrintWindow|CopyFromScreen|GetForegroundWindow'
```

```text
capture.ps1:78:    $h = [DshShot]::GetForegroundWindow()
capture.ps1:126: $g.CopyFromScreen($rect.Left, $rect.Top, 0, 0, $bmp.Size)
```

判据：技能的窗口模式先要求「前台窗口」，再用屏幕像素拷贝——既不按任意 HWND 抓，也会被遮挡影响；这与 `MUST NOT 置前` 直接冲突。工件写「用 PrintWindow 按 HWND 抓窗」，但全仓没有任何工具或代码提供这条路，任务里也没有一步去造它。

## 五、结论

「被挡也能抓」对 WebView2 dock 是**未经验证的能力断言**：官方文档只定义了 WM_PRINT 路径，没有为 DirectComposition 内容背书；仓库零实现、零读数；项目自己的文档还记录了本机硬件合成内容抓不到。它被写成事实并当成 4.2 的 MUST，属于无中生有（程度：misleading，因为不是已被证伪，而是没有依据就写成结论）。
