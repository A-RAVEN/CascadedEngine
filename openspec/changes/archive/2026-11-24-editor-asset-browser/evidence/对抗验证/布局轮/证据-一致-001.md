# 证据-一致-001：set-size 判据与三分区几何互斥

- 攻击面：工件一致性（布局修订第 ① 点：三分区几何与既有尺寸合法性判据）
- 结论：三分区几何三处（design.md 的 D9 节 / editor-window-panel 的 MODIFIED 壳要求 / tasks 3.2）语义一致（tasks 3.2 只在运算符两侧省了空格，坐标与公式无出入）；但它们与同一份规范里未随修订更新的 set-size 判据互斥——合法输入可造出视口高 ≤ 0 的布局。

## 逐字引文（两处矛盾）

### 处一：MODIFIED 壳要求里的 set-size 判据（仍是两分区口径）

> `openspec/changes/editor-asset-browser/specs/editor-window-panel/spec.md:4`
> ……set-size 的宽 MUST > 面板宽、高 MUST >0，否则 E_INVALID_ARG。

> `openspec/changes/editor-asset-browser/specs/editor-window-panel/spec.md:15`
> - **WHEN** set-size 携带 width≤面板宽（含 0/负数，视口宽将≤0）或 height≤0

括号里的理由是「否则视口宽 ≤ 0」——说明这条判据的意图是保证视口有正尺寸；但修订后视口高改由「客户区高 − dock 高」决定，这条判据只管到客户区高 > 0。

### 处二：同一份 MODIFIED 壳要求里的三分区几何

> `openspec/changes/editor-asset-browser/specs/editor-window-panel/spec.md:23`
> ① **场景视口**（左上）原生渲染占位，宽 = 客户区宽 − 面板宽、高 = 客户区高 − dock 高……
> ③ **资产浏览器 dock**（底部通栏）**第二个 WebView2 控制器**，Bounds = (0, ClientHeight − DockHeight, ClientWidth, DockHeight)……（**dock 高默认值 CASCADED_EDITOR_DOCK_HEIGHT 可配，范围 1..客户区高−1，README 配置表登记**……）

dock 高可以取到客户区高 − 1，则 set-size 的 height 只要落在 1..dock 高 区间，就是「规范允许」的输入，却让视口高 = height − dock 高 ≤ 0。两条 MUST 在同一份规范里无法同时成立。

### 处三：tasks 里没有对应条目

> `openspec/changes/editor-asset-browser/tasks.md:23`（3.2 全文）
> ……新增 dock 高可配 `CASCADED_EDITOR_DOCK_HEIGHT`（默认值+范围 1..客户区高−1……）……验收：构建过；读数行含 panel/viewport/dock 三矩形且铺满客户区……

> `openspec/changes/editor-asset-browser/tasks.md:24`（3.3 全文）
> ……面板矩形/视口区域断言改为三分区铺满客户区（视口高=ClientHeight−DockHeight），像素读回中心仍按新视口区域精确匹配 (255,0,0,255)；改尺寸同步断言含两控制器 Bounds。

3.2、3.3 与 4.1 都没有「set-size 高度判据加 dock 高」的条目，也没有「height = dock 高 必须被拒」的断言。

现状（两分区）只校验「宽度大于面板宽、高度大于 0」就足以保证视口宽高皆正；三分区下视口高还要减去 dock 高，这条判据不再充分。若按现规则放行，视口尺寸变成 0 或负数，`EditorSceneView.Build` 会以「视口尺寸非法」失败（`EditorSceneView.cs:85-88`），而规范要求的 `E_INVALID_ARG` 不会出现。

## 为什么算矛盾（不是措辞问题）

- 同一份 MODIFIED 规范的两条 MUST：「高 MUST >0 才合法」与「视口高 = 客户区高 − dock 高」在 height ∈ [1, dock 高] 时给出相反结论（前者说合法、后者推出非正尺寸）。
- tasks 3.3 的验收（视口高 = ClientHeight − DockHeight）在这个区间会拿到 ≤ 0 的期望值，判据无法写出有意义的期望矩形。
- 项目规则要求「能失败的验收」；本条缺的正是「height ≤ dock 高 被拒」这条能变红的断言。

## 建议修法

1. spec.md:4 与 :15 的判据改成「宽 MUST > 面板宽、高 MUST > dock 高」，场景名与括号理由同步（仍是「杜绝视口尺寸 ≤ 0」）。
2. tasks 3.2 增加实现条目（`EditorService` 的 set-size 校验加 dock 高），4.1 或 3.3 增加断言：height = dock 高时回 `E_INVALID_ARG`、目标窗口尺寸不变、零原生调用。
3. 写清窗口尺寸变化后客户区高 ≤ dock 高（含配置越界）的处置，避免「同步布局」落到未定义状态。
