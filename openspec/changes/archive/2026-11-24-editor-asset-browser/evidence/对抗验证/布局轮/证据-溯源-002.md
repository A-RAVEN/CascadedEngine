# 证据-溯源-002：「照面板宽先例」只引到了先例的一半

## 一、先例原文（默认值与下界）

命令：

```powershell
Select-String -Path 'Scripting/Managed/Editor/EditorService.cs' -Pattern 'DefaultPanelWidth|s_panelWidth < 1'
```

真实输出：

```text
EditorService.cs:61: internal const int DefaultPanelWidth = 320;
EditorService.cs:350: s_panelWidth = DefaultPanelWidth;
EditorService.cs:353: if (!int.TryParse(text, NumberStyles.Integer, CultureInfo.InvariantCulture, out s_panelWidth) ||
EditorService.cs:354:     s_panelWidth < 1)
```

`TryReadPanelWidth`（:344-360）全函数只有「正整数」这一个判据：

```text
344:        private static bool TryReadPanelWidth(out string error)
345:        {
346:            error = string.Empty;
347:            string text = Environment.GetEnvironmentVariable("CASCADED_EDITOR_PANEL_WIDTH");
348:            if (string.IsNullOrEmpty(text))
349:            {
350:                s_panelWidth = DefaultPanelWidth;
351:                return true;
352:            }
353:            if (!int.TryParse(text, NumberStyles.Integer, CultureInfo.InvariantCulture, out s_panelWidth) ||
354:                s_panelWidth < 1)
355:            {
356:                error = "CASCADED_EDITOR_PANEL_WIDTH=\"" + text + "\" 非法（要求正整数像素）";
357:                return false;
358:            }
359:            return true;
360:        }
```

判据：范围上界「1..客户区宽-1」**不在**被引的 :61 / :344 里。

## 二、范围上界与越界处置的真实位置

命令：

```powershell
Get-Content 'Scripting/Managed/Editor/EditorWindow.cs' | Select-Object -Skip 238 -First 26
```

真实输出（逐字，含注释）：

```text
239:        /// <summary>按新的客户区尺寸重算分栏并同步控制器 Bounds（面板在右，视口在左）。</summary>
240:        internal void ApplyLayout(int clientWidth, int clientHeight)
241:        {
242:            if (clientWidth <= 1 || clientHeight <= 1)
243:            {
244:                Fail("窗口客户区过小，无法分栏：" + clientWidth + "x" + clientHeight);
245:                return;
246:            }
247:            // B2（工件修订）：面板宽范围 1..客户区宽-1；越界是配置错误，明确禁用（不静默 clamp 成怪布局）。
248:            if (m_ConfiguredPanelWidth < 1 || m_ConfiguredPanelWidth >= clientWidth)
249:            {
250:                Fail("CASCADED_EDITOR_PANEL_WIDTH=" + m_ConfiguredPanelWidth + " 超出范围（1..客户区宽-1=" +
251:                     (clientWidth - 1) + "）");
252:                return;
253:            }
254:            int panel = m_ConfiguredPanelWidth;
255:            ClientWidth = clientWidth;
256:            ClientHeight = clientHeight;
257:            PanelWidth = panel;
258:            ViewportWidth = clientWidth - panel;
```

所以面板宽先例实际是「四处」：环境变量名、默认值常量 320、读入时下界校验、**布局时上界校验 + Fail 禁用（不 clamp）**。工件只引了前两处的行号。

## 三、dock 高默认值全仓没有数字

命令与真实输出：

```powershell
git log --oneline -S 'CASCADED_EDITOR_DOCK_HEIGHT' --all
# （无输出，全历史零命中）

git log --oneline -S 'CASCADED_EDITOR_PANEL_WIDTH' --all
# 2ead9b0 editor-window-panel：网页编辑器首切片（单窗口分栏 + 本机服务 + scene view 证明）

Select-String -Path 'CSharpHost/README.md' -Pattern 'DOCK_HEIGHT'
# （无输出）

Select-String -Path 'CSharpHost/README.md' -Pattern 'CASCADED_EDITOR_PANEL_WIDTH'
# CSharpHost/README.md:119:| `CASCADED_EDITOR_PANEL_WIDTH` | 右侧面板宽（像素） | `320` | `1`..`客户区宽-1`（越界明确禁用并点名范围） |
# CSharpHost/README.md:392:| `CASCADED_EDITOR_PANEL_WIDTH` | 右侧面板宽（像素） | `320`（`1`..`客户区宽-1`） |
```

判据：面板宽的 320 是有出处的产品既有常量；dock 高没有任何常量、没有 README 行、没有历史提交。所以「照先例」可以借来「可配 + 范围 + README 登记」的形状，借不来默认值的**数字**——tasks 3.2 的「默认值+范围」里的默认值，实现时必须自己发明，除非先取到一个新依据。

## 四、与 一致-002 的关系

`主张-一致-002`（并行 agent）已主张「dock 高默认值在工件与 README 都没有具体数字」。本条不重复该结论，只补两件它没覆盖的事：① 被引的 `EditorService.cs:61/344` 不含范围上界；② 上界与越界处置在 `EditorWindow.cs:248-251`，且那里是 Fail 禁用而不是 clamp —— dock 沿用同一范围时，行为出处必须写清。
