# 证据-一致-002：dock 高默认值五处工件与 README 均无数字

- 攻击面：工件一致性（布局修订第 ② 点：配置键名、默认值、范围）
- 结论：键名拼写一致（`CASCADED_EDITOR_DOCK_HEIGHT`），范围一致（1..客户区高−1），**默认值缺失**；README 配置表没有该键，全仓命中只在 change 工件内。

## 为什么算矛盾（不是措辞问题）

- 规范要求「dock 高 MUST 可配（`CASCADED_EDITOR_DOCK_HEIGHT`，默认值与范围登记 README）」，但五处工件都没给出默认值——登记任务（tasks 5.5）没有可登记的内容，验收「README 与 3.2 一致」两边都是空。
- 项目规则禁止发明数量上下限/默认值；配置项要求「默认值与可配范围都写出来」并在用户文档配置键表出现。本项三项缺一（默认值）。
- tasks 3.3 要把「视口高 = ClientHeight − DockHeight」写死成期望值，没有默认值就只能取读数行自比，判据变永真。

## 建议修法

1. 定一个默认值（照面板宽先例的做法：新增常量如 `DefaultDockHeight`，并把数字同时写进 design.md 的 D9 节、MODIFIED 壳要求、tasks 3.2）；数字的问法要交给用户或给出可追溯来源，不能由实现者临场定。
2. README 配置表按同一数字登记，5.5 的验收写成「README 的默认值/范围字符串与 design.md 的默认值/范围字符串逐字相等」并给出 grep 期望串。
3. 3.3 的期望矩形用同一常量写死。
