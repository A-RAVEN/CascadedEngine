## 二、现有 TS 类型无法表达非对象事件

`EditorWeb/src/protocol.ts` 原文（逐字）：

> ```ts
> export interface EventMessage {
>   type: 'event';
>   event: 'object-changed' | 'object-invalidated';
>   objectId: number;
>   fields: Partial<Pick<EditorObject, 'title' | 'width' | 'height'>>;
> }
> ```

- `objectId` 是必填 `number`；`assets-changed` 是非对象作用域。`specs/editor-window-panel/spec.md` 增量的协议行原文（逐字）：「事件（object-changed / object-invalidated / **assets-changed**）广播给所有已连接客户端（assets-changed 无 objectId）」——增量明确说无 objectId，现有 `EventMessage` 却要求 `objectId: number`。
- `fields` 的类型只允许 title/width/height 的子集；「变更摘要」如果是新增/删除文件列表，按现有类型过不了编译。
- tasks 1.2 只说「EventMessage 加 'assets-changed'」；照字面只改 `event` 联合，`objectId` 仍然必填，类型与实际事件形状不一致；若把 `objectId` 改成可选，又没有任务说明这是有意的类型改动。

C# 侧同样没有负载定义：`EditorProtocol.cs` 现有 `BuildChangedEvent(objectId, fields)` / `BuildInvalidatedEvent(objectId)` 都固定带 objectId；tasks 1.3 只写一个方法名 `BuildAssetsChangedEvent`，没有签名与字段。

## 三、验收不覆盖负载

`tasks.md` 4.1 原文（逐字）：

> 新增文件刷新断言 +1 + assets-changed → 空根空态 → 门面未绑/根非法显式错误。验收：--list 23 行含 TestEditorAssetBrowser；两后端 --headless 该用例过；失败面各自能红（evidence/4.1-*.txt）。

这条只要求「客户端收到 assets-changed」；事件发一个 `{type:"event",event:"assets-changed",fields:{}}` 也能过。spec 要求 2 的「字段名逐字一致」因此没有可核对的期望值：没有字段清单，就没有「不一致」可判。

## 四、结论与改法

`assets-changed` 目前只有名字，没有可镜像的形状；「三处镜像逐字一致」对 `AssetEntry` 可执行，对事件不可执行。实现者只能各自发明 fields，三个镜像必然漂移，而 4.1 不会红。

建议在 design D2、spec 要求 2、tasks 1.1/1.2/1.3 写死同一份 payload：至少给出 `type`、`event`、`fields` 三个键，并给出 fields 的字段名与类型（例如 `added: string[]` / `removed: string[]` / `changed: string[]`，或明确只给 `count: number`）；TS 侧为该事件单独定义联合成员（省略 objectId 或明确 objectId 不适用）；tester 4.1 增加 payload 字段的逐字断言。
