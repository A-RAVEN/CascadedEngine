三、没有独立注入读数的分支（如实登记，不编造）
==================================================================

按 design D2 与 tasks 1.2③：下面几支只做实现检查 + 走读证明，**无独立注入读数**。

1. 二进制"读不足"（`LoadBinaryFile` 的 `gcount()` 检查）：
   `tellg` 与 `read` 在同一次调用内，单线程用例无法在两者之间截短文件；并发截短线程的竞态不可靠，
   故没有稳定注入手段。走读证明（CACore/private/FileLoader.cpp）：
       file_src.read(reinterpret_cast<char*>(result.data()), static_cast<std::streamsize>(size));
       if (static_cast<size_t>(file_src.gcount()) != static_cast<size_t>(size))
       {
           throw file_error("加载二进制文件", file_source, "实际读到的字节数少于文件尺寸");
       }

2. 文本"读取未完成"（`LoadStringFile` 的流状态检查）：同样无稳定注入手段。走读证明：
       while (std::getline(file_src, line)) { result += line + "\n"; }
       if (file_src.bad() || !file_src.eof())
       {
           throw file_error("加载文本文件", file_source, "读取未完成（流状态异常且未到文件末尾）");
       }

3. `WriteBinaryFile` 的 write / flush / close 失败三支：要制造"open 成功但写失败"需要磁盘满或只读句柄，
   测试里没有稳定手段。走读证明：write 后 `if (!file_dst)`、flush 后 `if (!file_dst)`、close 后
   `if (!file_dst)` 三处各自抛 file_error（原因分别为 写入失败 / 刷新缓冲区失败 / 关闭文件失败）。

4. 红态只覆盖 ①②④（缺失路径读 ×2、缺失目录写）；③⑤ 是对照。这与 tasks 1.2 的四项判据一致。
