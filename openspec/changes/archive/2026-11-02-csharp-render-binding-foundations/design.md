# csharp-render-binding-foundations 设计

## Context

`docs/ROADMAP.md` 阶段 4 已把本 change 定为简单三角形之前的基础能力。现有绑定生成器能处理窗口接口的标量、文本、回调、部分记录和句柄，但相关逻辑按返回类型分成多条特判路径，参数转换与公开 C# 表面并不完整。

已核对的现状锚点：

- `Tools/CodeGen/CodeGenMain.cpp` 只收集纯虚方法，过滤条件是“`clang_CXXMethod_isPureVirtual(cursor) == 0u`”。本 change 不扩大方法收集范围。
- 同文件的记录方法规则写着“`只有 defaulted 比较运算符允许`”，因此 `GPUBufferDescriptor::SizeInByte` 和静态 `Create` 也会阻止镜像。
- 同文件的公开记录判断要求存在嵌套关系，函数名是“`mirrorNeedsPublicRecord`”；平坦记录即使能到 C ABI，也不会形成公开 C# 方法。
- 同文件的智能指针返回分支直接写“`auto result = object->`”并遍历投影后的参数名，没有先重建记录、枚举或智能指针实参。
- 同文件的句柄查找按“`entry.interfaceTag != &`”加发行接口标签拒绝；这能防止跨接口误释放，但也使目标资源接口无法解析发行接口返回的资源。
- `CACore/header/HashKeys.h` 已给出包装值的取值与重建语义：`NameHash` / `PathHash` 是文本，`HashObj<T>` 是 `T`，`uenum::EnumFlags<T>` 在 `CACore/header/uenum.h` 中是公开的 `m_mask`。
- `Scripting/Managed/Scripting.Managed.csproj` 已用“`$(CascadedBindingDir)\*.Bindings.cs`”收集生成物，因此共享公开值类型可以沿用同一目录和后缀。
- `Tools/CodeGen/BindableShapes.h` 的 `IBindRow10::ConsumeThing` 已有智能指针入参形状，但现有测试没有证明原生实现收到的是原对象；本 change 要把签名覆盖推进到行为覆盖。

本 change 的调用方是后续“C# 简单三角形纵向切片”，不是生产渲染接口本身。所有新能力先用独立夹具证明，不以给生产类型加标记作为验收。

## Goals / Non-Goals

**Goals:**

- 让公开平坦/嵌套数据记录、枚举、标志位、独立包装值和字节入参在 C ABI、原生 thunk、公开 C# 三层保持一致。
- 让任意已支持的参数形状能与智能指针返回组合，不再因返回分支而丢失实参转换。
- 让跨头文件资源返回、目标接口方法调用、配对释放、智能指针入参和失效检查形成同一条类型安全通路。
- 用可失败的生成期、原生运行期和托管编译期判据覆盖新行为，并保持现有窗口绑定行为。

**Non-Goals:**

- 不实现生产渲染绑定、渲染适配接口、宿主渲染实例接线或简单三角形。
- 不扩大纯虚方法收集规则，不处理通用重载、`CA_BIND_SKIP` 顺序或具体建图类。
- 不实现异步字节生命周期、`std::span`、包装值返回或嵌入、容器出参、映射容器、联合体、定长数组和通用序列化块。
- 不改变 ABI 版本、现有公开窗口签名或原生渲染与调度策略。

## Decisions

### 一、用一份逐方法转换描述驱动三层产物

在 `Tools/CodeGen/CodeGenMain.cpp` 内建立逐参数、逐返回值的转换描述。每个参数描述至少包含：原始 C++ 类型、C ABI 声明、原生调用前的局部转换、原生实参表达式、公开 C# 类型、托管调用前的固定或转换步骤、C ABI 实参和清理步骤。方法描述再组合参数、返回值、错误处理和函数表槽。

原生 thunk 不再按“是否句柄返回”选择一套各自为政的参数转发逻辑；普通返回、记录返回、字符串伴生和智能指针返回都消费同一份参数描述。公开 C# 方法及 `<接口>Calls` 也从同一描述生成。

任何形状只要缺少三层中的任意一层，就必须在写产物之前拒绝并点名接口、方法和参数；禁止退回 `void*`、零值 thunk 或静默省略公开方法。已有回调和两段式文本可以先保留专用伴生，但其参数与公开表面必须接入同一套类型判定，不得与新形状产生另一套含义。

**备选方案**：继续在现有句柄、镜像、容器分支上补条件。否决原因是分支优先级已经造成“返回类型决定参数是否转换”，后续每加一种组合都要重复修补。

### 二、按数据布局判定记录，不按有没有便利方法判定

记录允许公开数据字段、默认构造、默认或自定义比较、静态工厂和非虚便利查询。生成器必须拒绝虚函数、非公开字段、非默认构造、联合体，以及任意层级含文本、容器、指针、智能指针或自定义所有权成员的记录。生成产物保留真实 `sizeof` / `offsetof` 和启动布局清单，并增加标准布局与默认构造的编译期检查。

普通枚举在记录字段中按真实底层类型镜像；`EnumFlags<T>` 在记录字段中按 `MaskType m_mask` 镜像。普通枚举方法参数和返回继续沿用现有 `int32_t` 投影；`EnumFlags<T>` 方法参数按 `MaskType` 对应的定宽整数转换，并显式重建 `EnumFlags<T>`。不得把记录中的窄枚举统一拉宽成 `int32_t`，否则真实偏移会改变。

`toCSharpType` 与公开记录字段映射必须覆盖本 change 接受的全部定宽标量和 `bool`，包括 `uint16_t` 与 `bool`；不得把未识别标量回退成 `void*`。公开 C 镜像中的布尔仍按一个字节存储，公开记录字段还原为 `bool`。除完整标量表外，还必须有真实 CLR 布局验证：生成代码用 `Marshal.SizeOf` / `Marshal.OffsetOf` 读取 C# 结构体实际布局，再与同源清单及原生读数比较，不能只比较生成器写出的两组常量。

公开 C# 枚举从 libclang 读取枚举常量、底层类型和实际值；用于 `EnumFlags<T>` 的枚举带 `[Flags]`，托管方法直接使用枚举 `T`，不另造一个没有位运算语义的 `EnumFlags<T>` 类。

**备选方案**：删除生产描述符上的所有便利方法，或只允许默认比较。前者不必要地侵入 C++ 易用接口，后者会继续挡住纯数据描述符；只要布局与转换前提仍可静态验证，就没有理由把非虚方法当成所有权行为。

### 三、公开记录和枚举使用按类型共享的确定产物

每个接口仍生成 `<接口>.Bindings.cpp` 与 `<接口>.Bindings.cs`。接口需要的公开记录和枚举另外生成 `<类型短名>.Bindings.cs`，文件只包含该限定 C++ 类型的公开 C# 值类型；接口内部的 C 镜像、布局清单和转换函数仍留在各接口产物中。

同一限定类型被多个接口需要时，共享文件的内容必须逐字节相同。`build.py` 汇总每次生成的共享文件哈希，同名文件内容不同即构建失败；不同限定名但相同短名的类型必须报出两个限定名，不能靠后一次生成覆盖前一次。`Scripting.Managed.csproj` 现有通配符继续编译这些文件，不另建手工类型副本。

**备选方案**：把公开记录嵌套在各接口类中，或允许每个接口生成同名全局记录。前者会把同一个 C++ 描述符变成多个不相容的 C# 类型，后者会直接产生重复定义。

### 四、包装值只做有明确语义的入参转换

`NameHash` 与 `PathHash` 的独立入参沿用 `char const* + uint64_t len`，公开 C# 为 `string`。原生侧用带长度的 `castl::string` 构造目标类型，使名称哈希和路径规范化仍由现有 C++ 构造函数完成，不在生成器中另算哈希或另写路径规则。

`HashObj<T>` 的独立 `const&` 入参按 `T` 的已支持记录投影。原生侧先重建 `T`，再用 `HashObj<T>{value}` 重算哈希；跨界不复制缓存哈希、有效位或内部字符串视图。`T` 除满足本 change 的记录条件外，还必须有显式哈希来源：可被消费翻译单元看到的 `CA_REFLECT(serializable)` 生成特化、`custom_hash_trait<T>` 或 `CA_HASH_BY_BYTES`。正向夹具必须把哈希来源接入 `build.py` 与消费头；没有哈希来源的普通记录必须在生成期拒绝，不能留到 C++ 的静态断言才失败。

这三个类型以及 `EnumFlags<T>` 的返回方向、嵌入记录方向和容器元素方向不在本 change 内；遇到这些方向必须拒绝，不能悄悄丢掉有效位或把内部布局当作值语义。

### 五、字节入参是同步、一次复制的 `byte[]`

`castl::vector<uint8_t> const&` 投影为 `uint8_t const* + uint64_t count`，公开 C# 为 `byte[]`。托管 `<接口>Calls` 用 `fixed` 固定整个原生调用；空数组允许得到空指针和零长度，空指针配非零长度必须报空指针错误且不进入实现。托管 `null` 数组在调用前抛出参数异常，不与空数组合并。

原生 thunk 在调用前重建 `castl::vector<uint8_t>`，因此原生实现若在调用内继续复制到图或上传持有区，其生命周期由原生接口自己决定。返回托管后数组可以立即修改或回收，但本 change 不支持把原生实现保存输入指针的异步方法标成安全。

字节参数可以与记录、标量、文本、枚举、标志位和句柄参数组合。当前字节障碍是标量元素分支把 `uint8_t` 错拼成不存在的 `uint8_tC`，并不是记录容器的 `containerIn` 分支；实现必须在通用容器判定前建立专用字节转换描述，不能只解除 `containerIn` 的“唯一参数且 void 返回”限制。此路径明确包含一次原生向量重建，不宣称零拷贝。

### 六、发行者入口与目标接口入口分离，清单使用完整限定名

`CODEGEN_BINDINGS` 第三列继续只表示“必须出现的产物前缀”，不再兼任完整接口清单。每次构建先为每个输入头运行 `CodeGen.exe --list-bind-interfaces`，从主头实际 `CA_BIND` 形状收集 `<短名>=<完整限定名>`；`build.py` 汇总去重后，以重复的 `--known-interface <短名>=<完整限定名>` 传给正式生成。主头文件的 `CA_BIND` 仍决定实际产物，清单只用于投影和诊断。这样现有夹具中未列入“期望产物前缀”的接口也不会被误判为未登记，同短名不同命名空间则必须生成失败。

句柄表项同时记录发行者完整限定类型与目标对象完整限定类型，并提供两类入口：

- 现有 `<接口>_ResolveHandle`、`<接口>_ReleaseHandle` 和按方法生成的 `<接口>_Release<方法名>` 保持**发行者角色**。它们只校验发行者，继续服务现有原生调用、非接口数据对象的强/弱句柄以及旧窗口测试。现有“把 `IWindow` 发行的句柄交给 `IWindowSystem_ReleaseHandle` 必须失败”的断言不变。
- 每个接口在函数表末尾追加 `<接口>_ResolveTargetHandle` 与 `<接口>_ReleaseTargetHandle`，承担**目标对象角色**。公开 C# 的已绑定接口返回统一使用目标入口取得表面对象和释放租约；目标类型不符必须失败。新增槽只追加，不重排旧槽，ABI 版本不变。非接口数据对象没有目标接口入口，仍只走发行者入口。

因此，同一个 `IWindowSystem` 对象由 `IWindow` 发行时，旧的 `IWindowSystem_ReleaseHandle` 仍因发行者不符而失败，新的 `IWindowSystem_ReleaseTargetHandle` 则按目标类型合法释放；两种判据不再互相矛盾。

`shared_ptr<T>` 入参按参数目标类型查表：强句柄直接复用表内强引用，弱返回句柄在调用期间取得强引用，借用句柄因没有可持有的智能指针所有权而拒绝。类型不符、已失效或借用句柄都沿用现有句柄失效错误码并给出具体文本，且不得进入原生实现。`weak_ptr<T>` **入参**不在本 change 内，继续生成期拒绝；这里说的弱句柄仅指由 `weak_ptr<T>` 返回产生的句柄。公开 C# 的 `null` 对象参数在调用前拒绝，已释放表面对象抛出 `ObjectDisposedException`，不得继续进入原生 thunk。

借用返回区分旧原生入口与新公开目标入口：旧发行者路径保留现有行为，无见证借用句柄可以存在到显式释放；目标接口解析则要求发行者见证存在且仍存活，无见证或见证过期都拒绝，避免把无法证明生命周期的对象交给新的公开资源表面。两类释放都先按序号、代际和各自角色校验，再清除表项并进位；目标已死亡或见证过期不得阻止清理，不得因“先解析、失败即返回”而留下槽位和弱引用。强句柄释放仍同时释放表内强引用，借用释放不销毁目标，回调借用作用域不改。

公开租约的 `Dispose` 在目标释放后检查错误通道，成功才清租约；这使错误使用发行者入口会实际抛出，而不是静默清字段。现有原生发行者断言继续验证旧行为，新增托管探针验证目标释放和释放后调用。

**备选方案**：只把旧标签换成目标类型，或让所有接口都能解析任意句柄。前者会破坏现有发行者测试和非接口数据句柄，后者会失去跨类型误用保护。

### 七、测试必须先证明旧行为会失败，再证明新行为真实发生

新增三类夹具：

- `Tools/CodeGen/BindableShapes.RenderFoundation.h`：覆盖平坦与嵌套记录、`bool`、窄枚举、方法级与记录级标志位、非虚便利方法、带显式哈希来源的独立包装值、字节与标量/记录/文本/枚举/标志位/句柄混合参数。文件名继续匹配 `check_bindings.py` 现有的 `BindableShapes*.h` 夹具识别。
- `Tools/CodeGen/BindableShapes.RenderResource.h` 与 `Tools/CodeGen/BindableShapes.RenderOwner.h`：分头声明资源接口和发行接口，覆盖跨头文件返回、发行者与目标两类入口、智能指针入参、错误目标类型、弱句柄和借用句柄。
- `Tools/CodeGen/BindableShapes.RenderReject*.h`：按失败原因分开覆盖虚函数记录、非公开字段、非默认构造、缺少哈希来源、包装值返回或嵌入、`weak_ptr` 入参、未登记抽象接口返回和同短名不同限定名。`BindingsRenderFoundationTest.cpp` 新增 `RunRenderRejectProbe`，逐个启动 `CodeGen.exe` 并断言非零退出与对应诊断；空指针配非零字节长度则直接调用生成 thunk，验证运行期拒绝。

`Test/CoreTests/BindingsRenderFoundationTest.cpp` 检查真实字段、枚举值、掩码、名称、路径、哈希对象所含值、字节内容和原生实参身份；`Test/CoreTests/BindingsCrossInterfaceTest.cpp` 检查目标接口方法调用、释放后失效、错误类型不进入实现、弱引用计数、无见证目标借用拒绝和过期见证释放清理。`Scripting/Managed/SurfaceSignatureCheck.cs` 除委托赋值外，还实际读取枚举常量值与底层类型、`[Flags]`、公开记录字段顺序、`Marshal.SizeOf` / `Marshal.OffsetOf`，并由 `Host.Boot` 执行这些检查；只编译委托不算值与布局验收。

`Scripting/Managed/Host.cs` 用现有 `IWindow::GetWindowSystem` 返回对象增加目标释放探针：合法 `Dispose` 不得报错，释放后调用必须抛 `ObjectDisposedException`，原窗口系统表面对象仍可使用。`Tools/check_window_system_bindings.py` 对日志做对应断言。`Tools/CodeGen/check_bindings.py` 的 `check_surface` / `check_alignment` 只处理有对应 `.Bindings.cpp` 的接口文件，共享公开值类型文件走独立的内容与唯一性判据，不再被误当成接口表面。

每项修复先在未修生成器上运行对应夹具并保存非零退出、编译失败或缺失公开签名的红态，再保存实现后的绿态；证据放本 change 的 `evidence/`。只生成到文本、只比较函数名或只检查退出码 0 不算完成。

### 八、现有窗口回归是共享句柄表修改的必检项

本 change 不改窗口需求，但会修改共用句柄表并追加目标接口入口。现有 `IWindow::GetWindowSystem` 的发行者原生断言、弱窗口句柄、回调借用作用域、窗口释放和布局自检必须沿用原测试重跑；公开 C# 则改走目标入口并新增释放后调用探针。`CSharpHost/private/CSharpHost.cpp` 的函数表大小断言按追加后的真实槽数更新，ABI 版本不变。完整构建后运行 CoreTests、绑定检查脚本以及 D3D12 / Vulkan 的现有 GPUBackendTester 全套测试；不以“不修改渲染代码”为理由省略窗口运行时回归。

## Risks / Trade-offs

- **共享公开值类型发生同名冲突或内容不一致** → 以限定名判定身份，同名不同限定名生成失败，`build.py` 对重复文件做哈希对账。
- **放宽便利方法后误收有对象语义的记录** → 保留公开字段、标准布局、默认构造、无 virtual 和递归成员限制；非法夹具必须证明生成期拒绝。
- **跨头文件目标名或解析接口写错** → 清单使用实际声明的完整限定名，发行者与目标入口分离；两个独立夹具头做真实调用，并逐字保留现有 `IWindow::GetWindowSystem` 发行者回归。
- **智能指针入参把借用对象误当成可持有对象** → 按句柄种类拒绝借用句柄，测试原生实现调用次数保持为 0。
- **字节数组在调用结束后被原生异步使用** → 本 change 只承诺同步重建；含异步保存输入指针语义的接口必须留到专门的回读或生命周期 change。
- **统一转换描述扩大改动面并影响旧形状** → 旧夹具逐项保留，函数表 ABI 版本不变，窗口与回调完整回归；不允许用删除旧断言的方式取得通过。
- **字节和包装值转换增加复制成本** → 本 change 选择正确性和明确所有权，不宣称热路径零拷贝；后续若真实消费者证明需要快路，再按既有快路规范另立设计。

## Migration Plan

1. 先加入夹具、期望签名与红态证据，再修改生成器和共用句柄表。
2. 每次只实现一类转换并运行对应夹具；现有形状出现回归时先修复组合规则，不删除旧断言。
3. 全量重新生成绑定并编译托管程序集，确认共享公开值类型都进入编译且没有重复定义。
4. 运行 CoreTests、绑定判据、窗口运行时回归和双后端完整测试，保存命令与真实输出。
