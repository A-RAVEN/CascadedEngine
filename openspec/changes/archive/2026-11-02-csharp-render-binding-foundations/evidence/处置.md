# csharp-render-binding-foundations 对抗审查处置

## 审查对账

- 五个审查面共提出 21 条主张，21 条均由不同上下文独立复核；主张、证据、复核和裁决文件合计 64 份，与回执一致，缺口为 0。
- 裁决保留 15 条：7 条阻断问题、5 条会误导实现的问题、3 组规则矛盾。
- 以下 15 条全部通过修订工件处置，没有“不修改”的条目，也没有修改产品代码、测试代码或运行项目。

## 逐条处置

| 序号 | 裁决条目 | 处置与修订位置 |
|---|---|---|
| 1 | 共享 `.Bindings.cs` 会被现有表面与对齐判据误当成接口 | 在 `specs/csharp-bindings/spec.md` 增加“逐接口判据不得把共享值类型当成接口”场景；`tasks.md` 4.1 明确 `check_surface` / `check_alignment` 只处理有对应 `.Bindings.cpp` 的接口，共享类型走独立判据。 |
| 2 | `HashObj<T>` 缺少显式哈希来源时会在原生编译期才失败 | `design.md` 决策四、两份增量规范和 `tasks.md` 1.1 / 2.4 增加生成期哈希来源前提；正向夹具接入 `CA_REFLECT(serializable)` 与 `CODEGEN_ANNOTATED`，负向夹具覆盖无来源记录。 |
| 3 | 生成期负向夹具没有独立文件和执行入口 | `design.md` 决策七与 `tasks.md` 1.3 改为 `BindableShapes.RenderReject*.h` 按原因分头，并由 `RunRenderRejectProbe` 逐个启动 `CodeGen.exe`；运行期空指针反例直接调 thunk。 |
| 4 | `bool` 公开记录字段会回退成 `void*` | `design.md` 决策二、`specs/csharp-bindings/spec.md` 和 `tasks.md` 1.1 / 2.2 强制补齐 `bool` 与定宽整数映射，布尔公开字段为 `bool`、C 镜像为一个字节，未知标量禁止回退指针。 |
| 5 | 方法级 `uint16_t` 标志位没有实现和夹具 | `tasks.md` 1.1 / 2.2 / 2.5 同时覆盖方法级与记录级标志位、混合参数和 `ushort` 函数表槽；规范禁止未知标量回退指针。 |
| 6 | 期望产物前缀不是完整接口清单，会误拒现有接口 | `design.md` 决策六、跨头文件清单 Requirement 和 `tasks.md` 3.1 改为先以 `--list-bind-interfaces` 收集所有实际 `CA_BIND`，期望前缀只保留产物存在性检查。 |
| 7 | 新夹具文件名不匹配现有 `BindableShapes*.h` 识别规则 | 所有计划夹具更名为 `BindableShapes.RenderFoundation.h`、`BindableShapes.RenderResource.h`、`BindableShapes.RenderOwner.h` 和 `BindableShapes.RenderReject*.h`；`tasks.md` 4.1 明确验证夹具识别。 |
| 8 | 布局自检只比较生成常量，未读取真实 CLR 布局 | `design.md` 决策二与七、公开值类型 Requirement、`tasks.md` 1.3 / 2.2 / 2.3 增加 `Marshal.SizeOf` / `Marshal.OffsetOf` 的实际布局断言和字段宽度红态。 |
| 9 | 字节障碍被误写成记录容器限制，实际还有 `uint8_tC` 错误 | `design.md` 决策五与 `tasks.md` 2.5 明确标量字节专用路径必须先于通用容器判定，验收直接挡住 `uint8_tC`，不再只解除 `containerIn` 限制。 |
| 10 | 无见证借用与过期见证释放会留下永久句柄或残渣 | 双角色规则要求公开目标借用解析必须有存活见证，旧发行者无见证行为仅限兼容；两类释放都必须在目标死亡或见证过期后清表项并进位。已写入 `design.md`、两份句柄 Requirement 和 `tasks.md` 1.2 / 3.2。 |
| 11 | 目标释放与释放后调用没有托管行为判据 | `tasks.md` 1.3 / 3.3 要求 `Dispose` 检查错误通道、释放后抛 `ObjectDisposedException`，并在 `Host.cs` 与 `Tools/check_window_system_bindings.py` 增加真实探针；仅做签名断言不算通过。 |
| 12 | 公开枚举值和记录字段顺序只有签名验收 | `design.md` 决策七、公开值类型 Requirement、`tasks.md` 1.3 / 2.3 增加枚举常量值、底层类型、`[Flags]`、字段顺序的实际启动断言及对应红态。 |
| 13 | 单纯改目标类型校验会与现有发行者测试和非接口数据句柄冲突 | 采用双角色句柄：旧 `ResolveHandle` / `ReleaseHandle` / 按方法释放保持发行者角色，新 `ResolveTargetHandle` / `ReleaseTargetHandle` 服务公开目标表面；旧 `IWindowSystem_ReleaseHandle` 错配仍失败，新目标释放合法。`WindowBindingsCompileTest.cpp` 旧断言逐字保留。 |
| 14 | “智能指针入参”会被理解为也支持 `weak_ptr<T>` | `proposal.md`、`design.md`、两份智能指针 Requirement 和 `tasks.md` 1.3 / 3.3 明确只实现 `shared_ptr<T>` 入参；`weak_ptr<T>` 入参继续生成期拒绝，弱返回句柄仍在调用期间取得强引用。 |
| 15 | 短名清单无法区分同短名不同限定名 | `--known-interface` 改为 `<短名>=<完整限定名>`，由实际声明收集；同短名冲突、清单与目标限定名不一致均生成失败。已同步 `design.md`、清单 Requirement 和 `tasks.md` 3.1。 |
