# 证据-影响-002：1.4+1.5 只能把审计脚本从「僵尸行」推到「汇总表不符」，永远到不了 114

## 结论

tasks 1.4 追加九条主表行，1.5 给脚本 `INTERFACES` 加门面一项。这两步之后脚本仍会退出 1，因为审计文件顶部还有一张**范围汇总表**：

```text
| 接口 | 方法条数 | 所在头文件 |
| `graphics_backend::CRenderBackend` | 16 | … |
...
| **合计** | **105** | |
```

脚本要求每个 `INTERFACES` 接口在汇总表里有一行，且合计等于所有方法数。只做 1.4+1.5，汇总表既没有门面的行，合计也还是 105，于是 1.5 的验收「输出接口数 13→14、方法对账数 105→114」永远到不了。反过来，若按脚本要求补上汇总行，1.4 的 `Select-String 'IResourceRegistry'` 计数至少是 10（9 条主表行 + 1 条汇总行；若同时更新「谁实现」表则更多），不等于 9。两处验收互相排斥。

```text
输出：扫描 13 个接口、对账 105 条方法、命中 0 处问题（审计表：openspec\changes\archive\2026-10-18-csharp-bindable-surface\evidence\bindable-audit.md）
```

审计表当前合计行：

```text
| **合计** | **105** | |
```

加门面后头文件实算：13 个接口 + 1 = 14，105 条方法 + 9 = 114。

## 任务原文（当前版本）

- 1.4：「审计表追加九行……只追加不动旧行。验收：`Select-String 'IResourceRegistry'` 在该文件计数 = 9；脚本绿须与 1.5 同步完成（单独追加九行会因僵尸行红，见 1.5）。」
- 1.5：「`Tools/CodeGen/check_bindable_audit.py` 的 `INTERFACES` 表加 … 一项。验收：`python Tools/CodeGen/check_bindable_audit.py` exit 0，输出接口数 13→14、方法对账数 105→114……」
- design D7：「……同时给该脚本的 `INTERFACES` 表加 `cs_script::IResourceRegistry` 一项……改后脚本绿（接口数 13→14、方法数 105→114，实测基线）。」
- design Risks：「只追加九行，不动旧行。」

三处都没有「汇总表加一行」「合计 105→114」。1.5 的红态设计（1.4 已做、1.5 未做时脚本报僵尸行）是对的，但它只证明了「脚本缺 INTERFACES 会红」，没有证明「绿态要改汇总表」；验收要求 114，却不给达成 114 的动作。

## 改法

1. 1.4 或 1.5 增加汇总表动作：
   - 加 `| `cs_script::IResourceRegistry` | 9 | `Interface/ScriptHost/header/ScriptHost/IResourceRegistry.h` |`；
   - 合计 `105`→`114`。
2. 1.4 的 `Select-String` 计数改成「至少 10」，或改成「主表 `cs_script::IResourceRegistry::` 行数 = 9」这种能区分主表/汇总表的判据。
3. 1.5 绿态验收加：脚本输出「扫描 14 个接口、对账 114 条方法」、`grep '| **合计** | **114** |'` 命中 1。
4. design D7 与 Risks 同步写明汇总行与合计改动，避免执行者只改主表和脚本。
