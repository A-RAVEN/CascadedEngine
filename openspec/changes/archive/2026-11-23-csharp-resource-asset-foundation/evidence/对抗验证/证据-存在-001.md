## 二、本条主张展开：验收 `check_bindable_audit.py exit 0` 为何跑不成

### 现态基线

```text
$ python Tools\CodeGen\check_bindable_audit.py
扫描 13 个接口、对账 105 条方法、命中 0 处问题（审计表：openspec\changes\archive\2026-10-18-csharp-bindable-surface\evidence\bindable-audit.md）
exit = 0
```

唯一的审计表确实只有一份（脚本用 glob 找，`len(audits) > 1` 直接返回 2）：

```text
$ Get-ChildItem -Recurse -File -Filter 'bindable-audit.md'
openspec\changes\archive\2026-10-18-csharp-bindable-surface\evidence\bindable-audit.md
```

所以 design D7 里「全仓唯一一份、实测 glob 只命中归档那一份」是成立的；不成立的是它下一句「九行追加进那一份……脚本绿」。

### 为什么追加九行会红

被审计接口集合是脚本内的字典，不是扫出来的：

```text
$ (Select-String -Path 'Tools\CodeGen\check_bindable_audit.py' -Pattern 'cs_script').Count
0
```

`INTERFACES`（L27-54）13 项：`graphics_backend::{CRenderBackend, IReadbackToken, GPUGraph, ShaderStruct, GPUTexture, WindowHandle, GPUBuffer}`、`cawindow::{IWindow, IWindowSystem}`、`resource_management::{IResource, IResourceFactory, ResourceImporter, ResourceImporterProductions}` —— 没有 `cs_script::IResourceRegistry`。

期望集只从 `INTERFACES` 生成（L274-281）：

```text
for interface in INTERFACES:
    methods = header_methods(repo, interface)
    ...
    expected[(interface, method)] = expected.get(...) + 1
```

表里出现期望集外的行即记问题（L298-303）：

```text
key = (row["interface"], row["method"])
actual[key] = actual.get(key, 0) + 1
if key not in expected:
    problems.append(f"僵尸行：审计表里出现了接口中不存在的方法 {row['interface']}::{row['method']}")
```

`problems` 非空 ⇒ 返回 1。于是 tasks 1.4 的两条验收在同一个动作下互斥：追加九行 ⇒ 脚本红（僵尸行）；不追加 ⇒ `Select-String 'IResourceRegistry'` 计数 = 0 ≠ 9。而 `INTERFACES` 的注释（L175-177）已经把这种情形点名成「新增接口却漏改本文件的 INTERFACES」，说明这是已知的漏项形态，工件只是又犯了一次。

### 修法为什么不是放松判据

僵尸行判据保留，只补「审计面认这张新表」这一行登记；顺带给一条能失败的红态（删掉 `INTERFACES` 那一行必须红）。这样 tasks 1.4 的两条读数（行数 9、脚本 exit 0）才能同时成立。
