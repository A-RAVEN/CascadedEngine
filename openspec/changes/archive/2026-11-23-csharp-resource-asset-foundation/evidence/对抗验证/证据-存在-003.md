# 证据-存在-003：Mesh 顶点布局与 `SceneRenderer` 现用布局对不上

对应主张：`主张-存在-003.json`（misleading）
工件逐字引文（`design.md:84`）：

```text
- `Mesh : ResourceBase`：`byte[] VertexData`（位置 float3 + 颜色 float4 交错，与场景着色器输入布局一致——`SceneRenderer` 现用布局）、`byte[] IndexData`（uint32 索引）、`VertexCount`/`IndexCount`（int）。Serialize：魔数 `CAMH` + formatVersion=1 + 两个计数 + 两段长度 + 两段字节。
```

## 一、被引用方（`SceneRenderer`）的真实读数

```text
$ Select-String -Path 'Scripting\Managed\Scene\SceneRenderer.cs' -Pattern 'VertexStride|PositionOffset|ColorOffset'
L41: // 顶点布局与既有三角形探针一致：位置 float3（偏移 0）+ 颜色 float3（偏移 12），步长 24。
L42: private const uint VertexStride = 24;
L43: private const uint PositionOffset = 0;
L44: private const uint ColorOffset = 12;
```

消费点在 L324：

```text
L324: if (!Check(m_Graph.SetPositionColorStream(bufferName, VertexStride, PositionOffset, ColorOffset),
L325: "SetPositionColorStream", out error))
```

着色器输入（`CAResources/Shaders/Test/TestSimpleTriangle.slang` L2-6）：

```text
struct VertexInput
{
    float3 position : POSITION;
    float3 color : COLOR;
};
```

着色器输出侧才是 float4（`SV_POSITION` 由 `float4(input.position, 1.0f)` 拼出来），与顶点缓冲里存的「颜色分量个数」不是一回事；工件把输出侧的 4 写到了顶点数据上。

## 二、对不上在哪

| 项 | 工件 D5 的说法 | 真实布局 | 差 |
|---|---|---|---|
| 位置分量 | float3 | float3（偏移 0） | 一致 |
| 颜色分量 | **float4** | **float3**（偏移 12） | 多 1 个分量 |
| 每顶点字节 | 隐含 28（或 32 对齐） | **24** | 与 `VertexStride = 24` 不符 |
| 布局归属 | 「与场景着色器输入布局一致——`SceneRenderer` 现用布局」 | 本条即 `SceneRenderer` 的真实布局 | 引文反向 |

## 三、后果链（为什么不是文风问题）

- `tasks.md:21` `3.1 [P] ...与 Mesh.cs：继承 ResourceBase，字段与 Serialize() 格式按 design D5` —— 实现者照 D5 写出 28 字节步长的顶点字节。
- `tasks.md:30` `4.3 渲染消费：... Mesh → CreateGPUBuffer → 索引绘制；两后端真实像素检查` —— 顶点流由 `SetPositionColorStream(stride, positionOffset, colorOffset)` 描述；步长 24 / 颜色偏移 12 是既有引擎侧常数，28 字节数据会被按 24 步长切开，第 2 个顶点起位置与颜色全部错位。
- 失败现象会表现为「像素不对」，排查指向 4.3 而不是 D5 那一行定义；而且 design 自称「与现用布局一致」，反而降低了实现者复核布局的动力。

## 四、建议改法（逐字可核）

D5 那一句改为：

```text
- `Mesh : ResourceBase`：`byte[] VertexData`（位置 float3 偏移 0 + 颜色 float3 偏移 12，逐顶点 24 字节交错；与 `Scripting/Managed/Scene/SceneRenderer.cs` 的 `VertexStride = 24` / `PositionOffset = 0` / `ColorOffset = 12` 一致）、`byte[] IndexData`（uint32 索引）、`VertexCount`/`IndexCount`（int）。
```

`tasks.md` 3.1 的验收补一条能失败的：

```text
验收：C# 侧 `VertexStride = 24`、`ColorOffset = 12`，与 `SceneRenderer` 同名常数逐字相同（`Select-String` 两处命中且数值相等）；把任一常数改成 28/16 后 4.3 的网格像素判据必须红。
```

`specs/csharp-asset-layer/spec.md:5` 的「顶点布局与场景着色器现用输入一致」不必改（它没写错具体数字），但建议加一句指向（「逐顶点 24 字节：位置 float3 @0 + 颜色 float3 @12」），让「一致」成为可核事实。
