# 证据-一致-002：两段式已写进 D8/5.1，Goals 与 Migration 仍是「既有产物逐字节不变是硬判据」

## 主张

修订已经把 `design.md` D8 与 `tasks.md` 5.1 改成两段式：既有**各接口**产物逐字节不变；三份**聚合**登记产物（`BindingRegistry.Bindings.h/.cpp`、`EngineApi.Bindings.cs`）允许变，但每处差异要逐处指认到门面编号 13。可是同一份 `design.md` 的 Goals 与 Migration Plan、以及 asset-layer spec 的回归要求，仍保留「既有绑定产物逐字节不变」「既有产物逐字节不变是硬判据，红了即停」「回归 MUST 与基线零差异」这类全量断言。三份聚合产物也是既有产物，这些断言与两段式冲突。

## 原文对照

仍保留全量断言的三处：

`design.md` Goals：

> GeneralResources 与生成器**零改动**；既有绑定产物逐字节不变；既有 21 个 tester 用例与 CoreTests 全绿。

`design.md` Migration Plan：

> 纯增量：加头 / 加实现 / 加清单行 / 加 C# 文件 / 加用例。回滚 = 撤这些增量；无数据迁移（新格式资产文件只在用例临时目录产生）。既有产物逐字节不变是硬判据，红了即停。

`specs/csharp-asset-layer/spec.md` 回归要求：

> 回归 MUST 与基线零差异。

已改成两段式的两处：

`design.md` D8：

> 既有**各接口**产物（含 codegen 产物）逐字节不变；三份**聚合**产物（`BindingRegistry.Bindings.h/.cpp`、`EngineApi.Bindings.cs`）允许变，但每处差异 MUST 逐处指认到门面编号 13 的登记行，指认不出即红；新锚**期望 221 条** = 218 + 3 份新增……

`tasks.md` 5.1：

> 既有**各接口**产物（含 codegen 产物）逐字节零差异；三份聚合产物（BindingRegistry.Bindings.h/.cpp、EngineApi.Bindings.cs）的每处差异逐处指认到门面编号 13 登记行，指认不出即红；新锚**期望 221 条** = 218 + 3 份新增……

`specs/csharp-resource-registry/spec.md`：

> 既有**各接口**绑定产物 MUST 逐字节不变；三份聚合登记产物（`BindingRegistry.Bindings.h/.cpp`、`EngineApi.Bindings.cs`）允许变化，但每处差异 MUST 能指认到门面编号 13 的登记行。

## 为什么这不是措辞问题

- 三份聚合产物必然变化：上一 change 的换锚记录已实测「不一致 3 = BindingRegistry.Bindings.cpp/.h + EngineApi.Bindings.cs（宿主登记表新号 11/12，合法变化）」。本次加编号 13，同样会改这三份。
- 「既有产物逐字节不变是硬判据，红了即停」把这三份合法变化也判红；执行者按字面执行只能误停，或把差异藏掉。
- 两段式判据本身没有放松：各接口产物仍要求零差异；聚合产物只放行到「逐处指认到编号 13 登记行」，指认不出仍红。错的只是残留的全量断言。

## 改法

1. `design.md` Migration Plan 改成：「既有各接口产物逐字节不变；三份聚合登记产物允许变但每处差异逐处指认，未指认即红」；「红了即停」补限定为「未指认的差异」。
2. `design.md` Goals 的「既有绑定产物逐字节不变」改成「既有各接口产物逐字节不变（三份聚合登记产物按 D8 两段式）」。
3. `specs/csharp-asset-layer/spec.md` 的「回归 MUST 与基线零差异」改成「各接口产物零差异 + 聚合产物差异逐处指认，任何未指认差异即红」。
4. 保留 D8 / 5.1 的两段式措辞与「新锚期望 221 条」，它们是当前正确的判据。

## 复核方式

```powershell
# 修改后重跑：三份聚合产物应有差异，其余各接口产物应零差异
python Tools\CodeGen\check_binding_baseline.py --baseline openspec/changes/archive/2026-11-23-resource-importer-refactor/evidence/新锚.txt --product-dir out/build/x64-debug/codegen/bindings
```

若仍按 Migration 的「既有产物逐字节不变」作为硬判据，这条命令的「不一致 3」就是红态；而 D8/5.1 的两段式要求的是「不一致 3 均能指认到编号 13 登记行」。两者不能同时作为同一个 change 的验收口径。
