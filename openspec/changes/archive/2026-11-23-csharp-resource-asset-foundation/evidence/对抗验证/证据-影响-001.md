# 证据-影响-001：对外文档只同步了清单，两处计数会静默过期

## 结论

tasks 4.4 只点名了 `docs/testing.md` 的测试清单和 `CSharpHost/README.md` 的编号表。但本批会让两类**已存在的文档读数**变化，而它们不在任何任务与判据里：

- `docs/testing.md`：四处「21」条计数要变 22；
- `Tools/CodeGen/README.md`：审计脚本的输出与范围说明要变「14 个接口 / 114 条方法」并新增门面接口名。

`Tools/CodeGen/verify_readme.py` 抓不到第二类，因为它只执行以 `CodeGen.exe ` 开头的命令行；README 里 `python Tools/CodeGen/check_bindable_audit.py` 那段输出不在它的扫描面内。这是「影响面漏算 + 静默腐烂」，不是单纯的文风问题。

## 实测：docs/testing.md 的四处 21

```text
第 10 行：| **② 进程内行为** | `Test/GPUBackendTester`（当前 **21** 个测试，…）
第 32 行：### ② `Test/GPUBackendTester`（21 个测试）
第 95 行：### 层 ②：`TestScriptHost`（加它的时候是第 9 条；当前全量一共 21 条）
第 229 行：两份全量 report 里 21 条 `status` 全为 `pass`；…
```

第 229 行是最小回归集合的一部分，执行完整验收时会照着它核对「21 条全 pass」；本批新增第 22 条 `TestCSharpAssets` 后，这里会让人以为还该是 21 条。

## 实测：Tools/CodeGen/README.md 的 13 / 105

```text
第 1052 行：扫描 13 个接口、对账 105 条方法、命中 0 处问题（审计表：openspec\changes\archive\2026-10-18-csharp-bindable-surface\evidence\bindable-audit.md）
第 1058 行：- 审计范围现在是 13 个接口（`CRenderBackend` / `IReadbackToken` / `GPUGraph` / `ShaderStruct` / `GPUTexture` / `WindowHandle` / `GPUBuffer` / `IWindow` / `IWindowSystem` / `IResource` / `IResourceFactory` / `ResourceImporter` / `ResourceImporterProductions`），合计 105 条公开方法。…
```

这两行是**真实命令输出**的抄录，不是说明性文字。本批改完后实跑会是：

```text
扫描 14 个接口、对账 114 条方法、命中 0 处问题
```

README 若不改，就是「文档写的输出 ≠ 工具真实输出」，而 `verify_readme.py` 不跑 `python` 开头的命令，所以它不会红。

## 判据现状

- `tasks.md` 4.4：「对外文档：`docs/testing.md` 清单加第 22 用例；`CSharpHost/README.md` 编号表加 13（门面）。验收：testing.md 清单与 `--list` 输出逐条一致；README 表含 13 且与锁文件一致（grep 对照）。」
- `verify_readme.py` 的命令识别：`CMD_RE = re.compile(r"^CodeGen\.exe (.+)$")`，只匹配 `CodeGen.exe` 行。
- 当前实跑审计脚本：`扫描 13 个接口、对账 105 条方法、命中 0 处问题`（exit 0）。

「清单与 `--list` 一致」只能证明第 36 行那条长清单对，证明不了四处计数和第 1052/1058 行。

## 改法

1. `tasks.md` 4.4 加两项：
   - `docs/testing.md` 四处 21→22（验收：`git grep -n "21 个测试\|一共 21 条\|21 条 \`status\`" -- docs/testing.md` 为 0 命中，且对应位置是 22）；
   - `Tools/CodeGen/README.md` 审计输出 14/114 并把 `cs_script::IResourceRegistry` 加进接口名清单（验收：该文件里 `13 个接口` / `105 条` 为 0 命中）。
2. 因为 `verify_readme.py` 不管 `python …` 输出，4.4 再加一条「README 审计输出行与实跑 `python Tools/CodeGen/check_bindable_audit.py` 输出逐字一致」的人工对账，避免 README 再次静默腐烂。
3. 若认为 `Tools/CodeGen/README.md` 属于「审计脚本自己的文档」而不是本批的对外文档，也要在 proposal 的「不动/影响」里写明不改的理由；现在它既不在影响里，也不在不动里，属于漏算。
