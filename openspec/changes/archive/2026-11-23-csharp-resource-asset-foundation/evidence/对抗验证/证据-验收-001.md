## 残留问题二：新锚份数从实测推导（恒绿）

spec 场景原文（`specs/csharp-resource-registry/spec.md:10`）：

> ……新增产物份数 MUST 与实测一致（新锚 = 218 + 实测新增）；比对脚本 MUST 能因任何一份未指认差异而非零退出

「与实测一致」= 期望值由被测物自己给出。少生成一个文件（例如 `.Bindings.cs` 没出）、多生成一个文件（例如多一个分片），新锚都「与实测一致」。`check_binding_baseline.py` 的换锚对账只比「当前产物 vs 刚写的锚」，上一批原文「新锚 evidence/新锚.txt（218 条 = 213+5），自洽对账 缺失0/不一致0/多余0」——份数写多少都能自洽。

按现有机制可以写死：每接口产物 2 份（`<线形>.Bindings.cpp` / `.Bindings.cs`，实测 `cawindow__IWindow`、`resource_management__IResourceFactory` 均如此）+ 新登记分片 1 份（`build.py` 注释「分片标签必须一头一个」）= 218 + 3 = **221**。
