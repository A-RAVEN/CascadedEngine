# 证据-影响-003：门面头按基名 include，CSharpHost 缺一个 include 目录，接线清单漏算

## 结论

生成器写产物时用的是**源头的基名**：

```text
// 接口自己的声明从哪来：写源头的文件名（用基名，靠调用方的 include 目录解析）。
cpp += "#include \"" + base + "\"\n";
```

现有产物实测：

```text
out/build/x64-debug/codegen/bindings/graphics_backend__GPUBuffer.Bindings.cpp:
#include "GPUBuffer.h"
```

CSharpHost 的 `CSharpHost.cpp` 直接 `#include "BindingRegistry.Bindings.cpp"`，而后者逐份 `#include "<线形>.Bindings.cpp"`。所以新门面产物会以 `#include "IResourceRegistry.h"` 进入 CSharpHost 的编译单元。

门面头按 design D1/D7 放在 `Interface/ScriptHost/header/ScriptHost/IResourceRegistry.h`。CSharpHost 当前的 include 路径（`out/build/x64-debug/compile_commands.json` 实测）：

```text
-IE:\Projects\CascadedEngine\CSharpHost\header
-IE:\Projects\CascadedEngine\out\build\x64-debug\codegen\bindings
-IE:\Projects\CascadedEngine\WindowSystem\header\CAWindow
-IE:\Projects\CascadedEngine\GeneralResources\header\CAResource
...
-IE:\Projects\CascadedEngine\Interface\ScriptHost\header
```

`Interface\ScriptHost\header` 下没有 `IResourceRegistry.h`（该目录只有 `ScriptHost\IScriptHost.h`；`Test-Path Interface\ScriptHost\header\IResourceRegistry.h` 为 False）。要按基名解析，必须再加一层 `...\header\ScriptHost`。当前 `CSharpHost/CMakeLists.txt` 的 include 列表只补了：

```text
${CMAKE_SOURCE_DIR}/WindowSystem/header/CAWindow
${CMAKE_SOURCE_DIR}/GeneralResources/header/CAResource
```

后一条的注释正是上一批踩过的同一个坑：

```text
# csharp-reverse-interface-binding 7.1：反向资源产物 `#include "IResource.h"` 按基名找头
# （与所有正向产物同一规则），所以 `CAResource` 目录要在这个目标上可见。
```

本批的 proposal Impact、design D7、tasks 1.1–1.3 都没有 `CSharpHost/CMakeLists.txt` 这一项；tasks 1.3 / 5.3 却要求「构建过」。按当前接线，第一次把门面头加进 `CODEGEN_BINDINGS` 后，CSharpHost 编译会报找不到 `IResourceRegistry.h`（C1083），构建验收必红，而且红在一个任务没有列出的改动面上。

## 不是生成器的问题

也可以让生成器对子目录头写 `#include <ScriptHost/IResourceRegistry.h>`，但那要改正向生成器，与本 change「正向生成器零改动」的硬约束冲突；正确落点是 CSharpHost 的 CMake。

## 旁证：tester 侧可以不改

`Test/GPUBackendTester/CMakeLists.txt` 链接了 `ScriptHost` 目标，tester 的编译命令里已经有 `-IE:\Projects\CascadedEngine\Interface\ScriptHost\header`，所以 `Main.cpp` 若写 `#include <ScriptHost/IResourceRegistry.h>` 能编译。缺的只有 CSharpHost 对**基名** include 的解析目录，这一处必须补。

## 改法

1. `CSharpHost/CMakeLists.txt` 的 `target_include_directories(${PROJECT_NAME} PRIVATE ...)` 里加 `${CMAKE_SOURCE_DIR}/Interface/ScriptHost/header/ScriptHost`（与 `WindowSystem/header/CAWindow`、`GeneralResources/header/CAResource` 同一段）。
2. proposal Impact 的代码清单加 `CSharpHost/CMakeLists.txt`；tasks 1.3 的改动面与验收同步加这一条（验收：compile_commands 里 CSharpHost 命令含该目录，且构建后产物 `cs_script__IResourceRegistry.Bindings.cpp` 能被编译、不再报 C1083）。
3. 如果不想加这一行，就必须在 CODEGEN_BINDINGS 之外手工把该头放到已被 include 的目录——但那会偏离 design 固定路径，不建议。
