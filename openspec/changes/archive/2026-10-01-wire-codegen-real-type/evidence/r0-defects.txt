# 任务 1.3 —— 根因的直接证据（工具内一次性 [DIAGDUMP]，抄下输出后已删除并重新构建）
#
# 做法：在字段收集处临时加一行 fprintf 打印 clang 报的类型种类，构建后跑下面这条命令，抄下输出
#       再删掉那一行并重新构建。夹具是入库的：
#   cmd: CodeGen.exe openspec/changes/wire-codegen-real-type/evidence/fixtures/type_kinds.h TypeKinds -I CACore/header --emit-reflection -o <临时输出>
#
# 原样输出（2026-09-20，x64-debug）：
[DIAGDUMP] field=spelled_uint spelled=unsigned int CXTypeKind=9
[DIAGDUMP] field=typedef_uint spelled=uint32_t CXTypeKind=119
[DIAGDUMP] field=spelled_ull spelled=unsigned long long CXTypeKind=11
[DIAGDUMP] field=typedef_ull spelled=uint64_t CXTypeKind=119
# exit=0
#
# 结论：clang 报的种类就是根因 —— 9 = CXType_UInt（直接写 `unsigned int`），11 = CXType_ULongLong，
# 而 119 = CXType_Elaborated（`uint32_t` / `uint64_t` 这类别名写法）。分类器只对前两者有分支，
# 119 落进 `default: return "TypeKind::Opaque"`。修法是判定前取规范化类型（见 codegen-container-semantics）。
# 收尾：诊断行已删除、工具已重新构建；删除后同一条命令仍 exit 0 且不再打印 DIAGDUMP。
