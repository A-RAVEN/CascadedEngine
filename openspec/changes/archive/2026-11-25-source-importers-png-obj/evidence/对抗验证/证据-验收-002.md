# 证据-验收-002：Texture2D.Parse / Mesh.Parse 读回在 C++ 用例里不可达

面：① PNG 像素逐字断言。severity：misleading。

## 工件原文

- `specs/source-importers-png-obj/spec.md:5`：「落盘文件经 `Texture2D.Parse` 读回 MUST 与源 PNG 解码像素逐字一致。」
- `specs/source-importers-png-obj/spec.md:19`：「落盘经 `Mesh.Parse` 读回顶点/索引 MUST 与写死期望逐字一致。」
- `tasks.md:20`：「断言 ② 落盘存在 + Texture2D.Parse/Mesh.Parse 读回像素/顶点/索引==写死期望（逐字节）……」

## 命令与真实输出

```powershell
Select-String -Path 'Scripting\Managed\Assets\*.cs' -Pattern 'Texture2D\.Parse|Mesh\.Parse|internal static Payload Parse'
```

真实输出：

```text
AssetDatabase.cs:111: return new ParsedAsset { Kind = AssetKind.Texture2D, Texture = Texture2D.Parse(bytes, path) };
AssetDatabase.cs:115: return new ParsedAsset { Kind = AssetKind.Mesh, MeshPayload = Mesh.Parse(bytes, path) };
Mesh.cs:84: internal static Payload Parse(byte[] bytes, string sourcePath)
Texture2D.cs:75: internal static Payload Parse(byte[] bytes, string sourcePath)
```

`Parse` 是 `internal static`，唯一调用方是 C# 的 `AssetDatabase.Load`；Tester 是 C++ 进程，没有绑定能调到 C# 类型。仓库里 C# 只有一个工程：

```powershell
Get-ChildItem Scripting -Recurse -Filter *.csproj | Select-Object -ExpandProperty FullName
```

真实输出：

```text
E:\Projects\CascadedEngine\Scripting\Managed\Scripting.Managed.csproj
```

没有 C# 单测工程；`ResourceAssetProbe` 的 phase 机只使用固定的 `Assets/Probe.tex` / `Assets/Probe.mesh`（`Scripting/Managed/ResourceAssetProbe.cs:33` 一带），没有「给一个路径、调 Load 并输出读数」的通用阶段。

## 结论

tasks 3.1 只点名新增 `TestSourceImporters`（C++，`Main.cpp` + `--list`），没有新增 C# 探针阶段或读数文件；照字面实现时，「Texture2D.Parse/Mesh.Parse 读回」没有执行主体。实现者最可能退化为 C++ 直接读 `.tex`/`.mesh` 文件字节——这对像素/顶点仍是有效对照，但规范写死的「Parse 往返」没有验收。要么补 C# 读数通道，要么把判据改写成「C++ 读 CATX/CAMH 载荷 + C# Load 往返读数」两条。
