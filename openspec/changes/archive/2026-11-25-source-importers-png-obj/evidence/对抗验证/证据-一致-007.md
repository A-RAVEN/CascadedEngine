# 证据-一致-007：默认「仓库根/SourceAssets」在托管侧不可解析

## 主张

spec 的「源目录 MUST 可配（env 覆盖，默认仓库根/SourceAssets）」无法实现：托管代码没有仓库根概念（CWD 是 bin 目录），仓库里也没有 SourceAssets 目录；既有做法是 C++ 侧找到仓库根后把绝对路径经 env 传给 C# 导入器（两个着色器导入器 + 探针都是这个套路）。`ResourceImporter.h` 还要求 C# 导入器必须自己声明非空目录。三条约束合起来，spec 的默认值只能靠凭空猜路径。

## 为什么是 blocking

1. spec 的关键 MUST 没有实现路径：`GetSourceDirectory()` 返回 "SourceAssets" 时，C++ 侧会 `path("SourceAssets", generic_format)` 相对 CWD 解析（`ResourceImportingSystem.cpp` 第 57–59 行），CWD 是 `out/build/.../bin`，扫不到任何源。
2. 若返回空串（跟随调用方传入的根），则 C# 导入器又违反 `ResourceImporter.h` 第 27–28 行「不能留空」；而且 C# 反向实现读不到传入的根（同注释）。
3. 目录与夹具都不存在：tasks 3.1 用临时目录，3.2 却要「真实 PNG/OBJ」（见 主张-一致-008），默认目录始终无人创建。

## 改法

三处统一为可执行口径（推荐）：

- `CASCADED_SOURCE_IMPORTERS_DIR` 由 C++ 侧按 `rootPath` 拼绝对路径注入（与 `CASCADED_CSHARP_IMPORTER_SOURCE` 同款）；
- 未注入时导入器 `Produce()` 零产出并打一行 `[源导入] 未配置源目录：CASCADED_SOURCE_IMPORTERS_DIR（不做默认猜测）`；
- 新增任务：在仓库内建 `SourceAssets/` 并提交已知 PNG/OBJ 夹具；`CSharpHost/README.md` 环境变量表登记该变量与默认值。

若坚持「默认仓库根/SourceAssets」，则必须新增一条 C++ 侧任务：`ScanSourceDirectory` 之前把 `(rootPath / "SourceAssets")` 写进 env，并新增用例验证默认值真的被用上。

## 复核方式

1. 改后 `Select-String -Path 'openspec/changes/source-importers-png-obj' -Pattern '仓库根/SourceAssets'` 的每处都应能指到同一个注入机制，不能出现「C# 自己算仓库根」。
2. 跑 `TestSourceImporters` 时日志应打出实际使用的源根绝对路径；把它与 `rootPath` 对照。
3. 红态：不设 env 直接跑，导入器必须零产出 + 点名日志，不能去扫 CWD 下的 "SourceAssets"。
