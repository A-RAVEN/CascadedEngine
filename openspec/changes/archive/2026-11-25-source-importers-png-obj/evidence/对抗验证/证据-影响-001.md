# 证据-影响-001：门控接入 Host.Tick 无法把 C# 导入器交给管线

审查对象：`design.md` D1、`tasks.md` 2.3、`spec.md`「导入必须与注册分离」；对照 `Scripting/Managed/Host.cs`、`Scripting/Managed/ResourceImporterProbe.cs`、`GeneralResources/header/CAResource/ResourceImportingSystem.h`、`GeneralResources/private/ResourceImportingSystem.cpp`、`Test/GPUBackendTester/Main.cpp`、生成的 `resource_management__ResourceImporter.Bindings.cs`。

`design.md` 第 21 行（逐字引文）：

> 门控 `CASCADED_SOURCE_IMPORTERS=1`（默认关，Host.Tick 里 EnsureBound 后调；零行为不影响现有用例）。

`tasks.md` 2.3（逐字引文）：

> 门控接入 Host.cs（EnsureBound 后调两导入器 Tick，默认关零行为）+ 管线 ScanSourceDirectory 拉取注册落盘（复用既有管线，不改接口）。验收：构建过；门控关现有用例零差异；门控开导入→② CAAssets/Textures/*.tex + Meshes/*.mesh 落盘 + HasResource 真。

>
> `ResourceImporterProbe.Tick(s_api);`

## 2. C# 侧没有任何 ScanSourceDirectory / AddImporter 绑定

查询命令（pwsh，只读）：

```powershell
Get-ChildItem 'E:\Projects\CascadedEngine\Scripting' -Recurse -Filter *.cs |
  Select-String -Pattern 'ScanSourceDirectory|AddImporter|ResourceImportingSystem'
```

输出（全部命中，只有一句注释）：

```text
Scripting\Managed\Assets\AssetDatabase.cs:13: /// 同构（`ResourceImportingSystem.cpp` L80-92）。MUST NOT 先释放再读文件：那会让损坏 / 缺失文件
```

`ResourceImportingSystem.h` 全文只有三行虚函数，且类上没有反向绑定标注（逐字引文）：

> `class ResourceImportingSystem`
>
> `virtual void AddImporter(ResourceImporter* importer) = 0;`
>
> `virtual void ScanSourceDirectory(const castl::string& sourceDirectory) = 0;`

对比同目录的 `ResourceImporter.h` / `IResource.h` / `IResourceFactory.h` 都带 `CA_BIND_REVERSE()`，`ResourceImportingSystem.h` 没有——它不投射到 C#。

## 3. AddImporter / ScanSourceDirectory 的现有调用点（全在 C++）

`TestCSharpImporter` 的做法（逐字引文）：

> `resource_management::ResourceImporter* csharpImporter =`
>

工件 `design.md` / `tasks.md` 里没有等价的读数通道或句柄交接步骤（新门控只有 `CASCADED_SOURCE_IMPORTERS` 与 `CASCADED_SOURCE_IMPORTERS_DIR` 两个名字）。

## 5. EnsureBound 不绑导入器需要的三张反向表

`ResourceImporterProbe.cs`（逐字引文）：

> `private static void BindReverseTables(EngineApiMirror* api)`
>
> `BindOne(api, EngineApiBindings.ResourceManagement__ResourceImporterInterfaceId, "ResourceImporter",`
>
> `BindOne(api, EngineApiBindings.ResourceManagement__ResourceImporterProductionsInterfaceId,`
>
> `BindOne(api, EngineApiBindings.ResourceManagement__ResourceInterfaceId, "IResource",`

这个方法只在探针门控内被调用（逐字引文）：

> `if (Environment.GetEnvironmentVariable(ProbeVariable) != "1")`
>
> `{`
>
> `return;`
>
> `}`

生成的 `resource_management__ResourceImporter.Bindings.cs` 对未绑表直接抛（逐字引文）：

> `if (CreateImplSlot == null) { throw new InvalidOperationException("反向接口 resource_management::ResourceImporter 的函数表还没绑定（先取表再调 Bind）"); }`

`Host.cs` 的 `EnsureBound` 只做窗口/系统表与渲染表（逐字引文）：

> `uint windowSize = s_api->GetInterfaceApi(InterfaceIdWindow, null, EngineApiBindings.TableVersion, 0, null, null);`
>
> `IWindowBindings.Bind(windowTable);`
>
> `IWindowSystemBindings.Bind(systemTable);`
>
> `BindRenderInterfaces();`

所以「EnsureBound 后调」既不保证三张反向表已绑，也不说明由谁绑。

## 6. 结论边界

本条只陈述「任务 2.3 只改 Host.cs 时落盘不可达」这一事实链；C++ 侧补 AddImporter + ScanSourceDirectory 可以把路走通，但那一步与句柄通道在工件里都不存在。
