## 命令与真实输出

在 `E:\Projects\CascadedEngine` 下只读解析现有两张 PNG 的 IHDR/IDAT（跳 2 字节 zlib 头，解压后逐行读滤波字节）：

```powershell
Get-FilterSet 'CAResources\Images\test.png'
Get-FilterSet 'CAResources\Images\vulkanlogo.png'
```

真实输出：

```text

vulkanlogo.png: 尺寸 1300x500 colorType=6 出现滤波类型=1,2,4
```

两张图都没有 Average（滤波类型 3）。`CAResources/Images` 下可作为源夹具的 PNG 只有这两张（`Get-ChildItem CAResources\Images\*.png` → `test.png`、`vulkanlogo.png`）；仓库没有 `SourceAssets` 目录（`Test-Path SourceAssets` → `False`）。

`stb_image_write.h` 的默认行为（`out/build/x64-debug/_deps/stb-src/stb_image_write.h`）：

> 1146-1169：`for (j=0; j < y; ++j) { … if (force_filter > -1) { filter_type = force_filter; … } else { // Estimate the best filter by running through all of them: … for (filter_type = 0; filter_type < 5; filter_type++) { … } … filter_type = best_filter; } … }`
> 69-70：`int stbi_write_png_compression_level; // defaults to 8; …` / `int stbi_write_force_png_filter; // defaults to -1; set to 0..5 to force a filter mode`

即：不显式设置 `stbi_write_force_png_filter` 时，每行滤波是 0..4 里按熵挑出来的，不保证覆盖 Average；Tester 已包含 `stb_image_write.h`（`Test/GPUBackendTester/Main.cpp:61`）并已有多处 `stbi_write_png` 调用，具备强制滤波的手段，但工件没写要用。

## 结论

「五种滤波各覆盖一例」目前只是验收文案：没有夹具能核到滤波类型，也没有断言要求五种都出现。只实现 None 并把数据原样拷贝的解码器、甚至把 Sub/Up/Average/Paeth 全写成恒等，都可以让「写死像素」断言全绿。要让它能失败，必须把五张夹具的滤波类型与期望像素一起写死，并让测试自己解析 IDAT 断言滤波集合等于 `{0,1,2,3,4}`。
