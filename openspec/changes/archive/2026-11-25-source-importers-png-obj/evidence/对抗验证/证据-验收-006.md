# 证据-验收-006：「MUST NOT 落盘垃圾」没有文件系统断言

面：③ 红态与异常可观测性。severity：minor。

## 工件原文

- `specs/source-importers-png-obj/spec.md:15`：「MUST 抛 AssetFormatException 点名路径与原因；MUST NOT 落盘垃圾资产或静默返回空。」
- `specs/source-importers-png-obj/spec.md:29`：「MUST 抛 AssetFormatException 点名路径与原因；MUST NOT 落盘垃圾或静默。」
- `tasks.md:20`：「红态：坏 PNG/坏 OBJ→AssetFormatException 点名……验收：--list 含 TestSourceImporters；独立进程过；红态各能红（evidence/3.1-*.txt）。」

## 命令与真实输出

```powershell
$h = Select-String -Path 'openspec\changes\source-importers-png-obj\tasks.md' -Pattern '垃圾|不落盘|旧资产|不存在'
if ($h) { $h } else { '无匹配' }
```

真实输出：

```text
无匹配
```

tasks 里没有任何「坏文件对应的输出路径不存在」「HasResource 为假」「旧资产仍在」的断言；`HasResource 真` 只出现在正控（2.3/3.1）。

## 结论

红态只要「能红」就算过：一个抛异常后仍留下半截 `.tex`/`.mesh`、或把旧资产毁掉的实现，只要异常本身被断言到，验收不会发现。MUST NOT 的最关键一半（不落盘垃圾/不毁旧资产）没有被核。加两条 `Test-Path` + `HasResource` + 旧字节比对的断言即可让它可失败。
