# 证据-验收-011：list-assets 断言没有绑到导入产物

面：⑤ 资产浏览器联动。severity：misleading。

## 先回答「扩展名映射是否真在 editor-asset-browser D4」

是。当前生效规范 `openspec/specs/editor-asset-browser/spec.md:44` 写「种类映射 MUST 覆盖已知扩展名（.shLib/.tex/.mesh/.res），未知扩展名 MUST 落默认种类而非报错」；代码在 `Scripting/Managed/Editor/AssetDisplay.cs:111-112`：

```text
[".tex"] = "texture",
[".mesh"] = "mesh",
```

所以 `.tex`→`texture`、`.mesh`→`mesh` 的映射真实存在，`source-importers` 的 design D4 引用这一条没有造假。

## 工件原文

- `tasks.md:20`：「……资产浏览器 list-assets 含 kind=texture/mesh registered=true 条目……」

没有点名条目 `path` / `nodeId` / `sizeBytes`，也没有要求该条目就是本次导入的产物。

## 既有先例证明这条断言可以「无导入」变绿

`Test/GPUBackendTester/Main.cpp:6410` 的 TestEditorAssetBrowser 预置夹具：

```text
{ "Assets/Registered.tex", 142, "texture", "2024-03-04T05:06:07.0000000Z", 2024, 3, 4, 5, 6, 7, true },
```

`Main.cpp:6443-6449` 用探针工厂把任意资源登记到同一个 `.tex` 路径：

```text
if (!ctx.pResourceManagingSystem->CreateResource("AssetBrowserProbe", "Assets/Registered.tex"))
...
if (!ctx.pResourceManagingSystem->HasResource("Assets/Registered.tex"))
```

`list-assets` 的 `kind` 只看扩展名、`registered` 只看 `HasResource(相对路径)`，所以只要测试先注册两个探针资源到 `Textures/Fake.tex` / `Meshes/Fake.mesh`，这条断言就满足——即使导入器完全没产条目。

## 结论

该断言能失败（条目缺失/registered=false 会红），但它证明不了「导入→浏览器联动」：没有点名路径，也没有排除探针注册或上一次运行遗留的文件。需要写死两条 `path/nodeId`（`Textures/<夹具名>.tex`、`Meshes/<夹具名>.mesh`）、`kind`、`registered=true` 与 `sizeBytes`（例如 4×4 RGBA 的 CATX = 28+64 = 92 字节），并断言恰好这两条。另：`list-assets` 是 WebSocket 命令，3.1 还需写明启动 EditorService（`CASCADED_EDITOR=1`、专用端口、`CASCADED_EDITOR_ASSET_ROOT` 指到资源根、发请求等 result），照 `TestEditorAssetBrowser` 的 `Main.cpp:6480` 起写法；否则这条断言本身不可执行。
