# 证据-一致-004：design D4 的「工厂 + AssetDatabase」路径＝在 Produce 里调注册表

## 主张

design D4 给了两条并列路径，其中第一条「经 Texture2DFactory/MeshFactory 的 Create 入队 + AssetDatabase 出队填数据」必然在导入器 Produce 内触碰注册表门面：`AssetDatabase.Create` 的第一行就是 `m_registry.CreateResource(typeName, path)`，而门面 `CreateResource` 的定义就是「查工厂 → Create → 包 shared_ptr → 注册」。这与同一 change 的 spec「导入器 MUST NOT 调注册表、注册由管线做」冲突；而且工件没有任何任务去改 AssetDatabase/工厂或做工厂注册/门面绑定。

## 逐字引文

> 导入器 NextResource 交出 Texture2D/Mesh（经 Texture2DFactory/MeshFactory 的 Create 入队 + AssetDatabase 出队填数据，沿用 csharp-resource-asset-foundation D4/D5 模式；或直接 new 资产填数据交迭代器，由管线 CreateProxy 注册）。

`Scripting/Managed/Assets/AssetDatabase.cs`：

`openspec/specs/csharp-resource-registry/spec.md` 第 49 行：

## 为什么是 blocking

1. 与 spec 的核心断言（导入/注册分离）相反；实现者按 D4 第一条做就违反 spec，按 spec 做就违反 design D4。
2. 既有 resource-importer 规范的「产出所有权」要求：C# 导入器 NextResource 返回的新对象 MUST 经 `CreateProxy`（新对象尚无代理/借用句柄，MUST NOT 用 ResolveImpl）；走 AssetDatabase 的新对象已经有代理（注册表持有），再交给管线会二次代理/二次所有权，机制上不成立。
3. 缺件：若要这条路成立，必须改 AssetDatabase（暴露填数据/不注册的新建）、增加工厂注册与门面绑定任务——工件的 Impact 与 tasks 都没有，属于「任务清单不可完成」。
4. 判据假绿：五写入口 grep 只查字面名字，间接调用不出现名字，按 spec 验收会通过却违反它的意图。

## 改法

- design D4 删掉工厂/AssetDatabase 分支，只留「直接 new → 填字段 → 交迭代器 → 管线 CreateProxy 注册」。
- tasks 2.1/2.2 的验收加一条 grep：导入器文件里 `AssetDatabase`、`IResourceRegistry`、`IResourceRegistryBindings`、`CreateResource`、`ReleaseResource`、`RegisterResource`、`GetOrLoadResource`、`GetOrNewResource` 全部 0 命中；再加一条「Produce 内只做文件 IO + 解码/解析 + new 资产」。
- proposal 依赖句删掉「资产工厂 + AssetDatabase」（或改成「复用导入器机制与管线」）。
