# 证据-一致-008：3.2 视觉验收要「真实 PNG/OBJ」，但没有任何真实源与触发任务

## 主张

tasks 3.2 是编辑器类硬验收（AGENTS §2：截图 + `read_image` 核对，缺一即不通过），它要求「导入真实 PNG/OBJ 后交互打开资产浏览器」。可四份工件都没有给出真实源：仓库无 `SourceAssets/`，没有提交 PNG/OBJ 的任务，也没有规定交互运行时如何触发一次扫描导入（见 主张-一致-011）。3.1 的夹具明确只在临时目录、且 spec 要求不动用户真实源。3.2 因此无法执行。

## 为什么是 blocking

1. 3.2 是「没有截图无条件不通过」的硬验收，而它依赖的源文件不存在于任何已定义位置；实施者只能临场编造输入，验收对象因此不受控。
2. 即使编造，也绕不开「谁触发一次导入」：交互模式的唯一启动扫描发生在托管首个 Tick 之前（见 证据-一致-011），门控放在 Host.Tick 根本赶不上；要 3.2 成立，必须先补 C++ 侧接线任务（或在测试里复用 `TestCSharpImporter` 式的 AddImporter+Scan 路径）。
3. spec 又写着「测试用临时目录……MUST NOT 动用户真实源」，所以把夹具塞进用户 CAAssets 也不合规。

## 改法

- 方案 A（推荐）：加一条任务在仓库建 `SourceAssets/` 并提交两份已知夹具（给出 PNG 尺寸/像素、OBJ 顶点/索引的写死期望），3.2 直接用它；同时在 spec 里补一句「仓库自带的 SourceAssets 夹具是 ① 源，允许被导入」。
- 方案 B：3.2 改成「用临时源目录 + 3.1 同一份夹具，资源根 `CASCADED_EDITOR_ASSET_ROOT` 指向临时目录」，写清命令行与门控；spec 的「真实 PNG/OBJ」改成「已知 PNG/OBJ 夹具」，并把「不动用户真实源」的约束保留。
- 无论哪条，3.2 都要写明触发导入的方式（谁 AddImporter、谁 Scan），否则截图窗口里不会出现 texture/mesh 条目。

## 复核方式

1. 改后 `Test-Path SourceAssets`（方案 A）或 3.2 里点名的临时目录构造步骤（方案 B）必须可照着执行。
2. 按 3.2 的命令真实打开界面截图，`read_image` 必须看到 `Textures/*.tex` 与 `Meshes/*.mesh` 且「已注册」列为真；若列表为空或只有 shLib/res，判 3.2 不通过。
3. 检查 `CAAssets` 五份既有文件未被移动/删除（对照上面 `Get-ChildItem` 列表）。
