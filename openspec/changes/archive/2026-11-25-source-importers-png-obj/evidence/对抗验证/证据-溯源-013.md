# 证据-溯源-013：两道完整性校验都不做，坏像素会被静默吞下

> 定位以逐字引文为准；行号是 2026-11-24 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-013
- 攻击面：无中生有（把「解码成功」当成「数据完好」，凭空省掉两道校验）
- 严重度：blocking（与 D5「失败可见、不静默」冲突，且红态覆盖不到）
- 工件：`design.md:28`、`design.md:40`、`tasks.md:9`、`spec.md:5`、`spec.md:15`
- 一句话：zlib 的 Adler-32 明确不校验，PNG 每块的 CRC32 全文没提；损坏但长度合法的 PNG 会静默变成错误贴图。

## 二、工件原文

`design.md:28`（节选）：

> + IDAT（zlib 流，跳 2 字节 zlib 头用 `DeflateStream` 解压，**忽略 4 字节 adler32**）

`design.md:40`（D5 节选，坏 PNG 的清单）：

> 坏 PNG（签名/IHDR/滤波/长度不符、不支持的位深/隔行）/坏 OBJ（缺顶点/索引越界/空）抛 `AssetFormatException`（路径+原因）

`tasks.md:9`（红态节选）：

> 坏 PNG（**错签名/截断**）抛 AssetFormatException（evidence/1.1-*.txt）

`spec.md:15`（场景节选）：

> **WHEN** 源 PNG 签名错/截断/不支持位深
> **THEN** MUST 抛 AssetFormatException 点名路径与原因；MUST NOT 落盘垃圾资产或静默返回空

## 三、规范原文

RFC 1950（zlib）第 353-354 行：

> A compliant decompressor must check CMF, FLG, and ADLER32, and
> provide an error indication if any of these have incorrect values.

RFC 2083（PNG）第 1657-1663 行：

> The check value stored at the end of the zlib datastream is
> calculated on the uncompressed data represented by the datastream.
> ...
> The zlib check value is useful
> mainly as a cross-check that the deflate and inflate algorithms are
> implemented correctly.  Verifying the chunk CRCs provides adequate
> confidence that the PNG file has been transmitted undamaged.

即：PNG 作者认为「校验块 CRC 就够」，而本工件既跳过 zlib 校验值，也没提块 CRC——两条完整性通道同时关闭。

## 五、结论与建议

- 具体可复现的坏路径：一个 IDAT 里含 deflate stored（未压缩）块、长度与 IHDR 完全对得上的 PNG，把其中一个像素字节改掉。解码器：长度校验通过、滤波重建通过、逐字节比对自然对不上——但如果测试期望是从解码结果抄的，就发现不了；若测试用写死期望，这类文件也根本不在红态清单里。
- 即使 deflate 是压缩块，很多单比特改动仍能解出数据（尤其在 stored 块或 Huffman 表未命中的位置），结果同样静默。
- 建议改法（判据只加严）：
  1. `design.md:28` 把「忽略 adler32」改成「校验 Adler-32」；最省事的实现是改用 `ZLibStream`（net8.0 自带，自动校验头与 Adler-32）；
  2. 增加「逐块校验 IDAT 的 CRC32」，不符即抛 `AssetFormatException` 点名块与期望/实际值；
  3. 红态补一条：「IDAT 内容改一个字节、CRC 不变/不符」的 PNG 必须抛异常，evidence 落盘实测输出；
  4. `design.md:40` / `tasks.md:9` 的坏 PNG 清单补上「校验值不符」。
- 严重度定 blocking 的理由：这不是性能取舍，而是「失败可见」这一条 MUST 的直接漏洞；实现按现有工件写出来会在正常路径上静默接受损坏输入。

## 六、边界

- 核了：RFC 1950 的合规解压器要求、RFC 2083 关于 zlib 校验值与块 CRC 的说明、工件里 CRC/adler 的出现位置。
- 没核：没有造损坏 PNG 实测（只读环境，禁跑构建/测试）；没有评估 `DeflateStream` 对 stored 块的容错细节（该细节只影响「多大比例的单比特改动会被 deflate 自身拒绝」，不改变「没有校验就无法发现」的结论）。
