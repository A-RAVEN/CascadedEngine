## 注册链的既有先例

`CSharpHost/README.md:379`：

> `// 注册（C++ 侧）：强句柄 + ResolveImpl 借用指针 → ResourceImportingSystem::AddImporter`

`Test/GPUBackendTester/Main.cpp:8850-8887`（TestCSharpImporter）逐字展示了这条链：

> `// ---- ① C# 导入器经 CreateImpl 注册（强句柄 → ResolveImpl 借用指针 → AddImporter）----`
> `tick("create-importer");`
> `const uint64_t importerHandle = readU64("importer_handle");`
> `resource_management::ResourceImporter* csharpImporter = static_cast<resource_management::ResourceImporter*>(importerTable->ResolveImpl(importerHandle));`
> `ctx.pImportingSystem->AddImporter(csharpImporter);`
> `ctx.pImportingSystem->ScanSourceDirectory(ctx.resourcePath);`

这条先例要求 C# 先把 `importer_handle` 写进读数文件，C++ 再读、再注册、再扫描。source-importers 的 tasks 2.1/2.2/2.3/3.1 没有写这个读数文件、没有写 C++ 注册步骤、也没有写重扫；启动时那次 `ScanSourceDirectory(ctx.resourcePath)` 在 `Main.cpp:10588`，早于任何测试用例与 C# 导入器的存在。

## 结论

设 `CASCADED_SOURCE_IMPORTERS=1` 后，C# 侧最多造出两个导入器对象与句柄，管线根本不知道它们存在；不会发生第二次 `ScanSourceDirectory`，② 不会出现 `.tex`/`.mesh`。2.3/3.1 的「门控开导入→落盘」没有可执行的驱动步骤，tester 只能空等或永远失败。必须补一条 C# 读数 + C++ ResolveImpl/AddImporter/ScanSourceDirectory 的任务（或 CSharpHost 的等价 C++ 钩子）。
