# 证据-溯源-004：Mesh 的 stride 24 / 偏移 0 / 偏移 12 有逐字出处

> 定位以逐字引文为准；行号是 2026-11-24 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-004
- 攻击面：无中生有（顶点布局数字是否凭空写死）
- 严重度：falsePositive（三个数字与场景侧常量逐字一致）
- 工件：`design.md:7`、`design.md:32`、`tasks.md:10`、`spec.md:19`
- 一句话：24 / 0 / 12 不是编的，`Mesh.cs` 与 `SceneRenderer.cs` 各有一份同值常量，且注释互相点名。

## 二、工件原文

`design.md:7`（节选）：

> `Mesh`（VertexData 位置 float3+色 float3 stride 24 / IndexData uint32，CAMH 格式，HeaderSize 32，布局与 SceneRenderer 三常量逐字一致）

`design.md:32`（节选）：

> 顶点布局**位置 float3 偏移 0 + 色 float3 偏移 12 步长 24**（与 Mesh.VertexStride/PositionOffset/ColorOffset 逐字一致）

`spec.md:19`（节选）：

> 产出 `Mesh`（VertexData 位置 float3 偏移 0+色 float3 偏移 12 步长 24，与 Mesh.VertexStride/PositionOffset/ColorOffset 逐字一致…）

## 五、结论与建议

- 不成立（falsePositive）：三个数字都有逐字出处，且「与 SceneRenderer 三常量逐字一致」这句对照是真的。
- 判据建议（不改也算过）：tasks 1.2 的验收已经要求「与 Mesh 三常量逐字一致」，但更硬的做法是断言 `Mesh.VertexStride == 24`、`Mesh.PositionOffset == 0`、`Mesh.ColorOffset == 12` 三个写死值，而不是「等于 Mesh 常量」——后者在有人同时改两处时会一起绿。

## 六、边界

- 核了：Mesh.cs、SceneRenderer.cs、EditorSceneView.cs 三处常量与 Mesh.cs 的布局注释。
- 没核：没有跑构建，也没读着色器输入布局的 GLSL/HLSL 侧；本主张只核「数字有出处、对照为真」。
