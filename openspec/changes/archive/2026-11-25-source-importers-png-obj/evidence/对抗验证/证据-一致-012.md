# 证据-一致-012：「调两导入器 Tick」不存在，反向表/代理注册任务也缺

## 主张

tasks 2.3 写「门控接入 Host.cs（EnsureBound 后调两导入器 Tick，默认关零行为）」。但 `ResourceImporterBase` 只有四个抽象方法（`GetTags` / `GetSourceDirectory` / `GetDestDirectory` / `Produce`），没有 Tick；导入器也不会自动进入原生列表（唯一入口 `ResourceImportingSystem::AddImporter`，C++ 独占）。先例 `ResourceImporterProbe` 的 Tick 只做「建对象 + 写读数」，真正 AddImporter 由 C++ 测试完成，且探针还显式绑了三张反向表。tasks 2.x / 3.1 没有绑表、建实例、交给原生的任何一条，Host 里的「Tick」无物可调。

## 为什么是 blocking

1. 任务字面要求的东西（导入器上的 Tick）在接口层不存在；实施者要么自己发明「Tick」语义（并把它塞进 Host 的 if 分支），要么把任务改写成别的东西 —— 两者都会让 2.3 的验收「门控开导入→落盘+HasResource 真」无据可依。
2. 缺三件必要接线：① 反向表绑定（ResourceImporter / Productions / IResource）——不绑则 `Create` 与 `NextResource` 的 `CreateProxy` 都会因缺表失败（先例 `ResourceImporterProbe` 专门写了 `BindReverseTables` 并在失败时点名）；② 导入器实例的创建与句柄生命周期；③ 把实例交给原生 `AddImporter`。
3. `Produce` 返回的 C# 资源要经 `CreateProxy` 才有原生代理（`resource-importer` 第 24 行），这一步与「绑 IResource 表」绑定在一起，tasks 里完全没有。

## 改法

把 2.3 拆成三条并各给验收：

- 2.3a：`Host.Tick` 门控分支创建 `PngTextureImporter` / `ObjMeshImporter`，按 `ResourceImporterProbe.BindReverseTables` 绑三张反向表，拿 `ResourceImporterBindings.Create` 的强句柄并写读数（门控关时零行为、零日志）。
- 2.3b：C++ 侧（`TestSourceImporters` 或启动接线）`ResolveImpl(句柄)` → `AddImporter` → `ScanSourceDirectory`；断言 `Produce` 被调用 1 次、产出两条路径。
- 2.3c：`NextResource` 的 `CreateProxy` 生效：断言保活计数 1、注册后 `HasResource` 真、`SerializeAll` 后文件存在；坏文件路径断言 `Produce` 抛 `AssetFormatException` 且管线不中止其它导入器。

## 复核方式

1. 改后 `Select-String -Path 'openspec/changes/source-importers-png-obj/tasks.md' -Pattern 'BindReverseTables|ResourceImporterBindings.Create|AddImporter'` 至少各 1 命中。
2. 跑 `TestSourceImporters`：日志里应出现「三张反向表绑定成功」与「AddImporter 后 Produce 调用 1 次」的读数。
3. 红态：删掉 IResource 表绑定，`NextResource` 的 `CreateProxy` 必须失败并点名叫「取 IResource 反向函数表失败」，以此证明绑表任务不是可选项。
