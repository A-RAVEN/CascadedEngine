# 证据-验收-009：「现有用例零差异」证明不了门控关零行为

面：④ 门控与管线。severity：misleading。

## 工件原文

- `specs/source-importers-png-obj/spec.md:33`：「门控 `CASCADED_SOURCE_IMPORTERS` 默认关 MUST 零行为（现有用例零差异）。」
- `specs/source-importers-png-obj/spec.md:37-38`：「**WHEN** 未设 CASCADED_SOURCE_IMPORTERS=1 跑现有用例 / **THEN** 导入器 MUST 零行为；现有用例 name+status MUST 与基线零差异。」
- `tasks.md:25`：「验收：零差异 + CoreTests 26 + 基线 0/0/0。」

## 命令与真实输出

```powershell
$b = Get-Content 'openspec\changes\archive\2026-11-24-editor-web-render-spike\evidence\4.1-全量-d3d12.json' -Raw | ConvertFrom-Json
"基线条目数: $($b.Count)"
"第 1 条: $($b[0] | ConvertTo-Json -Compress)"
```

真实输出：

```text
基线条目数: 22
第 1 条: {"name":"TestSimpleTriangle","status":"pass","duration_ms":57,"exit_code":0}
```

基线每条只有 `name/status/duration_ms/exit_code`；tasks 4.1 只要求 `name+status` 与基线零差异。

## 结论

这个判据抓不到以下「非零行为」：① 默认开的导入器扫一个不存在的 `SourceAssets`，只打 WARN（stdout 不在 name+status 里）；② 默认开的导入器把资源根里已有资产按同字节重写（文件集合/内容不变，mtime 变但基线没有 mtime）；③ 默认开的导入器写自己的读数文件或临时文件（不影响测试结果）。反过来，门控永远关（包括 `CASCADED_SOURCE_IMPORTERS=1` 时也不工作）同样满足「现有用例零差异」。要证明「默认关零行为」，必须直接断言「不设 env 时没有源导入相关日志/读数/新文件/资源根变化」，并配一条门控开的正控证明开关真的能开。
