## 二、blocking 五条（按修复优先级）

| 编号 | 一句话 | 落点 |
|---|---|---|
| 主张-溯源-003 | 工件没写「所有 IDAT 块拼接成一条 zlib 流」；多 IDAT 的合法 PNG 会被只读首块的实现判坏，验收夹具也抓不到 | design D2 / tasks 1.1 / spec PNG 需求 |
| 主张-溯源-006 | 「4×4 PNG」与「五种滤波各覆盖一例」数字互斥：4 行最多 4 种滤波 | tasks 1.1 与 3.1 / design D6 |
| 主张-溯源-011 | 颜色类型 0（灰度）与 4（灰度+alpha）既不在支持面也不在拒绝面，8 位灰度 PNG 落进未定义分支 | design D2 / spec / tasks 1.1 |
| 主张-溯源-013 | 明确「忽略 adler32」，也从不提块 CRC：两道完整性校验都不做，损坏但长度合法的 PNG 静默变错误贴图 | design D2/D5 / tasks 1.1 红态 |
| 主张-溯源-015 | design D4 允许导入器用 `AssetDatabase`，而它内部就是 `CreateResource`/`ReleaseResource`/`SerializeAll`；「grep 五写入口 0」照样通过 | design D4 / tasks 2.1-2.2 / spec 第三条需求 |

| 主张-溯源-012 | RGB 补的 alpha 值、OBJ 默认顶点色都没钉死（design 用「如」），验收「逐字节一致」的期望可由实现自证 |

## 六、给复核者的三条提醒

1. **我没跑实现**：change 还没 apply，以上全部是对工件的静态核对；blocking 的修复都是改工件一句话或加一条夹具要求，不涉及产品代码。
