# 证据-影响-004：坏文件在管线边界变成 1012，且整轮扫描中止；adler32 被明确忽略

审查对象：`design.md` D2/D5、`spec.md` 两个「显式失败」场景、`tasks.md` 3.1 红态；对照生成的 `resource_management__ResourceImporter.Bindings.cs` / `.Bindings.cpp`、`GeneralResources/private/ResourceImportingSystem.cpp`。

## 1. 工件声称的失败形态

`design.md` D5（逐字引文）：

> 坏 PNG（签名/IHDR/滤波/长度不符、不支持的位深/隔行）/坏 OBJ（缺顶点/索引越界/空）抛 `AssetFormatException`（路径+原因），管线透出失败不静默灌垃圾。导入器 Produce 内解码失败 MUST 点名具体文件与原因（不吞异常返回空资产）。

`spec.md`（逐字引文）：

> **THEN** MUST 抛 AssetFormatException 点名路径与原因；MUST NOT 落盘垃圾资产或静默返回空

`tasks.md` 3.1（逐字引文）：

> 红态：坏 PNG/坏 OBJ→AssetFormatException 点名；门控关零行为。

## 3. C++ 代理：同一次 Produce 内把异常换成 1012 抛出

生成的 `resource_management__ResourceImporter.Bindings.cpp`（逐字引文）：

> `resource_management::ResourceImporterProductions* Produce() override`
>
> `{`
>
> `reportPendingError("Produce");`
>
> `if (m_slots.Produce == nullptr) { return nullptr; }`
>
> `void* created = m_slots.Produce(m_user);`
>
> `if (created == nullptr)`
>
> `{`
>
> `const std::string detail = takeImplementationError();`
>
> `setError(resource_management__ResourceImporter_ERROR_REVERSE_EXCEPTION, detail.empty() ? "反向工厂 Create 返回了空指针" : detail);`
>
> `reportPendingError("Produce");`
>
> `return nullptr;`
>
> `}`

以及（逐字引文）：

> `// 失败的可观测契约：错误先落槽，**下一次**注册线程调用把它抛出去（不静默继续）。`
>
> `throw cascaded_reverse::ReverseBindingError(code, message);`

→ 从 C++ 的 `ScanSourceDirectory` 调用方看，抛出的类型是 `ReverseBindingError`（错误码 1012，文本里带路径与原因），不是 `AssetFormatException`。

## 4. 整轮扫描中止，且跳过 SerializeAll

`ResourceImportingSystem.cpp`（逐字引文）：

> `castl::shared_ptr<ResourceImporterProductions> productions(`
>
> `importer->Produce(),`
>
> `[](ResourceImporterProductions* releasedProductions) { delete releasedProductions; });`
>
> `if (!productions)`
>
> `{`
>
> `CA_LOG_WARN("ScanSourceDirectory：导入器没有交出产出迭代器（标签 {}）", importer->GetTags());`
>
> `continue;`
>
> `}`
>
> `// 无论源目录在不在、导入器有没有产出：本轮的注册内容都要落盘（旧路径的早退曾跳过这里）。`
>
> `m_ResourceManagingSystem->SerializeAll();`

`Produce()` 抛 1012 时，函数在 `m_ResourceImporters` 循环里直接展开：后面的导入器不会再被调用，`SerializeAll()` 也不会执行（该函数没有 try/catch）。注意：`if (!productions)` 那条「警告后继续」只处理 `Produce` 返回 null 且代理没抛的情况——本条的路径是代理在同一次调用里先抛，所以连这条警告都到不了。

## 5. 明确忽略 adler32、全篇无 CRC 校验

`design.md` D2（逐字引文）：

> `PngDecoder.cs`：解析 PNG 签名 + IHDR（宽/高/位深 8/颜色类型 6 RGBA 或 2 RGB→补 alpha）+ IDAT（zlib 流，跳 2 字节 zlib 头用 `DeflateStream` 解压，忽略 4 字节 adler32）+ 逐扫描线滤波重建（None/Sub/Up/Average/Paeth 五种）→ RGBA8 像素（宽×高×4）。

`design.md` D2 末句（逐字引文）：

> 只支持 8 位深非隔行（Adam7 隔行/16 位/调色板明确抛 AssetFormatException 点名不支持）。

全文（design / spec / tasks）没有出现「CRC」或「chunk 校验」；`spec.md` 的失败面只列签名错/截断/不支持位深。像素数据损坏但仍能 inflate 的 PNG 不在任何失败分支里。

## 6. 结论边界

本条陈述三点可核事实：托管异常在反向代理边界必然变成 1012；`Produce` 抛出会中止整轮扫描并跳过落盘；解码器按设计不校验 adler32 与 PNG 分块 CRC。它不判断实现者是否会在 `Produce` 内自行 catch 后重新抛——无论怎么做，边界类型仍是 1012。
