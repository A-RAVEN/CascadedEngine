# 证据-一致-002：读回判据与既有 resource-importer 规范的「MUST NOT 验加载回读」对撞

## 主张

新 spec 把「落盘文件经 `Texture2D.Parse` / `Mesh.Parse` 读回」写成 MUST，但生效中的 `openspec/specs/resource-importer/spec.md` 明写 C# 资源 **只**验 Serialize 写 + 注册 + GetResource 同一实例、**MUST NOT 验加载回读**；proposal 的 Modified Capabilities 又声称「无（……不改其要求）」。这是一条同时打在「spec 对 spec」和「spec 对 proposal 声明」上的矛盾，必须在 apply 前裁决。

## 为什么是 blocking

1. 既有规范是「生效规范」（`openspec/specs/` 下唯一算数的地方）。新 change 的 ADDED 规范与它冲突时，change 必须显式 MODIFIED，否则归档后两条 MUST 同时存在、互相否定。
2. 判据执行层面也会打架：既有规范的验收场景 `TestCSharpImporter` 明确「不验回读」；新用例若真去 `Parse` 读回，两个用例对 C# 资源的验收口径就分叉了。
3. 「裸字节自解析」与「注册表加载回读」可以调和，但工件没有做这个区分；proposal 又声明不改既有要求，等于把矛盾留给实施者临场发明解释。

## 改法

- 首选：proposal 的 Modified Capabilities 加 `resource-importer`，spec 里加一条 MODIFIED Requirement，逐字写「允许对落盘**原始字节**做 C# 自解析（不经注册表、不调 Deserialize / GetOrLoadResource）；既有『不验加载回读』对注册表路径继续有效」。同时把 `docs/testing.md` 里 `TestCSharpImporter` 的说明补一句边界。
- 备选：删掉新 spec 与 tasks 3.1 的 Parse 读回判据，改成 C++ 按 CATX/CAMH 头部读文件字节（与 `csharp-asset-layer` 的「C++ 侧读文件」同款），proposal 的「不改其要求」即可保持成立。

## 复核方式

1. `Select-String -Path 'openspec/specs/resource-importer/spec.md' -Pattern 'MUST NOT 验加载回读'` 仍应命中（既有规范未被删改）。
2. 改后 `openspec validate source-importers-png-obj` 仍 valid；若加了 MODIFIED，`openspec show` 应能看到 resource-importer 的 delta。
3. 新用例若保留读回，日志里必须能读出「没有调 Deserialize / GetOrLoadResource」的证据（例如 C# 探针里不引用这两个符号，或 C++ 侧断言 1013 未被触发）。
