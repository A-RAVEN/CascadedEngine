# 证据-溯源-001：spec 的「DeflateStream zlib」措辞与 DeflateStream 的真实形态不符

> 定位以逐字引文为准；行号是 2026-11-24 审查时实测值，工件修订后会漂移，复核请用引文 grep。

## 一、主张摘要

- 主张编号：主张-溯源-001
- 攻击面：无中生有（把一个需要两步的外部 API 用法写成一步）
- 严重度：misleading（design 写对了；spec 正文没写「跳头」，按字面会做错）
- 工件：`specs/source-importers-png-obj/spec.md`、`design.md`
- 一句话：DeflateStream 只吃 raw deflate，不吃 zlib 头/尾；spec 的「DeflateStream zlib」把这层事实抹掉了。

## 二、工件原文

`specs/source-importers-png-obj/spec.md:5`（节选）：

> MUST 有 C# `PngTextureImporter : ResourceImporterBase`，门控 `CASCADED_SOURCE_IMPORTERS=1`（默认关零行为），扫源目录 `.png`，**纯 C# 解码**（DeflateStream zlib + PNG 五种滤波重建，8 位 RGBA/RGB→RGBA8，不调 native stb、不动绑定面）

`design.md:28`（节选）：

> `PngDecoder.cs`：解析 PNG 签名 + IHDR（…）+ IDAT（zlib 流，跳 2 字节 zlib 头用 `DeflateStream` 解压，忽略 4 字节 adler32）+ 逐扫描线滤波重建（None/Sub/Up/Average/Paeth 五种）

## 三、事实出处（.NET 源码与文档）

`CompressionFormat.cs`（dotnet/runtime，main 分支；经 GitHub contents API 取回）：

> /// <summary>Raw deflate format (no header/trailer).</summary>
> Deflate,
> /// <summary>ZLib format (zlib header/trailer).</summary>
> ZLib,

同一文件的 `ResolveWindowBits`：

> CompressionFormat.Deflate => -windowLog,
> CompressionFormat.ZLib => windowLog,

`DeflateStream.cs:35`：

> public DeflateStream(Stream stream, CompressionMode mode, bool leaveOpen) : this(stream, mode, leaveOpen, ZLibNative.Deflate_DefaultWindowBits)

`ZLibStream.cs:29`：

> _deflateStream = new DeflateStream(stream, mode, leaveOpen, ZLibNative.ZLib_DefaultWindowBits);

Microsoft Learn：[DeflateStream](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.deflatestream) 只写「by using the Deflate algorithm」；[ZLibStream](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.zlibstream) 明确写「by using the zlib data format specification」。两者的窗口位在源码里分家（Deflate 走 `Deflate_DefaultWindowBits`、ZLib 走 `ZLib_DefaultWindowBits`），这就是 raw 与 zlib 的差别。

PNG 一侧：RFC 2083 第 5 章「Deflate/Inflate Compression」（本地下载 rfc2083.txt，第 1631-1637 行）：

> Deflate-compressed datastreams within PNG are stored in the "zlib" format, which has the structure:
>    Compression method/flags code: 1 byte
>    Additional flags/check bits:   1 byte
>    Compressed data blocks:        n bytes
>    Check value:                   4 bytes

## 五、结论与建议

- design.md 的写法（跳 2 字节 + 忽略尾部 4 字节）在机制上成立，不构成 blocking。
- spec.md 只写「DeflateStream zlib」，没有写「跳 2 字节头」。照 spec 字面实现会把 zlib 的 CMF/FLG 两字节当成 deflate 块头读，必然失败。建议把 spec 改成与 design 同义的表述：「IDAT 是 zlib 流，跳过 2 字节 zlib 头后用 DeflateStream（raw deflate）解压」。
- 顺带：net8.0 已有 `ZLibStream`（.NET 6 起），可直接吃 zlib 并校验 Adler-32；用它是本条的替代实现，但改不改不影响本主张的成立。
