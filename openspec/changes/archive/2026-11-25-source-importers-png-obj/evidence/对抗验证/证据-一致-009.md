# 证据-一致-009：新门控/目录变量未登记 README，`check_csharp_host_readme.py` 必红

## 主张

design 与 tasks 都把新门控接进 `Host.cs`；但既有工具 `Tools/check_csharp_host_readme.py` 的判据 ④ 要求「`Host.cs` / `UserScript.cs` 里 `GetEnvironmentVariable("CASCADED_*")` 读到的每一个名字都在 README 环境变量表出现」，否则打印缺失项并退出 1。`CASCADED_SOURCE_IMPORTERS` 与 `CASCADED_SOURCE_IMPORTERS_DIR` 在 README 里 0 命中，而 tasks 4.1 的回归清单不含该脚本、四份工件也没有 README 更新任务。

## 逐字引文

> ④ 探针开关：`Host.cs` / `UserScript.cs` 里读的环境变量（`CASCADED_*`）每一个都在 README 的
> 环境变量表里出现。

## 为什么是 blocking

1. 这是既有工具的硬判据，不是风格问题：只要新门控按 design 写在 `Host.cs` 里，脚本就退出 1。
2. `docs/testing.md` 第 245 行把 `check_csharp_host_readme.py` 列进「必须退出码 0」的清单；tasks 4.1 的回归口径没有它，等于漏掉一条既有闸门。
3. 若实施者为了绿把门控读移到 `Assets/Importers/*.cs`（脚本不扫这些文件），则 design 的「Host.Tick 里调」被违反，且环境变量仍然无文档 —— 两种结局都不符合工件。

## 改法

1. 在 `CSharpHost/README.md` 环境变量表加两行：`CASCADED_SOURCE_IMPORTERS`（默认不设；语义、谁设置）、`CASCADED_SOURCE_IMPORTERS_DIR`（绝对路径；未设时的行为，MUST 零猜测）。
2. tasks 增一条「README 环境变量表登记 + `python Tools/check_csharp_host_readme.py` exit 0」，并把该读数写进 4.1 的证据文件名（例如 `evidence/4.1-README对账.txt`）。
3. 若采纳 主张-一致-007 的方案（C++ 注入 env），也仍要在 README 写清「谁设置」，因为该表是 CASCADED_* 的唯一对外说明。

## 复核方式

1. 改后 `(Select-String -Path 'CSharpHost/README.md' -Pattern 'CASCADED_SOURCE_IMPORTERS' | Measure-Object).Count` 应为 2（门控 + 目录）。
2. `python Tools/check_csharp_host_readme.py` exit 0，输出「问题 0 处」。
3. 红态：把 README 里新加的一行删掉再跑，脚本必须打印「README 的环境变量表缺这些开关：CASCADED_SOURCE_IMPORTERS」并退出 1。
