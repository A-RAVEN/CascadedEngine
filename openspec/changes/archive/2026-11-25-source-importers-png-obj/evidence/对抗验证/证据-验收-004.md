# 证据-验收-004：AssetFormatException 在 C++ 侧不可观测

面：③ 红态与异常可观测性。severity：Blocking。

## 工件原文

- `tasks.md:20`：「……红态：坏 PNG/坏 OBJ→AssetFormatException 点名；门控关零行为。」
- `design.md:40`：「坏 PNG（签名/IHDR/滤波/长度不符、不支持的位深/隔行）/坏 OBJ（缺顶点/索引越界/空）抛 `AssetFormatException`（路径+原因），管线透出失败不静默灌垃圾。导入器 Produce 内解码失败 MUST 点名具体文件与原因（不吞异常返回空资产）。」

tasks 3.1 的观测者是新 tester 用例（C++）；工件没有写这个用例怎么拿到托管异常类型。

## 逐字引文与源码事实

`CSharpHost/README.md:328-331`：

> **失败契约**：C# 覆写抛的异常在托管桥里被捕获（不穿过 C ABI），长度槽返回 `UINT64_MAX` 哨兵；代理中止（写路径**不写、不提交**）并把错误落槽，**下一次注册线程调用**抛 `cascaded_reverse::ReverseBindingError`（`Code()` = 1012，消息含反向标识与原始异常文本）。非注册线程调用被代理拒绝（1005，C# 覆写不会执行）。

`GeneralResources/private/ResourceImportingSystem.cpp:69-76`：

> `castl::shared_ptr<ResourceImporterProductions> productions(importer->Produce(), …);`
> `if (!productions) { CA_LOG_WARN("ScanSourceDirectory：导入器没有交出产出迭代器（标签 {}）", importer->GetTags()); continue; }`

`GeneralResources/private/ResourceImportingSystem.cpp:96`：

> `m_ResourceManagingSystem->SerializeAll();`

即：Produce 抛异常后，C++ 侧要么在后续调用上收到 1012，要么看到「没有交出产出迭代器」的 WARN 后继续，随后照常 SerializeAll；两种情况下 C++ 都拿不到 `AssetFormatException` 这个类型。

C# 侧已有捕获并写读数的先例：`Scripting/Managed/ResourceAssetProbe.cs:504-515` 的 `CaptureAssetFormatFailure` 把 `ex.GetType().Name` 与 `ex.Message` 写进读数，C++ 再断言读数。source-importers 的 tasks 没有对应的探针/读数通道。

## 结论

红态写成「→AssetFormatException 点名」，但照 tasks 3.1 的 C++ 用例写，断言不到该类型：只能断 1012 的 `ReverseBindingError` 与文本，或者断 WARN 日志。前者与工件字面不符，后者恰好会把「失败」当成「没产出」的静默路径。必须在导入器里捕获并写 `error_type/error_text` 读数后再抛，或把验收改成 1012 + 原文，否则这条红态无法按字面执行。
