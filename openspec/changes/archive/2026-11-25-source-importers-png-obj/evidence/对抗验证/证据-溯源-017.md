# 证据-溯源-017：`Texture2D.Parse` / `Mesh.Parse` 是 internal，tester 直接调不到

> 定位以逐字引文为准；行号是 2026-11-24 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-017
- 攻击面：无中生有（验收里点名的调用面在真实 API 上不可达）
- 严重度：misleading（有等价的公开路径 `AssetDatabase.Load`，但工件写的不是它）
- 工件：`spec.md:5`、`spec.md:19`、`tasks.md:20`
- 一句话：两个 `Parse` 都是 internal；C++ tester 要拿读数，必须经一个编进 C# 程序集的探针（或改用 public 的 `AssetDatabase.Load`）。

## 三、代码原文

`Scripting/Managed/Assets/Texture2D.cs:41` 与 `:75`：

> internal readonly struct Payload

`Scripting/Managed/Assets/Mesh.cs:48` 与 `:84`：

> internal readonly struct Payload
> …

`Scripting/Managed/Assets/AssetDatabase.cs:44-49`（公开的读回入口）：

> /// <summary>
> /// 自读加载（design D6）：`GetResourceFullPath` → C# 读文件 → 按魔数解析；
> /// 全部成功后才释放旧条目（若有）→ `CreateResource` → 出队 → 填数据。
> /// 文件缺失 / IO 错误 / 魔数或版本或长度不符一律抛 `AssetFormatException` 并点名路径与原因。

即：`Parse` 只能在 `Scripting.Managed` 程序集内部调，`Load` 是 public 的、内部会调 `Texture2D.Parse` / `Mesh.Parse` 并把数据填进返回的资产。

## 四、既有测试是怎么跨进程拿 C# 读数的

`Scripting/Managed/ResourceImporterProbe.cs:25-26` 与 `:135-145`：

> private const string ReadingsVariable = "CASCADED_CSHARP_IMPORTER_READINGS";
> …
> private static void Write(string key, object value)
> {
>     string path = Environment.GetEnvironmentVariable(ReadingsVariable);
>     …
>     File.AppendAllText(path, text, new UTF8Encoding(false));
> }

C++ 侧（`Test/GPUBackendTester/Main.cpp:8798-8814`）设置环境变量、加载 C# 探针，然后读同一个文件逐行断言：

> ::SetEnvironmentVariableA("CASCADED_CSHARP_IMPORTER_PROBE", "1");
> ::SetEnvironmentVariableA("CASCADED_CSHARP_IMPORTER_READINGS", readings.string().c_str());
> …
> auto read = [&](char const* key) { return ReadProbeValue(readings, key); };

也就是说：**读数必须由 C# 程序集内部的代码写出来**，C++ 不能直接调 C# 的 internal 方法。

## 六、结论与建议

- 照 spec/tasks 字面，C++ tester 无法直接写 `Texture2D.Parse(...)`；实现者要么改验收表述，要么偷偷加一个探针（tasks 没点名，产物归属不清）。
- 建议改法（判据不放松）：
  1. 把 spec/tasks 的「`Texture2D.Parse` / `Mesh.Parse` 读回」改成「经公开的 `AssetDatabase.Load` 读回」——它内部就是走这两个 Parse，语义等价；
  2. 若坚持直接用 internal Parse，就在 tasks 3.1 里点名新增 `Scripting/Managed/SourceImporterProbe.cs`（同 ResourceAssetProbe 形态，把读数写进 `CASCADED_SOURCE_IMPORTERS_READINGS` 指定的文件），并把「探针文件存在」写成验收产物；
  3. 无论走哪条，`tasks.md:20` 的「Texture2D.Parse/Mesh.Parse 读回」都要改，免得实现者拿不到可执行判据。
- 严重度是 misleading 而非 blocking：`AssetDatabase.Load` 提供了等价能力，工件改一句就能落成；但**按当前原文**这条验收不可执行。

## 七、边界

- 核了：两个 Parse 与 Payload 的访问修饰符、AssetDatabase.Load 的 public 声明、既有探针的读数写入形态。
- 没核：没有查 tester 是否已有反射/托管调用通道（按既有测试形态看没有；C++ 侧只读探针写的文本）。
