审查对象：`design.md` D4/D6、`tasks.md` 3.1；对照 `GeneralResources/private/ResourceImportingSystem.cpp`、`ShaderImporter_Vulkan.cpp`、`ShaderImporter_D12.cpp`、`Test/GPUBackendTester/Main.cpp`、`CAAssets` 实际内容。

## 1. 管线对「所有导入器」调 Produce，末尾无条件 SerializeAll

`ResourceImportingSystem.cpp`（逐字引文）：

> `for (ResourceImporter* importer : m_ResourceImporters)`
>
> `castl::shared_ptr<ResourceImporterProductions> productions(`
>
> `importer->Produce(),`
>
> `while (productions->HasNext())`
>
> `m_ResourceManagingSystem->ReleaseResource(relativePath);`
>
> `m_ResourceManagingSystem->RegisterResource(relativePath, resource);`
>
> `// 无论源目录在不在、导入器有没有产出：本轮的注册内容都要落盘（旧路径的早退曾跳过这里）。`
>
> `m_ResourceManagingSystem->SerializeAll();`

`SerializeAll` 写的是**全部**已注册资源（逐字引文）：

> `m_PathToResource.for_each([&](cacore::PathHash const& key, castl::shared_ptr<IResource>& val)`
>
> `castl::filesystem::path destPath = m_AssetRootPath / key.Get();`

而 `GetDestDirectory` 只进 `SetScanDirectories`（逐字引文）：

> `castl::string const declaredDest = importer->GetDestDirectory();`
>
> `path destRoot = declaredDest.empty()`
>
> `? callerDestRoot`
>
> `: path(declaredDest, cafs::path::format::generic_format);`
>
> `importer->SetScanDirectories(sourceRoot.generic_string(), destRoot.generic_string());`

→ `design.md` D4 的「② 文件落 CAAssets/Textures/*.tex」实际由「资源根 + NextPath」决定，`GetDestDirectory` 返回什么不影响写盘位置。

## 2. 着色器导入器：根存在但没有 .slang 时仍产出一条空库

`ShaderImporter_Vulkan.cpp`（逐字引文）：

> `cafs::path effectiveSourcePath(GetScanSourceDirectory(), cafs::path::format::generic_format);`
>
> `if (!cafs::exists(effectiveSourcePath))`
>
> `{`
>
> `if (!m_SourceDirectory.empty() && cafs::exists(m_SourceDirectory))`
>
> `return new resource_management::SingleResourceProductions(castl::string(), nullptr);`

（只有「根不存在」才早退；根存在就往后续走。）

> `auto* shaderLibrary = new ShaderLibrary();`
>
> `shaderLibrary->m_ShaderPrograms.clear();`
>
> `shaderLibrary->m_ShaderFiles.clear();`
>
> `shaderLibrary->m_ShaderStructs.clear();`

> `shaderLibrary->m_ShaderRootStructs.clear();`

## 4. 工件只隔离了「源」，没有隔离「目标」

`design.md` D6 与 `tasks.md` 3.1（逐字引文）：

> 预置**已知 PNG**（写死像素，如 4×4 RGBA 渐变）+ **已知 OBJ**（写死顶点/面，如立方体 8 顶点 12 三角）到临时源目录 → 触发导入 → 断言 ② 落盘文件存在 …

`design.md` Risks（逐字引文）：

> [源目录约定] → env 可配 + 默认 SourceAssets；测试用临时目录预置夹具，不动用户真实源。

对照同类资产用例 `TestCSharpAssets` 的做法（逐字引文）：

> `// 资源根：临时目录（用例自建、收尾清；按后端名分开，避免两后端并行时互相清目录）。`
>
> `std::filesystem::path root = std::filesystem::temp_directory_path() / ("CascadedAssetProbe_" + ctx.backendName);`
>
> `ctx.pResourceManagingSystem->SetResourceRootPath(root.generic_string());`
>
> `std::filesystem::remove_all(rootPath, ignored);`

工件没有对应任务（既没有临时资源根，也没有收尾清理），所以按现在的验收写法导入产物会落进仓库 `CAAssets`。

## 5. 全量名单是硬编码的 22 条，工件没写新用例不进全量

统计命令（只读）：取 `Main.cpp` 行 10799–10839 内 `runTestWithDiagnostics("` 的调用数 = **22**；`--list` 与全量是两个独立名单（`TestEditorAssetBrowser` 等只在 `--list`、不进全量）。

`tasks.md` 3.1 只写了「独立进程」，没有写「只进 --list、不进全量同进程顺序跑」；归档 change 的同类任务写明了这一条（`openspec/changes/archive/2026-11-24-editor-web-render-spike/tasks.md` 2.2 逐字引文）：

> **进 --list 不进全量同进程顺序跑**

## 6. 结论边界

本条陈述的是「一次 ScanSourceDirectory 的波及面」：扫描根选临时夹具目录 → 空 shLib 覆盖真实文件；不临时改资源根 → 新资产落用户 CAAssets。两者都不依赖新导入器自身的实现质量。
