# 证据-一致-006：资产创建路径在 proposal/design/spec/tasks 三说两不一

## 主张

同一件事（资产怎么造、谁注册）在四份工件里出现三种写法：proposal 写「复用 Texture2DFactory/AssetDatabase」；design D4 把工厂路径与「直接 new」用「或」并列；spec 与 tasks 只写「产出 Texture2D/Mesh、入迭代器、经管线注册」。既有 `resource-importer` 规范只允许「新对象经 CreateProxy」一条，所以只有「直接 new」合规；proposal 与 design 的工厂/AssetDatabase 说法要么违反规范，要么是空承诺。

## 逐字引文

`proposal.md`：

> **PNG 贴图导入器**（C# `ResourceImporterBase`）：扫源目录 `.png`，纯 C# 解码（zlib deflate via `DeflateStream` + PNG 滤波重建）→ RGBA8 像素 → `Texture2D` 资产（复用 Texture2DFactory/AssetDatabase），产出到 ② `CAAssets/Textures/*.tex`。

## 为什么是 misleading

- 它不是某一条规范被违反那么简单，而是**同一工件集内部给出互斥指令**：proposal 要求「复用工厂/AssetDatabase」，spec 要求「不调注册表、管线注册」，design 用「或」逃避选择。实施者必须先自己裁一次，而裁哪边都会让另一边变空承诺。
- 该 change 的 Impact 只列「新增 Importers/ + 门控接入 Host.cs + 测试夹具 + 用例」，没有任何「改 AssetDatabase/工厂」或「注册工厂」的任务；所以 proposal 的依赖句实际无法兑现。
- 与既有规范的关系：只有「直接 new」符合 `resource-importer` 第 24 行；这不影响归为 misleading（因为不是新规范与旧规范对撞，而是自家工件不自洽）。

## 改法

统一措辞（四处一致）：导入器在 Produce 内 `new Texture2D()` / `new Mesh()` 并填字段，交 `ResourceImporterProductionsBase`；注册/落盘/替换由管线 `ScanSourceDirectory` 做；导入器 MUST NOT 调 AssetDatabase、门面或资产工厂。删 proposal 第 9/29 行的「复用 AssetDatabase/资产工厂」，删 design D4 的「或经工厂」分支；Impact 依赖只写「导入器机制 + 管线」。

## 复核方式

1. 改后 `Select-String -Path $files -Pattern 'AssetDatabase|Factory'` 在四份工件里应只剩 0 或解释性文字（不再作为实现要求）。
2. `openspec validate source-importers-png-obj` 仍 valid。
3. 实施时按 tasks 2.1/2.2 的 grep 判据验证导入器文件不含门面/数据库符号（见 证据-一致-004）。
