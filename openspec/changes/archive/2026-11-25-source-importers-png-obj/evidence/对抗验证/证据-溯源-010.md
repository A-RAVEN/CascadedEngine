# 证据-溯源-010：「C# 读不到管线扫描根」属实，不是编的限制

> 定位以逐字引文为准；行号是 2026-11-24 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-010
- 攻击面：无中生有（凭空造一条反向接口限制，给「目录自声明」找理由）
- 严重度：falsePositive（限制真实存在，有头文件注释与生成基类双重证据）
- 工件：`design.md:22`
- 一句话：原生侧把扫描根写进 `ResourceImporterScanContext`，C# 反向基类没有对应入口，所以 C# 导入器必须自己声明目录。

## 二、工件原文

`design.md:22`：

> - `GetSourceDirectory` 返回 ① 源目录（env `CASCADED_SOURCE_IMPORTERS_DIR` 覆盖，默认仓库根/SourceAssets）；`GetDestDirectory` 返回 ② 目标（CAAssets 下 Textures/ 或 Meshes/）。**C# 反向读不到管线扫描根（ResourceImporter.h 注释），目录自声明。**

## 三、代码原文

`GeneralResources/header/CAResource/ResourceImporter.h:25-28`：

> //   * `GetSourceDirectory()` / `GetDestDirectory()` 返回**空** = 导入器跟随管线传入的根；
> //     管线把有效根写进这里，原生导入器在 Produce() 里读 `GetScanSourceDirectory()`。
> //   * C# 反向实现读不到这两个值（托管代码没有入口），所以 C# 导入器 MUST 在自己的
> //     GetSourceDirectory()/GetDestDirectory() 里声明目录 —— 不能留空。

`GeneralResources/header/CAResource/ResourceImporter.h:55-58`（同一个接口的三个目录方法，只出不进）：

> // 导入器自己固定的源根；**空 = 跟随 ScanSourceDirectory 传入的根**（见基类注释）。
> virtual castl::string GetSourceDirectory() const = 0;
> // 导入器自己固定的目标根；空 = 跟随资源系统的资源根（同样见基类注释）。
> virtual castl::string GetDestDirectory() const = 0;

`GeneralResources/private/ResourceImportingSystem.cpp:64-65`（只有原生侧写）：

> // 原生导入器从这里读有效根（C# 反向实现读不到，必须自己声明目录）。
> importer->SetScanDirectories(sourceRoot.generic_string(), destRoot.generic_string());

`out/build/x64-debug/codegen/bindings/resource_management__ResourceImporter.Bindings.cs:14-26`（托管侧基类全部成员）：

> public abstract string GetTags();
> public abstract string GetSourceDirectory();
> public abstract string GetDestDirectory();
> public abstract ResourceImporterProductionsBase Produce();

没有 `GetScanSourceDirectory` / `GetScanDestDirectory` 之类的属性，也没有把 `SetScanDirectories` 投到托管侧。

`Scripting/Managed/ResourceImporterProbe.cs:93-98`（既有先例，用 env 自声明源目录）：

> // C# 反向实现读不到管线传入的扫描根（见 ResourceImporter.h 的注释），
> // 所以目录必须自己声明；这里给工程根的 CAResources（C++ 侧只核"非空"）。
> public override string GetSourceDirectory()
> {
>     return Environment.GetEnvironmentVariable("CASCADED_CSHARP_IMPORTER_SOURCE") ?? string.Empty;
> }

## 五、结论与建议

- 不成立（falsePositive）：「C# 读不到扫描根」是真实存在的反向面限制，`design.md:22` 的说法与头文件注释、生成基类、既有探针三处一致。
- 一个精确化建议（与主张-溯源-016 呼应）：读不到**扫描根**是真的，但「GetDestDirectory 声明了目标就影响落盘位置」是另一回事——管线只用 NextPath 当注册键/落盘相对路径，GetDestDirectory 只被写进原生 scan context 且 C# 读不到。design 里把这两件事写在一句里，容易让实现者以为 NextPath 可以只写文件名。见主张-溯源-016。

## 六、边界

- 核了：头文件注释、接口声明、管线写入点、生成基类的全部抽象成员、既有探针的用法。
- 没核：没有跑任何导入（只读环境）；没有别的语言绑定面（本批只涉及 C#）。
