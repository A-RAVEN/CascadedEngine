# 证据-溯源-002：「五种滤波」的名称与数量属实

> 定位以逐字引文为准；行号是 2026-11-24 审查时实测值。

## 一、主张摘要

- 主张编号：主张-溯源-002
- 攻击面：无中生有（怀疑滤波种类数量或名称是编的）
- 严重度：falsePositive（核到规范逐字一致）
- 工件：`design.md:28`、`tasks.md:9`、`spec.md:5`
- 一句话：PNG 滤波方法 0 恰好有 5 种：None / Sub / Up / Average / Paeth，工件写的名称与数量都对。

## 二、工件原文

`design.md:28`（节选）：

> +IDAT（跳 2 字节 zlib 头用 DeflateStream 解压）+逐扫描线五种滤波重建（None/Sub/Up/Average/Paeth）

## 三、规范原文（RFC 2083，本地 rfc2083.txt）

目录第 91-95 行：

> 6.2. Filter type 0: None ...................................... 32
> 6.3. Filter type 1: Sub ....................................... 33
> 6.4. Filter type 2: Up ........................................ 33
> 6.5. Filter type 3: Average ................................... 34
> 6.6. Filter type 4: Paeth...................................... 35

第 1733 行（滤波在压缩前的形态）：

> compression step, each scanline is preceded by a filter type byte

即滤波类型是**每扫描线一个字节**，取值 0-4；工件点名的五种与规范章节标题逐字一致。

## 五、结论与建议

- 不成立（falsePositive）：名称、编号、数量都属实，不需要改。
- 一个不构成缺陷的提示：工件只写了名字，没写每像素字节数 bpp（Sub/Average/Paeth 的「左邻字节」是按 bpp 回看的）。这是实现细节详略问题，不是事实错误；实现时按颜色类型/位深算 bpp = 通道数（RGB 为 3、RGBA 为 4）即可。

## 六、边界

- 核了：RFC 2083 第 6.2-6.6 节目录、第 1733 行的「每扫描线一个滤波字节」。
- 没核：没有读 PNG 第三版（W3C）正文，因为五种滤波自 PNG 1.0 以来未变；也没有跑任何解码代码。
