# 证据-影响-003：「导入器不调注册表」的 grep 判据可被工件点名的 AssetDatabase 路线喂绿

审查对象：`design.md` D4、`proposal.md` What Changes、`spec.md`「导入必须与注册分离」；对照 `Scripting/Managed/Assets/AssetDatabase.cs`、`Scripting/Managed/ResourceAssetProbe.cs`、`GeneralResources/private/ResourceImportingSystem.cpp`、`Scripting/Managed/Host.cs`。

## 1. 工件同时给了两条实现路线，其中一条经门面注册

`design.md` D4（逐字引文）：

> 导入器 NextResource 交出 Texture2D/Mesh（经 Texture2DFactory/MeshFactory 的 Create 入队 + AssetDatabase 出队填数据，沿用 csharp-resource-asset-foundation D4/D5 模式；或直接 new 资产填数据交迭代器，由管线 CreateProxy 注册）。

`proposal.md`（逐字引文）：

> 纯 C# 解码（zlib deflate via `DeflateStream` + PNG 滤波重建）→ RGBA8 像素 → `Texture2D` 资产（复用 Texture2DFactory/AssetDatabase），产出到 ② `CAAssets/Textures/*.tex`。

`spec.md`（逐字引文）：

> 导入器 MUST 纯转换（Produce 产迭代器，NextResource 交资产），MUST NOT 调注册表（RegisterResource/ReleaseResource/CreateResource/GetOrLoadResource/GetOrNewResource grep 0）

`tasks.md` 2.1/2.2 的验收（逐字引文）：

> **不调注册表**（五写入口 grep 0）

## 2. AssetDatabase.Create 的第一步就是注册表门面调用

`AssetDatabase.cs`（逐字引文）：

> /// <summary>新建：门面 `CreateResource`（注册表查工厂 → Create → 注册）→ 从工厂队列取出对象。</summary>
>
> `public ResourceBase Create(string typeName, string path)`
>
> `{`
>
> `m_registry.CreateResource(typeName, path);`
>
> `return AssetFactoryBase.Dequeue(typeName);`
>
> `}`

查询命令与输出（pwsh，只读）：

```powershell
Select-String -Path 'E:\Projects\CascadedEngine\Scripting\Managed\Assets\AssetDatabase.cs' `
  -Pattern 'RegisterResource|ReleaseResource|CreateResource|GetOrLoadResource|GetOrNewResource'
```

```text
34: m_registry.CreateResource(typeName, path);
57: m_registry.ReleaseResource(path);
（其余命中行均为注释：第 16、17、31、46 行）
```

即：导入器文件里 grep 五个名字 = 0，但调用经 `AssetDatabase.Create` 到达 `CreateResource`。

## 5. 结论边界

本条不判断哪条实现路线「应该」被采用；它只说明：工件自己写进 D4/proposal 的 AssetDatabase 路线会在 Produce 内触发注册表写，而验收判据（导入器文件 grep 五写入口 0）对这条路径恒绿；并且该路线还依赖一个只有资产探针门控才会注册的工厂。
