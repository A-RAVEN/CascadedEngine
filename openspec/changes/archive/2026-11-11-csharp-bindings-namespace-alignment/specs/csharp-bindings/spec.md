# csharp-bindings 增量

## MODIFIED Requirements

### Requirement: 跨头文件接口投影必须有构建期已知接口清单
`build.py` SHALL 先通过 `CodeGen.exe --list-bind-interfaces` 从每个主头实际 `CA_BIND` 形状收集 `<短名>=<完整限定名>`，聚合后通过重复的 `--known-interface <短名>=<完整限定名>` 传给正式生成。`CODEGEN_BINDINGS` 的期望产物前缀只用于产物存在性检查，MUST NOT 被当作完整接口清单。已知清单 MUST 只用于类型投影和诊断，不得让未在主头文件标注的接口额外生成产物。

跨头文件返回抽象接口时，目标接口的完整限定名 MUST 在已知清单中，否则生成器 MUST 非零退出并说明缺少哪个目标。非接口数据对象的智能指针返回可以继续只提供原生发行者句柄，但不得因此生成伪造的公开 C# 资源对象。共享公开类型与接口的身份 MUST 以完整限定名为准（短名只作显示名）；两个不同 C++ 类型映射到同一 C# 全名（命名空间镜像路径 + 类名）MUST 非零退出并点名冲突双方，不得只凭短名或部分限定名猜测目标（例：`AB::Widget` 与 `Ab::Widget` 都映射为 `Ab.Widget`，必拒；`a_b::Widget` 与 `a::b::Widget` 分别映射 `AB.Widget`/`A.B.Widget`——`::` 分层、`_` 层内分段拼接——合法共存）。

#### Scenario: 分头生成的发行接口与资源接口能够组合
- **WHEN** 资源接口和发行接口位于不同头文件，构建清单包含双方并分别运行生成器
- **THEN** 发行接口的公开 C# 方法 MUST 返回目标资源表面对象，目标接口的函数表 MUST 能解析和释放返回句柄，托管构建不得缺少目标类型

#### Scenario: 清单来自实际标记而非部分期望产物
- **WHEN** 一个输入头包含多个 `CA_BIND` 接口，而 `CODEGEN_BINDINGS` 的期望产物前缀只列其中一部分
- **THEN** 收集清单 MUST 仍包含全部实际标记接口及其完整限定名，既有跨接口返回不得因未列入期望前缀而被判未登记

#### Scenario: 跨命名空间同名接口各自成面
- **WHEN** 两个命名空间中存在同短名接口（如 `ns1::Device` 与 `ns2::Device`），都被标注进同一构建
- **THEN** 两者 MUST 各自生成到自己的镜像命名空间、各自经 `--update-ids` 追加发号入登记表（既有锁行一字不动），构建 MUST 全绿——MUST NOT 以同短名为由拒绝（用户 2026-11-09 裁定：拒绝跨命名空间同名等于牺牲 C++ 接口易用性）

#### Scenario: 映射后全名冲突必须拒绝
- **WHEN** 两个不同的 C++ 类型经命名空间镜像映射后得到同一 C# 全名（如 `AB::Widget` 与 `Ab::Widget` 都映射为 `Ab.Widget`），或已知清单条目与返回目标的完整限定名不一致
- **THEN** 生成或清单聚合 MUST 非零退出并点名冲突双方的完整限定名，MUST NOT 只凭短名选择目标接口

#### Scenario: 未登记抽象接口不得生成悬空公开类型
- **WHEN** 一条跨头文件方法返回一个具有纯虚方法、但不在构建期已知清单中的接口
- **THEN** 生成器 MUST 非零退出并点名目标接口与缺失清单，不得留下引用不存在 C# 类型的产物

### Requirement: 接口编号由锁文件治理，标注与判据脚本都不携带编号
进入宿主登记表的接口，其编号的唯一来源 MUST 是入库文件 `Tools/CodeGen/interface-ids.lock`（数据行制表符四列：编号、短名、完整限定名、头文件路径；按 `# scope host` / `# scope fixture` 注释分段，每段带该段历史最高号水位——短名列在本批起为显示名，身份以完整限定名列为准）。`CA_BIND` 标注 MUST NOT 带编号参数——带编号的标注 MUST 被生成期非零拒绝并点名；`Tools/CodeGen/check_bindings.py` MUST 以锁文件为期望来源，MUST NOT 保留手抄编号表。默认构建只做核对，**口径一律按段**：段内编号唯一、段内从该段起点连续、登记表输入的接口限定名集合与锁内该段限定名集合完全相等（多一行少一行都点名）——宿主段与夹具段是各自独立的号空间，夹具段永不进宿主路由，构建模式 MUST NOT 改写锁文件。分配新编号 MUST 只经显式 `--update-ids` 模式：既有名字的号保持不动，新名字由工具自动取该段下一个可用号并推进水位，其余行一字不动。"编号与名字的绑定"一旦变化（改号、换号），生成常量与 `Tables` 清单必然变化，MUST 被"产物逐字节基线对账"抓到——构建核对不承诺抓名字集合不变的换号。编号换源前后，既有全部绑定产物与登记表产物 MUST 逐字节不变。

#### Scenario: 标注上写编号必须被拒绝
- **WHEN** 某个进入登记表输入的接口写成了 `CA_BIND(8)`
- **THEN** 生成器 MUST 非零退出并点名该接口，文本 MUST 说明编号由锁文件治理、标注只声明绑定意图；MUST NOT 产出任何登记产物

#### Scenario: 新接口进表由工具发号，人不接触数字
- **WHEN** 一个无参 `CA_BIND` 接口新进入登记表输入而锁里没有它，先跑 `--update-ids --config Debug` 再跑构建
- **THEN** `--update-ids` MUST 只在锁中追加它一行（该段下一个可用号），既有行逐字不动；随后构建 MUST 通过，且该号在登记表 C++ 常量、托管编号常量与 `Tables` 清单三处一致

#### Scenario: 删行与换号分别有各自的抓法
- **WHEN** ①删除锁中任一接口行后重跑构建；②把锁中两行的编号互换（限定名集合不变）后重跑构建与产物对账
- **THEN** ①构建 MUST 非零并点名受影响接口；②构建核对 MAY 通过，但产物逐字节基线对账 MUST 不一致并点名差异文件；两态还原后 MUST 全绿且哈希复锚

## ADDED Requirements

### Requirement: C# 绑定命名空间必须镜像 C++ 完整限定名
生成器发射的公开托管类型 MUST 按接口完整限定名的命名空间部分分层落命名空间：命名空间按 `::` 与 `_` 分段、每段首字母大写其余小写，拼于根 `Scripting.Generated.Bindings` 之下（`graphics_backend::GPUGraph` → `Scripting.Generated.Bindings.GraphicsBackend.GPUGraph`），类名保持原样；夹具段接口同规则。平铺命名空间（全部类型直挂根下）MUST NOT 再出现。C ABI 槽名、函数表与登记表产物名 MUST 以限定名线形（命名空间段与短名、方法名以双下划线 `__` 分隔）命名，短名槽名 MUST NOT 再出现。产物文件名（`<限定名线形>.Bindings.cs/.cpp`）与文件内 C++ 辅助标识符（thunk/fromC/LayoutFieldData/Handle/错误码枚举等）MUST 同限定名线形——同短名不同命名空间的接口同构建时产物不得互相覆盖、同翻译单元不得重定义。锁文件、审计表、check 判据与绑定失败点名文本 MUST 以完整限定名为身份键。

#### Scenario: 跨命名空间同名接口同构建共存
- **WHEN** 夹具或真实头里 `ns1::Device` 与 `ns2::Device` 同时挂 `CA_BIND` 进同一构建
- **THEN** 两个镜像命名空间各自生成完整表面，登记表两行各自发号，构建与全部判据 MUST 全绿

#### Scenario: 映射后全名冲突生成期点名
- **WHEN** `AB::Widget` 与 `Ab::Widget` 这类映射后同全名（都映射为 `Ab.Widget`）的两个类型同构建
- **THEN** 生成器 MUST 非零退出并点名双方完整限定名与映射结果；MUST NOT 产出任一表面

#### Scenario: 同短名接口产物不互相覆盖
- **WHEN** `ns1::Device` 与 `ns2::Device` 同构建发射产物并被登记表 include 进同一翻译单元
- **THEN** 两份产物文件名与文件内辅助标识符各自带限定名线形，磁盘互不覆盖、编译无重定义；产物清单（登记/期望前缀）两行各自在案

#### Scenario: 既有接口迁移后旧平铺引用为零
- **WHEN** 本批迁移完成后全仓搜索旧平铺命名空间引用（`Scripting.Generated.Bindings` 后紧跟非命名空间段）与旧短名槽名
- **THEN** MUST 0 命中；糖层、宿主、测试与判据脚本全部改用镜像命名空间与限定名线形槽名
