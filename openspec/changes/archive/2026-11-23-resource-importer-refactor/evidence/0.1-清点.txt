## 六、开工即发现的阻塞（设计与生成器能力不符，v2 D2）

两条接口形状在生成器里都拿不到可用产物；逐条核到代码：

1) 反向投影的参数只支持标量
- Tools/CodeGen/CodeGenMain.cpp 第 7819-7838 行：逐参 `findReverseScalar(...)`，为空即打印拒绝
  （第 7825-7829 行消息逐字含：`参数 %zu 的形状 ... 不在反向投影支持的形状里（只支持标量参数；其它形状要另立批并在 README 登记）`）
- Tools/CodeGen/README.md 第 1137-1139 行逐字：`支持的方法形状只有四种（其余生成期拒绝并点名）`：
  `void` / 标量参数与返回、`castl::string` 返回、`void Serialize(WBatch*)` 写路径、返回另一个反向接口的裸指针
- 夹具实证：Tools/CodeGen/BindableShapes.Reverse.h 第 19-25 行只有标量参数（Add(int32_t,int32_t)、Describe()、Reset()、IsReady()）
⇒ `ResourceImporter::Import(castl::string const&, castl::string const&, IImportOutput*)` 的第 1 个参数就会被拒。

2) 正向投影没有"形参是反向接口裸指针"的映射
- CodeGenMain.cpp 第 4029-4046 行：非标量裸指针落到兜底 `params->push_back({bare + "C const*", name})`
  ⇒ `IResource*` 会变成 `IResourceC const*`（不存在的类型）
- 托管表面在第 13053-13059 行对不映射的形参整条跳过（消息逐字：`[托管表面] 跳过 %s::%s —— 返回/形参里有本轮不映射的形状`）
⇒ `IImportOutput::Add(castl::string const&, IResource*)` 生成不出可调的 C# 表面（且 C ABI 结构里会出现 `IResourceC`）。

3) 结论
- spec 的 Scenario「生成 MUST 不拒绝（rejected=0）」在现工件形状下不可能通过；
- 要满足它只有两条路：改生成器（与任务书「不扩生成器」和 design D2「无需 CodeGen 形状扩展」冲突），
  或改接口形状（与 spec Requirement「Import MUST 为 (string, string, IImportOutput*)」冲突）。
- 两条路都要先改工件，故按停工条件「设计与规范冲突」上报主循环修订；在此之前不动实现代码，避免按错误形状返工。
