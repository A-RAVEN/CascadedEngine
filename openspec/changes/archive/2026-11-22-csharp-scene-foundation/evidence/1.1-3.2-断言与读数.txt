  证据（`probe=scene-format` 行）：
    rtChecked=54 rtMismatch=0 file1Bytes=1734 file2Bytes=1734 diffBytes=1 reloadDeltaMicros=500000
  判读：54 = 2 实体 × 26 个字段（id / name / position 3 / rotation 3 / scale 3 / meshRenderer 非空 /

        reloadDeltaMicros=500000 ⇒ 再从磁盘读回来读到的就是改后的值（差 0.5，按微秒精确相等）。
  判据落点：`E_SCENE_ROUNDTRIP`（rtChecked=54 / rtMismatch=0 / diffBytes>0 / reloadDeltaMicros=500000）。

这些判据怎么变红（可失败性）
======================================================================
· `E_SCENE_IDENTITY`   ：Entity.Create 不复用 Guid（例如 id 写成空串 / 用编辑器整数编号）⇒ 36 字符检查或 id 相等检查红。
· `E_SCENE_ROUNDTRIP` ：SceneCodec 改用 `JsonSerializer.Serialize(生成镜像)`（public 字段被 STJ 漏掉）⇒
                        rtMismatch 涨 / rtChecked 变 0；漏写某个字段 ⇒ diffBytes 变 0。
· `E_SCENE_TRUNC/VERSION/MISSING_ID`：Load 里把抛异常改成「补默认值继续」⇒ 读数变成 `none`（已实测：
                        正例读数是 `SceneFormatException` 这五个词，改成吞掉就立刻不是它）。
· `E_SCENE_DT`         ：`CASCADED_CSHARP_SCENE_SELFTEST=skip-onupdate`（Debug 自检开关，见 SceneRuntime.cs）
                        ⇒ OnUpdate 不被调、lastDtMicros=0 ⇒ 红。
· `E_SCENE_PIXEL`      ：`CASCADED_CSHARP_SCENE_SELFTEST=bad-color` ⇒ 顶点色被换成蓝色、中心不再是纯红 ⇒ 红。
· `E_SCENE_TRANSFORM`  ：把 Rotation 也施加到顶点（或漏掉 Scale/Position）⇒ 读数不再是 (-250000,-500000,0)。
· `E_SCENE_RENDER`     ：一实体一 pass（不按着色器分组）⇒ pass 数变 4 而不是 2；漏掉离屏目标 ⇒ capture=0。
· `E_SCENE_BAD_RES`    ：把「着色器没登记」改成静默 `continue`（跳过该实体）⇒ Tick 回值正常、LastError 里没有那个路径 ⇒ 红。
· `E_SCENE_UNREGISTER` ：Unregister 只置空引用不释放表面 ⇒ pass/present 不为 0 ⇒ 红。
· `E_SCENE_IDLE`       ：无活动场景时也建图 / 调钩子 ⇒ onStart/onUpdate/renderFrames 不为 0 ⇒ 红。

（红态实跑读数：`skip-onupdate` 与 `bad-color` 两档由主循环代跑后追加到本文件末尾。）
