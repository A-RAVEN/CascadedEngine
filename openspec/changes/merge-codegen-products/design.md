## Context

现在每个类型出三份头：`<类型名>.Reflection.h` / `.Serialization.h` / `.Hash.h`（`build.py` 的
`CODEGEN_PRODUCTS = ["Reflection", "Serialization", "Hash"]` 决定文件名中段），76 条清单 = **228 份产物**，
全部落在构建目录 `codegen/<模块>/` 下，源码树里没有它们。

`build.py` 的生成段为这三份做的事（每一件都要跟着改）：登记时**先写三个占位文件**（让别的行的 `#include`
在冷启动时解析得到）、跑一次 `--emit-all`、按工具打印的 `CodeGen wrote: ` 名单**逐个核对三份都写出来了**、
把它们的存在性记进账本 `codegen.stamp.json`、失败的行的占位文件删掉。

消费侧：**26 个源码文件、267 行** include（`Reflection` 79 / `Serialization` 88 / `Hash` 100）。
按"文件 × 类型"配对算，合并后是 **137 行**。26 个文件里 12 个含三节、4 个含两节、1 个混合、9 个只含一节。
（这一组是执行时实测的读数。成文时写的是 270 / 80 / 89 / 101、138 与"12-6-8"，那是施工中途取的数、
收尾没重量，误差 3 行 / 1 行的根因与逐项读数见 `evidence/baseline-products.md` 的「1.3」一节。）

**这件事已经出过一次事故**：漏 include 一份生成物 → 同一个类型的哈希在那个编译单元里走了另一条分支 →
链接期合并后整个二进制的该类型哈希口径被换掉（`clear-codegen-parse-blockers` 的 design D10，含改前/改后读数
与两次对照构建）。合并成一份不去治那条根，但把"漏哪一份"这个判断去掉。

## Goals / Non-Goals

**Goals:**

- 一个类型在构建目录里只有**一份**生成物：`<类型名>.codegen.h`，含这次请求的节（反射 / 序列化 / 哈希）。
- 每节正文与改造前**由同一段发射代码产出**（判据：用 `-o` 单节输出与改造前的同名产物逐字节比，76 × 3 = 228 次全同）。
- 命令行的搭配关系与拒绝语义一个都不动（含 `--out-dir` 只与 `--emit-all` 搭配这条）。
- 26 个消费文件的 include 从 267 行收到 137 行；源码树里旧后缀**零命中**；所有 preset 的构建目录里旧命名产物**零残留**。

**Non-Goals:**

- 不改"漏了就静默换算法"这条兜底（ODR 的根）。
- 不把递归模板搬到生成器（另一个 change）。
- 不改接入清单 76 行、不新增开关、不改判定逻辑。
- 不做生成目录的整目录 GC（见 D5 的边界说明）。

## Decisions

### D1 文件名：`<类型名>.codegen.h`

- **不叫 `<类型名>.h`**：生成目录在 include 路径上（各模块 `CMakeLists.txt` 把 `${CMAKE_BINARY_DIR}/codegen/<模块>`
  加进去），与真实头同名会**遮蔽**真实头（例如 `ShaderLibrary.h`）。
- **不叫 `<类型名>.Generated.h`**：现有读法是"点分后缀"（`EmitSample.Reflection.h`），`.codegen.h` 直接说清
  "这一份全是 CodeGen 出的东西"，也便于写"旧后缀零残留"这条判据。
- **备选（否决）**：三份照旧、由 `build.py` 拼第四份 —— 多一道拼接，且"三份必须一致"没有任何地方保证。

### D2 合并文件的结构

固定顺序 **反射 → 序列化 → 哈希**；文件头注释、`#pragma once`、运行时头的 `#include`
（`CodeGenMeta.h` / `CodeGenSerialization.h` / `CodeGenHash.h`）各出现一次；每节保留自己的
`// Generated by CodeGen <某个> emitter for <类型>` 注释行。

⚠ **由此产生的一条边界（原稿写错过，这里写死）**：合并文件里的节**不可能**与旧的三份文件逐字节相同 ——
旧文件每份都自带 `#pragma once` 与运行时头 include，而合并文件里这些只出现一次。所以"每节逐字节不变"这条
不变量**只能通过 `-o` 单节输出对拍来证明**（`-o` 的输出与旧产物逐字节相同，已实测），不能拿"切出来的段"去比。

### D3 拒绝语义不动（`--emit-all` 仍要求三节都能出）

- **备选（否决）**：改成"能出哪节出哪节"。否决理由：静默省略是本项目反复禁止的形态；接入清单 76 行
  全部用 `CA_REFLECT(serializable)` 标注（任务里要逐条复核），让退出码 9 继续当错误更安全。
- 不变量清单：**2 / 5 / 6 / 9 / 10 / 13 / 14 / 15 / 16 / 17**。**退出码 6 与 5 必须进清单** ——
  6 的原文是"解析不可信：环境残缺…或文件本身有错误级诊断"，而占位文件改名、跨行 include 正是本次改动唯一
  会碰到的路径，弄坏它最容易报 6；5 是"含非公有成员"的拒发码，也在同一段判定里。
- 判定逻辑（`scanDiagnostics` / 各发射器的守卫）**一行不改**。

### D4 `--out-dir` 与 `-o` 的搭配关系保持原样（原稿把今天的行为写错了）

实测今天的输出（退出码 2）：

```
CodeGen: --out-dir only applies together with --emit-all; use -o <file> for a single emitter.
```

所以：`--emit-reflection --out-dir <目录>` 今天**不是**"写 `<类型名>.Reflection.h`"，而是一个用法错误。
本 change **保持这条契约**：`--out-dir` 仍只与 `--emit-all` 搭配（一次写一份合并文件）；单节输出走 `-o <路径>`
（对拍判据正是用这条现成能力）。不新增开关、不放松用法检查。

### D5 旧命名的产物必须清掉，且覆盖**所有 preset**

- 生成段在跑之前清掉 `out/build/*/codegen/**/<类型名>.{Reflection,Serialization,Hash}.h`。
- 为什么"先清再生成"：任何漏改的 `#include "<类型名>.Hash.h"` 会在解析或编译时**当场失败**
  （`file not found` / `C1083`），而不是静默用上一轮的旧文件。
- **边界与后果（必须写明）**：只清"旧命名的三份"，**不做整目录 GC**。因此**新文件名那边的孤儿产物不会被清** ——
  某个类型从接入清单里删掉之后，它在构建目录里留下的 `<类型名>.codegen.h` 会一直躺着（今天三份命名的产物
  也有同样的问题）。本次不处理它：要处理得先定"哪些文件算 CodeGen 的产物"这条判据（按扩展名扫会误删无关文件），
  那是另一件事；这里只把边界与后果写清楚。

### D6 核心不变量的判据：用 `-o` 单节输出与基线逐字节比（228 次）

- 改工具**之前**：把当前构建目录里的 228 份产物**保持目录结构**复制到 `%TEMP%\codegen_baseline_merge\`，
  并记下**取数时的 git 状态**（HEAD 提交号 + `git status` 的改动文件数）—— 工作区带着未提交的改动，
  不记状态这份读数别人复现不了。
- 改完之后：对每个类型、每一节，用 `-o <路径>` 输出到**另一个临时目录**（不许写进基线目录，否则就是自己跟自己比），
  与基线同名文件逐字节比较。
- 这条判据能失败：合并时若把节写错、去重掉多了/少了、或发射代码被动过，就不相等。

### D7 `build.py` 的账本与占位按一份改

- `CODEGEN_PRODUCTS` 三个后缀 → 一个；`outputs` 一份；占位文件一份；`absent` 核对一份；账本 `out` 映射一份。
- 核对逻辑要**防"键名改错导致空检查"**：改完之后必须能在"工具说写了一份、但那一份不在磁盘上"时失败
  （任务里用一次故意的改名来实测这条仍然有效）。
- 指纹因此变化 → 第一次构建预期**全量重跑 76 条**。

### D8 被本改动推翻的既有判据要同改

`openspec/changes/archive/2026-10-07-clear-codegen-parse-blockers/evidence/probe_parse_gate.py` 里逐字写着
`PRODUCTS_EXPECTED = 3`，绿态判据是"四个类型各写出 3 份产物"。合并成一份之后它必然报
`只写出 1 份产物（应为 3 份）`。这是**本改动造成的失效**，必须同改（改成一份，并把"产物份数"这条判据
与"不出现 `no annotated types`"一起保留）。顺手把该文件的注释里"三份"字样改掉。
另有一条**归档**造成的失效（不是本改动）：同一个文件里逐字写着 `REPO = Path(__file__).resolve().parents[4]`，
那个层数是按归档前的位置（`openspec/changes/<change>/evidence/`）写的，归档之后落到 `openspec/` 而不是
仓库根，跑之前要改回来。

### D9 回滚与工作区重叠（原稿那句会毁掉上一份成果）

- 本 change 要改的文件与 `clear-codegen-parse-blockers` **未提交的改动重叠**：`GPUPipelineInstance.{h,cpp}`、
  `GPUGraph.h`、`CPipelineStateObjectAssertions.cpp`、`GeneratedHashTest.cpp`、`build.py`、`Tools/CodeGen/README.md`。
- 所以：① **执行前先把那一份提交**（用户下令才提交；没下令就先把那批文件复制到 `%TEMP%` 留一份可恢复副本）；
  ② design 里的回滚说明**不许**写成"`git checkout -- <文件>` 即可" —— 那句话在未提交状态下会把上一份成果一起抹掉；
  要写清"回滚只回滚本 change 引入的差异，且必须先确认上一份已提交或已备份"。

## Risks / Trade-offs

- [漏改某个消费点] → 三条判据：源码树旧后缀零命中（grep 限定 `*.h` / `*.cpp`，排除 `openspec/` 与脚本注释）、
  所有 preset 的构建目录里旧后缀 0 份、构建必须过。漏改会在解析/编译期当场失败（D5 为此把"先清再生成"定死）。
- [合并时内容被改坏] → D6 的 228 次对拍，且输出到独立临时目录。
- [README 与工具报错文本继续写三份] → `verify_readme.py` 只跑示例、**覆盖不到描述性段落**，所以任务里另加
  关键句 grep（锚点要具体到新文件名与"一份"的搭配，不许用"一份"这种会恒真的词）。
- [`check_legacy_symbols.py` 的扫描读数是"源码 + 构建目录"，不是产物件数] → 任务里把两个量分开写，
  不许拿 517 这种数与"228 → 76"并排。
- [26 个编译单元多解析 241.5 KB（平均每个 9.3 KB）] → 已量化，相对运行时头可忽略；不改。
- [跨代文档仍写三份] → 仓库内的 `.claude/workflows/scripts/verify-codegen-tasks-order.js` 要改；
  `~/.dsh/AGENTS.md` 里那份对照表（逐字写着 `<类型>.{Reflection,Serialization,Hash}.h`）在仓库之外，
  本次只能**报告给用户**、不擅自改。

## Migration Plan

0. **前置**：确认 `clear-codegen-parse-blockers` 的改动已提交或已备份（D9）。
1. 固化基线：复制 228 份产物到 `%TEMP%`（保持目录结构），记下 HEAD 提交号、`git status` 改动数、件数与总字节。
2. 改工具（`CodeGenMain.cpp`）：命名、合并写入与去重、`CodeGen wrote: ` 一行、用法文本、`--emit-all` 报错文本；
   **不动判定逻辑**。
3. 改 `build.py`：`CODEGEN_PRODUCTS`、占位、核对、账本，外加**所有 preset** 的旧产物清理。
4. **一次性改完 26 个消费文件**的 include（12 个各删两行、6 个各删一行、8 个只改名字），
   **不引入"新旧都写"的过渡开关** —— 替换是机械的、失败立刻可见，留过渡开关反而会变成"静默不生效的钩子"。
   注意第 3 步"先清再生成"一旦生效，消费点还写着旧名字就会构建失败，所以这两步要在同一次改动里做完。
5. 同改 D8 的探针、`CLAUDE.md`（先核）、README。
6. 全量构建（`--codegen-all`）→ 228 次对拍 → `CoreTests` → 两个后端 tester → 扫描器 → 文档复核。
7. 回滚：见 D9（先确认上一份已提交/已备份；只回滚本 change 的差异）。
